# NumPy

> _Массив вместо цикла: считаешь над миллионом чисел одной строкой_

---

**NumPy** (Numerical Python) — фундамент научных вычислений на [Python](../../Python.md). Его ядро — **ndarray**, быстрый массив чисел одного типа. Операции над ним идут не питоновским циклом, а сразу над всем массивом на скомпилированном C-коде — отсюда скорость в десятки раз выше списков. На NumPy стоят [pandas](../../Библиотеки/Сторонние/pandas.md), scikit-learn и почти вся ML-экосистема.

## Зачем, если есть списки

Список Python хранит указатели на разнотипные объекты, разбросанные по памяти, — перебор его циклом медленный. **ndarray** хранит числа одного типа компактным блоком в памяти, а операции применяет ко всему массиву разом (векторизация).

```python
# чистый Python — цикл, медленно
result = [x * 2 for x in range(1_000_000)]

# NumPy — векторизация, быстро и коротко
import numpy as np
result = np.arange(1_000_000) * 2
```

## ndarray — создание

```python
import numpy as np

np.array([1, 2, 3])            # из списка
np.zeros((2, 3))               # матрица 2×3 из нулей
np.ones(5)                     # вектор из единиц
np.full((2, 2), 7)             # матрица 2×2, забитая семёрками
np.eye(3)                      # единичная матрица 3×3: единицы по диагонали
np.arange(0, 10, 2)            # [0 2 4 6 8] — как range, но массив
np.linspace(0, 1, 5)           # 5 точек от 0 до 1 включительно
np.random.rand(3, 3)           # 3×3 случайных числа [0, 1)
```

> **`arange` против `linspace`.** У `arange` задаёшь **шаг** и не контролируешь число точек, у `linspace` — **число точек** и не считаешь шаг. Для дробного шага бери `linspace`: `arange(0, 1, 0.1)` из-за неточности float может дать 10 элементов, а может 11.

## Атрибуты массива

Массив описывают пять свойств — первые три ключевые:

- **`shape`** — форма (размеры по осям): `(2, 3)` — 2 строки, 3 столбца;
- **`dtype`** — тип элементов (`int64`, `float64`); один на весь массив;
- **`ndim`** — число измерений (осей);
- **`size`** — сколько всего элементов (произведение `shape`);
- **`itemsize`** — сколько байт занимает один элемент.

```python
a = np.array([[1, 2, 3], [4, 5, 6]])
a.shape     # (2, 3)
a.dtype     # int64
a.ndim      # 2
a.size      # 6      — всего элементов
a.itemsize  # 8      — байт на элемент (int64 = 64 бита)
a.nbytes    # 48     — весь массив: size × itemsize
```

### dtype — и чем он опасен

Тип у массива **один на всех** и выбирается при создании. Это источник скорости — и источник двух ловушек.

```python
np.array([1, 2, 3]).dtype           # int64   — целые
np.array([1, 2, 3.0]).dtype         # float64 — одно дробное «поднимает» весь массив
np.array([1, 2, 3], dtype=np.int8)  # тип можно задать руками
```

```python
# ЛОВУШКА 1 — переполнение: тип не расширяется, значение заворачивается по кругу
a = np.array([120], dtype=np.int8)   # int8 держит −128…127
a + 10                               # → [-126]   вместо 130, без единой ошибки

# ЛОВУШКА 2 — присваивание молча обрезает дробную часть в целочисленный массив
b = np.zeros(3, dtype=int)
b[0] = 2.7                           # → [2 0 0]   не 2.7 и не ошибка
```

Причина одна: в отличие от `int` Python, у которого разрядность растёт под число, `ndarray` — фиксированный блок памяти. Восемь бит — значит восемь бит. Отсюда правило: считаешь суммы больших чисел — бери `dtype=np.int64` или `float64` явно.

## Форма: reshape и resize

**`reshape`** меняет форму, не трогая данные, и возвращает **новый взгляд** на тот же массив. **`resize`** меняет массив **на месте**.

```python
a = np.arange(6)             # [0 1 2 3 4 5]
a.reshape(2, 3)              # [[0 1 2], [3 4 5]] — новый вид, a не изменился
a.reshape(3, -1)             # -1 = «посчитай сам»: 6/3 = 2 → форма (3, 2)

a.resize(3, 2)               # изменил сам a на месте, ничего не вернул
```

> **`-1` — рабочая лошадка.** `reshape(-1)` вытягивает любой массив в одномерный, `reshape(2, -1)` фиксирует только число строк. Число элементов должно совпадать: `reshape(4, 2)` для шести элементов упадёт с `ValueError`.

## Векторизация

Арифметика применяется **поэлементно** ко всему массиву — без циклов:

```python
a = np.array([1, 2, 3])
b = np.array([10, 20, 30])
a + b          # [11 22 33]
a * 2          # [2 4 6]
a ** 2         # [1 4 9]
np.sqrt(a)     # корень из каждого элемента
```

## Матрицы: умножение и транспонирование

Главная развилка: **`*` — поэлементно, `@` — по правилу матриц.** Их путают чаще всего.

```python
A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])

A * B          # [[5 12], [21 32]]   — поэлементно: каждый с каждым на своём месте
A @ B          # [[19 22], [43 50]]  — матричное умножение: строка × столбец
np.dot(A, B)   # то же самое, старая форма записи
```

Матричное умножение требует, чтобы **столбцов у левой было столько же, сколько строк у правой**: `(2, 3) @ (3, 4)` → `(2, 4)`. Не сошлось — `ValueError`.

**Транспонирование** — отражение относительно диагонали: строки становятся столбцами.

```python
a = np.array([[1, 2, 3], [4, 5, 6]])    # форма (2, 3)
a.T                                      # [[1 4], [2 5], [3 6]] — форма (3, 2)
a.transpose()                            # то же самое, полная форма записи

np.rot90(a)                              # поворот на 90° против часовой стрелки
np.rot90(a, k=2)                         # два поворота = разворот на 180°
```

```python
# типовое применение: скалярное произведение векторов и «матрица × вектор»
v = np.array([1, 2, 3])
v @ v                                    # → 14   скалярное произведение (1+4+9)
A = np.array([[1, 2, 3], [4, 5, 6]])
A @ v                                    # → [14 32]  матрица на вектор
```

> **`.T` не копирует данные** — он возвращает другой взгляд на тот же блок памяти (меняется только порядок обхода осей). Поэтому транспонирование бесплатно по памяти, но запись в `a.T` изменит и `a`.

## Индексация и срезы

Помимо обычных срезов NumPy даёт два мощных способа выборки:

```python
a = np.array([[1, 2, 3], [4, 5, 6]])
a[0, 1]              # 2 — элемент [строка, столбец]
a[:, 0]              # [1 4] — весь первый столбец

# булева маска — выбрать по условию
a[a > 3]             # [4 5 6]

# fancy indexing — по списку индексов
v = np.array([10, 20, 30, 40])
v[[0, 2]]            # [10 30]

# flat — обход многомерного массива как одномерного, без reshape
for x in a.flat:     # 1, 2, 3, 4, 5, 6 — по строкам
    ...
a.flat[3]            # 4 — сквозной индекс через всю матрицу
```

> Обычный `for x in a` по двумерному массиву даёт **строки**, а не числа: `for строка in a` → `[1 2 3]`, потом `[4 5 6]`. Нужны элементы — бери `a.flat` или `a.ravel()`. Но цикл по массиву — почти всегда признак того, что задача решается векторизацией.

> **Булева маска** — главный приём NumPy: `a > 3` даёт массив `True/False`, а `a[маска]` возвращает подходящие элементы. Так фильтруют данные без единого `if`.

## Broadcasting

**Broadcasting** — правила, по которым NumPy «растягивает» массивы разной формы под общую операцию. Например, прибавить вектор к каждой строке матрицы:

```python
matrix = np.array([[1, 2, 3], [4, 5, 6]])
row = np.array([10, 20, 30])
matrix + row          # row прибавляется к КАЖДОЙ строке
# [[11 22 33]
#  [14 25 36]]
```

Скаляр (`a * 2`) — простейший случай broadcasting: число «растягивается» на весь массив.

## Агрегации по осям

Свёртки (сумма, среднее) можно считать по всему массиву или вдоль оси через `axis`:

```python
a = np.array([[1, 2, 3], [4, 5, 6]])
a.sum()            # 21 — всё
a.sum(axis=0)      # [5 7 9] — по столбцам (сворачиваем строки)
a.sum(axis=1)      # [6 15]  — по строкам (сворачиваем столбцы)
a.mean()           # 3.5
a.reshape(3, 2)    # изменить форму на 3×2
```

> **`axis`** сбивает с толку: `axis=0` — вдоль строк (результат по столбцам), `axis=1` — вдоль столбцов. Запомни: `axis` — это ось, которая **исчезает** после свёртки.

## Почему это быстро

Разница со списком не в «оптимизированном коде», а в двух вещах сразу:

- **память** — список хранит указатели на объекты `int`, разбросанные по куче; `ndarray` хранит сами числа подряд одним блоком, и процессор читает их линейно, попадая в кэш;
- **цикл** — перебор списка идёт по одному элементу через интерпретатор (проверка типа, разыменование, вызов `__add__`); в `ndarray` цикл выполняется внутри скомпилированного C-кода, без интерпретатора.

Замерить на своей машине:

```python
import numpy as np, timeit

размер = 1_000_000
список = list(range(размер))
массив = np.arange(размер)

timeit.timeit(lambda: [x * 2 for x in список], number=10)   # секунды
timeit.timeit(lambda: массив * 2, number=10)                # десятки раз меньше
```

Выигрыш на простой арифметике — порядок и больше; точная цифра зависит от машины, размера и операции. Правило простое: **чем больше массив и чем меньше в коде питоновских циклов, тем сильнее выигрыш**. Один `for` по `ndarray` съедает всё преимущество — он медленнее, чем цикл по списку, потому что каждый элемент ещё и заворачивается обратно в объект Python.

## Сквозной пример: нормализация данных

Привести числа к диапазону [0, 1] — типичный шаг перед машинным обучением.

```python
import numpy as np

data = np.array([10, 20, 30, 40, 50])

# 1. min и max по массиву
mn, mx = data.min(), data.max()
# 2. векторизованная формула — сразу для всех элементов, без цикла
normalized = (data - mn) / (mx - mn)
print(normalized)     # [0.   0.25 0.5  0.75 1.  ]
```

**Как это читать.** `data - mn` вычитает число из каждого элемента (broadcasting), деление — тоже поэлементно. Одна формула обрабатывает весь массив — в этом суть NumPy: думаешь массивами, а не элементами.
