# SOAP

> _Строгий XML-конверт с контрактом: тяжеловеснее REST, но с гарантиями — для банков и enterprise_

---

**SOAP (Simple Object Access Protocol)** — протокол обмена структурированными сообщениями в веб-сервисах на основе **XML**. В отличие от [REST](../../../Фреймворки/DJANGO/API.md#что-такое-rest-api) (это архитектурный *стиль*), SOAP — строгий *протокол* со своим форматом сообщения, машиночитаемым контрактом и набором корпоративных стандартов. Обычно работает поверх HTTP (но не привязан к нему — может и по SMTP).

## Структура сообщения

Каждое сообщение — XML-**конверт** (Envelope) фиксированной структуры:

```xml
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope">
  <soap:Header>        <!-- метаданные: аутентификация, транзакции (опц.) -->
    ...
  </soap:Header>
  <soap:Body>          <!-- сама операция и данные -->
    <getBalance><account>123</account></getBalance>
  </soap:Body>
</soap:Envelope>
```

- **Envelope** — корень, обёртка всего сообщения.
- **Header** — необязательные метаданные (безопасность, транзакции).
- **Body** — вызов операции и данные (или ответ).
- **Fault** — стандартизированный блок ошибки внутри Body (в REST для этого — коды состояния).

## WSDL — контракт

**WSDL (Web Services Description Language)** — XML-документ, **машиночитаемо** описывающий сервис: какие операции есть, какие типы данных на вход/выход, по какому адресу. По нему инструменты **генерируют клиентский код** автоматически. Это «contract-first»: сначала строгий контракт, потом реализация.

## WS-\* — корпоративные стандарты

Поверх SOAP есть семейство стандартов **WS-\***, которых нет «из коробки» у REST:

- **WS-Security** — шифрование и подпись на уровне сообщения (не только транспорта);
- **WS-ReliableMessaging** — гарантированная доставка;
- **WS-AtomicTransaction** — распределённые транзакции.

Именно поэтому SOAP живёт в банках, платёжных системах, телекоме и госсервисах.

## SOAP против REST

| | SOAP | [REST](../../../Фреймворки/DJANGO/API.md#что-такое-rest-api) |
|---|---|---|
| **Что это** | протокол (строгие правила) | архитектурный стиль |
| **Формат** | только XML | обычно JSON (любой) |
| **Контракт** | WSDL (обязателен, кодогенерация) | опционально (OpenAPI/Swagger) |
| **Использует HTTP** | как транспорт (обычно POST) | использует семантику HTTP (методы, коды) |
| **Вес** | тяжёлый, многословный | лёгкий |
| **Безопасность/транзакции** | встроены (WS-\*) | поверх (TLS, токены) |
| **Где** | enterprise: банки, платежи, легаси | веб, мобильные, публичные API |

## Когда SOAP, когда REST

- **SOAP** — строгие корпоративные требования: гарантированная доставка, транзакции, безопасность на уровне сообщения, формальный контракт; интеграция с легаси/госсистемами.
- **REST** — почти всё остальное: публичные и мобильные API, веб, где важны простота, JSON и скорость разработки. Для большинства новых проектов берут REST (или [FastAPI](../../../Фреймворки/FastAPI.md)/gRPC).

## Работа из Python

Клиент SOAP — библиотека **zeep** (сама читает WSDL и строит методы):

```python
from zeep import Client

client = Client("https://example.com/service?wsdl")   # загрузить контракт
result = client.service.getBalance(account="123")      # вызвать операцию как метод
```
