# bisect

> _Список уже отсортирован — не сортируй заново, вставляй в нужное место за $O(\log n)$._

---

**bisect** — модуль стандартной библиотеки для работы с **отсортированным** списком: найти, куда вставить элемент, чтобы порядок сохранился, — за $O(\log n)$. Под капотом — бинарный поиск, только вместо «нашёл / не нашёл» он возвращает **позицию вставки**.

Зачем это на контесте: ручной бинарный поиск легко написать с ошибкой в границах (`lo`, `hi`, `mid`). `bisect` — уже отлаженный бинарный поиск, из которого собираются almost все «поиск по отсортированному» задачи: сколько чисел в диапазоне, ближайшее значение, первое число ≥ X.

> Работает только на **отсортированном** списке. `bisect` его **не сортирует** — если данные не по порядку, результат бессмысленный.

## Две главные функции

**`bisect_left(a, x)`** — индекс, куда вставить `x`, чтобы он оказался **слева** от равных ему. **`bisect_right(a, x)`** (синоним `bisect`) — **справа** от равных.

```python
import bisect

a = [1, 3, 3, 3, 5]
bisect.bisect_left(a, 3)    # → 1  (перед первой тройкой)
bisect.bisect_right(a, 3)   # → 4  (после последней тройки)
bisect.bisect_left(a, 4)    # → 4  (4 нет — но вставить надо сюда)
```

Разница видна только на **дубликатах**. Мнемоника: `left` встаёт левее равных, `right` — правее.

```
       0   1   2   3   4
  a = [1,  3,  3,  3,  5]
        ↑                    bisect_left(a, 3)  = 1
                    ↑        bisect_right(a, 3) = 4
```

## insort — вставить и сохранить порядок

`insort_left` / `insort_right` находят позицию и **вставляют** элемент, оставляя список отсортированным.

```python
a = [1, 3, 5]
bisect.insort(a, 4)     # a → [1, 3, 4, 5]
```

Сама вставка в список — $O(n)$ (сдвиг элементов), поиск места — $O(\log n)$. Если нужно много вставок в середину — думай про [сбалансированное дерево](../../../Данные/Структуры%20данных/Дерево.md), а не список.

## Параметр key (Python 3.10+)

С версии 3.10 у всех функций есть `key` — искать по производному значению, не меняя сам список.

```python
data = [("a", 1), ("b", 3), ("c", 5)]
bisect.bisect_left(data, 3, key=lambda p: p[1])   # → 1
```

> До 3.10 `key` нет. Обходной приём — держать отдельный список ключей и искать по нему.

## Практические паттерны (контест)

**Есть ли элемент в отсортированном списке:**

```python
def есть(a, x):
    i = bisect.bisect_left(a, x)
    return i < len(a) and a[i] == x
```

**Сколько чисел в диапазоне `[lo, hi]`** — классика на подсчёт:

```python
def count_in_range(a, lo, hi):
    return bisect.bisect_right(a, hi) - bisect.bisect_left(a, lo)
```

**Первый элемент ≥ x** (нижняя граница) и **последний < x**:

```python
i = bisect.bisect_left(a, x)     # a[i] — первый ≥ x (если i < len(a))
j = bisect.bisect_left(a, x) - 1 # a[j] — последний < x (если j >= 0)
```

**Ближайшее значение к x:**

```python
def ближайшее(a, x):
    i = bisect.bisect_left(a, x)
    кандидаты = []
    if i < len(a): кандидаты.append(a[i])
    if i > 0:      кандидаты.append(a[i - 1])
    return min(кандидаты, key=lambda v: abs(v - x))
```

**Наибольшая возрастающая подпоследовательность (LIS) за $O(n \log n)$** — приём, который часто спрашивают:

```python
def lis(nums):
    tails = []                       # tails[k] — мин. «хвост» подпоследовательности длины k+1
    for x in nums:
        i = bisect.bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)          # x продолжает самую длинную
        else:
            tails[i] = x             # улучшаем хвост длины i+1
    return len(tails)

lis([10, 9, 2, 5, 3, 7, 101, 18])    # → 4  ([2, 3, 7, 18/101])
```

## Сравнение функций

| Функция | Что делает | На дубликатах |
|---|---|---|
| `bisect_left(a, x)` | индекс вставки | слева от равных |
| `bisect_right(a, x)` / `bisect` | индекс вставки | справа от равных |
| `insort_left(a, x)` | вставить | перед равными |
| `insort_right(a, x)` / `insort` | вставить | после равных |

## Связи

- Бинарный поиск — теория и ручная реализация того, что делает `bisect`;
- Сортировка — `bisect` требует заранее отсортированного списка;
- Вычислительная сложность — $O(\log n)$ поиск против $O(n)$ линейного;
- [Массив](../../../Данные/Структуры%20данных/Массив.md) — почему вставка в середину списка стоит $O(n)$.
