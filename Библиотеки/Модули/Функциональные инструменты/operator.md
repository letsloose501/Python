# operator

> _Операторы `+`, `<`, `[]` — тоже функции. `operator` даёт к ним доступ по имени._

---

**operator** — модуль, где каждый оператор языка (`+`, `*`, `<`, `[]`, `.атрибут`) доступен как **обычная функция**. Нужен там, где функцию надо **передать** — в `sorted(key=...)`, `map`, [reduce](../../../Библиотеки/Модули/Функциональные%20инструменты/functools.md#reduce--свернуть-последовательность-в-одно-значение) — а писать `lambda` громоздко и медленнее.

Зачем на контесте: `itemgetter` — самый частый и быстрый способ задать ключ сортировки по элементу кортежа или по нескольким полям сразу.

## itemgetter — ключ по индексу/ключу

**`itemgetter(i)`** возвращает функцию «достать элемент `i`». Заменяет `lambda x: x[i]` — короче и быстрее (реализован на C).

```python
from operator import itemgetter

пары = [("Аня", 25), ("Боря", 19), ("Вера", 31)]

sorted(пары, key=itemgetter(1))         # по возрасту → [('Боря',19),('Аня',25),('Вера',31)]
sorted(пары, key=itemgetter(0))         # по имени
```

**Сортировка по нескольким полям** — просто перечисли индексы:

```python
данные = [("A", 2), ("B", 1), ("A", 1)]
sorted(данные, key=itemgetter(0, 1))    # сначала по 0, при равенстве по 1
# → [('A', 1), ('A', 2), ('B', 1)]
```

## attrgetter и methodcaller

**`attrgetter("имя")`** достаёт атрибут объекта, **`methodcaller("метод", args)`** вызывает метод.

```python
from operator import attrgetter, methodcaller

sorted(люди, key=attrgetter("age"))               # по object.age
sorted(слова, key=methodcaller("lower"))          # по word.lower()
```

## Операторы как функции

Каждый оператор — вызываемая функция. Полезно в `reduce` и функциональном коде.

```python
from operator import add, mul, lt
from functools import reduce

reduce(mul, [1, 2, 3, 4])       # → 24   произведение (add дал бы сумму)
add(3, 4)                       # → 7
lt(2, 5)                        # → True   (2 < 5)
```

| Функция | Оператор | Функция | Оператор |
|---|---|---|---|
| `add(a,b)` | `a + b` | `lt / le` | `< / <=` |
| `sub(a,b)` | `a - b` | `eq / ne` | `== / !=` |
| `mul(a,b)` | `a * b` | `gt / ge` | `> / >=` |
| `truediv(a,b)` | `a / b` | `getitem(o,k)` | `o[k]` |
| `mod(a,b)` | `a % b` | `contains(o,x)` | `x in o` |

## Почему не просто lambda

`itemgetter(1)` и `lambda x: x[1]` делают одно и то же, но `itemgetter` **быстрее** (C-реализация) и читается как намерение, а не как код. На больших сортировках разница ощутима.
