# ssl

> _Обёртка, превращающая обычное сетевое соединение в защищённое: шифрование трафика и проверка, что сервер — тот, за кого себя выдаёт._

---

**ssl** — модуль, добавляющий к сетевым соединениям **TLS/SSL**: шифрование передаваемых данных и проверку подлинности сервера по сертификату. Это то, что превращает `http` в `https`. Модуль оборачивает обычный сокет в защищённый.

> На практике `ssl` **напрямую почти не используют** — за тебя это делают [requests](../../../Библиотеки/Сторонние/Работа%20с%20WEB/requests.md), `urllib`, веб-серверы. Но понимать, что происходит под `https`, важно: сертификаты, проверка, ошибки TLS.

Зачем знать: диагностировать ошибки сертификатов, настроить защищённое соединение, понимать модель безопасности веба.

## Что даёт TLS

- **Шифрование** — данные в канале нечитаемы для перехватчика;
- **Аутентификация** — сертификат подтверждает, что сервер настоящий (а не подставной);
- **Целостность** — подмену данных в пути обнаружат.

Как стороны договариваются о ключах шифрования по открытому каналу — в [HTTPS и обмен ключами Диффи — Хеллмана](../../../Алгоритмы/Иные/HTTPS%20и%20обмен%20ключами%20Диффи%20—%20Хеллмана.md).

## Контекст по умолчанию

Правильный способ — взять **безопасный контекст по умолчанию**: он сам проверяет сертификат и имя хоста.

```python
import ssl, socket

контекст = ssl.create_default_context()      # безопасные настройки + проверка сертификата

with socket.create_connection(("example.com", 443)) as sock:
    with контекст.wrap_socket(sock, server_hostname="example.com") as ssock:
        ssock.version()          # → 'TLSv1.3'  установленная версия протокола
```

`wrap_socket` оборачивает обычный сокет в защищённый: дальше читаешь/пишешь как обычно, но трафик шифруется.

## Ловушка: отключение проверки

Иногда в примерах из интернета встречается отключение проверки сертификата — это **дыра в безопасности**, открывающая атаку «человек посередине».

```python
# ОПАСНО — только для локальной отладки, никогда в проде:
контекст = ssl.create_default_context()
контекст.check_hostname = False
контекст.verify_mode = ssl.CERT_NONE
```

> Ошибка `SSL: CERTIFICATE_VERIFY_FAILED` означает, что сертификат не прошёл проверку. Правильное решение — починить сертификаты/цепочку доверия, а **не** отключать проверку.
