# multiprocessing

> _Один Python-процесс из-за GIL считает в один поток. Хочешь задействовать все ядра — запусти несколько процессов._

---

**multiprocessing** — модуль параллельного выполнения через **отдельные процессы**. Он существует, чтобы обойти **GIL** (Global Interpreter Lock) — блокировку, из-за которой потоки Python не исполняют байткод по-настоящему одновременно. Каждый процесс имеет свой интерпретатор и свой GIL, поэтому процессы реально работают на разных ядрах параллельно.

Зачем: ускорить **вычислительные** (CPU-bound) задачи — обработку данных, расчёты — за счёт всех ядер процессора.

## Проблема: GIL и потоки

**GIL** пропускает к выполнению байткода только один поток за раз (подробнее — Асинхронность и многопоточность). Поэтому несколько [потоков](../../../Библиотеки/Модули/Параллелизм/threading.md) не ускоряют вычисления — они по очереди держат GIL. Потоки хороши для **ожидания** (сеть, диск), но не для счёта.

**Процессы** обходят это: у каждого свой GIL, они бегут по-настоящему параллельно. Цена — процессы тяжелее потоков и не делят память напрямую (данные приходится пересылать).

## Process — запустить функцию в отдельном процессе

```python
from multiprocessing import Process

def работа(имя):
    print(f"процесс {имя} считает")

if __name__ == "__main__":           # обязательно на Windows!
    p = Process(target=работа, args=("A",))
    p.start()                        # запустить
    p.join()                         # дождаться завершения
```

> **Ловушка:** на Windows код запуска процессов должен быть под `if __name__ == "__main__":`. Иначе дочерний процесс заново импортирует модуль и породит бесконечную рекурсию создания процессов.

## Pool — распараллелить обработку списка

Чаще всего нужен **`Pool`**: раздать элементы списка по процессам и собрать результаты. Это параллельный `map`.

```python
from multiprocessing import Pool

def квадрат(x):
    return x * x

if __name__ == "__main__":
    with Pool(processes=4) as pool:              # 4 рабочих процесса
        результат = pool.map(квадрат, range(10))  # раздать по процессам
    print(результат)      # → [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
```

Выгода появляется, только если работа над каждым элементом **тяжёлая** — иначе накладные расходы на процессы съедят выигрыш.

## Обмен данными

Процессы не делят память, поэтому общаются явно — через `Queue` (очередь) или `Pipe`. Аргументы и результаты автоматически сериализуются ([pickle](../../../Библиотеки/Модули/Форматы%20данных/pickle.md)), поэтому они должны быть picklable.

## Когда что: процессы vs потоки vs async

| Задача | Инструмент |
|---|---|
| Вычисления (CPU-bound) | **multiprocessing** — обходит GIL, все ядра |
| Ожидание I/O (сеть, диск) | [threading](../../../Библиотеки/Модули/Параллелизм/threading.md) или **async** — GIL не мешает ждать |
| Много одновременных сетевых операций | **asyncio** — один поток, кооперативно |

> Простое правило: **считаешь — процессы, ждёшь — потоки/async**.
