# queue

> _Очередь, безопасная для потоков: несколько потоков кладут и забирают задачи, не мешая друг другу._

---

**queue** — модуль потокобезопасных очередей для обмена данными между [потоками](../../../Библиотеки/Модули/Параллелизм/threading.md). Когда одни потоки производят задачи, а другие их обрабатывают (схема «производитель — потребитель»), нужна очередь, к которой можно безопасно обращаться из нескольких потоков одновременно. `queue.Queue` берёт синхронизацию на себя.

Зачем: распределять работу между потоками без ручных [блокировок](../../../Библиотеки/Модули/Параллелизм/threading.md) и гонок.

## Чем отличается от collections.deque

[`deque`](../../../Библиотеки/Модули/Коллекции%20и%20структуры%20данных/collections.md) — быстрая очередь, но **не** рассчитана на потоки: два потока, кладущие данные одновременно, могут её повредить. `queue.Queue` **потокобезопасна** и умеет **блокирующее** ожидание: `get()` на пустой очереди ждёт, пока кто-то положит элемент.

| | `collections.deque` | `queue.Queue` |
|---|---|---|
| Потокобезопасность | нет | да |
| Блокирующее ожидание | нет | да (`get` ждёт элемент) |
| Когда | один поток, алгоритмы | обмен между потоками |

## Основные операции

```python
from queue import Queue

q = Queue()
q.put("задача 1")        # положить (блокирует, если задан maxsize и очередь полна)
q.put("задача 2")

q.get()                  # → 'задача 1'  забрать (блокирует, если очередь пуста)
q.qsize()                # примерный размер
q.empty()                # пуста ли
```

## Три вида очередей

```python
from queue import Queue, LifoQueue, PriorityQueue

Queue()          # FIFO — первым пришёл, первым вышел (обычная очередь)
LifoQueue()      # LIFO — как стек
PriorityQueue()  # по приоритету — put((приоритет, элемент)), get отдаёт наименьший
```

`PriorityQueue` внутри использует [кучу](../../../Библиотеки/Модули/Коллекции%20и%20структуры%20данных/heapq.md) — тот же принцип, но потокобезопасно.

## Producer–consumer с task_done/join

Классическая схема: producers кладут задачи, consumers забирают. `join()` ждёт, пока все задачи обработаны, а `task_done()` отмечает завершение каждой.

```python
q = Queue()

def worker():
    while True:
        задача = q.get()          # ждёт задачу
        обработать(задача)
        q.task_done()             # отметить, что эта задача выполнена

# запустить потоки-обработчики, наполнить очередь...
q.join()                          # блокирует, пока task_done не вызван для всех задач
```
