# threading

> _Несколько задач в одном процессе. Из-за GIL это ускоряет ожидание, но не вычисления._

---

**threading** — модуль работы с **потоками**: несколькими линиями выполнения внутри одного процесса, разделяющими общую память. Главный нюанс Python — **GIL** (Global Interpreter Lock): в каждый момент байткод исполняет только один поток. Поэтому потоки ускоряют задачи, где программа **ждёт** (сеть, диск), но не задачи, где она **считает**.

Зачем: параллельно ждать много ответов сети, качать файлы, обрабатывать запросы — пока один поток ждёт I/O, GIL свободен, и работают другие.

## Запуск потока

```python
from threading import Thread

def загрузить(url):
    ...                          # операция с ожиданием (сеть)

потоки = [Thread(target=загрузить, args=(u,)) for u in urls]
for t in потоки:
    t.start()                    # запустить
for t in потоки:
    t.join()                     # дождаться завершения всех
```

## GIL: потоки не ускоряют вычисления

Пока поток **ждёт** ответа сети или диска, он отпускает GIL — другие потоки работают. Но если поток **считает** (крутит цикл), он держит GIL, и остальные стоят. Для вычислений на всех ядрах нужны процессы — [multiprocessing](../../../Библиотеки/Модули/Параллелизм/multiprocessing.md).

| Задача | threading помогает? |
|---|---|
| Ждать сеть/диск (I/O-bound) | **да** — пока один ждёт, другие работают |
| Считать (CPU-bound) | **нет** — GIL пропускает по одному; нужен multiprocessing |

## Ловушка: гонки и Lock

Потоки делят память, поэтому одновременный доступ к общим данным ведёт к **состоянию гонки** (race condition) — результат зависит от того, кто успел первым.

```python
from threading import Lock

счётчик = 0
lock = Lock()

def увеличить():
    global счётчик
    with lock:                   # только один поток за раз в этом блоке
        счётчик += 1             # без lock += 1 не атомарен → потеря обновлений
```

**`Lock`** (замок) допускает в критическую секцию только один поток. Правило: общие изменяемые данные — под замком.

## threading vs multiprocessing vs asyncio

| Инструмент | Параллелизм | Для чего |
|---|---|---|
| **threading** | потоки (общий GIL) | I/O-bound, немного задач |
| **multiprocessing** | процессы (свой GIL) | CPU-bound, вычисления |
| **asyncio** | один поток, корутины | много одновременных I/O-операций |

> Правило: **считаешь** → процессы, **ждёшь немного** → потоки, **ждёшь массово** (тысячи соединений) → asyncio.
