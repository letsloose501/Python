# typing

> _Аннотации типов — это документация, которую проверяют инструменты. Сам Python их в рантайме не навязывает._

---

**typing** — модуль для **аннотаций типов**: подсказок, какого типа переменная, аргумент или результат функции. Python остаётся [динамически типизированным](../../../Python.md#python-2-vs-python-3) — аннотации не проверяются при выполнении, но их читают IDE и статические анализаторы (**mypy**, Pyright), находя ошибки **до запуска**.

Зачем: на больших проектах типы ловят баги и служат живой документацией. На них построен [pydantic](../../../Библиотеки/Сторонние/pydantic.md) и [FastAPI](../../../Фреймворки/FastAPI.md), где аннотация превращается в реальную валидацию.

## Базовые аннотации

```python
имя: str = "Аня"
возраст: int = 25

def приветствие(name: str, count: int = 1) -> str:   # -> тип результата
    return f"Привет, {name}! " * count
```

## Контейнеры с типом содержимого

С Python 3.9 встроенные типы сами принимают параметр — отдельные `List`, `Dict` из `typing` больше не нужны.

```python
числа: list[int] = [1, 2, 3]
индекс: dict[str, int] = {"a": 1}
пара: tuple[int, str] = (1, "a")
множество: set[str] = {"x", "y"}
```

## Optional, Union и «или»

**`Optional[X]`** = «`X` или `None`». **`Union[A, B]`** = «`A` или `B`». С Python 3.10 короче через `|`.

```python
from typing import Optional, Union

def найти(id: int) -> Optional[str]:     # вернёт строку или None
    ...

x: Union[int, str]      # старый синтаксис
x: int | str            # Python 3.10+ — то же самое
y: str | None           # эквивалент Optional[str]
```

## Полезные конструкции

```python
from typing import Any, Callable, Literal

f: Callable[[int, int], int]      # функция: два int на входе, int на выходе
режим: Literal["r", "w", "a"]     # только одно из перечисленных значений
что_угодно: Any                   # выключить проверку типа (крайняя мера)
```

| Конструкция | Значение |
|---|---|
| `list[int]`, `dict[str, int]` | контейнер с типом элементов |
| `Optional[X]` / `X \| None` | значение или `None` |
| `Union[A, B]` / `A \| B` | одно из нескольких |
| `Callable[[args], ret]` | функция как аргумент |
| `Literal[...]` | фиксированный набор значений |
| `Any` | любой тип (проверка отключена) |

> **Ловушка `Callable`: имена параметров теряются.** `Callable[[int, str], None]` описывает функцию с **позиционными** параметрами, поэтому вызов `send(chat_id=1, message="hi")` mypy отвергнет: `Unexpected keyword argument "chat_id"`. И понять из самой аннотации, что первое число — это `chat_id`, а не `user_id`, невозможно. Когда функция передаётся как зависимость с осмысленным контрактом, вместо `Callable` берут протокол с `__call__`: он сохраняет имена и ловит опечатки в них — [как это выглядит](../../../ООП/Принципы/Полиморфизм%20Python.md#протокол-для-вызываемого-объекта).

## Ловушка: типы не проверяются в рантайме

Аннотация — **не** проверка. Python спокойно выполнит код с «неправильным» типом:

```python
def double(x: int) -> int:
    return x * 2

double("ой")        # → 'ойой'   — Python НЕ упадёт, аннотация проигнорирована
```

Ошибку поймает только внешний инструмент (`mypy файл.py`). Нужна проверка **во время выполнения** — это [pydantic](../../../Библиотеки/Сторонние/pydantic.md): он берёт те же аннотации и реально валидирует данные.

## Связи

- [pydantic](../../../Библиотеки/Сторонние/pydantic.md) — превращает аннотации в рантайм-валидацию;
- [FastAPI](../../../Фреймворки/FastAPI.md) — из аннотаций строит валидацию запросов и автодокументацию;
- [Функции Python](../../../Ядро%20языка/Функции%20Python.md) — где ставятся аннотации аргументов и результата;
- [dataclass](../../../Библиотеки/Модули/Типы%20и%20объекты/dataclass.md) — поля класса задаются аннотациями типов.
