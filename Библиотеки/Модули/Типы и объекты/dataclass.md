# dataclasses

> _Класс для хранения данных без ручного `__init__`, `__repr__` и `__eq__` — их пишет декоратор._

---

**dataclasses** — модуль (декоратор `@dataclass`), который по описанию полей **автоматически генерирует** служебные методы класса: конструктор `__init__`, читаемый `__repr__`, сравнение `__eq__`. Ты объявляешь только поля с типами — рутину пишет Python.

> Модуль называется `dataclasses` (импорт `from dataclasses import dataclass`), хотя заметка и декоратор — `dataclass`.

Зачем: когда класс нужен просто чтобы хранить связанные данные (точка, заказ, конфиг), обычный класс требует много повторяющегося кода. `@dataclass` убирает его.

## Проблема: рукописный класс-хранилище

```python
# БЕЗ dataclass — много рутины:
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"
    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)
```

```python
# С dataclass — то же самое:
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

p = Point(3, 4)
p                       # → Point(x=3, y=4)      __repr__ готов
Point(3, 4) == Point(3, 4)   # → True            __eq__ готов
```

## Значения по умолчанию

```python
@dataclass
class User:
    name: str
    age: int = 18            # значение по умолчанию → поле необязательно
```

> **Ловушка изменяемого дефолта:** нельзя `tags: list = []` — список создастся один раз и станет общим для всех экземпляров (та же ловушка, что с изменяемым аргументом функции). Для изменяемых значений — **`field(default_factory=...)`**:

```python
from dataclasses import dataclass, field

@dataclass
class Cart:
    items: list = field(default_factory=list)   # новый список для каждого объекта
```

## Полезные параметры

```python
@dataclass(frozen=True)      # неизменяемый: поля нельзя менять после создания (и он хешируем)
class Point:
    x: int
    y: int

@dataclass(order=True)       # добавляет <, >, <=, >= — можно сортировать
class Version:
    major: int
    minor: int
```

`__post_init__` — доработать объект сразу после генерации `__init__` (вычислить производное поле, проверить данные).

## Ловушки

### `frozen` замораживает только ссылки, не содержимое

`frozen=True` запрещает **переприсваивать** поля, но не делает объект неизменяемым вглубь: если поле хранит изменяемый объект (список, словарь), его **содержимое менять можно**.

```python
@dataclass(frozen=True)
class Config:
    hosts: list = field(default_factory=list)

c = Config()
c.hosts = ["a"]        # FrozenInstanceError — переприсваивание запрещено
c.hosts.append("a")    # но ЭТО работает — мутируем сам список внутри
```

Опаснее всего это с хешированием. `frozen=True` генерирует `__hash__`, и объект можно класть в `set`/использовать как ключ `dict`. Но хеш считается по полям — а если поле изменяемое и ты **поменял его содержимое**, хеш «уедет», и объект **потеряется** в множестве:

```python
c = Config(hosts=["a"])
s = {c}                 # положили в set по текущему хешу
c.hosts.append("b")     # изменили содержимое → хеш другой
c in s                  # → False! объект «пропал» из своего же set
```

> **Замораживаешь — храни внутри только неизменяемое** (`tuple`, `frozenset`, числа, строки). Иначе `frozen` даёт ложное чувство безопасности, а мутируемое поле ломает и хеш, и логику словарей.

### Равенство и наследование

Сгенерированный `__eq__` считает объекты равными, только если у них **один и тот же класс**. Экземпляры разных dataclass-ов (даже родитель и наследник с идентичными полями) **никогда не равны**:

```python
@dataclass
class Point:
    x: int; y: int

@dataclass
class ColorPoint(Point):
    color: str = "black"

Point(1, 2) == Point(1, 2)              # → True
Point(1, 2) == ColorPoint(1, 2)         # → False — разные классы, хоть x,y совпали
```

Наследник — тоже dataclass: его поля идут **после** полей родителя. Отсюда правило про значения по умолчанию: **поле без дефолта нельзя объявить после поля с дефолтом** — в том числе унаследованного. Если у родителя есть поле со значением по умолчанию, все поля наследника тоже должны быть с дефолтами, иначе `TypeError` при определении класса.

```python
@dataclass
class Base:
    a: int = 0

@dataclass
class Child(Base):
    b: int          # TypeError: non-default argument 'b' follows default argument
```

## Утилиты

```python
from dataclasses import asdict, astuple

asdict(p)       # → {'x': 3, 'y': 4}   превратить в словарь (например, для JSON)
astuple(p)      # → (3, 4)
```

## Сравнение с соседями

| Инструмент | Изменяемость | Валидация | Когда |
|---|---|---|---|
| `@dataclass` | да (или `frozen`) | нет | хранить данные внутри программы |
| `namedtuple` ([collections](../../../Библиотеки/Модули/Коллекции%20и%20структуры%20данных/collections.md)) | нет | нет | лёгкий неизменяемый кортеж |
| `pydantic` ([pydantic](../../../Библиотеки/Сторонние/pydantic.md)) | да | **да, в рантайме** | данные извне (API, файлы) |

> Правило: данные **внутренние** → `dataclass`; данные **из внешнего мира** (запрос, файл) → `pydantic`, потому что их надо проверять.
