# enum

> _Вместо магических чисел и строк, разбросанных по коду, — набор именованных значений в одном месте._

---

**enum** — модуль **перечислений**: наборов именованных констант. Вместо того чтобы хранить статус как `0`/`1`/`2` или `"active"`/`"blocked"` (и гадать, что они значат), объявляешь `Enum` с понятными именами. Код становится читаемым, а неверное значение — невозможным.

Зачем: статусы заказа, роли пользователей, направления, режимы — везде, где значение выбирается из фиксированного набора.

## Проблема магических значений

```python
# ПЛОХО: что такое 2? откуда знать допустимые значения?
if заказ.status == 2:
    ...
заказ.status = 99          # никто не мешает записать бессмыслицу
```

```python
# ХОРОШО: имена говорят сами за себя
from enum import Enum

class Status(Enum):
    NEW = 1
    PAID = 2
    SHIPPED = 3

if заказ.status == Status.PAID:
    ...
```

## Доступ к членам

```python
Status.PAID            # → <Status.PAID: 2>
Status.PAID.name       # → 'PAID'    имя
Status.PAID.value      # → 2         значение
Status(2)              # → Status.PAID   получить член по значению
Status["PAID"]         # → Status.PAID   по имени

list(Status)           # → [Status.NEW, Status.PAID, Status.SHIPPED]  перебор
Status.PAID in Status  # → True
```

## auto — не нумеровать вручную

Когда конкретные числа не важны, `auto()` присвоит их сам:

```python
from enum import Enum, auto

class Direction(Enum):
    NORTH = auto()     # 1
    EAST = auto()      # 2
    SOUTH = auto()     # 3
```

## Разновидности

| Класс | Особенность |
|---|---|
| `Enum` | базовый; члены не равны своим значениям (`Status.NEW != 1`) |
| `IntEnum` | члены — это ещё и `int`: сравнимы с числами (`Status.NEW == 1`) |
| `StrEnum` | члены — строки (Python 3.11+); удобно для JSON/API |
| `Flag` | битовые флаги, комбинируются через `|` |

> **Отличие `Enum` от `IntEnum`:** обычный `Enum` намеренно **не равен** числу — это защищает от случайного сравнения с сырым значением. `IntEnum` берут, когда член должен вести себя как число (например, для сериализации или сравнения с данными из БД).

## enum vs Literal

Для простого «одно из значений» без поведения хватает `Literal` из [typing](../../../Библиотеки/Модули/Типы%20и%20объекты/typing.md) (`Literal["r", "w"]`). `Enum` нужен, когда у значений есть имена, методы или их перебирают.

## Связи

- [typing](../../../Библиотеки/Модули/Типы%20и%20объекты/typing.md) — `Literal` как лёгкая альтернатива, когда не нужны имена и методы;
- [Принципы ООП в Python](../../../ООП/Принципы/Принципы%20ООП%20в%20Python.md) — `Enum` это класс, члены — его экземпляры;
- [json](../../../Библиотеки/Модули/Форматы%20данных/json.md) — `StrEnum`/`IntEnum` удобно сериализуются в API-ответы.
