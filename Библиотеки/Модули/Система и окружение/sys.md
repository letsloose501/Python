# sys

> _Мост между твоей программой и интерпретатором: ввод-вывод, аргументы, пределы, выход._

---

**sys** — модуль доступа к самому интерпретатору Python и его окружению: потоки ввода-вывода, аргументы командной строки, предел рекурсии, аварийный выход. Для бэкенда и скриптов это «системная панель» процесса.

Зачем на контесте: `sys` — источник **быстрого ввода-вывода** и **снятия лимита рекурсии**. На больших входных данных `input()` и `print()` в цикле слишком медленны, а рекурсивный [DFS](../../../Алгоритмы/Поиск/DFS.md) упирается в предел глубины 1000. Оба потолка снимаются через `sys`.

## Быстрый ввод (контест)

Обычный `input()` на каждой строке делает лишнюю работу. `sys.stdin` читает поток напрямую — в разы быстрее.

```python
import sys

input = sys.stdin.readline          # переопределить: теперь input() быстрый
n = int(input())                    # не забыть, что readline оставляет '\n'

# прочитать сразу весь ввод и разобрать на токены — самый быстрый способ:
data = sys.stdin.buffer.read().split()
n = int(data[0])
nums = list(map(int, data[1:1 + n]))
```

> **Ловушка:** `sys.stdin.readline()` **оставляет** символ `\n` в конце. Для чисел `int()` его проглотит, но для строк делай `.rstrip()`, иначе сравнение сломается.

### Когда число строк заранее неизвестно

`input()` при конце ввода бросает `EOFError`, и цикл приходится оборачивать в `try`. `sys.stdin` — обычный поток, поэтому по нему просто идут циклом: он сам кончается на EOF.

```python
import sys

for строка in sys.stdin:              # самый частый способ: строка за строкой, лениво
    обработать(строка.rstrip())

строки = sys.stdin.readlines()        # все строки списком (с '\n' на конце каждой)
текст = sys.stdin.read()              # весь ввод одной строкой
числа = list(map(int, sys.stdin.read().split()))   # весь ввод сразу в числа
```

**Чем отличаются.** `for` держит в памяти одну строку — годится для файла любого размера. `readlines()` и `read()` загружают всё целиком: на контесте это быстрее (одно системное обращение вместо тысяч), на потоковых данных — риск съесть память.

> **Как закончить ввод с клавиатуры.** Программа, читающая до EOF, из терминала не остановится сама — ты должен сказать «ввод кончился»: **Ctrl+Z и Enter** в Windows, **Ctrl+D** в Linux и macOS. При запуске через файл (`python solve.py < input.txt`) EOF наступает сам, поэтому в Контесте об этом думать не нужно — только при отладке руками.

## Быстрый вывод (контест)

Много `print` в цикле — медленно (каждый вызов сбрасывает буфер). Собери ответ и выведи разом.

```python
import sys

ответы = [str(x) for x in результаты]
sys.stdout.write("\n".join(ответы) + "\n")     # один вызов вместо тысяч print
```

## Предел рекурсии

Python по умолчанию обрывает рекурсию на глубине **1000** (`RecursionError`), чтобы не переполнить стек. Для глубокого [рекурсивного](../../../Алгоритмы/Стратегии/Рекурсия.md) обхода лимит поднимают.

```python
import sys
sys.setrecursionlimit(300_000)       # поднять потолок
sys.getrecursionlimit()              # → текущий предел
```

> Поднятие лимита не бесконечно: слишком глубокая рекурсия всё равно уронит процесс по стеку ОС. Надёжнее переписать обход итеративно ([DFS](../../../Алгоритмы/Поиск/DFS.md) на явном [стеке](../../../Данные/АТД/Стек.md)).

## Аргументы, выход, окружение

```python
import sys

sys.argv          # список аргументов командной строки; argv[0] — имя скрипта
sys.exit()        # немедленно завершить программу (sys.exit(1) — с кодом ошибки)
sys.maxsize       # максимальный размер контейнера (~9.2e18 на 64 бит) — НЕ бесконечность
sys.version_info  # версия Python как кортеж: (3, 12, 1, ...)
sys.platform      # 'win32', 'linux', 'darwin'
sys.getsizeof(x)  # размер объекта в байтах
```

`sys.argv` — как командная строка передаёт данные скрипту (см. Терминал):

```python
# запуск:  python script.py файл.txt 10
sys.argv          # → ['script.py', 'файл.txt', '10']
```

## Три стандартных потока

| Поток | Дескриптор | Что это |
|---|---|---|
| `sys.stdin` | `0` | стандартный ввод (клавиатура/канал) |
| `sys.stdout` | `1` | стандартный вывод (`print` пишет сюда) |
| `sys.stderr` | `2` | поток ошибок — отделён от вывода, чтобы логи не мешались с результатом |

Это обычные файловые объекты, поэтому их можно читать, писать, подменять и перенаправлять. Полный разбор — как устроены слои, почему вывод в конвейер приходит рывками, что делать с кодировкой на Windows — в **[Стандартные потоки — stdin, stdout, stderr](../../../Ядро%20языка/Стандартные%20потоки%20—%20stdin,%20stdout,%20stderr.md)**.

> ⚠️ **Самое частое, что кусает за пределами контеста.** В терминале `stdout` сбрасывается построчно, а в файл или конвейер — **блоками по 8 КБ**; `stderr` построчно всегда. Поэтому логи из конвейера приходят рывками, а порядок строк `stdout` и `stderr` перемешивается. Лечится `flush=True`, `python -u` или `PYTHONUNBUFFERED=1` — [разбор с замером](../../../Ядро%20языка/Стандартные%20потоки%20—%20stdin,%20stdout,%20stderr.md#буферизация--главная-практическая-ловушка).
