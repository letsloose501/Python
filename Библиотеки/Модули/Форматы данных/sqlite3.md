# sqlite3

> _Полноценная SQL-база внутри одного файла — без сервера, без установки, прямо из стандартной библиотеки._

---

**sqlite3** — встроенный драйвер базы данных **SQLite**: настоящей реляционной СУБД, которая живёт в **одном файле** (или в памяти) и не требует отдельного сервера. Вся база — это файл `.db`, а движок работает внутри твоего процесса.

Зачем: локальное хранилище приложения, прототипы, тесты, небольшие проекты. Отличный способ потренировать SQL без разворачивания PostgreSQL. API повторяет стандарт Python DB-API, поэтому переход на «взрослые» драйверы ([psycopg2](../../../Библиотеки/Сторонние/Работа%20с%20БД/psycopg2.md)) потом лёгкий.

## Подключение и курсор

```python
import sqlite3

conn = sqlite3.connect("app.db")     # файл базы (или ":memory:" — база в ОЗУ)
cur = conn.cursor()                  # курсор — через него выполняют запросы
```

## Создать таблицу и вставить данные

```python
cur.execute("""
    CREATE TABLE IF NOT EXISTS users (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        age INTEGER
    )
""")

cur.execute("INSERT INTO users (name, age) VALUES (?, ?)", ("Аня", 25))
conn.commit()        # ЗАФИКСИРОВАТЬ: без commit изменения не сохранятся в файл
```

> **Ловушка:** без `conn.commit()` вставки и обновления пропадут при закрытии — они висят в незавершённой транзакции.

## Параметры — защита от SQL-инъекций

Значения подставляй через **`?`**, а не форматированием строки. Иначе злоумышленник вставит SQL в данные (SQL-инъекция).

```python
# ОПАСНО — SQL-инъекция:
cur.execute(f"SELECT * FROM users WHERE name = '{имя}'")

# ПРАВИЛЬНО — параметр, движок сам экранирует:
cur.execute("SELECT * FROM users WHERE name = ?", (имя,))
```

## Чтение результатов

```python
cur.execute("SELECT name, age FROM users WHERE age > ?", (18,))

cur.fetchone()      # одна строка → ('Аня', 25) или None
cur.fetchall()      # все строки → [('Аня', 25), ...]

for name, age in cur.execute("SELECT name, age FROM users"):
    print(name, age)      # курсор итерируется построчно
```

## Контекстный менеджер

Соединение как менеджер контекста ([contextlib](../../../Библиотеки/Модули/Отладка%20и%20утилиты/contextlib.md)) автоматически делает `commit` при успехе и `rollback` при исключении:

```python
with sqlite3.connect("app.db") as conn:
    conn.execute("INSERT INTO users (name) VALUES (?)", ("Боря",))
    # commit автоматически при выходе без ошибки
```

## sqlite3 vs серверные СУБД

| | SQLite | PostgreSQL/MySQL |
|---|---|---|
| Сервер | не нужен (файл) | отдельный процесс |
| Установка | встроен в Python | ставить и настраивать |
| Конкурентная запись | ограничена | сильная |
| Когда | локально, тесты, прототип | продакшн, много клиентов |

## Связи

- SQL — язык запросов, на котором работает sqlite3 (тренируй SQL прямо здесь);
- Базы данных — реляционная модель, таблицы, ключи;
- [psycopg2](../../../Библиотеки/Сторонние/Работа%20с%20БД/psycopg2.md) — драйвер PostgreSQL с почти таким же DB-API (execute/fetch/commit);
- [SQLAlchemy](../../../Библиотеки/Сторонние/ORM/SQLAlchemy.md) — ORM поверх sqlite3 и других БД.
