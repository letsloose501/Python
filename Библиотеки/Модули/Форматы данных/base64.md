# base64

> _Упаковать двоичные данные в обычные буквы и цифры, чтобы они прошли там, где ждут только текст._

---

**base64** — модуль кодирования двоичных данных в **текст** из 64 безопасных символов (A–Z, a–z, 0–9, `+`, `/`). Нужен там, где канал передаёт только текст — JSON, URL, email, HTML — а данные двоичные (картинка, файл, ключ).

> **Это не шифрование и не сжатие.** Base64 не скрывает данные (раскодировать может кто угодно) и не уменьшает их — наоборот, увеличивает объём примерно на **33%**. Его задача — *безопасно представить*, а не защитить.

## Кодирование и декодирование

Работает с **байтами** в обе стороны:

```python
import base64

сырые = "привет".encode()               # b'\xd0\xbf\xd1\x80...'  двоичные данные
код = base64.b64encode(сырые)           # b'0L/RgNC40LLQtdGC'     текст-байты
код.decode()                            # '0L/RgNC40LLQtdGC'      строка

base64.b64decode(код).decode()          # → 'привет'   обратно
```

## Зачем это на практике

Двоичные данные содержат байты, которые текстовый формат воспримет как управляющие символы или разделители — и сломается. Base64 переводит их в «безобидные» буквы.

- **JSON/HTML** — встроить картинку прямо в текст (`data:image/png;base64,iVBOR...`);
- **Email** — вложения (MIME) кодируются в base64, т.к. почта исторически текстовая ([email](../../../Библиотеки/Модули/Безопасность%20и%20интернет/email.md));
- **Basic Auth** — логин:пароль в HTTP-заголовке кодируют base64 (не шифруют!);
- **Токены/ключи** — двоичный ключ отдать как строку.

## urlsafe — для ссылок

В обычном base64 есть символы `+` и `/`, которые в URL имеют особый смысл. `urlsafe`-вариант заменяет их на `-` и `_`:

```python
base64.urlsafe_b64encode(b"data\xff")   # безопасно вставлять в URL
```
