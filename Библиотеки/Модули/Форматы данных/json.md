# json

> _Язык обмена данными между сервисами: словарь Python ↔ строка, понятная любому языку._

---

**json** — модуль для перевода между объектами Python и форматом **JSON** (JavaScript Object Notation) — текстовым стандартом обмена данными в вебе. API-запросы, конфиги, ответы серверов — почти всё это JSON. Модуль делает две вещи: **сериализует** (Python → строка) и **десериализует** (строка → Python).

Зачем на бэкенде: любой обмен с фронтендом и внешними API идёт через JSON. Понимать `dumps`/`loads` — базовый навык.

## Четыре функции

Две пары: работа со **строкой** (`s` на конце) и с **файлом**.

```python
import json

json.dumps(obj)    # объект → строка JSON        (dump String)
json.loads(s)      # строка JSON → объект         (load String)
json.dump(obj, f)  # объект → записать в файл f
json.load(f)       # прочитать объект из файла f
```

```python
data = {"имя": "Аня", "возраст": 25, "теги": ["a", "b"]}

s = json.dumps(data)         # '{"имя": ...}'  строка
back = json.loads(s)         # обратно в dict
```

## Соответствие типов

JSON знает меньше типов, чем Python — при переводе они отображаются друг в друга:

| Python | JSON |
|---|---|
| `dict` | object `{}` |
| `list`, `tuple` | array `[]` |
| `str` | string |
| `int`, `float` | number |
| `True` / `False` | `true` / `false` |
| `None` | `null` |

> **Ловушка:** ключи в JSON — всегда **строки**. `json.dumps({1: "a"})` превратит ключ `1` в `"1"`, и после `loads` он не станет числом обратно.

Отображение **не взаимно однозначно**: два питоновских типа схлопываются в один JSON-овский, и обратно возвращается только один из них. Это ломает круговой обход «записал → прочитал»:

```python
данные = {1: "a", 2: "b"}
json.loads(json.dumps(данные))        # → {'1': 'a', '2': 'b'}   ключи стали строками
json.loads(json.dumps((1, 2)))        # → [1, 2]                 кортеж стал списком

# ПРАВИЛЬНО — вернуть числовые ключи руками при чтении:
сырое = json.loads(json.dumps(данные))
{int(k): v for k, v in сырое.items()}  # → {1: 'a', 2: 'b'}
```

> Из этого следует практическое правило: **не храни в JSON структуры, чей тип важен**. Нужны числовые ключи, кортежи, множества, `datetime` — либо конвертируй вручную на входе и выходе, либо бери [pickle](../../../Библиотеки/Модули/Форматы%20данных/pickle.md) (только для своих данных) или схему на [pydantic](../../../Библиотеки/Сторонние/pydantic.md).

## Читаемый вывод и кириллица

Два параметра, которые нужны почти всегда при записи для человека:

```python
json.dumps(data, indent=2, ensure_ascii=False)
# {
#   "имя": "Аня",          ← ensure_ascii=False: кириллица как есть, а не и...
#   "возраст": 25          ← indent=2: отступы, читаемо
# }
```

> **Ловушка с кириллицей:** по умолчанию `ensure_ascii=True` — русские буквы кодируются как `и`. Для читаемого вывода на русском **всегда** ставь `ensure_ascii=False`.

## Свои типы — параметр default

`json` не умеет сериализовать произвольные объекты (`datetime`, `Decimal`, свои классы) — будет `TypeError`. Функция `default` говорит, как их превратить в понятный JSON тип:

```python
from datetime import datetime

json.dumps(
    {"момент": datetime.now()},
    default=str,                    # неизвестное превращать в строку
)
```

## Сквозной пример: конфиг в файле

```python
import json
from pathlib import Path

конфиг = {"host": "localhost", "port": 8080, "debug": True}

# 1. записать (с отступами и кириллицей)
Path("config.json").write_text(
    json.dumps(конфиг, indent=2, ensure_ascii=False), encoding="utf-8"
)

# 2. прочитать обратно в dict
данные = json.loads(Path("config.json").read_text(encoding="utf-8"))
данные["port"]      # → 8080
```
