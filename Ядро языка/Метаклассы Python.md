# Метаклассы Python

> **Метакласс** — класс, экземплярами которого являются другие классы. Если объект создаётся классом, то класс создаётся **метаклассом**. По умолчанию это `type`. Механизм редкий, но на нём стоят ORM (Django, SQLAlchemy), `ABC`, автоматическая регистрация плагинов.

---

В Python [всё — объект](../ООП/Принципы/Принципы%20ООП%20в%20Python.md#всё--объект), и класс — тоже объект: его можно присвоить переменной, передать в функцию, создать в рантайме. А раз класс — объект, у него есть **тип**, и этот тип называется метаклассом. Понимание метаклассов объясняет, «откуда берутся» классы и как фреймворки магически меняют твои классы при объявлении.

## Класс — тоже объект

Экземпляр создаётся классом. Но и сам класс кем-то создан — его «тип» показывает `type()`:

```python
class A:
    pass

a = A()
type(a)        # → <class '__main__.A'>   — тип объекта это его класс
type(A)        # → <class 'type'>          — тип КЛАССА это метакласс type
type(int)      # → <class 'type'>          — встроенные классы тоже
type(type)     # → <class 'type'>          — type это метакласс самого себя
```

Класс можно использовать как обычное значение — присвоить, вернуть, положить в список:

```python
классы = [int, str, A]     # классы как элементы списка
alias = A                  # присвоить переменной
alias() == A()             # тот же класс
```

## `type` в двух ролях

Встроенный `type` делает две разные вещи:

```python
# 1) с ОДНИМ аргументом — вернуть тип объекта:
type(42)                   # → <class 'int'>

# 2) с ТРЕМЯ аргументами — СОЗДАТЬ новый класс:
Dog = type("Dog", (), {"bark": lambda self: "Гав"})
#         имя     базы  пространство имён (атрибуты и методы)
Dog().bark()               # → "Гав"
```

Вторая форма — и есть «фабрика классов». Обычное объявление `class` — просто удобный синтаксис над ней:

```python
# это:
class Dog:
    def bark(self):
        return "Гав"

# ровно эквивалентно:
Dog = type("Dog", (), {"bark": lambda self: "Гав"})
```

## Что происходит при `class X:`

Когда интерпретатор встречает объявление класса, он:

1. Выполняет тело класса, собирая имена в **пространство имён** (словарь) — методы, атрибуты класса.
2. Вызывает **метакласс** (по умолчанию `type`) как `metaclass(имя, базы, пространство_имён)`.
3. Полученный объект-класс привязывает к имени.

```
class X(Base):        имя = "X"
    y = 1        →    базы = (Base,)          →   type("X", (Base,), namespace)   →   класс X
    def m(): ...      namespace = {"y": 1, "m": <function>}
```

Подменив метакласс, ты вклиниваешься в шаг 2 — можешь **изменить класс в момент его создания**.

## Свой метакласс

Метакласс наследуют от `type` и переопределяют `__new__` (создать класс) или `__init__` (донастроить). Классу его задают ключевым словом `metaclass=`:

```python
class Meta(type):
    def __new__(mcs, name, bases, ns):
        ns["created_by"] = "Meta"                 # добавить атрибут ВСЕМ классам
        cls = super().__new__(mcs, name, bases, ns)
        print(f"[Meta] создан класс {name}")
        return cls

class Service(metaclass=Meta):                    # → печатает "[Meta] создан класс Service"
    pass

Service.created_by     # → "Meta"     — метакласс дописал атрибут
type(Service)          # → <class 'Meta'>  — тип класса теперь Meta, а не type
```

`__new__` метакласса получает `name, bases, ns` — те же три вещи, что и `type(...)`. Внутри можно проверить, дополнить или переписать класс до его рождения.

## Зачем на практике

Метакласс срабатывает **на объявлении класса**, до создания любых объектов — поэтому им автоматизируют то, что касается самого класса:

- **Регистрация подклассов** — метакласс базового класса складывает всех наследников в реестр (плагины, обработчики).
- **Валидация структуры** — проверить, что класс объявил нужные поля/методы, иначе `TypeError` уже при импорте.
- **Автопостроение** — Django ORM: пишешь `name = models.CharField()`, а метакласс `ModelBase` превращает поля в столбцы таблицы и генерирует служебный код.
- **`ABC`** — абстрактные классы ([Абстракция Python](../ООП/Принципы/Абстракция%20Python.md#абстрактные-классы--abc)) работают через метакласс `ABCMeta`, который на создании собирает `__abstractmethods__`.

```python
from abc import ABC
type(ABC)              # → <class 'abc.ABCMeta'>  — ABC стоит на метаклассе
```

> ⚠️ **Часто метакласс — избыточен.** Регистрацию/проверку подклассов проще сделать через [`__init_subclass__`](../ООП/Принципы/Наследование%20Python.md#__init_subclass__--перехват-создания-подкласса) или декоратор класса. Метакласс нужен, только когда меняешь **само создание** класса. Правило Тима Питерса: _«если ты не уверен, нужны ли тебе метаклассы — они тебе не нужны»_.

## Метакласс наследуется

Задавать `metaclass=` в каждом подклассе не нужно — он передаётся по иерархии от базового класса:

```python
class Service(metaclass=Meta): pass
class Sub(Service): pass          # metaclass= не указан

type(Sub)      # → <class 'Meta'> — метакласс унаследован от Service
```

## Можно ли миксовать — конфликт метаклассов

Да, но с ограничением. Если класс наследует от **двух баз с разными метаклассами**, Python не знает, какой из них применить — и падает с **`metaclass conflict`**:

```python
class MetaB(type): pass
class MetaC(type): pass
class B(metaclass=MetaB): pass
class C(metaclass=MetaC): pass

class D(B, C):        # ✗ TypeError: metaclass conflict
    pass
# «the metaclass of a derived class must be a (non-strict) subclass
#  of the metaclasses of all its bases»
```

**Правило:** метакласс потомка обязан быть подклассом метаклассов всех баз. Решение — **общий производный метакласс**, наследующий от обоих:

```python
class MetaBC(MetaB, MetaC):       # объединяющий метакласс
    pass

class D(B, C, metaclass=MetaBC):  # ✓ теперь совместимо
    pass

type(D)     # → <class 'MetaBC'>
```

Именно из-за этого правила `ABC` и сторонние библиотеки с собственными метаклассами иногда не смешиваются напрямую — приходится городить объединяющий метакласс.

## Когда НЕ нужны — что взять вместо

| Задача | Достаточно | Метакласс нужен? |
|---|---|---|
| Отреагировать на создание подкласса | `__init_subclass__` | нет |
| Изменить/зарегистрировать готовый класс | декоратор класса (`@register`) | нет |
| Контролировать создание **экземпляра** | `__new__` в самом классе | нет |
| Вмешаться в **создание самого класса**, для всей иерархии | — | да |
