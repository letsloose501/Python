# Ловушки Python

> Тему по-настоящему понимаешь не на «как надо», а на «как ошибаются и почему». Здесь собраны неочевидные места Python, где интуиция подводит. Каждая ловушка — с разбором механизма под ней.

---

## Числа-ключи в словаре сливаются

`True == 1 == 1.0`, и хеши у них равны — для словаря это **один и тот же ключ**. Остаётся **первый** вставленный ключ, но значение — от **последнего** присваивания:

```python
a = {True: 'да', 1: 'нет', 1.0: 'возможно', None: None}
a               # → {True: 'возможно', None: None}
```

Разбор: словарь считает ключи одинаковыми, если `hash(k1) == hash(k2)` **и** `k1 == k2`. `hash(True) == hash(1) == hash(1.0) == 1`, и все они равны — значит, три записи бьют в одну ячейку. Ключ уже занят `True` (вставлен первым), поэтому имя ключа не меняется, а значение перезаписывается до `'возможно'`.

> Не смешивай `bool`/`int`/`float` как ключи одного словаря — молча потеряешь записи. Ключи-«числа» с одинаковым значением неотличимы.

## inf и nan — арифметика бесконечностей

```python
a = float('inf'); b = float('inf')
a - b            # → nan     — ∞ − ∞ не определено
type(a - b)      # → float   — nan это float, не отдельный тип
a == b           # → True    — две бесконечности равны между собой
```

**`nan` («не число») не равен ничему, даже себе:**

```python
n = float('nan')
n == n           # → False   (!) — единственный объект, не равный самому себе
n < 1, n > 1     # → (False, False) — любое сравнение с nan это False
```

Отсюда — **`nan` ломает сортировку**: алгоритм опирается на сравнения, а с `nan` они все ложны, и порядок получается мусорным:

```python
sorted([1.0, float('nan'), 2.0, float('nan'), 0.0])
# → [1.0, nan, 2.0, nan, 0.0]   — НЕ отсортировано!
```

> Проверяй на `nan` через `math.isnan(x)`, а не `x == nan` (всегда False). Перед сортировкой отфильтруй `nan`. Подробнее про float — в [Примитивные типы данных Python](../Данные/Примитивные%20типы%20данных%20Python.md#float--число-с-плавающей-точкой).

## Смена класса объекта на лету — `__class__`

Объекту можно **переприсвоить класс** прямо в рантайме. Но меняются только **методы** (откуда они берутся), а **данные экземпляра остаются на месте**:

```python
class A:
    def __init__(self): self.x = 10
    def who(self): return "Я объект класса A"

class B:
    def __init__(self): self.y = 20
    def who(self): return "Я объект класса B"

obj = A()
obj.who()            # → "Я объект класса A"
obj.__class__ = B    # сменили класс на лету
obj.who()            # → "Я объект класса B"   — методы теперь от B
obj.x                # → 10                     — старый атрибут ОСТАЛСЯ
hasattr(obj, 'y')    # → False                  — B.__init__ НЕ вызывался
obj.__dict__         # → {'x': 10}
```

Разбор: у объекта два «источника». **Методы** ищутся в классе (`type(obj)` → его MRO) — сменил класс, сменились методы. **Данные** лежат в собственном словаре объекта `obj.__dict__` — класс их не хранит и при смене не трогает. Присваивание `__class__` меняет только указатель на класс; конструктор нового класса **не запускается**, поэтому `y` не появляется. Получается «химера»: ведёт себя как `B`, а данные — от `A`.

> Смена `__class__` — легальный, но экзотический приём (иногда для «прокачки» объекта в подтип). В обычном коде — источник трудноуловимых багов.

## Нет `++` и `--`

`_++++--+__` не «инкремент» — в Python нет `++`/`--`. Это цепочка **унарных** `+`/`-`:

```python
_ = 1; __ = 1
_ ++++--+ __       # = _ + (+ + + - - + __) = 1 + 1 = 2
```

Каждый `+`/`-` — унарная операция над числом. `+x` не меняет знак, `-x` меняет; двойной `--` возвращает как было. Для увеличения на 1 в Python пишут `x += 1`.

## `...` — это объект `Ellipsis`

Троеточие — не синтаксическая заглушка, а настоящий объект-синглтон `Ellipsis`, его можно присваивать и класть в словарь:

```python
{...: None}         # → {Ellipsis: None}   — валидный ключ
x = ...             # x это Ellipsis
```

Применяется как «заглушка тела» (`def f(): ...`), в аннотациях (`Callable[..., int]`) и в срезах NumPy. Подробнее — [Специальные типы данных Python](../Данные/Специальные%20типы%20данных%20Python.md).

## `dict.fromkeys` с изменяемым значением — общая ссылка

`dict.fromkeys(ключи, значение)` кладёт во **все** ключи **один и тот же** объект — не копию. С изменяемым значением (список, словарь) это ловушка:

```python
d = dict.fromkeys(["a", "b", "c"], [])
d["a"].append(1)
d               # → {'a': [1], 'b': [1], 'c': [1]}   — изменились все!
```

Разбор: `[]` вычисляется **один раз**, и эта единственная ссылка раздаётся всем ключам. `d["a"]`, `d["b"]`, `d["c"]` — один и тот же список, поэтому `append` виден везде. Та же природа, что у изменяемого аргумента по умолчанию `def f(x=[])`.

```python
# ПРАВИЛЬНО — свой объект на каждый ключ:
d = {k: [] for k in ["a", "b", "c"]}   # comprehension создаёт новый список
d["a"].append(1)
d               # → {'a': [1], 'b': [], 'c': []}
```

> `fromkeys` безопасен только с **неизменяемым** значением (`None`, `0`, `""`). Для изменяемого — dict comprehension.

## Ещё две классические (описаны отдельно)

- **Изменяемый аргумент по умолчанию** `def f(x=[])` — список создаётся один раз и общий для всех вызовов. Разбор и фикс — [Функции Python](../Ядро%20языка/Функции%20Python.md#значения-по-умолчанию).
- **`is` вместо ` == `** — `is` сравнивает идентичность, а не значение; из-за кэша малых чисел `a is b` иногда «случайно» True. Разбор — [Операторы Python](../Ядро%20языка/Операторы%20Python.md).
- **Строка не может кончаться на `\`** — обратный слэш экранирует закрывающую кавычку, даже в `r"..."`. Разбор и фикс — [Примитивные типы данных Python](../Данные/Примитивные%20типы%20данных%20Python.md#ловушка-строка-не-может-кончаться-на-слэш).
- **`import *` внутри функции** — `SyntaxError: import * only allowed at module level`. Разбор — [Модули и пакеты Python](../Ядро%20языка/Модули%20и%20пакеты%20Python.md#где-делать-импорты).
- **`return`/`raise` в `finally`** — выход из `finally` затирает `return` и исключение из `try`: ошибка пропадает молча. Разбор и фикс — [Обработка ошибок Python](../Ядро%20языка/Обработка%20ошибок%20Python.md#ловушка-return-в-finally-перекрывает-try-и-глотает-исключение).
