# Стиль кода Python — PEP 8 и Google Style Guide

> Код читается намного чаще, чем пишется. Все правила ниже направлены на одно: чтобы любой разработчик мог быстро понять чужой код. Соблюдение стиля внутри одного модуля важнее соблюдения стиля вообще — не ломай обратную совместимость ради PEP 8.

[PEP 8 — официальный стиль кода Python](https://pep8.org/) · [Google Python Style Guide](https://google.github.io/styleguide/pyguide.html)

Связанные файлы: [Python](../Python.md) · [Синтаксические конструкции Python](../Ядро%20языка/Синтаксические%20конструкции%20Python.md) · [Обработка ошибок Python](../Ядро%20языка/Обработка%20ошибок%20Python.md)

### Когда можно отступить от стиля

Правила — не догма. Можно (и нужно) нарушить правило если:

- применение сделает код **менее** читаемым
- окружающий код написан иначе, и единообразие важнее
- код должен остаться совместимым со старыми версиями Python

Приоритет: `модуль/функция > проект > PEP 8`.

### Отступы и длина строки

**4 пробела** на уровень. Никаких табов — смешивание вызывает `TabError`.

**79 символов** — максимум для кода. 72 — для docstring и комментариев. Google допускает до **80**. Для строк URL и импортов — допустимо превышать.

```python
# Перенос через скобки — предпочтительнее обратного слеша:
результат = (первое_значение
             + второе_значение
             + третье_значение)

# Аргументы функции:
def длинная_функция(
        аргумент_один,
        аргумент_два,
        аргумент_три):
    тело()

# Если закрывающая скобка на новой строке:
мой_список = [
    1, 2, 3,
    4, 5, 6,
]  # ← скобка под первым символом строки

# Оператор разрыва — ПЕРЕД оператором (не после):
# Правильно:
доход = (зарплата
         + премия
         - налоги)

# Неправильно:
доход = (зарплата +
         премия -    # оператор в конце строки — хуже
         налоги)
```

### Пустые строки

```python
# Между функциями и классами верхнего уровня — 2 пустые строки:
def функция_а():
    pass


def функция_б():
    pass


class МойКласс:

    # Между методами класса — 1 пустая строка:
    def метод_один(self):
        pass

    def метод_два(self):
        pass

    # Внутри функции — пустые строки для разделения логических блоков:
    def сложная_функция(self):
        # блок 1: подготовка данных
        данные = получить_данные()
        очищенные = очистить(данные)

        # блок 2: обработка
        результат = обработать(очищенные)
        return результат
```

### Импорты

```python
# Каждый модуль — на отдельной строке:
import os
import sys              # ✓

import os, sys          # ✗

# Порядок групп (разделять пустой строкой):
# 1. Стандартная библиотека
import os
import sys
from pathlib import Path

# 2. Сторонние библиотеки
import requests
import numpy as np

# 3. Локальные модули проекта
from myproject.utils import helper
from myproject import config

# Импорты — всегда в начале файла, после docstring модуля и до кода.

# Относительные импорты — не рекомендуются (Google Style):
# Даже внутри пакета — используй полный путь.
from sound.effects import echo    # ✓ (Google)

# Wildcard-импорт — только если это явно задумано API:
from module import *   # почти всегда плохо

# from x import y as z — только при конфликте имён или длинном имени:
import numpy as np           # стандартная аббревиатура — OK
from xml.etree import ElementTree as ET   # длинное имя — OK
```

### Именование

|Что|Стиль|Пример|
|---|---|---|
|Переменные, функции, методы|`snake_case`|`user_name`, `get_data()`|
|Классы|`PascalCase`|`MyClass`, `HttpClient`|
|Константы|`UPPER_SNAKE_CASE`|`MAX_SIZE`, `DEFAULT_TIMEOUT`|
|Модули, пакеты|`snake_case`|`my_module.py`, `utils/`|
|Защищённые атрибуты|`_single_underscore`|`_cache`, `_internal`|
|Приватные атрибуты (name mangling)|`__double_underscore`|`__password`|
|Магические методы|`__dunder__`|`__init__`, `__str__`|
|Аргумент экземпляра|`self`|всегда `self`|
|Аргумент класса|`cls`|всегда `cls`|

```python
# Имена — описательные, без сокращений (кроме общепринятых):
# Плохо:
def calc(u, p, t):
    return u * p * t

# Хорошо:
def calculate_price(units: int, price_per_unit: float, tax_rate: float) -> float:
    return units * price_per_unit * (1 + tax_rate)

# Не используй:
# l (строчная L), O (заглавная О), I (заглавная i) — путаются с 1 и 0
l = 1   # ✗
O = 0   # ✗

# Имена, которые конфликтуют со встроенными — добавь _:
list_ = [1, 2, 3]    # ✓
type_ = "string"      # ✓

# Исключения — заканчиваются на Error (Google Style):
class ValidationError(ValueError): pass    # ✓
class HttpError(Exception): pass           # ✓
class FooFooError(Exception): pass         # ✗ — не дублируй имя модуля
```

### Docstrings (PEP 257)

```python
# Однострочный — закрывающие """ на той же строке:
def квадрат(x):
    """Возвращает квадрат числа."""
    return x ** 2

# Многострочный — закрывающие """ на отдельной строке:
def сложная_функция(данные, параметр=None):
    """Краткое описание в одну строку.

    Расширенное описание: что делает, зачем, какие допущения.
    Может занимать несколько абзацев.

    Args:
        данные: Описание аргумента данные.
        параметр: Описание. По умолчанию None.

    Returns:
        Описание возвращаемого значения.

    Raises:
        ValueError: Если данные пустые.
        TypeError: Если тип данных неверный.
    """
    pass

# Генератор — Yields вместо Returns (Google Style):
def строки_файла(путь):
    """Читает файл построчно.

    Args:
        путь: Путь к файлу.

    Yields:
        Очередная строка файла без символа переноса.
    """
    with open(путь) as f:
        for строка in f:
            yield строка.rstrip()

# Класс — docstring описывает класс, не __init__:
class МойКласс:
    """Описание что делает класс.

    Attributes:
        атрибут_один: Описание атрибута.
        атрибут_два: Описание другого атрибута.
    """

    def __init__(self, значение):
        self.атрибут_один = значение
```

### Аннотации типов (Type Hints)

```python
# Базовые аннотации (PEP 484):
def приветствие(имя: str) -> str:
    return f"Привет, {имя}!"

def обработать(данные: list[int], максимум: int = 100) -> dict[str, int]:

    pass

# Python < 3.10 — через Optional:
from typing import Optional
def найти(ключ: str) -> Optional[str]:
    pass

# Коллекции из collections.abc (предпочтительнее typing):
from collections.abc import Sequence, Mapping, Callable, Iterator

class Пример:
    def метод(self) -> None:   # ✓

        pass
```

### Строки

```python
# Одинарные и двойные кавычки — одинаково допустимы.
# Главное — единообразие внутри проекта.
# Google Style: предпочтительны одинарные для простых строк,
# двойные для строк с апострофами.

# f-строки — предпочтительный способ форматирования (Python 3.6+):
имя = "Иван"
x = f"Привет, {имя}!"          # ✓

# % и format — тоже допустимы, но f-строки читаемее:
x = "Привет, %s!" % имя         # допустимо
x = "Привет, {}!".format(имя)   # допустимо

# Конкатенация через + — только для единичного объединения:
x = "часть" + переменная + "конец"   # OK для одной строки

# Для многих строк — join:
части = ["а", "б", "в"]
x = ", ".join(части)   # ✓
x = "" + части[0] + ", " + части[1]  # ✗ — O(n²)

# Многострочные строки — через скобки, не через \:
длинная = (
    "первая часть "
    "вторая часть "
    "третья часть"
)

# Логирование — не форматируй строку заранее:
import logging
logging.warning("Ошибка для %s", имя)       # ✓ — форматирование отложено
logging.warning(f"Ошибка для {имя}")        # ✗ — форматируется всегда
```

### Исключения

```python
# Использовать встроенные классы исключений, где это уместно:
def подключиться(порт: int) -> int:
    if порт < 1024:
        raise ValueError(f"Порт должен быть >= 1024, получен {порт}")
    # ...

# Свои исключения — наследовать от существующих, заканчиваться на Error:
class AppError(Exception):
    """Базовый класс ошибок приложения."""

class ValidationError(AppError):
    pass

# НЕ использовать assert для проверки бизнес-логики (Google Style):
# assert отключается при python -O

# Плохо — assert как проверка аргумента:
def функция(данные):
    assert данные is not None   # ✗ — отключится при -O

# Хорошо:
def функция(данные):
    if данные is None:
        raise ValueError("данные не могут быть None")  # ✓

# assert OK только в тестах (pytest) и для самопроверки алгоритма:
assert результат >= минимум, f"Неожиданное значение {результат}"  # для отладки

# Минимизировать тело try:
try:
    значение = словарь[ключ]   # ✓ — только опасный вызов
except KeyError:
    значение = None

# Не писать:
try:
    данные = получить_данные()   # ✗ — слишком широкий try
    обработать(данные)
    сохранить(данные)
except Exception:
    pass

# Никогда:
except:        # ✗ — ловит вообще всё включая KeyboardInterrupt
    pass

except Exception:   # ✗ — если не перебрасываешь и не логируешь
    pass
```

### Comprehensions

```python
# Простые — хороши и читаемы:
квадраты = [x**2 for x in range(10)]   # ✓

# Сложные — разбей на несколько строк:
результат = [
    трансформировать(значение)
    for значение in генератор(входные_данные)
    if условие_выполнено(значение)
]   # ✓

# Несколько for в одном comprehension — запрещено (Google Style):
# Слишком сложно для чтения.
результат = [(x, y) for x in range(10) for y in range(5) if x * y > 10]   # ✗

# Лучше явный цикл:
результат = []
for x in range(10):
    for y in range(5):
        if x * y > 10:
            результат.append((x, y))   # ✓

# Итерация по словарю — через items(), не через keys():
for ключ, значение in словарь.items():   # ✓
for ключ in словарь.keys():              # ✗ — избыточно
for ключ in словарь:                     # ✓ — итерация по ключам
```

```python
# Мутабельные объекты как дефолтные аргументы — главная ловушка Python:
def добавить(элемент, список=[]):    # ✗ — список создаётся ОДИН РАЗ

# Неизменяемые дефолты — OK:
def функция(параметры=(), флаги=frozenset()):   # ✓ — tuple и frozenset неизменяемы
    pass

# Не использовать вычисляемые выражения как дефолт:
import time
def f(t=time.time()):   # ✗ — вычисляется при определении функции, не при вызове
    pass
```

### lambda и условные выражения

```python
# lambda — только для однострочных простых функций:
сортировать = lambda x: x[1]     # ✓ — простая key-функция
квадрат = lambda x: x**2         # ✓

# Если длиннее 60–80 символов — именованная функция:
# Плохо:
f = lambda x, y: x * 2 + y ** 3 - math.sqrt(x * y + 1) / (x + y)

# Хорошо:
def вычислить(x, y):
    return x * 2 + y ** 3 - math.sqrt(x * y + 1) / (x + y)

# Предпочитай generator expression вместо map()/filter() + lambda (Google):
квадраты = list(map(lambda x: x**2, числа))   # хуже
квадраты = [x**2 for x in числа]              # лучше

# Условное выражение (тернарный оператор) — только если умещается в строку:
значение = "да" if условие else "нет"   # ✓

# Плохо — слишком длинное:
значение = ("очень длинный текст для истинного случая"
            if какое_то_сложное_условие(переменная)
            else "другой длинный текст")  # ✗ — лучше if/else блок
```

### Декораторы

```python
from functools import wraps

# Декоратор — документировать так же, как функцию:
def мой_декоратор(func):
    """Описание что делает декоратор."""
    @wraps(func)
    def обёртка(*args, **kwargs):
        # логика
        return func(*args, **kwargs)
    return обёртка

# Не использовать внешние зависимости внутри декоратора (Google Style):
# (файлы, сокеты, БД) — они могут быть недоступны при импорте.

# staticmethod — только если вынуждает API сторонней библиотеки.
# Лучше — функция на уровне модуля (Google Style):

# Плохо:
class Утилиты:
    @staticmethod
    def помочь():
        return 42

# Лучше:
def помочь():   # просто функция модуля
    return 42

# classmethod — только для named constructor или работы с глобальным состоянием класса:
class Соединение:
    @classmethod
    def из_строки(cls, строка_подключения: str) -> "Соединение":
        """Named constructor."""
        хост, порт = строка_подключения.split(":")
        return cls(хост, int(порт))
```

### PEP 8 vs Google Style — ключевые отличия

|Правило|PEP 8|Google Style|
|---|---|---|
|Длина строки|79 символов|80 символов|
|Относительные импорты|Допустимы|Запрещены|
|`from x import *`|Не рекомендуется|Запрещён|
|`staticmethod`|Без ограничений|Только для интеграции с внешним API|
|Формат TODO|Не определён|`# TODO: issue-link - описание`|
|`assert` в коде|Допустим|Только в тестах и для самопроверки|
|Мутабельное глобальное состояние|Не запрещено|Запрещено|
|Именование исключений|`Error` в конце|`Error` в конце, без дублирования имени модуля|
|Документирование генераторов|`Returns:`|`Yields:`|

> Основной принцип: **код читается намного чаще, чем пишется**. Оба руководства — инструмент читаемости, не самоцель.
