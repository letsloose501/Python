## Что такое магические методы

**Магические методы** (dunder-методы, от _double underscore_) — специальные методы класса с двойным подчёркиванием с обеих сторон: `__метод__`.

Они не вызываются напрямую. Python вызывает их **автоматически** в ответ на определённые операции над объектом: арифметику, сравнение, вывод, вхождение в цикл, обращение по индексу и так далее.

```python
a + b          # Python вызывает a.__add__(b)
len(x)         # Python вызывает x.__len__()
print(x)       # Python вызывает x.__str__()
x[0]           # Python вызывает x.__getitem__(0)
x in коллекция # Python вызывает коллекция.__contains__(x)
```

> Магические методы — это **протокол**. Реализуешь нужные методы в своём классе — и объект начинает вести себя как встроенный тип: складываться, сравниваться, итерироваться.

---

## Зачем нужны

**Перегрузка операторов** — определить что значит `+`, `-`, ` == ` для своего класса.

**Интеграция со встроенными функциями** — `len()`, `str()`, `repr()`, `hash()`, `bool()` работают через магические методы.

**Протоколы** — итерируемость, контекстные менеджеры (`with`), дескрипторы, работают через магические методы.

```python
class Вектор:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):       # v1 + v2
        return Вектор(self.x + other.x, self.y + other.y)

    def __str__(self):              # print(v)
        return f"({self.x}, {self.y})"

    def __len__(self):              # len(v)
        return 2

v1 = Вектор(1, 2)
v2 = Вектор(3, 4)
print(v1 + v2)   # → (4, 6)  — вызвал __add__ и __str__
```

## Категории магических методов

### Жизненный цикл объекта

|Метод|Когда вызывается|
|---|---|
|`__new__(cls)`|При создании объекта (до `__init__`)|
|`__init__(self, ...)`|При инициализации объекта|
|`__del__(self)`|При удалении объекта сборщиком мусора|

> **Класс — фабрика объектов.** Вызов `Класс(args)` идёт в два шага: `__new__(cls, ...)` **создаёт** пустой экземпляр (выделяет память, возвращает объект), затем `__init__(self, ...)` **наполняет** его атрибутами. Обычно переопределяют только `__init__`; `__new__` трогают редко — для неизменяемых типов или синглтона (см. [Порождающие паттерны](../ООП/Паттерны/Порождающие%20паттерны.md)). Как создаётся сам класс — в [Метаклассы Python](../Ядро%20языка/Метаклассы%20Python.md).

```python
class Точка:
    def __new__(cls, *args):
        print("__new__ — создаётся объект")
        return super().__new__(cls)
    def __init__(self, x, y):
        print("__init__ — наполняется")
        self.x, self.y = x, y

Точка(1, 2)   # → __new__ — создаётся объект
              # → __init__ — наполняется
```

### Представление

|Метод|Когда вызывается|
|---|---|
|`__str__(self)`|`str(x)`, `print(x)` — для людей|
|`__repr__(self)`|`repr(x)`, вывод в REPL — для отладки|
|`__format__(self, spec)`|f-строки: `f"{x:.2f}"`|
|`__bytes__(self)`|`bytes(x)`|

**`__str__` vs `__repr__` — на примере.** `__str__` — человекочитаемо (для `print`), `__repr__` — однозначно и для отладки (REPL, вывод в контейнерах, отладчик). Если задан только `__repr__` — он используется и вместо `__str__`.

```python
class Пользователь:
    def __init__(self, имя, возраст):
        self.имя, self.возраст = имя, возраст

    def __str__(self):                 # для людей — print(u)
        return f"{self.имя}, {self.возраст} лет"

    def __repr__(self):                # для отладки — repr(u), REPL, в списке
        return f"Пользователь({self.имя!r}, {self.возраст})"

u = Пользователь("Иван", 25)
print(u)          # → Иван, 25 лет                (вызвал __str__)
u                 # → Пользователь('Иван', 25)    (REPL вызвал __repr__)
[u]               # → [Пользователь('Иван', 25)]  — контейнеры печатают __repr__ элементов
```

> `__repr__` по возможности должен выглядеть как валидный вызов конструктора (`Пользователь('Иван', 25)`) — по выводу сразу видно, как воссоздать объект. `!r` в f-строке подставляет `repr` вложенного значения (у строк — с кавычками).

### Отражённые операторы (правый операнд)

Вызываются если левый операнд не знает как обработать операцию:

|Метод|Оператор|
|---|---|
|`__radd__(self, other)`|`other + self`|
|`__rsub__(self, other)`|`other - self`|
|`__rmul__(self, other)`|`other * self`|

| Метод                 | Оператор |
| --------------------- | -------- |
| `__eq__(self, other)` | **==**   |
| `__ne__(self, other)` | `!=`     |
| `__lt__(self, other)` | `<`      |
| `__le__(self, other)` | `<=`     |
| `__gt__(self, other)` | `>`      |
| `__ge__(self, other)` | `>=`     |

### Логические и булевы

|Метод|Когда вызывается|
|---|---|
|`__bool__(self)`|`bool(x)`, `if x:`, `while x:`|
|`__hash__(self)`|`hash(x)`, использование в `set` и как ключ `dict`|

> ⚠️ **`__eq__` и `__hash__` связаны контрактом, и это частый вопрос секций.** Определил `__eq__` — Python **автоматически убирает** `__hash__`, и объект становится нехешируемым (`TypeError: unhashable type`), потому что равные объекты обязаны иметь равный хеш, а сам он этого гарантировать не может. Правило и как чинить (`__hash__ = hash((поля))`) — [Хеш-таблица](../Данные/Структуры%20данных/Хеш-таблица.md#хешируемый-объект).

### Атрибуты

|Метод|Когда вызывается|
|---|---|

## Как Python ищет магический метод

1. Смотрит в **тип** объекта (класс), не в сам объект
2. Если не нашёл — идёт по цепочке наследования (`MRO`)
3. Если не нашёл нигде — `TypeError`

```python
x = 42
x + 1
# Python берёт тип: int
# ищет int.__add__
# вызывает int.__add__(x, 1)
```

## Сквозной пример — сравнение объектов по среднему баллу

Классический кейс: система студентов и преподавателей ([наследование](../ООП/Принципы/Наследование%20Python.md) `Mentor → Lecturer/Reviewer`). Магические методы делают объекты «человеческими»: `__str__` — красивый вывод, `__eq__`/`__gt__`/`__lt__` — сравнение по вычисляемому среднему баллу.

```python
class Student:
    def __init__(self, name, surname):
        self.name = name
        self.surname = surname
        self.grades = {}                      # {курс: [оценки]}

    def avg_grade(self):                       # средний балл по всем курсам
        if not self.grades:
            return 0
        total = sum(sum(g) for g in self.grades.values())
        count = sum(len(g) for g in self.grades.values())
        return total / count

    def __str__(self):                         # print(student)
        return (f'Имя: {self.name}\n'
                f'Фамилия: {self.surname}\n'
                f'Средняя оценка: {self.avg_grade():.1f}')

    def __eq__(self, other):                   # student1 == student2
        return self.avg_grade() == other.avg_grade()

    def __gt__(self, other):                   # student1 > student2
        return self.avg_grade() > other.avg_grade()

    def __lt__(self, other):                   # student1 < student2
        return self.avg_grade() < other.avg_grade()

s1 = Student('Ольга', 'Алёхина'); s1.grades = {'Python': [9, 8]}
s2 = Student('Евгений', 'Попов');  s2.grades = {'Python': [7, 6]}

s1 > s2               # → True   — 8.5 > 6.5
max([s1, s2]).name    # → 'Ольга' — сравнение работает во встроенных функциях
```

Поскольку `__gt__`/`__lt__` возвращают `bool`, объекты сразу работают в `max()`, `min()`, `sorted(key=...)`. Определив `__eq__`, ты неявно отключаешь `__hash__` (объект становится нехешируемым) — см. предупреждение в [контракте `__eq__`/`__hash__`](../ООП/Принципы/Инкапсуляция%20Python.md#dataclass--автоматизация-служебных-методов).

> **Ловушка:** сравнение-методы должны возвращать `bool`, а не строку-сообщение. Если `__lt__` вернёт `"меньше"` (truthy-строку), `x < y` и `y < x` окажутся оба истинными — `sorted()` и `max()` дадут неверный результат. Сообщения выводи отдельно (`print`), а из dunder возвращай `True`/`False`.
