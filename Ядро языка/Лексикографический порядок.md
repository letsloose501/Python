# Лексикографический порядок

> _`"apple" > "animal"` — `True`. Python не «знает алфавит», он сравнивает коды символов по порядку — как слова в словаре._

---

**Лексикографический порядок** — способ сравнивать последовательности «как в словаре»: посимвольно слева направо, до первого различия. На нём держатся операторы `<`/`>` для строк и вся сортировка. Понять его нужно, чтобы не удивляться, почему `"Apple" < "apple"` и как одной строкой отсортировать данные сразу по нескольким критериям.

## Как сравниваются строки

Сравнение идёт **по парам символов**: первый с первым, второй со вторым, и так далее. Как только пара различается — результат готов, дальше не смотрим.

```python
"apple" > "animal"   # → True: на индексе 1 'p'(112) > 'n'(110), остальное неважно
"abc"   < "abd"      # → True: различие на индексе 2, 'c' < 'd'
```

Сравниваются не «буквы», а их **коды Unicode** (что возвращает `ord()`). Отсюда правило про регистр:

```python
ord("A"), ord("a")   # → (65, 97)   заглавные идут РАНЬШЕ строчных
"Apple" < "apple"    # → True: на индексе 0 'A'(65) < 'a'(97)
"Zoo"   < "apple"    # → True: 'Z'(90) < 'a'(97) — любая заглавная < любой строчной
```

**Префикс — меньше.** Если одна строка совпадает с началом другой, но короче — она считается «меньшей» (у неё раньше «кончились» символы):

```python
"cat" < "catastrophe"   # → True: "cat" — префикс, и он короче
```

> **Честная сортировка без учёта регистра** — приводи к одному регистру ключом: `sorted(words, key=str.lower)`. Иначе `"Яблоко"` уедет вперёд `"арбуза"` только из-за заглавной буквы.

## Так сравнивается любая последовательность

Правило «поэлементно до первого различия» работает **не только для строк**, а для всех последовательностей: списков, кортежей, `bytes`. Элементы сравниваются на каждом индексе.

```python
[1, 2, 3] < [1, 2, 4]       # → True: различие на индексе 2, 3 < 4
[1, 2]    < [1, 2, 0]       # → True: [1,2] — префикс, короче
(45, 1, 13) < (45, 7, 4)    # → True: на индексе 1  1 < 7 (13 и 4 уже неважны)
```

Это и делает кортежи удобным инструментом сортировки.

## Кортежи как ключ сортировки

Раз кортежи сравниваются по элементам по порядку, **упаковав данные в кортеж, получаешь сортировку по нескольким критериям сразу**: сначала по первому полю, при равенстве — по второму, и так далее.

```python
students = [
    (1978, "Little"),
    (1978, "Gonzalez"),
    (1977, "Anders"),
]
sorted(students)
# → [(1977,'Anders'), (1978,'Gonzalez'), (1978,'Little')]
#    сначала по году, при равном годе — по фамилии
```

Для объектов задают **функцию-ключ**, возвращающую кортеж полей в нужном порядке:

```python
# по возрасту, при равном — по имени:
sorted(people, key=lambda p: (p.age, p.name))

# обратный порядок одного поля — минус для чисел или reverse для всего:
sorted(people, key=lambda p: (-p.age, p.name))   # возраст по убыванию, имя по возрастанию
```

Тот же приём — очередь с приоритетом: кладут кортеж `(приоритет, объект)`, и структура сама упорядочивает по приоритету (см. [heapq](../Библиотеки/Модули/Коллекции%20и%20структуры%20данных/heapq.md)).

## Ловушки

**Разные типы сравнивать нельзя.** Лексикографическое сравнение доходит до пары элементов **несравнимых типов** — и падает с `TypeError`:

```python
[1, 2] < (1, 2)         # TypeError: список и кортеж несравнимы
"10"  < 10              # TypeError: str и int несравнимы (в Python 3)
[1, "a"] < [1, 2]       # TypeError: на индексе 1 сравниваются 'a' и 2
sorted([1, "2", 3])     # TypeError: sorted тоже сравнивает элементы между собой
```

> В Python 2 `"10" < 10` «работало» (сравнивало по типам) — источник тихих багов. Python 3 честно бросает `TypeError`: смешанные по типу данные приводи к общему типу до сравнения (`key=int`, `key=str`).

**Число как строка сортируется как строка** — посимвольно, не по величине:

```python
sorted(["2", "10", "1"])         # → ['1', '10', '2']   '1' < '2', длина неважна
sorted(["2", "10", "1"], key=int)  # → ['1', '2', '10']   сравнение как числа
```
