# Декораторы для асинхронных функций

> **Асинхронный декоратор** — декоратор, обёртка которого объявлена через `async def` и ждёт оригинал через `await`. Нужен потому, что обычный декоратор на корутине **не падает, а молча врёт**: он оборачивает не результат работы функции, а объект-корутину, созданный за микросекунду.

---

Обычный [декоратор](../Ядро%20языка/Декораторы%20Python.md) на `async def`-функции — самая тихая ошибка в теме. Код запускается, ответ возвращается правильный, тесты зелёные, а декоратор при этом не делает ничего из того, что должен. Замер времени показывает нули, retry не ловит ошибку, лог пишется до того, как работа началась.

## Что именно ломается

Возьмём рабочий декоратор-таймер и наденем его на асинхронную функцию:

```python
import asyncio, functools, time

def timer(func):                                  # обычный, синхронный декоратор
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)            # ← вызов, но НЕ ожидание
        print(f"заняло: {time.perf_counter() - start:.6f} с")
        print(f"вернулось: {type(result).__name__}")
        return result
    return wrapper

@timer
async def slow():
    await asyncio.sleep(0.3)
    return 42

print(asyncio.run(slow()))
# заняло: 0.000001 с          ← функция спала 0,3 с, а таймер намерял микросекунду
# вернулось: coroutine        ← это не 42, это ещё не начатая работа
# 42                          ← и всё-таки 42: снаружи ничего не сломалось
```

Итог: **результат верный, декоратор бесполезный**. Ошибки нет, и найти её можно только глазами.

## Почему так

Вызов `async def`-функции **не выполняет её тело**. Он мгновенно создаёт объект-корутину — заготовку работы, которая начнётся только когда её кто-то дождётся через `await`.

```
обычная функция:   func()  ──▶ тело выполняется ──▶ результат
корутина:          func()  ──▶ объект-корутина        (тело ещё не тронуто)
                   await   ──▶ тело выполняется ──▶ результат
```

Синхронная обёртка успевает всё: засечь старт, «вызвать» функцию, засечь финиш — и вернуть заготовку наружу. Работа же начнётся позже, когда `await` доберётся до неё уже за пределами декоратора. Отсюда и микросекунда на таймере.

> Это ровно та же природа, что у [декоратора на генераторной функции](../Ядро%20языка/Декораторы%20Python.md#тонкость-декоратор-на-генераторную-функцию): и там и там вызов возвращает объект отложенной работы, а не значение. Разница лишь в том, что генератор перебирают циклом, а корутину ждут через `await`.

## Правильный асинхронный декоратор

Правится двумя словами: обёртка становится `async def`, а вызов оригинала — `await`.

```python
def timer(func):
    @functools.wraps(func)
    async def wrapper(*args, **kwargs):           # 1. обёртка сама корутинная
        start = time.perf_counter()
        result = await func(*args, **kwargs)      # 2. дожидаемся настоящей работы
        print(f"заняло: {time.perf_counter() - start:.6f} с")
        return result
    return wrapper

@timer
async def slow():
    await asyncio.sleep(0.3)
    return 42

asyncio.run(slow())      # заняло: 0.309361 с   ← теперь честно
```

Сам декоратор при этом остаётся **обычной синхронной функцией** — `async def timer` не нужен и был бы ошибкой. Декоратор ведь вызывается один раз при `def`, а не внутри событийного цикла; корутинной должна быть только обёртка. Правило короткое: **`async` там, где `await`**.

## Универсальный декоратор — на оба вида функций

Библиотечный декоратор не знает заранее, что на него наденут. Тогда внутри держат две обёртки и выбирают нужную по типу функции:

```python
import inspect

def timer(func):
    @functools.wraps(func)
    async def async_wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = await func(*args, **kwargs)
        print(f"{func.__name__}: {time.perf_counter() - start:.4f} с")
        return result

    @functools.wraps(func)
    def sync_wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__}: {time.perf_counter() - start:.4f} с")
        return result

    return async_wrapper if inspect.iscoroutinefunction(func) else sync_wrapper
```

Выбор делается **один раз при декорировании**, а не на каждом вызове — проверка типа в горячий путь не попадает.

> **Бери `inspect.iscoroutinefunction`, а не `asyncio.iscoroutinefunction`.** Второй — устаревший псевдоним первого: помечен deprecated в Python 3.14 и назначен к удалению в 3.16. Замена безопасна для любых версий: `inspect.iscoroutinefunction` существует с Python 3.5.

Две тонкости самой проверки:

- **`functools.partial` она разворачивает** — `partial` от корутинной функции тоже даёт `True` (с 3.8).
- **Синхронную функцию, возвращающую корутину, она не опознаёт** — с Python 3.12 такую помечают вручную через `inspect.markcoroutinefunction`.

## Как это аннотировать

Частая ошибка в аннотации — написать, что декоратор принимает `Coroutine`. Он принимает **корутинную функцию**, а корутина — это то, что она возвращает при вызове:

```python
from collections.abc import Callable, Coroutine
from typing import Any, TypeVar

T = TypeVar("T")

# НЕПРАВИЛЬНО — здесь сказано «принимаю уже созданную корутину»
def deco(func: Coroutine): ...

# ПРАВИЛЬНО — «принимаю функцию, которая при вызове вернёт корутину с результатом T»
def deco(
    func: Callable[..., Coroutine[Any, Any, T]],
) -> Callable[..., Coroutine[Any, Any, T]]:
    ...
```

Три параметра `Coroutine[Y, S, R]` — это тип отправляемого в неё значения, тип принимаемого и **тип результата**; на практике важен только третий, первые два ставят `Any`.

> Берите `Coroutine` из `collections.abc`, а не из `typing`: с Python 3.9 (**PEP 585**) `typing`-псевдонимы абстрактных классов помечены устаревшими, и официальная документация показывает импорт именно из `collections.abc`.

## Ловушка: блокирующий вызов внутри асинхронной обёртки

Обёртка асинхронная — значит, она выполняется **внутри событийного цикла**, и любая синхронная задержка в ней останавливает весь сервис, а не одну функцию:

```python
# НЕПРАВИЛЬНО — retry, который вешает цикл
async def wrapper(*args, **kwargs):
    for попытка in range(3):
        try:
            return await func(*args, **kwargs)
        except ConnectionError:
            time.sleep(2)          # ⚠️ встал весь event loop, все запросы ждут

# ПРАВИЛЬНО
            await asyncio.sleep(2)  # уступили управление другим задачам
```

Та же история с записью лога в файл и походом в синхронную БД внутри обёртки — подробно про цену такой паузы в [Блокирующий код в event loop](../Библиотеки/Модули/Параллелизм/Блокирующий%20код%20в%20event%20loop.md).

## Ловушка: `@lru_cache` на корутине

Кэш из [functools](../Библиотеки/Модули/Функциональные%20инструменты/functools.md) на асинхронной функции выглядит рабочим, а ломается со второго обращения:

```python
@functools.lru_cache(maxsize=None)
async def fetch(x):
    await asyncio.sleep(0.01)
    return x * 2

await fetch(5)    # → 10
await fetch(5)    # → RuntimeError: cannot reuse already awaited coroutine
```

Причина прямо следует из первого раздела: `lru_cache` кэширует то, что функция вернула, — то есть **объект-корутину**, а не результат. Корутину можно дождаться ровно один раз; повторный `await` того же объекта — ошибка.

Рабочая замена — кэшировать не корутину, а **задачу** (`Task`): её, в отличие от корутины, можно ждать сколько угодно раз, и все ожидающие получат один результат.

```python
def async_cache(func):
    cache = {}
    @functools.wraps(func)
    async def wrapper(*args):
        if args not in cache:
            cache[args] = asyncio.ensure_future(func(*args))   # запускаем ОДИН раз
        return await cache[args]                               # ждать можно многократно
    return wrapper

@async_cache
async def fetch(x):
    await asyncio.sleep(0.05)
    print(f"реальный вызов для {x}")
    return x * 2

# три подряд await fetch(5) → «реальный вызов для 5» печатается ОДИН раз, ответ 10 у всех
```

Побочная выгода: если десять задач одновременно спросят один ключ, поход наружу будет один — это Single Flight в миниатюре. Такой словарь не вытесняет записи, так что для долгоживущего сервиса ему нужен предел размера или TTL.

## Сводка

| Что надето на `async def` | Что происходит | Признак |
|---|---|---|
| Синхронная обёртка | оборачивает создание корутины, а не работу | таймер ~0, в логе `coroutine` |
| `async def` обёртка + `await` | правильно | замеры совпадают с реальностью |
| `@lru_cache` | кэширует корутину | `RuntimeError` на втором вызове |
| `time.sleep` внутри обёртки | стоит весь событийный цикл | падает пропускная способность сервиса |
