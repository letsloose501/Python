# Ветвление Python

> Ветвление — развилка: программа выбирает, какой код выполнить, в зависимости от условия. Без него код всегда идёт по одному пути.

---

**Ветвление (условный оператор)** — конструкция, которая выполняет разные ветки кода в зависимости от того, истинно условие или нет. Базовая форма — `if / elif / else`.

## if / elif / else

```python
if условие1:
    ...              # если условие1 истинно
elif условие2:       # иначе если условие2
    ...
else:                # если ни одно не подошло
    ...
```

- `if` обязателен; `elif` и `else` — опциональны, `elif` может быть сколько угодно;
- проверка идёт **сверху вниз**, выполняется **первая** истинная ветка, остальные пропускаются;
- условие — любое выражение: оно приводится к [bool](../Данные/Примитивные%20типы%20данных%20Python.md#bool--логический-тип) (пустые коллекции, `0`, `None`, `""` — ложны).

```python
if score >= 90:
    grade = "A"
elif score >= 70:      # проверится, только если score < 90
    grade = "B"
else:
    grade = "C"
```

> Для «выбрать одно из двух значений» есть компактный [тернарный оператор](../Ядро%20языка/Операторы%20Python.md#тернарный-оператор) `A if C else B`. Для сопоставления с образцом — [match/case](../Ядро%20языка/Match%20Case%20Python.md) (3.10+).

## Ленивые вычисления в условиях

Операторы `and`/`or` **ленивы** (short-circuit): правый операнд вычисляется, только если по левому ещё не ясен ответ. Это и оптимизация, и защита:

```python
if x != 0 and 10 / x > 2:    # если x == 0, деление НЕ вычисляется — нет ZeroDivisionError
    ...

if user and user.is_admin:   # если user — None, .is_admin не трогаем
    ...
```

`and` возвращает первый ложный операнд (или последний, если все истинны), `or` — первый истинный. Подробно — [Операторы Python](../Ядро%20языка/Операторы%20Python.md#логические-операторы).

## Спагетти-код и вложенные условия

Глубоко вложенные `if` («стрелка», arrow anti-pattern) тяжело читать — глаз теряется в отступах:

```python
# ПЛОХО — «лесенка» вложенности
def process(user):
    if user is not None:
        if user.is_active:
            if user.has_access:
                return do_work(user)
            else:
                return "нет доступа"
        else:
            return "неактивен"
    else:
        return "нет пользователя"
```

Лечится **защитными условиями (guard clauses)** и **ранним возвратом**: отсекай негативные случаи сразу и выходи, а основную логику держи слева, без вложенности:

```python
# ХОРОШО — плоско, guard clauses
def process(user):
    if user is None:
        return "нет пользователя"
    if not user.is_active:
        return "неактивен"
    if not user.has_access:
        return "нет доступа"
    return do_work(user)          # основной путь — не вложен
```

> Правило: чем меньше уровней вложенности, тем читаемее. Ранний `return` / `continue` / `raise` «выпрямляет» код.

## Ветвление через словарь (dispatch)

Длинную цепочку `if/elif`, которая по значению выбирает действие, часто заменяют **словарём-диспетчером**: ключ → функция/значение.

```python
# вместо цепочки if/elif:
def operate(op, a, b):
    if op == "+": return a + b
    elif op == "-": return a - b
    elif op == "*": return a * b

# словарь-диспетчер:
OPS = {"+": add, "-": sub, "*": mul}
def operate(op, a, b):
    return OPS[op](a, b)          # выбор O(1), без длинной лесенки
    # OPS.get(op, default) — если ключа может не быть
```

Плюсы: короче, расширяется добавлением строки в словарь, выбор за O(1). Минусы — ниже.

### Ловушка: словарь вычисляет все ветки

В отличие от `if/elif`, словарь **вычисляет все значения сразу** при создании — ленивости нет. И если ключи совпадут, последний перезапишет остальные.

```python
def classify(x):
    return {
        isinstance(x, bool): "булево",
        x < 0: "отрицательное",
        x == 0: "ноль",
        x > 0: "положительное",
    }[True]

classify(1)      # → "положительное"  (истинно только x > 0)
```

Здесь ключи — **булевы результаты** условий, а берётся `[True]`. Для `x = 1` истинно лишь `x > 0`. Но:
- **все** условия вычисляются (нет short-circuit) — для `x = 0` посчитаются и `x < 0`, и `x > 0`;
- если истинны **два** условия, их общий ключ `True` схлопнется — победит последний: `classify(True)` даст `"положительное"`, а не `"булево"` (`isinstance(True, bool)` и `True > 0` оба `True`).

> «Словарь по `[True]`» — трюк для головоломок. В рабочем коде для взаимоисключающих числовых диапазонов бери `if/elif`: он ленив и с явным порядком.

## Как выбрать: if/elif или словарь

| | `if / elif / else` | Словарь-диспетчер |
|---|---|---|
| Условия | любые (диапазоны, сложные) | равенство ключу |
| Вычисление веток | ленивое (только нужную) | все значения при создании |
| Скорость выбора | O(n) проверок | O(1) по ключу |
| Расширение | добавить `elif` | добавить пару в словарь |
| Когда | диапазоны, сложные/зависимые условия | много веток по одному значению (команда, тип, код) |

Правило: **диапазоны и сложные условия → `if/elif`; выбор действия по конкретному значению из многих → словарь.** Для структурных образцов (тип, форма объекта) — [match/case](../Ядро%20языка/Match%20Case%20Python.md).
