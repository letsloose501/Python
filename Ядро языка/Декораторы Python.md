# Декораторы Python

> **Декоратор** — функция, которая принимает другую функцию и возвращает новую, добавляя поведение «вокруг» неё, не меняя её код. Логирование, замер времени, кэширование, проверка прав — всё это навешивается декоратором в одну строку `@decorator`.

---

Часто одно и то же поведение нужно многим функциям: логировать вызов, замерить время, проверить доступ. Копировать этот код в каждую функцию — дублирование. Декоратор выносит его в одно место и «оборачивает» им любую функцию. Держится на том, что в Python [функция — объект первого класса](../Ядро%20языка/Функции%20Python.md): её можно передать в другую функцию и вернуть из неё.

## Что такое декоратор

`@decorator` над функцией — это **синтаксический сахар**. Две записи эквивалентны:

```python
@logger
def summator(a, b):
    return a + b

# то же самое:
def summator(a, b):
    return a + b
summator = logger(summator)     # декоратор получил функцию и вернул новую
```

То есть `logger` — обычная функция, которая принимает функцию `summator` и возвращает **замену** для неё. Имя `summator` теперь указывает на то, что вернул `logger`.

## Когда выполняется декоратор

Декоратор применяется **один раз — в момент определения функции** (выполнение `def`, обычно при импорте модуля), а **не** при каждом вызове. `@dec` немедленно вызывает `dec(func)` и связывает имя с результатом.

```python
def dec(func):
    print(f"декорирую {func.__name__}")   # печатается СРАЗУ при def, до любых вызовов
    return func

@dec
def f(): ...
# → "декорирую f"   ← напечаталось уже здесь, ещё до вызова f()
```

Обёртка (`wrapper`) же выполняется при **каждом** вызове декорированной функции. Отсюда правило: тяжёлую подготовку (открыть файл, скомпилировать regex) делают в теле декоратора — один раз; на вызов оставляют лёгкую обёртку.

## Что можно декорировать

Декорировать можно всё, что стоит после `@`:

- **функции** — базовый случай;
- **методы** — в том числе встроенные `@classmethod`, `@staticmethod`, `@property`;
- **классы** — декоратор получает класс и возвращает класс/замену: так работают `@dataclass`, `@functools.total_ordering`.

```python
@dataclass          # декорирует КЛАСС — добавляет __init__, __repr__ и др.
class Point:
    x: int
    y: int
```

Синтаксически после `@` допустимо **любое выражение** (PEP 614, Python 3.9+) — вызов, индексация, лямбда (см. [Лямбда-декоратор](#лямбда-декоратор)).

## Простейший декоратор

Внутри декоратора создаётся **функция-обёртка** (`wrapper`): она вызывает оригинал, добавляя своё поведение до/после. Чтобы обёртка подходила к любой функции, аргументы принимаются через [`*args, **kwargs`](../Ядро%20языка/Функции%20Python.md#args--произвольное-число-позиционных-аргументов):

```python
def logger(func):
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)     # вызвать оригинал
        print(f"{func.__name__}{args} -> {result}")
        return result                       # обязательно вернуть результат!
    return wrapper

@logger
def summator(a, b=0):
    return a + b

summator(2, 2)     # печатает "summator(2, 2) -> 4", возвращает 4
```

> Частая ошибка — забыть `return result` в обёртке: тогда декорированная функция всегда возвращает `None`.

## @wraps — сохранить «личность» функции

Обёртка подменяет оригинал, поэтому у декорированной функции метаданные становятся от `wrapper` — теряются имя, docstring, сигнатура:

```python
@logger
def summator(a, b): ...

summator.__name__     # → 'wrapper'  (!) — а хотелось 'summator'
```

`functools.wraps` копирует `__name__`, `__doc__`, `__wrapped__` и др. с оригинала на обёртку:

```python
from functools import wraps

def logger(func):
    @wraps(func)                    # ← сохранить метаданные оригинала
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

summator.__name__     # → 'summator' — как надо
```

> `@wraps` — обязательная привычка. Без неё ломаются интроспекция, документация и другие декораторы, читающие `__name__`.

## Параметрический декоратор (декоратор-фабрика)

Чтобы декоратор принимал **аргументы** (`@logger("app.log")`), нужен ещё один уровень вложенности: внешняя функция принимает параметр и **возвращает декоратор**. Итого три уровня: `фабрика(параметр) → декоратор(функция) → обёртка(*args)`.

```python
from functools import wraps

def logger(path):                          # 1. фабрика — принимает параметр
    def decorator(func):                   # 2. настоящий декоратор — принимает функцию
        @wraps(func)
        def wrapper(*args, **kwargs):      # 3. обёртка — принимает аргументы вызова
            result = func(*args, **kwargs)
            with open(path, "a", encoding="utf-8") as f:
                f.write(f"{func.__name__}{args} -> {result}\n")
            return result
        return wrapper
    return decorator

@logger("app.log")          # logger("app.log") вернул decorator, им и декорируем
def div(a, b):
    return a / b

div(6, 2)                   # → 3.0, а в app.log ушла строка "div(6, 2) -> 3.0"
```

Читается изнутри наружу: `@logger("app.log")` сначала **вызывается** (`logger("app.log")`), результат-декоратор применяется к `div`.

## Несколько декораторов на одной функции

Декораторы можно ставить стопкой. Тогда каждый оборачивает результат предыдущего:

```python
@A
@B
@C
def f(): ...

# то же самое:
f = A(B(C(f)))
```

Порядок читается **снизу вверх**: ближайший к функции применяется первым. И вот главное место, где путаются: **порядок применения и порядок выполнения противоположны**.

```python
def mark(name):
    def decorator(func):
        print(f"ПРИМЕНЯЕТСЯ {name}")
        @wraps(func)
        def wrapper(*args, **kwargs):
            print(f"вход  {name}")
            r = func(*args, **kwargs)
            print(f"выход {name}")
            return r
        return wrapper
    return decorator

@mark("A")
@mark("B")
@mark("C")
def target():
    print("=== тело функции ===")
```

```
При def:              При вызове target():
ПРИМЕНЯЕТСЯ C         вход  A          ← внешний декоратор получает управление первым
ПРИМЕНЯЕТСЯ B         вход  B
ПРИМЕНЯЕТСЯ A         вход  C
                      === тело функции ===
   снизу вверх        выход C
                      выход B
                      выход A          ← и отпускает последним
```

Обёртки складываются матрёшкой: `A` снаружи, тело функции — в центре. Отсюда практические следствия:

- **Порядок не косметический.** `@login_required` должен стоять **выше** `@cache`, иначе неавторизованный запрос сначала получит ответ из кэша, а проверка прав случится потом или не случится вовсе.
- **Декоратор, отвечающий за регистрацию, ставят самым верхним** — иначе во фреймворк попадёт промежуточная обёртка, а не итоговая функция. По этой причине `@app.get(...)` в [FastAPI](../Фреймворки/FastAPI.md) пишут первым.
- **`@wraps` нужен каждому декоратору в стопке.** Без него верхний видит не исходную функцию, а обёртку нижнего:

```python
@logger          # логирует func.__name__
@no_wraps        # обёртка без @wraps
def важная_операция(): ...

важная_операция()          # → «логирую вызов функции: wrapper»  ⚠️ не то имя
важная_операция.__name__   # → 'wrapper'
```

## Тонкость: декоратор на генераторную функцию

[Генераторная функция](../Ядро%20языка/Циклы%20Python.md#генераторы) при вызове **не выполняет тело**, а сразу возвращает объект-генератор. Поэтому обычный декоратор, логирующий `result`, увидит не значения, а сам генератор:

```python
@logger("app.log")
def flat_generator(list_of_lists):
    for item in list_of_lists:
        if isinstance(item, list):
            yield from flat_generator(item)
        else:
            yield item

list(flat_generator([[1, [2]], [3]]))    # → [1, 2, 3]
# но в лог попадёт "<generator object flat_generator ...>", а не [1,2,3],
# потому что функция вернула генератор мгновенно, до перебора значений
```

> Чтобы логировать сами значения, декоратор должен сам итерировать генератор (`for x in gen: yield x`) — то есть быть написан специально под генераторы.

## Сквозной пример — декоратор-логгер

Реальный логгер: пишет в файл время, имя функции, аргументы и результат каждого вызова. Сначала базовая версия, затем — с настраиваемым путём (фабрика).

```python
import os
import datetime
from functools import wraps

# базовая версия — пишет в фиксированный main.log
def logger(old_function):
    @wraps(old_function)
    def new_function(*args, **kwargs):
        time = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
        result = old_function(*args, **kwargs)
        with open("main.log", "a") as f:
            f.write(
                f"Время: {time}, функция: {old_function.__name__}, "
                f"аргументы: {args} и {kwargs}, вывод: {result}\n"
            )
        return result
    return new_function

# параметрическая версия — путь к логу задаётся при декорировании
def logger(path):
    def __logger(old_function):
        @wraps(old_function)
        def new_function(*args, **kwargs):
            os.makedirs(os.path.dirname(path), exist_ok=True)
            time = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
            result = old_function(*args, **kwargs)
            with open(path, "a") as f:
                f.write(
                    f"Время: {time}, функция: {old_function.__name__}, "
                    f"аргументы: {args} и {kwargs}, вывод: {result}\n"
                )
            return result
        return new_function
    return __logger

@logger("logs/app.log")
def summator(a, b=0):
    return a + b

summator(4.3, b=2.2)     # → 6.5, в logs/app.log — строка с временем, args и выводом
```

Как читать: внешний `logger(path)` запоминает путь в замыкании, `__logger` оборачивает функцию, `new_function` на каждом вызове дописывает строку в файл и возвращает результат оригинала.

## Сводка

| Вид             | Синтаксис                   | Уровней вложенности                     | Когда                                  |
| --------------- | --------------------------- | --------------------------------------- | -------------------------------------- |
| Простой         | `@dec`                      | 2: `dec(func)` → `wrapper`              | добавить поведение без параметров      |
| Параметрический | `@dec(arg)`                 | 3: `dec(arg)` → `decorator` → `wrapper` | декоратору нужны настройки             |
| Класс-декоратор | `@dec` (класс с `__call__`) | класс + `__call__`                      | нужно хранить [состояние между вызовами](../Ядро%20языка/Декоратор%20с%20состоянием.md) |
| Асинхронный     | `@dec` над `async def`      | 2–3, но обёртка `async def`             | [оборачиваем корутину](../Ядро%20языка/Декораторы%20для%20асинхронных%20функций.md) |

Во всех видах: обёртка принимает `*args, **kwargs`, **возвращает результат** оригинала и помечена `@wraps(func)`.

> Два случая ломают обычный декоратор молча, без ошибки: **корутина** (обёртка успевает отработать до начала работы — [Декораторы для асинхронных функций](../Ядро%20языка/Декораторы%20для%20асинхронных%20функций.md)) и **генератор** (см. раздел выше). Признак у обоих один: функция возвращает объект отложенной работы, а не значение.

## Может ли декоратор не вызывать оригинал

Да. Декоратор возвращает **любую** функцию — она не обязана звать оригинал. Отсюда несколько приёмов:

```python
# 1. Заменить/заглушить — оригинал не вызывается вовсе:
def disabled(func):
    def wrapper(*args, **kwargs):
        print(f"{func.__name__} отключена")
    return wrapper

# 2. Регистрация — вернуть функцию как есть, попутно запомнив её:
handlers = {}
def register(name):
    def dec(func):
        handlers[name] = func     # запомнили
        return func               # без обёртки — поведение не изменилось
    return dec

# 3. Условный вызов (фича-флаг), кэш, retry — оригинал зовётся 0, 1 или много раз:
def feature(on):
    def dec(func):
        def wrapper(*args, **kwargs):
            return func(*args, **kwargs) if on else None
        return wrapper
    return dec
```

## Лямбда-декоратор

С Python 3.9 (**PEP 614**) после `@` допустимо любое выражение, а не только имя с точками. Поэтому декоратором может быть даже лямбда прямо на месте:

```python
@(lambda f: lambda x: (f(x), f(x) * 100)[int()])
def square(x):
    return x ** 2

print(square(3))     # → 9
```

Как читать: внешняя `lambda f` — декоратор, получает `square` как `f`; возвращает обёртку `lambda x: (f(x), f(x)*100)[int()]`. При `square(3)`: `int()` == 0, значит из кортежа `(f(3), f(3)*100)` = `(9, 900)` берётся элемент `[0]` — **9**. Оригинал тут вызывается **дважды** (оба элемента кортежа вычисляются).

> Трюк для головоломок, не для продакшена: лямбда-декоратор нечитаем и теряет `__name__`. В реальном коде — обычный `def`-декоратор с `@wraps`.

## Альтернативы декораторам и наследование

Декоратор — не единственный способ «добавить поведение вокруг»:

| Приём | Что оборачивает | Когда лучше декоратора |
|---|---|---|
| **Наследование / миксин** | классы и их методы | поведение — часть иерархии типов, много общего состояния |
| **Контекстный менеджер** `with` | блок кода | ресурс с чётким входом/выходом (файл, транзакция) |
| **Middleware / хук** | запрос/событие фреймворка | сквозная логика на уровне приложения |
| **Явная обёртка** `g = dec(f)` | конкретный вызов | разово, без синтаксиса `@` |

**Декоратор vs наследование:** декоратор добавляет поведение **функции** (или оборачивает объект), не трогая иерархию классов, — это композиция «обернуть»; наследование добавляет поведение **классу** через `super()` — это «быть подтипом». Для сквозной мелочи (лог, кэш, замер) — декоратор; для расширения типа с общим состоянием — наследование.
