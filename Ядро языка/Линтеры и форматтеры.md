# Линтеры и форматтеры

> _Стиль и чистоту кода не держат в голове — их автоматически проверяют и чинят инструменты_

---

Правила [PEP 8](../Ядро%20языка/Стиль%20кода%20Python%20—%20PEP%208%20и%20Google%20Style%20Guide.md) и чистого кода бессмысленно соблюдать вручную — их **автоматизируют**. Есть три разных типа инструментов, и их часто путают: **линтер** (находит проблемы), **форматтер** (переписывает стиль), **проверка типов** (ловит ошибки типов). Вместе они дают единообразный, предсказуемый код без ручной возни и споров о пробелах.

## Три типа инструментов

| Тип | Что делает | Меняет код? | Примеры |
|---|---|---|---|
| **Линтер** | статически **находит** проблемы (ошибки, неиспользуемые импорты, нарушения стиля) | нет, только сообщает | flake8, pylint |
| **Форматтер** | приводит код к единому стилю (отступы, кавычки, переносы) | **да**, переписывает | black, autopep8 |
| **Проверка типов** | по аннотациям ловит несовпадения типов | нет, сообщает | mypy, pyright |

Ключевое различие: **линтер анализирует, форматтер переписывает.** Линтер скажет «строка слишком длинная», форматтер сам её перенесёт. Форматтер не смотрит на логику — только на внешний вид.

## Линтер

**Линтер** (linter) — статический анализатор: читает код **не запуская** и указывает на подозрительное. Ловит то, что не ошибка синтаксиса, но пахнет проблемой: неиспользуемая переменная, затенение имени, недостижимый код, нарушение PEP 8.

```bash
flake8 myapp/          # проверить стиль и типичные ошибки
pylint myapp/          # более строгий анализ (+ оценка кода)
```

## Форматтер

**Форматтер** — приводит код к **единому** виду автоматически. **black** — «opinionated»: почти без настроек, жёсткий единый стиль, поэтому команда не спорит о форматировании.

```bash
black myapp/           # переформатировать по месту
black --check myapp/   # только проверить (для CI), не менять
isort myapp/           # отдельно отсортировать импорты
```

> **Форматтер снимает споры на ревью.** Стиль применяется автоматически и одинаково у всех — [ревью](../Код-ревью.md) обсуждает логику и дизайн, а не пробелы.

## Проверка типов

**mypy** — статически проверяет [аннотации типов](../Библиотеки/Модули/Типы%20и%20объекты/typing.md): если функция ждёт `int`, а ей передают `str`, mypy поймает это **до** запуска. Ловит целый класс багов, которые в динамическом Python иначе всплыли бы в рантайме.

```bash
mypy myapp/
```

## ruff — современный всё-в-одном

**ruff** — сверхбыстрый инструмент (написан на Rust), объединяющий **линтер + форматтер + сортировку импортов**. Заменяет связку flake8 + isort + во многом black, работая в десятки раз быстрее. Стал стандартом новых проектов.

```bash
ruff check myapp/      # линтинг (+ --fix для автоисправлений)
ruff format myapp/     # форматирование
```

## pre-commit — автозапуск перед коммитом

**pre-commit** — фреймворк git-хуков: настроенные линтеры/форматтеры запускаются **автоматически перед каждым коммитом** и не пускают грязный код в репозиторий.

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    hooks:
      - id: ruff          # линтинг
      - id: ruff-format   # форматирование
```

## Где запускать

Инструменты работают на двух рубежах:

- **Локально** — в редакторе (подсветка на лету) и через `pre-commit` при коммите: чинишь до пуша.
- **В [CI](../DevOps/CI%20CD.md)** — на pull request: пайплайн гоняет `ruff check`, `mypy`, тесты и **блокирует слияние**, если что-то не так. Это гарантирует, что в основную ветку не попадёт код, не прошедший проверки.
