# Связный список

**Связный список** — структура данных, в которой элементы разбросаны по памяти и связаны **цепочкой указателей**. Каждый элемент — **узел**: данные + адрес следующего.

> **Аналогия:** охота за сокровищем — на каждой подсказке написано, где искать следующую. Нельзя перепрыгнуть к пятой — нужно пройти все предыдущие.

Связный список — физическая структура. АТД поверх него — [Список](../../Данные/АТД/Список.md), [Стек](../../Данные/АТД/Стек.md), [Очередь](../../Данные/АТД/Очередь.md), [Дека](../../Данные/АТД/Очередь.md#атд-дека).

---

## Как устроен узел

```
┌───────────┬───────────┐
│   данные  │  next  ──────→  следующий узел
└───────────┴───────────┘
```

```
head
 ↓
[A | →]──→[B | →]──→[C | →]──→[D | None]
```

`head` — указатель на первый узел. Потеряешь `head` — потеряешь весь список.

---

## Операции и сложность

|Операция|Сложность|Причина|
|---|---|---|
|`prepend(x)`|$O(1)$|Только переставить head|
|`append(x)`|$O(n)$ / $O(1)$*|Нужно дойти до конца / есть tail|
|`delete_first()`|$O(1)$|Только переставить head|
|`delete(x)`|$O(n)$|Нужно найти предыдущий|
|`find(x)`|$O(n)$|Последовательный обход|
|`get(i)`|$O(n)$|Нет прямой адресации|

* При наличии указателя `tail` на последний узел.

Вставка и удаление при **известном месте** — $O(1)$: просто перенаправить указатели.

```
Вставить X между B и C:
до:  [B | →C]──→[C | →]
     новый = [X | →C]
     B.next = X
после: [B | →X]──→[X | →C]──→[C | →]
```

```
Удалить B (знаем предыдущий A):
A.next = B.next   →  [A | →C]
B выпал из цепочки, память освободится GC
```

> **«Остановиться за один шаг до»** — базовый приём для односвязного списка. Назад по нему идти нельзя, поэтому, чтобы изменить узел на позиции `i`, идут не к нему, а к `i - 1` и работают оттуда: `cur.next = cur.next.next` для удаления, сохранение старой ссылки для вставки. На этом приёме держится половина задач на списки; отдельный случай — голова, перед которой предыдущего узла нет ([лечится заглушкой](../../Алгоритмы/Приёмы/Фиктивный%20узел.md)). Разбор с кодом — [Проектирование связного списка](../../Алгоритмы/Задачки/Проектирование%20связного%20списка.md).

## Реализация

```python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None


class LinkedList:
    def __init__(self):
        self._head = None
        self._tail = None    # для O(1) append
        self._size = 0

    def prepend(self, x):              # O(1)
        новый = Node(x)
        новый.next = self._head
        self._head = новый
        if self._tail is None:
            self._tail = новый
        self._size += 1

    def append(self, x):               # O(1) — есть tail
        новый = Node(x)
        if self._tail:
            self._tail.next = новый
        else:
            self._head = новый
        self._tail = новый
        self._size += 1

    def delete_first(self):            # O(1)
        if not self._head:
            raise IndexError("список пуст")
        значение = self._head.data
        self._head = self._head.next
        if self._head is None:
            self._tail = None
        self._size -= 1
        return значение

    def delete(self, x):               # O(n)
        if not self._head:
            raise ValueError(f"{x} не найден")
        if self._head.data == x:
            return self.delete_first()
        текущий = self._head
        while текущий.next:
            if текущий.next.data == x:
                if текущий.next is self._tail:
                    self._tail = текущий
                текущий.next = текущий.next.next
                self._size -= 1
                return
            текущий = текущий.next
        raise ValueError(f"{x} не найден")

    def find(self, x):                 # O(n) → индекс или -1
        текущий = self._head
        i = 0
        while текущий:
            if текущий.data == x:
                return i
            текущий = текущий.next
            i += 1
        return -1

    def insert_after(self, x, new_data):   # O(n) найти + O(1) вставить
        текущий = self._head
        while текущий:
            if текущий.data == x:
                новый = Node(new_data)
                новый.next = текущий.next
                if текущий is self._tail:
                    self._tail = новый
                текущий.next = новый
                self._size += 1
                return
            текущий = текущий.next
        raise ValueError(f"{x} не найден")

    def reverse(self):                 # O(n)
        предыдущий = None
        текущий = self._head
        self._tail = self._head
        while текущий:
            следующий = текущий.next
            текущий.next = предыдущий
            предыдущий = текущий
            текущий = следующий
        self._head = предыдущий

    def __len__(self):
        return self._size

    def __iter__(self):
        текущий = self._head
        while текущий:
            yield текущий.data
            текущий = текущий.next

    def __contains__(self, x):
        return self.find(x) != -1

    def __bool__(self):
        return self._head is not None

    def __repr__(self):
        return "→".join(str(x) for x in self) + "→None"


ll = LinkedList()
ll.prepend(3); ll.prepend(2); ll.prepend(1); ll.append(4)
print(ll)               # → 1→2→3→4→None
ll.insert_after(2, 99)
print(ll)               # → 1→2→99→3→4→None
ll.delete(99)
ll.reverse()
print(ll)               # → 4→3→2→1→None
```

## Типичные алгоритмы на связных списках

### Найти середину — два указателя

Медленный движется на 1 шаг, быстрый на 2. Когда быстрый достигает конца — медленный в середине.

```python
def середина(head):
    slow, fast = head, head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow.data
```

### Обнаружить цикл — алгоритм Флойда

Если есть цикл — быстрый указатель догонит медленного.

```python
def есть_цикл(head):
    slow, fast = head, head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False
```

### N-й элемент с конца

```python
def с_конца(head, n):
    first = second = head
    for _ in range(n):
        first = first.next       # опередить на n
    while first:
        first = first.next
        second = second.next
    return second.data
```

## Массив vs Связный список

|Операция|[Массив](../../Данные/Структуры%20данных/Массив.md)|Связный список|
|---|---|---|
|Доступ по индексу|$O(1)$|$O(n)$|
|Вставка в начало|$O(n)$|$O(1)$|
|Вставка в конец|$O(1)$ аморт.|$O(1)$ с tail|
|Вставка в середину|$O(n)$|$O(1)$*|
|Cache locality|Отличный|Плохой|
|Память|Компактная|+8 байт на указатель|

Массив — выбор по умолчанию. Связный список — когда нужны частые вставки/удаления в начале.

# Двусвязный список

**Двусвязный список** — расширение: каждый узел хранит два указателя — `next` и `prev`. Движение в обе стороны. Удаление **известного узла** — $O(1)$ без поиска предыдущего.

```
None ←[A | ↔]↔[B | ↔]↔[C | ↔]↔[D | ↔]→ None
       ↑                              ↑
      head                           tail
```

---

## Операции

|Операция|Сложность|Отличие от односвязного|
|---|---|---|
|`prepend(x)`|$O(1)$|—|
|`append(x)`|$O(1)$|—|
|`delete_node(node)`|$O(1)$|Нет поиска предыдущего — он в `node.prev`|
|`delete_value(x)`|$O(n)$|Поиск по значению — как раньше|
|`insert_before(node, x)`|$O(1)$|Нужен только указатель на узел|

---

## Реализация

```python
class DNode:
    def __init__(self, data):
        self.data = data
        self.prev = None
        self.next = None


class DoublyLinkedList:
    def __init__(self):
        self._head = None
        self._tail = None
        self._size = 0

    def append(self, x):              # O(1)
        новый = DNode(x)
        if self._tail:
            новый.prev = self._tail
            self._tail.next = новый
        else:
            self._head = новый
        self._tail = новый
        self._size += 1
        return новый                  # возвращаем узел — для O(1) удаления

    def prepend(self, x):             # O(1)
        новый = DNode(x)
        if self._head:
            новый.next = self._head
            self._head.prev = новый
        else:
            self._tail = новый
        self._head = новый
        self._size += 1
        return новый

    def delete_node(self, node):      # O(1) — ключевое преимущество
        if node.prev:
            node.prev.next = node.next
        else:
            self._head = node.next
        if node.next:
            node.next.prev = node.prev
        else:
            self._tail = node.prev
        node.prev = node.next = None
        self._size -= 1

    def move_to_front(self, node):    # O(1)
        if node is self._head:
            return
        self.delete_node(node)
        node.next = self._head
        node.prev = None
        if self._head:
            self._head.prev = node
        self._head = node
        if self._tail is None:
            self._tail = node
        self._size += 1

    def __len__(self):
        return self._size

    def __iter__(self):               # вперёд
        текущий = self._head
        while текущий:
            yield текущий.data
            текущий = текущий.next

    def __reversed__(self):           # назад
        текущий = self._tail
        while текущий:
            yield текущий.data
            текущий = текущий.prev

    def __contains__(self, x):
        return any(v == x for v in self)

    def __bool__(self):
        return self._head is not None

    def __repr__(self):
        return "↔".join(str(x) for x in self)


dll = DoublyLinkedList()
n1 = dll.append(1); n2 = dll.append(2); n3 = dll.append(3)
print(dll)                  # → 1↔2↔3
dll.delete_node(n2)         # O(1) — нет поиска
print(dll)                  # → 1↔3
dll.move_to_front(n3)       # O(1)
print(dll)                  # → 3↔1
print(list(reversed(dll)))  # → [1, 3]
```

> Обрати внимание на `delete_node`: половина метода — это проверки «а если узел первый» и «а если последний». Они исчезают, если поставить по краям два пустых узла-заглушки: тогда у любого настоящего узла **всегда** есть оба соседа, и удаление сжимается до двух строк без единого `if`. Приём разобран в [Фиктивный узел](../../Алгоритмы/Приёмы/Фиктивный%20узел.md) — в промышленных реализациях списков он норма.

## LRU-кэш на двусвязном списке

Классическое применение и самая частая задача на собеседовании. Двусвязный список + словарь `{ключ: узел}` → все операции $O(1)$:

- Найти по ключу → словарь → $O(1)$
- Отметить как свежий → `move_to_front` → $O(1)$ — **и вот это возможно только потому, что список двусвязный**
- Вытеснить давно не использованный → удалить хвост → $O(1)$

Ради второго пункта здесь и нужны два указателя: чтобы вырезать узел из середины, надо починить связи обоих соседей, а в односвязном списке левого соседа пришлось бы искать за $O(n)$ — и вся конструкция развалилась бы.

Полный разбор — ход рассуждения, реализация, ловушка с ключом внутри узла, `OrderedDict` и устройство `functools.lru_cache` — в [LRU-кэш](../../Алгоритмы/Задачки/LRU-кэш.md).

## collections.deque

В Python нет отдельного класса двусвязного списка. `collections.deque` — двусвязный список из блоков фиксированного размера, реализован на C. Все операции с обоих концов строго $O(1)$.

```python
from collections import deque
d = deque([1, 2, 3])
d.appendleft(0)    # O(1)
d.append(4)        # O(1)
d.popleft()        # O(1)
d.pop()            # O(1)
d.rotate(1)        # сдвиг вправо: [3, 1, 2]
```

Как АТД — [Дека](../../Данные/АТД/Очередь.md#атд-дека).

# Кольцевой список

**Кольцевой список** (циклический) — список, у которого последний узел указывает не на `None`, а обратно на первый. Конца нет: обход идёт по кругу, пока его не остановят.

```
односвязный кольцевой              двусвязный кольцевой
   ┌──────────────────┐               ┌──────────────────────┐
   ↓                  │               ↓                      │
  [A] → [B] → [C] → ──┘             [A] ←→ [B] ←→ [C] ←→ ────┘
```

Бывает и односвязным, и двусвязным. Отличается не устройством узла, а тем, что **пропадает понятие «конец»** — и вместе с ним половина проверок на `None`.

## Что это меняет

- **Обход не может завершиться сам.** Условие выхода — не `cur is None`, а возвращение в точку старта: `while cur is not start`. Забыть об этом — получить бесконечный цикл.
- **Одна заглушка вместо двух.** В кольце [узел-страж](../../Алгоритмы/Приёмы/Фиктивный%20узел.md) играет обе роли сразу: `root.next` — первый элемент, `root.prev` — последний. Пустой список опознаётся как `root.next is root`. Так устроен кэш в `functools.lru_cache` ([разбор](../../Алгоритмы/Задачки/LRU-кэш.md#functoolslru_cache)).
- **Любой узел годится за точку входа.** Голова перестаёт быть особенной — от любого узла достижимы все остальные.

## Где применяется

- **Круговой перебор ресурсов** — планировщики с квантованием времени (round-robin), балансировка запросов по серверам: дошли до конца — автоматически начали сначала.
- **Кольцевой буфер** — очередь фиксированного размера, где новые данные затирают самые старые. На этом принципе работает защита PostgreSQL от вымывания кэша сканом: большому сканированию выдают маленькое кольцо страниц, которое он крутит по кругу, не трогая остальной пул.
- **Задача Иосифа** (Josephus problem) — классика на кольцевой список: по кругу выбывает каждый k-й.

> Обнаружение цикла в **обычном** списке — обратная задача: там кольцо это баг, и ищут его [алгоритмом Флойда](../../Данные/Структуры%20данных/Связный%20и%20двусвязный%20список.md#обнаружить-цикл--алгоритм-флойда). В кольцевом списке цикл — не баг, а контракт структуры.
