# Граф

**Граф** — структура данных из **вершин** и **рёбер**. Нет иерархии и корня — любая вершина может быть связана с любой другой.

> **Аналогия:** карта дорог — города вершины, дороги рёбра. Социальная сеть — люди вершины, дружба рёбра.

[Дерево](../../Данные/Структуры%20данных/Дерево.md) — частный случай графа: связный ациклический ненаправленный граф.

---

## Виды

**Ненаправленный** — рёбра без стрелок, связь взаимная.

```
A — B — C
|       |
D ──────┘
```

**Направленный** — рёбра со стрелками, связь в одну сторону.

```
A → B → C
↑       ↓
D ←─────┘
```

**Взвешенный** — рёбрам назначены числа (расстояние, стоимость, время).

```
A —(4)— B —(2)— C
```

**Полный** — есть все возможные рёбра: каждая вершина соединена с каждой. Рёбер ровно $\frac{n(n-1)}{2}$ — та же формула, что у топологии full mesh (Топология сетей). Полный граф — верхняя граница плотности, с ней сравнивают, «разреженный» граф или нет.

**Двудольный** — вершины делятся на две доли, и рёбра идут **только между долями**, внутри доли рёбер нет.

```
доля 1:   A   B   C
          |╲  |  ╱|
доля 2:   X   Y   Z
```

_Модель «кто с чем совместим»: работники и задачи, студенты и общежития, реклама и площадки._ Проверяется двудольность обходом с раскраской в два цвета: идём [BFS](../../Алгоритмы/Поиск/BFS.md), каждому соседу даём цвет, противоположный текущему; встретили соседа своего цвета — граф не двудольный (значит, в нём есть цикл нечётной длины).

**Мультиграф** — допускает **кратные рёбра** между одной парой вершин и петли (ребро из вершины в неё же). Обычный список смежности на `set` кратность теряет — под мультиграф нужен список или счётчик.

---

## Термины

|Термин|Описание|
|---|---|
|**Вершина**|Узел графа. Обозначение множества — $V$|
|**Ребро**|Связь между вершинами. Множество — $E$; сам граф записывают $G = (V, E)$|
|**Степень** $\deg(v)$|Число рёбер, инцидентных вершине. У направленного графа отдельно **входящая** и **исходящая** степень|
|**Смежность**|Вершины смежны, если соединены ребром|
|**Инцидентность**|Отношение «вершина — ребро»: ребро инцидентно двум своим вершинам|
|**Путь**|Последовательность вершин, связанных рёбрами|
|**Цикл**|Путь, начало = конец|
|**Связный граф**|Между любыми двумя вершинами есть путь|
|**DAG**|Directed Acyclic Graph — направленный граф без циклов|

> **Сумма степеней всех вершин равна $2E$** — каждое ребро добавляет по единице к двум своим концам. Отсюда следствие, которое иногда просят на секции: вершин нечётной степени в графе всегда чётное число.

---

## Представление в памяти

> **Иногда граф не хранят вовсе.** Если вершины — клетки матрицы, а рёбра задаются правилом «соседняя клетка», список смежности строить незачем: соседи вычисляются на лету смещениями. Так приходит больше половины «графовых» задач на собеседовании — [Обход клетчатого поля](../../Алгоритмы/Приёмы/Обход%20клетчатого%20поля.md).

### Список смежности — стандарт

Для каждой вершины — коллекция соседей. Память $O(V + E)$.

```python
# ненаправленный:
граф = {"A": {"B", "C"}, "B": {"A", "D"}, "C": {"A", "D"}, "D": {"B", "C"}}

# направленный:
граф = {"A": {"B", "C"}, "B": {"D"}, "C": set(), "D": set()}

# взвешенный:
граф = {"A": [("B", 4), ("C", 2)], "B": [("D", 3)], "C": [("D", 1)], "D": []}
```

`set` для соседей → проверка ребра $O(1)$ vs $O(\text{degree})$ у списка.

### Матрица смежности

`matrix[i][j] = 1` если есть ребро. Память $O(V^2)$ — плохо для разреженных графов.

```
     A  B  C  D
  A [0, 1, 1, 0]
  B [1, 0, 0, 1]
  C [1, 0, 0, 1]
  D [0, 1, 1, 0]
```

Проверка ребра `(i,j)` — $O(1)$. Используется для плотных графов.

### Список рёбер

Просто перечисление всех рёбер. Память $O(E)$ — самое компактное представление.

```python
рёбра = [("A", "B"), ("A", "C"), ("B", "D"), ("C", "D")]
рёбра = [("A", "B", 4), ("A", "C", 2), ("B", "D", 3)]   # взвешенный: (откуда, куда, вес)
```

Соседей вершины так быстро не найти — нужен проход по всем рёбрам, $O(E)$. Зато это **родной формат для алгоритмов, которые работают рёбрами, а не вершинами**: [Алгоритм Беллмана — Форда](../../Алгоритмы/Поиск/Алгоритм%20Беллмана%20—%20Форда.md) (перебирает все рёбра $V-1$ раз), алгоритм Краскала для минимального остовного дерева (сортирует рёбра по весу). Плюс это тот вид, в котором граф чаще всего **приходит на вход** в задаче: сначала $n, m$, потом $m$ строк с рёбрами — и первым делом его перекладывают в список смежности.

### Матрица инцидентности

Строки — вершины, столбцы — **рёбра**. Единица означает, что вершина принадлежит ребру; у ориентированного графа `+1` — дуга входит, `−1` — выходит.

```
      e1 e2 e3 e4        e1=(A,B)  e2=(A,C)  e3=(B,D)  e4=(C,D)
  A [ 1, 1, 0, 0 ]
  B [ 1, 0, 1, 0 ]
  C [ 0, 1, 0, 1 ]
  D [ 0, 0, 1, 1 ]
```

Память $O(V \cdot E)$ — самое расточительное представление, и на практике почти не используется. Знать стоит: спрашивают на секции как «а какие ещё бывают», и она полезна там, где рёбра сами по себе носят данные (потоки, электрические цепи).

### Сравнение — что выбирать

| | Список смежности | Матрица смежности | Список рёбер | Матрица инцидентности |
|---|---|---|---|---|
| **Память** | $O(V + E)$ | $O(V^2)$ | $O(E)$ | $O(V \cdot E)$ |
| **Есть ли ребро $(i,j)$** | $O(1)$ с `set` | $O(1)$ | $O(E)$ | $O(E)$ |
| **Перебрать соседей** | $O(\deg v)$ | $O(V)$ | $O(E)$ | $O(E)$ |
| **Добавить ребро** | $O(1)$ | $O(1)$ | $O(1)$ | пересобрать |
| **Когда брать** | **по умолчанию**: разреженный граф, обходы | плотный граф, частая проверка рёбер | вход задачи, Краскал, Беллман — Форд | почти никогда |

> 🔴 **Универсального способа нет — и это ровно то, что хотят услышать на секции.** Выбор диктует плотность: у разреженного графа ($E \approx V$) матрица смежности тратит $O(V^2)$ памяти почти на нули, у плотного ($E \approx V^2$) список смежности проигрывает по константе и по проверке ребра. **По умолчанию берут список смежности** — большинство реальных графов разреженные, и обходы ([BFS](../../Алгоритмы/Поиск/BFS.md), [DFS](../../Алгоритмы/Поиск/DFS.md)) работают именно по соседям.

## Компоненты связности

**Компонента связности** — максимальное множество вершин, попарно достижимых друг из друга, вместе со связывающими их рёбрами. У связного графа компонента одна; у графа «два острова» — две.

Алгоритм: запускать обход **из каждой непосещённой вершины**. Каждый запуск целиком выедает одну компоненту — значит число запусков и есть число компонент.

```python
def компоненты(граф, вершины):
    посещено = set()
    номер = {}                                # вершина → номер её компоненты
    всего = 0

    for старт in вершины:
        if старт in посещено:                 # уже съеден предыдущим запуском
            continue
        всего += 1                            # новый запуск = новая компонента
        стек = [старт]
        посещено.add(старт)
        while стек:                           # обычный DFS на явном стеке
            v = стек.pop()
            номер[v] = всего
            for сосед in граф[v]:
                if сосед not in посещено:
                    посещено.add(сосед)
                    стек.append(сосед)

    return всего, номер

граф = {"A": {"B"}, "B": {"A"}, "C": {"D"}, "D": {"C"}, "E": set()}
компоненты(граф, граф)[0]                     # → 3   {A,B}, {C,D}, {E}
```

Сложность — $O(V + E)$: каждая вершина и каждое ребро просматриваются один раз, независимо от числа компонент.

> **Здесь порядок обхода не важен** — [BFS](../../Алгоритмы/Поиск/BFS.md) и [DFS](../../Алгоритмы/Поиск/DFS.md) дают одинаковый ответ, потому что вопрос «достижима ли вершина», а не «за сколько шагов». Это удобный контраст с кратчайшим путём, где BFS обязателен, а DFS ответ портит. Одиночная вершина без рёбер — тоже компонента, и на этом краевом случае чаще всего ошибаются.
>
> Для **ориентированного** графа обычная связность заменяется на **сильную связность** (из каждой вершины достижима каждая) — это уже алгоритмы Косарайю или Тарьяна, и в базовом наборе их не спрашивают.

## Реализация

```python
from collections import defaultdict, deque

class Graph:
    def __init__(self, directed=False):
        self._adj = defaultdict(set)
        self._directed = directed
        self._vertices = set()

    def add_vertex(self, v):
        self._vertices.add(v)

    def add_edge(self, u, v, weight=None):
        self._vertices.update([u, v])
        self._adj[u].add(v)
        if not self._directed:
            self._adj[v].add(u)

    def remove_edge(self, u, v):
        self._adj[u].discard(v)
        if not self._directed:
            self._adj[v].discard(u)

    def neighbors(self, v):
        return self._adj[v]

    def has_edge(self, u, v):     # O(1) — set
        return v in self._adj[u]

    # --- обходы ---

    def bfs(self, start):
        visited, q, order = {start}, deque([start]), []
        while q:
            v = q.popleft()
            order.append(v)
            for n in sorted(self._adj[v]):
                if n not in visited:
                    visited.add(n)
                    q.append(n)
        return order

    def dfs(self, start):         # рекурсивный
        visited, order = set(), []
        def _go(v):
            visited.add(v); order.append(v)
            for n in sorted(self._adj[v]):
                if n not in visited:
                    _go(n)
        _go(start)
        return order

    def dfs_iter(self, start):    # итеративный — для больших графов
        visited, stack, order = set(), [start], []
        while stack:
            v = stack.pop()
            if v not in visited:
                visited.add(v); order.append(v)
                for n in sorted(self._adj[v], reverse=True):
                    if n not in visited:
                        stack.append(n)
        return order

    # --- анализ ---

    def has_cycle(self):
        visited = set()
        def _dfs(v, parent):
            visited.add(v)
            for n in self._adj[v]:
                if n not in visited:
                    if _dfs(n, v): return True
                elif n != parent:
                    return True
            return False
        return any(_dfs(v, None) for v in self._vertices if v not in visited)

    def connected_components(self):
        visited, components = set(), []
        for v in self._vertices:
            if v not in visited:
                comp, q = [], deque([v])
                visited.add(v)
                while q:
                    node = q.popleft(); comp.append(node)
                    for n in self._adj[node]:
                        if n not in visited:
                            visited.add(n); q.append(n)
                components.append(sorted(comp))
        return components

    def topological_sort(self):   # алгоритм Кана — только для DAG
        if not self._directed:
            raise ValueError("только для направленных графов")
        in_deg = defaultdict(int)
        for v in self._vertices:
            for n in self._adj[v]:
                in_deg[n] += 1
        q = deque(v for v in self._vertices if in_deg[v] == 0)
        order = []
        while q:
            v = q.popleft(); order.append(v)
            for n in self._adj[v]:
                in_deg[n] -= 1
                if in_deg[n] == 0:
                    q.append(n)
        if len(order) != len(self._vertices):
            raise ValueError("граф содержит цикл")
        return order

    # --- магические методы ---

    def __len__(self):
        return len(self._vertices)

    def __contains__(self, v):
        return v in self._vertices

    def __iter__(self):
        return iter(self._vertices)

    def __repr__(self):
        return f"Graph({dict(self._adj)})"


g = Graph()
for e in [("A","B"), ("A","C"), ("B","D"), ("C","D"), ("D","E")]:
    g.add_edge(*e)

print(g.bfs("A"))                # → ['A', 'B', 'C', 'D', 'E']
print(g.dfs("A"))                # → ['A', 'B', 'D', 'C', 'E']
print(g.has_cycle())             # → True
print(g.connected_components())  # → [['A', 'B', 'C', 'D', 'E']]
```

## Алгоритм Дейкстры

Кратчайший путь во взвешенном графе (неотрицательные веса). Использует [очередь с приоритетом](../../Данные/АТД/Очередь.md#очередь-с-приоритетом). Подробнее — в Алгоритм Дейкстры.

```python
import heapq

def дейкстра(граф, старт):
    # граф: {вершина: [(сосед, вес), ...]}
    dist = {v: float("inf") for v in граф}
    dist[старт] = 0
    parent = {старт: None}
    heap = [(0, старт)]

    while heap:
        d, v = heapq.heappop(heap)
        if d > dist[v]:
            continue
        for сосед, вес in граф[v]:
            новое = dist[v] + вес
            if новое < dist[сосед]:
                dist[сосед] = новое
                parent[сосед] = v
                heapq.heappush(heap, (новое, сосед))

    return dist, parent

def путь(parent, цель):
    p = []
    while цель is not None:
        p.append(цель); цель = parent[цель]
    return p[::-1]


граф = {
    "A": [("B", 4), ("C", 2)],
    "B": [("D", 3)],
    "C": [("B", 1), ("D", 5)],
    "D": [],
}
dist, par = дейкстра(граф, "A")
print(dist)           # → {'A': 0, 'B': 3, 'C': 2, 'D': 6}
print(путь(par, "D")) # → ['A', 'C', 'B', 'D']
```

## BFS vs DFS

| |BFS|DFS|
|---|---|---|
|Структура|[Очередь](../../Данные/АТД/Очередь.md)|[Стек](../../Данные/АТД/Стек.md) / рекурсия|
|Порядок|Уровень за уровнем|Вглубь перед вширь|
|Кратчайший путь (невзвешенный)|Да|Нет|
|Топологическая сортировка|Да (алгоритм Кана)|Да|
|Обнаружение цикла|Да|Да|

Подробнее — в BFS — поиск в ширину и DFS — поиск в глубину.

## Граф vs Дерево

| |[Дерево](../../Данные/Структуры%20данных/Дерево.md)|Граф|
|---|---|---|

|Корень|Есть|Нет|
|Связность|Всегда связное|Может быть несвязным|
|Обход|Не нужно отслеживать посещённые|Нужно|

## Связи

- Топология сетей — топология сети как граф: кольцо = цикл, полносвязная mesh = полный граф $K_n$, отказоустойчивость = связность;
- Алгоритмы поиска — BFS, DFS, Дейкстра, топологическая сортировка на графах;
- [Дерево](../../Данные/Структуры%20данных/Дерево.md) — частный случай графа: связный ациклический граф;
- Цепи Маркова — взвешенный ориентированный граф, где веса рёбер это вероятности перехода, а сумма по строке матрицы смежности равна 1;
- [PageRank](../../Алгоритмы/Иные/PageRank.md) — важность вершины через случайное блуждание по графу.
