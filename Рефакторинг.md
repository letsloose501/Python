# Рефакторинг

**Рефакторинг** — изменение **внутренней структуры** кода **без изменения его внешнего поведения**, чтобы код стал понятнее, проще и его было легче менять. Это не «переписать с нуля», не «добавить фичу» и не «починить баг» — меняется только форма, поведение остаётся прежним.

> Код читают в разы чаще, чем пишут. Рефакторинг — это плата за то, чтобы завтрашние изменения были дешёвыми. Делают его **маленькими шагами**, а не большим переписыванием.

## Обязательное условие — тесты

Рефакторинг без тестов — рулетка: любое улучшение может незаметно сломать поведение. **[Тесты](Библиотеки/Сторонние/Тесты/Юнит-тестирование%20Python.md) должны быть зелёными до и после каждого шага** — они и есть страховка, что поведение не изменилось. Именно поэтому «рефакторинг» — третий шаг цикла [TDD](Библиотеки/Сторонние/Тесты/Юнит-тестирование%20Python.md#tdd--тест-сначала) (red → green → **refactor**).

## Запахи кода (code smells)

**Запах кода** — не баг, а **признак**, что структура плоха и просит рефакторинга:

- **Дублирование** — один и тот же код в нескольких местах (нарушение [DRY](ООП/Принципы/Принципы%20разработки%20—%20DRY,%20KISS,%20DI.md)). Правило трёх: скопировал в третий раз — выдели общее.
- **Длинный метод / большой класс** — делает слишком много, тяжело читать и тестировать (нарушение [SRP](ООП/Принципы/SOLID%20Python.md)).
- **Длинный список параметров** — трудно вызывать и запоминать порядок.
- **Зависть к данным** (feature envy) — метод больше работает с полями чужого класса, чем со своими → вероятно, он не в том классе.
- **Магические числа и строки** — `if status == 3` вместо именованной константы/`Enum`.
- **Комментарии-оправдания** — объясняют запутанный код вместо того, чтобы его упростить.
- **Длинные `if/switch` по типу** — часто заменяются полиморфизмом.
- **Скрытая зависимость** — класс создаёт себе `PostgresRepo()` или читает глобальный `settings` внутри. По сигнатуре не видно, что ему нужно; в тестах не подменить (нарушение [DIP](ООП/Принципы/SOLID%20Python.md#d--dependency-inversion-инверсия-зависимостей)).
- **Класс с единственным методом** — обёртка ради обёртки. Если состояния нет, функция читается лучше: `send_telegram(...)` вместо `TelegramSender().send(...)`.

## Приёмы рефакторинга

Небольшие проверенные преобразования (по М. Фаулеру):

- **Extract Method** — выделить кусок кода в отдельный метод с говорящим именем (лечит длинный метод, дублирование).
- **Rename** — переименовать переменную/метод в самообъясняющее имя (самый частый и недооценённый).
- **Extract Variable** — назвать промежуточное выражение понятной переменной.
- **Replace Magic Number with Constant** — вынести число/строку в именованную константу или `Enum`.
- **Replace Conditional with Polymorphism** — заменить ветвление по типу объекта на вызов метода — прямой мост к [паттернам](ООП/Паттерны/Паттерны%20поведения.md) (Стратегия, Состояние).
- **Move Method / Move Field** — перенести туда, где лежат данные, с которыми он работает (лечит feature envy).
- **Introduce Parameter Object** — сгруппировать связанные параметры в объект.
- **Inject Dependency** — заменить `self.db = PostgresRepo()` внутри класса на параметр конструктора, а создание перенести в [композиционный корень](ООП/Принципы/Композиционный%20корень.md). Лечит скрытые зависимости и делает класс тестируемым.
- **Replace Conditional with Lookup Table** — заменить `if/elif` по значению на словарь «ключ → реализация» с запасным вариантом. Более лёгкая альтернатива полиморфизму, когда вариантов много, а поведение отличается только выбором объекта.

> Порядок для чужого кода, в котором «сломано всё»: сначала **Inject Dependency** (станет видно, кто от кого зависит), потом **Extract Method** по ответственностям, и только затем — полиморфизм и интерфейсы. Сквозной разбор на живом сервисе: [SOLID на практике — рефакторинг сервиса](ООП/Принципы/SOLID%20на%20практике%20—%20рефакторинг%20сервиса.md).

```python
# ЗАПАХ — длинный метод с дублированием и магическими числами
def price(order):
    total = 0
    for item in order.items:
        total += item.price * item.qty
    if total > 1000:            # что за 1000?
        total *= 0.9            # что за 0.9?
    return total

# ПОСЛЕ — Extract Method + именованные константы (поведение то же)
FREE_SHIP_THRESHOLD = 1000
DISCOUNT = 0.9

def price(order):
    total = _subtotal(order)
    return total * DISCOUNT if total > FREE_SHIP_THRESHOLD else total

def _subtotal(order):
    return sum(item.price * item.qty for item in order.items)
```

## Рефакторинг и паттерны

Паттерны показывают, **к какой структуре стремиться**; рефакторинг — **путь** к ней. Увидел длинный `if` по типу → рефакторинг «заменить условие полиморфизмом» приводит к паттерну Стратегия. Поэтому паттерны, применённые вовремя, сокращают будущий рефакторинг.

## Когда НЕ рефакторить

- **Нет тестов** — сначала покрой тестами, потом меняй структуру.
- **Прямо перед дедлайном** — рефакторинг не должен блокировать поставку; заведи техдолг.
- **Код проще выбросить** — если модуль безнадёжен и мал, переписать с нуля дешевле (это уже не рефакторинг).
