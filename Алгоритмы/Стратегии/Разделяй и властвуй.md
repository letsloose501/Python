# Разделяй и властвуй

**Разделяй и властвуй** (divide and conquer) — стратегия из трёх шагов: **разделить** задачу на меньшие подобные подзадачи, **решить** каждую (обычно рекурсивно), **объединить** их результаты в ответ на исходную задачу.

> **Аналогия:** чтобы отсортировать колоду, раздай её пополам двум помощникам, пусть каждый отсортирует свою половину, потом слей две отсортированные стопки в одну.

Опирается на [рекурсию](../../Алгоритмы/Стратегии/Рекурсия.md) и подходит задачам с **оптимальной подструктурой** — тем, что естественно делятся на похожие, но меньшие части.

---

### Схема

```
задача
├── подзадача A → решение A
└── подзадача B → решение B
                → объединить → решение задачи
```

Сложность часто получается $O(n \log n)$: $\log n$ уровней деления × $O(n)$ работы на объединение каждого уровня.

---

### Примеры

**Быстрое возведение в степень** — $O(\log n)$ вместо $O(n)$:

```python
def power(a, n):
    if n == 0:
        return 1
    half = power(a, n // 2)          # решаем половину задачи
    if n % 2 == 0:
        return half * half           # объединяем
    return half * half * a

power(2, 10)   # → 1024
```

**Сортировка слиянием** — делим массив пополам, сортируем части, сливаем ([подробно](../../Алгоритмы/Сортировка/Слиянием.md)):

```python
def merge_sort(a):
    if len(a) <= 1:                  # база
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])       # разделяй
    right = merge_sort(a[mid:])
    return merge(left, right)        # властвуй (слияние двумя указателями)
```

Другие классические представители: [быстрая сортировка](../../Алгоритмы/Сортировка/Быстрая.md) (partition), бинарный поиск, максимальный подмассив, умножение Карацубы.

### Каноничные задачи

Четыре задачи, на которых стратегию проверяют. У всех один и тот же ход мысли: **посчитать внутри половин рекурсией, а руками добрать только то, что лежит на стыке**.

#### Подсчёт инверсий — $O(n \log n)$

**Инверсия** — пара индексов $i < j$, где $a_i > a_j$. Число инверсий показывает, насколько массив далёк от отсортированного (у отсортированного — 0, у развёрнутого — максимум).

Наивно это $O(n^2)$ по всем парам. Ключ к ускорению: **если обе половины уже отсортированы, инверсии между ними считаются за один проход слияния**. Когда в слиянии берём элемент из правой половины, он меньше **всех** оставшихся в левой — а это сразу столько инверсий, сколько там осталось.

```python
def sort_count(a):
    """Вернуть (отсортированный список, число инверсий)."""
    if len(a) <= 1:
        return a, 0

    mid = len(a) // 2
    left, cl = sort_count(a[:mid])            # 1. инверсии внутри левой
    right, cr = sort_count(a[mid:])           # 2. внутри правой

    merged, cross = [], 0                     # 3. на стыке половин
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1
            cross += len(left) - i            # ← весь остаток левой больше right[j]
    merged += left[i:] + right[j:]

    return merged, cl + cr + cross

sort_count([2, 3, 9, 2, 9])[1]                # → 2   пары (3,2) и (9,2)
```

> Это и есть «вариация сортировки слиянием», о которой спрашивают: сам [merge sort](../../Алгоритмы/Сортировка/Слиянием.md) не меняется, к нему добавляется одна строка счётчика. Условие `left[i] <= right[j]` обязано быть нестрогим — иначе равные элементы посчитаются как инверсии.

#### Доминирующий элемент — $O(n \log n)$ и $O(n)$

**Доминирующий** (majority) — элемент, встречающийся **более чем в половине** позиций. Такой элемент либо один, либо его нет.

Ход через «разделяй и властвуй» опирается на свойство: **если $x$ доминирует во всём массиве, он доминирует хотя бы в одной из половин**. Значит, кандидатов всего два — по одному от каждой половины, и их достаточно пересчитать линейно. Это $O(n \log n)$.

Но у задачи есть решение лучше — **алгоритм Бойера — Мура**, за один проход и $O(1)$ памяти:

```python
def majority(a):
    кандидат, счётчик = None, 0
    for x in a:                               # 1. взаимное уничтожение
        if счётчик == 0:
            кандидат, счётчик = x, 1
        elif x == кандидат:
            счётчик += 1
        else:
            счётчик -= 1                      # разные элементы гасят друг друга
    # 2. проверка обязательна: кандидат есть всегда, доминирующий — нет
    return кандидат if a.count(кандидат) > len(a) // 2 else None

majority([2, 2, 1, 2, 3, 2])                  # → 2
majority([1, 2, 3])                           # → None
```

**Почему работает.** Каждый «чужой» элемент забирает с собой одного «своего». Если элемент занимает больше половины, уничтожить его полностью нечем — он останется кандидатом. Обратное неверно, поэтому **второй проход с пересчётом отбрасывать нельзя**: на `[1, 2, 3]` кандидатом останется `3`, хотя доминирующего нет.

#### Пара ближайших точек — $O(n \log^2 n)$

Единственная задача вычислительной геометрии в маршруте. Дано $n$ точек на плоскости — найти минимальное расстояние между двумя.

Перебор пар — $O(n^2)$. Стратегия: делим точки вертикальной линией пополам, находим минимумы $d_1$ и $d_2$ в половинах, берём $d = \min(d_1, d_2)$. Осталось проверить пары, **разорванные линией** — и вот главная идея: такая пара может быть ближе $d$ только если **обе точки лежат в полосе шириной $2d$** вокруг линии. Всё, что дальше, заведомо не ближе $d$ уже по одной координате $x$.

Внутри полосы, отсортированной по $y$, каждой точке достаточно проверить **несколько следующих** (полоса режется на квадраты $d \times d$, в каждом не больше 4 точек — значит число проверок ограничено константой, а не $n$).

```python
from itertools import combinations
from math import dist, inf

def ближайшая_пара(точки):
    px = sorted(точки)                                    # по x — один раз

    def рек(p):
        if len(p) <= 3:                                   # 1. база — перебор
            return min((dist(a, b) for a, b in combinations(p, 2)), default=inf)

        mid = len(p) // 2
        x_линии = p[mid][0]
        d = min(рек(p[:mid]), рек(p[mid:]))                # 2. половины

        полоса = sorted((t for t in p if abs(t[0] - x_линии) < d),
                        key=lambda t: t[1])               # 3. полоса 2d, по y
        for i, a in enumerate(полоса):
            for b in полоса[i + 1:i + 8]:                 # 4. 7 следующих — хватает
                if b[1] - a[1] >= d:
                    break                                 # дальше по y смысла нет
                d = min(d, dist(a, b))
        return d

    return рек(px)

ближайшая_пара([(0, 0), (3, 4), (1, 1), (7, 7)])          # → 1.4142…
```

> **Про сложность — честно.** Здесь полоса сортируется по $y$ на каждом уровне рекурсии, отсюда $T(n) = 2T(n/2) + O(n \log n) = O(n \log^2 n)$. Настоящий $O(n \log n)$ получается, если отсортировать по $y$ **один раз заранее** и на каждом уровне не сортировать, а **сливать** уже упорядоченные половины — как в merge sort. Для контеста версии выше почти всегда достаточно; знать про улучшение стоит, потому что про него спрашивают.

#### Разобранные в других заметках

- **Бинарный поиск** — вырожденный случай стратегии: одна половина отбрасывается целиком, объединять нечего, отсюда $O(\log n)$ вместо $O(n \log n)$.
- **[Трёхпутевое разбиение](../../Алгоритмы/Сортировка/Быстрая.md#трёхпутевое-разбиение-dutch-national-flag--для-массивов-с-дубликатами)** — та самая «модификация быстрой сортировки»: обычный quicksort на массиве из одинаковых элементов деградирует в $O(n^2)$, потому что разбиение даёт части $n-1$ и $0$. Деление на «меньше / равно / больше» выносит все равные опорному в середину и больше их не рекурсирует.
- **[Quickselect](../../Алгоритмы/Сортировка/Быстрая.md#применение)** — $k$-я порядковая статистика за $O(n)$ в среднем: рекурсия идёт только в ту половину, где лежит ответ.

### Отличие от динамического программирования

| |Разделяй и властвуй|[Динамическое программирование](../../Алгоритмы/Стратегии/Динамическое%20программирование.md)|
|---|---|---|
|Подзадачи|**Не пересекаются**|**Пересекаются**, результаты переиспользуются|
|Пример|Merge sort, бинпоиск|Фибоначчи, рюкзак|

Если подзадачи повторяются — «разделяй и властвуй» будет считать их заново (как наивный Фибоначчи); тогда нужна мемоизация → это уже ДП.

---

### Когда применять

- Задачу можно разбить на **независимые** одинаковые части.
- Объединение результатов дешевле полного перебора.
- Есть оптимальная подструктура (сортировки, поиск, геометрия).
