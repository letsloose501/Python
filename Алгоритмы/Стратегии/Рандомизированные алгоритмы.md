# Рандомизированные алгоритмы

**Рандомизированный алгоритм** — алгоритм, который в ходе работы принимает случайные решения. Случайность здесь не небрежность, а инструмент: она лишает входные данные возможности быть «специально плохими».

> **Аналогия:** если всегда ходишь домой одной дорогой, засаду устроить легко. Если каждый раз бросаешь монетку — заранее не подстеречь.

Часть семейства стратегий. Источник случайности в Python — [random](../../Библиотеки/Модули/Работа%20с%20числами/random.md).

---

### Зачем случайность

У детерминированного алгоритма есть **худший случай**, и его можно подсунуть. Классика — [быстрая сортировка](../../Алгоритмы/Сортировка/Быстрая.md) с опорным элементом «первый в массиве»: на уже отсортированном входе разбиение получается $1$ и $n-1$, и $O(n \log n)$ вырождается в $O(n^2)$.

```python
# детерминированный выбор — уязвим
def quicksort(a):
    if len(a) <= 1:
        return a
    опорный = a[0]                       # на отсортированном входе — всегда минимум
    ...
```

Случайный выбор опорного эту атаку убивает: чтобы получить $O(n^2)$, нужно угадать всю последовательность бросков.

```python
import random

def quicksort(a):
    if len(a) <= 1:
        return a
    опорный = random.choice(a)           # ← вся разница
    меньше = [x for x in a if x < опорный]
    равные = [x for x in a if x == опорный]
    больше = [x for x in a if x > опорный]
    return quicksort(меньше) + равные + quicksort(больше)
```

**Что изменилось в оценке.** Худший случай остался $O(n^2)$ — его не убрали, а сделали **невероятным**: теперь $O(n \log n)$ это не «в среднем по типичным данным», а **ожидаемое время для любого входа**. Плохой вход больше не свойство данных, а следствие неудачных бросков монетки.

> Разница тонкая, но её спрашивают: «средний случай» — усреднение по входам (предполагает, что входы случайны), «ожидаемое время» — усреднение по броскам монетки (входы могут быть любыми, включая враждебные).

### Два типа: Лас-Вегас и Монте-Карло

Развилка одна: где алгоритм допускает разброс — во **времени** или в **ответе**.

| | Лас-Вегас | Монте-Карло |
|---|---|---|
| **Ответ** | всегда верный | может быть неверным (с малой вероятностью) |
| **Время** | случайное, оценивается ожиданием | обычно фиксированное |
| **Как улучшить** | ждать дольше | прогнать несколько раз |
| **Примеры** | рандомизированный quicksort, quickselect | тест Миллера — Рабина, [Фильтр Блума](../../Алгоритмы/Иные/Фильтр%20Блума.md), [HyperLogLog](../../Алгоритмы/Иные/HyperLogLog.md) |

**Мнемоника:** в Лас-Вегасе выигрыш гарантирован, вопрос — когда; в Монте-Карло играешь на вероятность.

> ⚠️ **Одно название, три вещи.** «Монте-Карло» здесь — **класс алгоритмов** (время фиксировано, ответ вероятностный). Это не то же самое, что численный метод Монте-Карло (оценить величину, разыграв её много раз) и не то же, что схема кросс-валидации Монте-Карло в машинном обучении. Общий у них только принцип случайности.

```python
# Лас-Вегас: ответ точный, время случайное — quickselect, k-й наименьший за O(n) в среднем
# (реализация — в заметке «Быстрая»)

# Монте-Карло: ответ вероятностный — проверка простоты за O(k log³ n)
#   тест Миллера — Рабина: k случайных «свидетелей»; составное число
#   проскочит с вероятностью < 4^(-k). При k=20 это меньше 10^(-12)
```

> **Ошибку Монте-Карло можно сделать сколь угодно малой, но не нулевой.** Двадцать независимых проверок дают вероятность ошибки ниже, чем вероятность сбоя железа за то же время, — и на практике этого достаточно. Именно так работает проверка простоты в криптографии (Криптография и безопасность).

### Где это уже встречалось

Рандомизация — не отдельная экзотика, а способ, которым устроены знакомые вещи:

- **[Quicksort и quickselect](../../Алгоритмы/Сортировка/Быстрая.md)** — случайный опорный, Лас-Вегас;
- **[Хеширование](../../Данные/Структуры%20данных/Хеш-таблица.md)** — случайная соль хеш-функции защищает от подобранных коллизий (в Python включена по умолчанию, `PYTHONHASHSEED`);
- **[Фильтр Блума](../../Алгоритмы/Иные/Фильтр%20Блума.md)** — Монте-Карло с односторонней ошибкой: «нет» точное, «да» вероятностное;
- **[HyperLogLog](../../Алгоритмы/Иные/HyperLogLog.md)**, **[Локально-чувствительное хеширование (SimHash)](../../Алгоритмы/Иные/Локально-чувствительное%20хеширование%20%28SimHash%29.md)** — оценка вместо точного подсчёта, обмен точности на память;
- **[Стресс-тестирование](../../Алгоритмы/Приёмы/Стресс-тестирование.md)** — случайные маленькие входы, чтобы найти контрпример: та же идея, только применённая к поиску собственных багов.

### Односторонняя ошибка — важная деталь

У хорошего Монте-Карло ошибка **односторонняя**: он врёт только в одну сторону, и ты знаешь, в какую. [Фильтр Блума](../../Алгоритмы/Иные/Фильтр%20Блума.md) на вопрос «был ли элемент?» отвечает «точно не был» или «возможно, был» — ложное «да» бывает, ложного «нет» не бывает никогда.

Это делает алгоритм пригодным как **быстрый фильтр перед точной проверкой**: дешёвая проверка отсекает большинство, дорогая подтверждает остаток. Ровно так работает кеш «этого ключа точно нет в базе» — и это готовый ответ в [system design](../../Проектирование%20систем%20%28system%20design%29.md) на вопрос «а если данных очень много».

### Когда применять

- **Есть враждебный или неудачный худший случай** — рандомизация его размывает (quicksort);
- **Точный ответ дороже, чем нужно** — оценка за долю ресурсов лучше точности, которой никто не воспользуется (уникальные посетители через [HyperLogLog](../../Алгоритмы/Иные/HyperLogLog.md));
- **Детерминированный алгоритм сложен, а вероятностный короток** — простота реализации это тоже аргумент: меньше кода, меньше ошибок.

**Когда не применять:** ответ должен быть воспроизводим (отладка, тесты, финансовые расчёты) — тогда либо фиксируй `random.seed(...)`, либо бери детерминированный вариант. На контесте это важно: с фиксированным сидом баг воспроизводится, без него — «то падает, то нет».

```python
import random
random.seed(42)          # тот же прогон повторяется — для отладки обязательно
```

> ⚠️ **`random` — не для безопасности.** Модуль даёт предсказуемую последовательность (Mersenne Twister): зная несколько значений, можно вычислить остальные. Для токенов и паролей — только [secrets](../../Библиотеки/Модули/Безопасность%20и%20интернет/secrets.md).
