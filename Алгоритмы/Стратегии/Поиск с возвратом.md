# Поиск с возвратом (Backtracking)

**Поиск с возвратом** (backtracking) — стратегия построения решения шаг за шагом: делаем выбор, идём вглубь, а если зашли в тупик — **откатываемся** и пробуем другой вариант. Перебирает все допустимые комбинации, отсекая заведомо плохие ветви.

> **Аналогия:** лабиринт. Идёшь по коридору; упёрся в стену — возвращаешься к последней развилке и пробуешь другой поворот.

Полная противоположность жадному подходу: жадный никогда не откатывается, backtracking — только этим и живёт. Медленнее, но находит **гарантированно правильное** решение там, где жадный ошибается.

---

### Каркас: выбор → вглубь → откат

```python
def backtrack(состояние, путь, результат):
    if решение_готово(состояние):
        результат.append(путь[:])        # копия!
        return
    for вариант in допустимые_варианты(состояние):
        путь.append(вариант)             # выбор
        backtrack(следующее(состояние), путь, результат)   # вглубь
        путь.pop()                       # откат
```

Ключевое — **симметрия выбора и отката**: что добавили перед рекурсией, то убираем после.

---

### Примеры

**Все подмножества:**

```python
def subsets(nums):
    res, path = [], []
    def bt(start):
        res.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])     # выбор
            bt(i + 1)                # вглубь
            path.pop()               # откат
    bt(0)
    return res

subsets([1, 2, 3])   # → [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]
```

**Перестановки:**

```python
def permutations(nums):
    res, path = [], []
    used = [False] * len(nums)
    def bt():
        if len(path) == len(nums):
            res.append(path[:]); return
        for i in range(len(nums)):
            if used[i]:
                continue
            used[i] = True; path.append(nums[i])
            bt()
            path.pop(); used[i] = False
    bt()
    return res
```

**N ферзей** (с отсечением по диагоналям — это и есть «отбрасывание тупиков заранее»):

```python
def solve_n_queens(n):
    res = []
    cols, diag1, diag2 = set(), set(), set()
    board = []
    def bt(r):
        if r == n:
            res.append(board[:]); return
        for c in range(n):
            if c in cols or (r - c) in diag1 or (r + c) in diag2:
                continue                          # отсечение: клетка бита
            cols.add(c); diag1.add(r - c); diag2.add(r + c); board.append(c)
            bt(r + 1)
            board.pop(); cols.discard(c); diag1.discard(r - c); diag2.discard(r + c)
    bt(0)
    return res
```

---

### Отсечение (pruning)

Чем раньше отбрасываешь бесперспективную ветвь, тем быстрее перебор. В N ферзях мы не ставим ферзя на битую клетку — не спускаемся в заведомо мёртвую ветку. Более строгая версия отсечения с оценкой границ — [Ветви и границы](../../Алгоритмы/Стратегии/Ветви%20и%20границы.md).

---

### Сложность

Обычно экспоненциальная: $O(2^n)$ для подмножеств, $O(n!)$ для перестановок — это норма для полного перебора. Отсечения снижают константу и часто делают перебор практичным.

---

### Когда применять

- «Найти **все** комбинации / перестановки / расстановки, удовлетворяющие условию».
- Судоку, лабиринты, расстановка объектов с ограничениями, генерация вариантов.
- Есть чёткое правило «допустим ли следующий шаг» → можно отсекать рано.
