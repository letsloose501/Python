# Рекурсия

**Рекурсия** — стратегия, при которой функция решает задачу, **вызывая саму себя** с меньшим входом, пока не дойдёт до **базового случая**, на котором ответ известен без вызовов.

> **Аналогия:** матрёшка. Чтобы «обработать» матрёшку — открой и обработай матрёшку внутри; самая маленькая (без вложенной) — базовый случай.

Две обязательные части: **базовый случай** (условие остановки) и **рекурсивный случай** (сведение к меньшей задаче). Без базового случая — бесконечная рекурсия и переполнение стека.

---

### Как работает

```python
def factorial(n):
    if n <= 1:                     # базовый случай
        return 1
    return n * factorial(n - 1)    # рекурсивный случай — вход уменьшается

factorial(5)   # → 120  (5 * 4 * 3 * 2 * 1)
```

Каждый вызов кладётся в стек вызовов и ждёт, пока вернётся вложенный. Развёртка `factorial(3)`:

```
factorial(3) = 3 * factorial(2)
             = 3 * (2 * factorial(1))
             = 3 * (2 * 1) = 6
```

### Рекурсия естественна для самоподобных структур

```python
# Фибоначчи определён рекурсивно
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)    # ⚠️ O(2ⁿ) — дерево пересчитывает одно и то же
```

Наивный `fib` экспоненциален из-за повторных вычислений — это чинит [мемоизация](../../Алгоритмы/Приёмы/Мемоизация.md). Точное число вызовов — $2F(n+1)-1$, то есть $\Theta(\varphi^n)$ с $\varphi \approx 1{,}618$; привычная запись $O(2^n)$ — верхняя граница, завышенная при $n=40$ примерно в 3 300 раз.

```python
# высота бинарного дерева — рекурсия по структуре
def depth(node):
    if node is None:
        return 0
    return 1 + max(depth(node.left), depth(node.right))
```

Именно так работает обход [DFS](../../Алгоритмы/Поиск/DFS.md) и весь [backtracking](../../Алгоритмы/Стратегии/Поиск%20с%20возвратом.md).

### Ханойские башни — когда экспонента честная

Классическая демонстрация: перенести башню из $n$ дисков с одного стержня на другой, беря по одному диску и никогда не кладя больший на меньший. Десятки шагов вручную — и восемь строк рекурсией.

```python
def ханой(n, откуда, куда, через):
    if n == 0:                                  # база: нечего переносить
        return
    ханой(n - 1, откуда, через, куда)           # 1. верхние n-1 отложить на запасной
    print(f"диск {n}: {откуда} → {куда}")       # 2. переложить самый большой
    ханой(n - 1, через, куда, откуда)           # 3. вернуть n-1 сверху

ханой(3, "A", "C", "B")                         # → 7 перемещений
```

**Почему это работает.** Задача сводится к себе же меньшего размера: чтобы переложить $n$ дисков, надо уметь переложить $n-1$. Никакого «алгоритма» кроме этого сведения здесь нет — вся работа в трёх строках, и именно в этом красота приёма.

**Но за элегантность платят.** Каждый шаг удваивает работу: $T(n) = 2T(n-1) + 1$, то есть **$2^n - 1$ перемещений**. Для 64 дисков это ~1.8·10¹⁹ шагов — больше, чем секунд с начала Вселенной.

> 🔴 **Главный урок — контраст с Фибоначчи.** Наивный `fib` экспоненциален **из-за повторных вычислений**, и [мемоизация](../../Алгоритмы/Стратегии/Динамическое%20программирование.md) его лечит: разных подзадач всего $n$. У ханойских башен экспонента **в самом ответе** — перемещений действительно $2^n-1$, и кэшировать нечего. Отсюда правило: увидел экспоненту — сперва спроси, она от повторов (лечится) или от размера ответа (не лечится).

- Каждый вызов занимает память в стеке → глубокая рекурсия = переполнение.
- В Python **нет** оптимизации хвостовой рекурсии (tail-call) — хвостовой вызов стек не экономит.
- Лимит по умолчанию ~1000 кадров; поднимается вручную:

```python
import sys
sys.setrecursionlimit(10**6)   # осторожно: слишком много → падение интерпретатора
```

> ⚠️ **Лимит поднимается не везде.** С Python 3.12 глубина рекурсии через C-код ограничена отдельным счётчиком, и `setrecursionlimit` его не трогает. Практическое следствие: рекурсия, обёрнутая в `@lru_cache`, упирается в ~1000 вызовов даже при лимите 50 000, тогда как та же рекурсия с ручным словарём доходит до 49 998. Замеры и обходные пути — в [Мемоизация](../../Алгоритмы/Приёмы/Мемоизация.md).

### Итерация vs рекурсия

| |[Итерация](../../Алгоритмы/Стратегии/Итерация.md)|Рекурсия|
|---|---|---|
|Память|$O(1)$|$O(\text{глубина})$ — стек|
|Скорость|Быстрее|Медленнее (издержки вызовов)|
|Читаемость|Громоздче|Чище для деревьев/графов/делимых задач|

### Когда применять

- Задача **самоподобна**: дерево, граф, «разбить и решить части».
- [DFS](../../Алгоритмы/Поиск/DFS.md), [Поиск с возвратом](../../Алгоритмы/Стратегии/Поиск%20с%20возвратом.md), [Разделяй и властвуй](../../Алгоритмы/Стратегии/Разделяй%20и%20властвуй.md), обход вложенных структур (JSON, файловая система).
- Если рекурсия глубокая и линейная — перепиши [итеративно](../../Алгоритмы/Стратегии/Итерация.md) (или через явный [Стек](../../Данные/АТД/Стек.md)).
