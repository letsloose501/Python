# Итерация

**Итерация** — стратегия, при которой процесс повторяется в цикле до выполнения условия. Каждый проход — один шаг (итерация). Основа большинства алгоритмов: быстрая, предсказуемая, не тратит память на стек вызовов.

> **Аналогия:** поднимаешься по лестнице — один и тот же приём (переставить ногу) повторяешь, пока не дойдёшь до верха.

Часть семейства стратегий; прямая альтернатива [рекурсии](../../Алгоритмы/Стратегии/Рекурсия.md).

---

### Как работает

Почти любой цикл состоит из трёх частей: инициализация состояния → условие продолжения → обновление состояния на каждом шаге.

```python
# сумма чисел от 1 до n
def sum_to(n):
    result = 0                 # инициализация
    for i in range(1, n + 1):  # условие + обновление
        result += i
    return result

sum_to(5)   # → 15
```

### Инвариант цикла

Утверждение, истинное **перед каждой** итерацией. Помогает доказать корректность и не ошибиться на границах.

```python
# факториал: инвариант — result = (i-1)!
def factorial(n):
    result = 1
    for i in range(1, n + 1):
        result *= i     # перед шагом: result = (i-1)!
    return result       # после цикла: result = n!
```

### Досрочный выход

```python
# первый чётный — выходим сразу, не досматривая массив
def first_even(nums):
    for x in nums:
        if x % 2 == 0:
            return x
    return None
```

### Алгоритм Евклида — образцовая итерация

**НОД** (наибольший общий делитель) — самое большое число, на которое делятся оба нацело. Задача-эталон: показывает, как выбор шага меняет сложность на порядки.

**Наивно** — перебирать делители от меньшего числа вниз: $O(\min(a, b))$, на $10^9$ не проходит.

**Вычитанием** — пока числа не равны, вычитать меньшее из большего. Работает, но на паре `(10**6, 6)` делает больше миллиона шагов:

```python
def нод_вычитанием(a, b):
    while a != b:
        if a > b:
            a -= b
        else:
            b -= a
    return a
```

**Евклид** — заменить вычитание **остатком**. Одна операция вместо цепочки одинаковых вычитаний:

```python
def нод(a, b):
    while b:                        # инвариант: НОД(a, b) не меняется на каждом шаге
        a, b = b, a % b
    return a

нод(18, 35)     # → 1    взаимно простые
нод(48, 18)     # → 6
```

**Почему это быстро.** После двух шагов число уменьшается **минимум вдвое**, поэтому сложность — $O(\log \min(a, b))$: для чисел до $10^9$ это меньше сотни итераций вместо миллиарда.

**Почему это верно.** Инвариант: $\text{НОД}(a, b) = \text{НОД}(b, a \bmod b)$. Любой общий делитель $a$ и $b$ делит и остаток $a \bmod b$ — значит множество общих делителей на шаге не меняется, а числа уменьшаются. Цикл упирается в $b = 0$, где НОД равен $a$.

**НОК через НОД** — отдельного алгоритма не нужно:

$$\text{НОК}(a, b) = \frac{a \cdot b}{\text{НОД}(a, b)}$$

```python
def нок(a, b):
    return a * b // нод(a, b)       # делить ДО умножения, если числа большие: a // нод(a,b) * b

нок(6, 8)       # → 24    НОД = 2, значит 6*8/2
```

Причина формулы: в разложении на простые множители НОД берёт каждый множитель в **минимальной** степени, НОК — в **максимальной**; вместе они дают ровно произведение.

> В продакшене это одна строка — [`math.gcd`](../../Библиотеки/Модули/Работа%20с%20числами/math.md) и `math.lcm` (Python 3.9+), написанные на C. Писать руками стоит один раз, чтобы понимать инвариант: у Евклида его спрашивают как образцовый пример доказательства корректности цикла.

### Числа Фибоначчи — лестница от $O(2^n)$ до $O(\log n)$

Вторая задача-эталон. Ценность не в самой последовательности, а в том, что на ней видны **несколько разных уровней работы с одной и той же формулой** — и на собесе по ДП ждут именно движения по этой лестнице, а не готового ответа.

**Уровень 1 — наивная рекурсия, $O(2^n)$.** Дерево вызовов пересчитывает одно и то же ([подробно](../../Алгоритмы/Стратегии/Рекурсия.md)): `fib(40)` — около 300 млн вызовов.

> **Точная цена — не $2^n$, а золотое сечение.** Вызовов ровно $2F(n+1) - 1$ (проверено: 177 при $n=10$, 21 891 при $n=20$, 2 692 537 при $n=30$), то есть $\Theta(\varphi^n)$, где $\varphi \approx 1{,}618$. Оценка $2^n$ верна как верхняя граница, но грубая: при $n = 40$ она завышена в 3 300 раз. На собесе достаточно сказать «экспонента», но откуда берётся $\varphi$, стоит понимать: это корень уравнения $x^2 = x + 1$ — характеристического для самой рекуррентности $F_n = F_{n-1} + F_{n-2}$.

**Уровень 1.5 — мемоизация, $O(n)$.** Первое, что приходит в голову после «дерево пересчитывает одно и то же»: не переписывать код, а [навесить кэш](../../Алгоритмы/Приёмы/Мемоизация.md). Экспонента схлопывается в линию, потому что разных подзадач всего $n$.

```python
def fib(n):
    кэш = {}
    def внутр(k):
        if k < 2:
            return k
        if k not in кэш:
            кэш[k] = внутр(k - 1) + внутр(k - 2)
        return кэш[k]
    return внутр(n)
```

> ⚠️ **Именно эта ступень ломается на задаче «дай тысячное число».** Кэш убирает повторные вызовы, но цепочка `fib(1000) → fib(999) → …` остаётся — это 1000 кадров стека при лимите 1000, и `@lru_cache` здесь падает даже с поднятым `setrecursionlimit`. Разбор и обходные пути — в [Мемоизация](../../Алгоритмы/Приёмы/Мемоизация.md). Отсюда и переход на следующую ступень: рекурсию убирают не ради красоты, а чтобы не зависеть от стека.

**Уровень 2 — итерация, $O(n)$ и $O(1)$ памяти.** Хранить всю таблицу не нужно, достаточно двух последних значений:

```python
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b          # инвариант: a = F(i), b = F(i+1)
    return a

fib(40)                          # → 102334155   мгновенно
```

Это же и есть [ДП](../../Алгоритмы/Стратегии/Динамическое%20программирование.md) с экономией памяти — просто настолько простое, что таблицу видно целиком в двух переменных.

> 🔴 **«$O(n)$» здесь — ложь в модели, где сложение стоит константу.** $F_n$ занимает примерно $0{,}694n$ бит (замер: у $F_{100000}$ ровно 69 424 бита, у $F_{400000}$ — 277 696), и сложение таких чисел линейно по их длине, а не мгновенно. Суммарно получается $\Theta(n^2)$ битовых операций, и это видно на замерах: 0,08 с → 0,27 с → 0,98 с при удвоении $n$ (100 тыс. → 200 тыс. → 400 тыс.), то есть ×3,5 вместо ×2. На собесе оценка $O(n)$ считается правильной, потому что подразумевается машинное слово; но если числа не помещаются в него — оговорку стоит произнести вслух. Подробнее про допущение — Вычислительная сложность.

**Уровень 3 — по модулю: период Пизано.** Задача «последняя цифра $F_n$» или «$F_n \bmod m$» при $n$ до $10^{18}$: считать $n$ итераций уже нельзя. Спасает то, что **остатки $F_n \bmod m$ периодичны** — эта длина называется **периодом Пизано** $\pi(m)$.

```python
def период_пизано(m):
    a, b, период = 0, 1, 0
    while True:
        a, b = b, (a + b) % m
        период += 1
        if (a, b) == (0, 1):          # последовательность вернулась к началу
            return период

def fib_mod(n, m):
    return fib(n % период_пизано(m)) % m     # огромное n сводится к маленькому

fib_mod(10**18, 10)                          # последняя цифра F(10^18)
```

Период не превышает $6m$, поэтому его поиск дешёвый. Для $m = 10$ он равен 60: последняя цифра чисел Фибоначчи повторяется каждые 60 шагов.

**Уровень 4 — матричное возведение в степень, $O(\log n)$.** Один шаг Фибоначчи — это умножение на матрицу:

$$\begin{pmatrix} F_{n+1} \\ F_n \end{pmatrix} = \begin{pmatrix} 1 & 1 \\ 1 & 0 \end{pmatrix} \begin{pmatrix} F_n \\ F_{n-1} \end{pmatrix}$$

Значит $n$ шагов — это $n$-я степень матрицы, а степень берётся [быстрым возведением](../../Алгоритмы/Стратегии/Разделяй%20и%20властвуй.md#примеры) за $O(\log n)$:

```python
def умножить(A, B):
    return [[A[0][0]*B[0][0] + A[0][1]*B[1][0], A[0][0]*B[0][1] + A[0][1]*B[1][1]],
            [A[1][0]*B[0][0] + A[1][1]*B[1][0], A[1][0]*B[0][1] + A[1][1]*B[1][1]]]

def fib_быстро(n):
    результат = [[1, 0], [0, 1]]                 # единичная матрица
    основание = [[1, 1], [1, 0]]
    while n:                                     # то же дели-пополам, что для чисел
        if n & 1:
            результат = умножить(результат, основание)
        основание = умножить(основание, основание)
        n >>= 1
    return результат[0][1]                       # → F(n)

fib_быстро(100)                                  # → 354224848179261915075
```

**Тупиковая ветвь — формула Бине.** Соблазнительно взять замкнутую формулу и посчитать «за $O(1)$»:

$$F_n = \frac{\varphi^n - \psi^n}{\sqrt5}, \qquad \varphi = \frac{1+\sqrt5}{2}, \quad \psi = \frac{1-\sqrt5}{2}$$

Так как $|\psi| < 1$, второе слагаемое быстро исчезает, и достаточно округлить $\varphi^n/\sqrt5$. Ловушка в том, что считается это во float:

```python
def binet(n):
    return round(((1 + 5 ** 0.5) / 2) ** n / 5 ** 0.5)

binet(70)     # → 190392490709135   верно
binet(71)     # → 308061521170130   ошибка: точное значение ...129
```

Замер: совпадает с точным $F_n$ **до $n = 70$ включительно** и ломается на 71 — мантиссы `double` (53 бита) перестаёт хватать. Плюс возведение в степень само по себе не константа. Как ответ на собесе формула годится только с этой оговоркой; считать ею — нет.

**Полезные тождества** (закрывают задачи «сумма первых n» без цикла):

- $F_1 + F_2 + \dots + F_n = F_{n+2} - 1$
- $F_1^2 + F_2^2 + \dots + F_n^2 = F_n \cdot F_{n+1}$

**Где эта лестница пригодится на собеседовании — #70 Climbing Stairs.** Подняться на ступеньку `n` шагами по одной или по две можно ровно столькими способами, сколькими можно подняться на `n−1` (и шагнуть один раз), плюс на `n−2` (и шагнуть дважды). Это та же рекуррента, но **со сдвигом на единицу**:

$$\text{climb}(n) = F(n+1)$$

```python
def climb(n):
    a, b = 1, 1
    for _ in range(n):
        a, b = b, a + b
    return a

[climb(i) for i in range(1, 9)]   # → [1, 2, 3, 5, 8, 13, 21, 34]
```

Сдвиг проверен запуском для `n = 1..20`. Практический вывод: увидев «сколькими способами дойти», не выводи формулу заново — узнай Фибоначчи и сразу бери с этой лестницы нужный уровень. Заодно это ответ на вопрос «а какое ДП тут», который любят задавать следом ([Динамическое программирование](../../Алгоритмы/Стратегии/Динамическое%20программирование.md)).

> 🔴 **Урок лестницы, а не Фибоначчи.** Один и тот же ответ считается за $O(2^n)$, $O(n)$ и $O(\log n)$ — разница только в том, что заметили: сперва повторы подзадач, потом периодичность остатков, потом что шаг выражается умножением. Это и есть привычка, которую проверяет автопроверка эффективности: увидел лимит $n \le 10^{18}$ — линейное решение уже отброшено условием, ищи логарифм.

### Итерация vs рекурсия

| |Итерация|[Рекурсия](../../Алгоритмы/Стратегии/Рекурсия.md)|
|---|---|---|
|Скорость|Быстрее|Медленнее (издержки вызовов)|
|Память|$O(1)$|$O(n)$ — растёт стек вызовов|
|Читаемость|Громоздче для самоподобных задач|Чище для деревьев/фракталов|

Любой рекурсивный алгоритм можно переписать итеративно (иногда — с явным [стеком](../../Данные/АТД/Стек.md)). На контесте это важно: итеративный код быстрее и **не переполняет стек** на больших входах.

---

### Когда применять

- Линейный проход, накопление (сумма, максимум, счётчик).
- Известно число шагов или простое условие остановки.
- Нужна $O(1)$ память и максимальная скорость.
- Переписать глубокую рекурсию, упирающуюся в лимит стека ([setrecursionlimit](../../Библиотеки/Модули/Система%20и%20окружение/sys.md#предел-рекурсии)).
