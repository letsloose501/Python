# Динамическое программирование

**Динамическое программирование** (ДП, dynamic programming) — стратегия для задач с **перекрывающимися подзадачами**: разбить задачу на подзадачи, решить каждую **один раз**, сохранить результат и переиспользовать. Работает при двух условиях:

1. **Оптимальная подструктура** — оптимум задачи собирается из оптимумов подзадач.
2. **Перекрывающиеся подзадачи** — одни и те же подзадачи встречаются многократно.

> **Аналогия:** решаешь пример и записываешь ответ на полях. Встретив тот же пример снова — не пересчитываешь, а берёшь готовое.

Отличие от [«разделяй и властвуй»](../../Алгоритмы/Стратегии/Разделяй%20и%20властвуй.md): там подзадачи не пересекаются, здесь — пересекаются, и в этом вся выгода.

---

### Два стиля

#### Мемоизация (сверху вниз)

Пишешь обычную [рекурсию](../../Алгоритмы/Стратегии/Рекурсия.md) и кэшируешь результаты. Проще всего — декоратор [`functools.lru_cache`](../../Библиотеки/Модули/Функциональные%20инструменты/functools.md):

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fib(40)   # мгновенно: 40 вычислений вместо ~330 млн
```

> ⚠️ **У мемоизации есть жёсткий потолок — глубина рекурсии.** `fib(1000)` этим кодом падает с `RecursionError`: кэш убирает *повторные* вызовы, но цепочка из 1000 вложенных остаётся. Хуже того, `@lru_cache` реализован на C, и с Python 3.12 его глубина ограничена отдельно — `sys.setrecursionlimit` её не поднимает (замер: 999 против 49 998 у ручного словаря). Как писать кэш руками и что делать с глубиной — [Мемоизация](../../Алгоритмы/Приёмы/Мемоизация.md).

#### Табуляция (снизу вверх)

Сначала базовые случаи, затем строишь на них — без рекурсии, только массив состояний:

```python
def fib(n):
    dp = [0, 1]
    for i in range(2, n + 1):
        dp.append(dp[i - 1] + dp[i - 2])
    return dp[n]
```

| |Мемоизация|Табуляция|
|---|---|---|
|Направление|Сверху вниз (рекурсия)|Снизу вверх (цикл)|
|Считает|Только нужные состояния|Все состояния|
|Стек|Расходует (рекурсия)|Не расходует|
|Потолок по $n$|~1000 (глубина стека)|нет|
|Свернуть память до $O(1)$|нельзя|можно, см. ниже|

> **Как выбирать.** Мемоизация — когда переход придумывается легче, чем порядок заполнения (состояние многомерное, часть состояний недостижима). Табуляция — когда $n$ большое, память надо экономить или решение должно быть предсказуемым по стеку. На собесе нормальный ход — начать с мемоизации, а потом переписать её снизу вверх вслух: это ровно тот навык, который проверяют.

### Пример посложнее — размен монет

Минимум монет на сумму `amount`:

```python
def coin_change(coins, amount):
    dp = [0] + [float("inf")] * amount     # dp[s] = мин. монет на сумму s
    for s in range(1, amount + 1):
        for c in coins:
            if c <= s:
                dp[s] = min(dp[s], dp[s - c] + 1)
    return dp[amount] if dp[amount] != float("inf") else -1

coin_change([1, 3, 4], 6)   # → 2  (3 + 3)
```

Типичные ДП-задачи: лестница, грабитель (House Robber), наибольшая возрастающая подпоследовательность, редакционное расстояние, рюкзак. Готовые каркасы — в [Шпаргалка — шаблоны алгоритмов](../../Алгоритмы/Шпаргалка%20—%20шаблоны%20алгоритмов.md).

### Как подступиться к ДП-задаче

Порядок шагов всегда один и тот же — по нему решается любая задача, даже незнакомая:

1. **Состояние** — что достаточно знать, чтобы продолжить (индекс, остаток суммы, позиция в двух строках). Состояние — это то, что стоит в индексах `dp`.
2. **База** — тривиальные состояния, где ответ виден без вычислений.
3. **Переход** — как состояние выражается через меньшие. Это и есть рекуррентное соотношение.
4. **Порядок** — в какой последовательности заполнять таблицу, чтобы нужное уже было посчитано (для мемоизации порядок берёт на себя рекурсия).
5. **Оценка** — сложность = *число состояний × стоимость одного перехода*. Считать до того, как писать: $10^5 \times 10^5$ состояний не пройдёт.
6. **Восстановление и память** — нужен сам ответ, а не только его величина? Нужно ли хранить всю таблицу? См. раздел ниже.

> **Главный вопрос — пункт 1.** Почти все провалы в ДП это неверно выбранное состояние: либо в нём не хватает информации для перехода, либо в нём лишнее, и таблица не влезает в память.

### Каноничные задачи

Три задачи, через которые ДП спрашивают чаще всего. Стоит уметь написать каждую с нуля.

> **Не всякое ДП выглядит как таблица.** Два самых частых «незаметных» ДП разобраны отдельно, потому что состояние там сворачивается почти до нуля: [максимальный подмассив](../../Алгоритмы/Приёмы/Алгоритм%20Кадане.md) (#53) живёт на двух переменных, а [Counting Bits](../../Алгоритмы/Приёмы/Битовые%20приёмы.md#338-counting-bits--дп-по-битам) (#338) считает состояние не по индексу массива, а **по самому числу**: `dp[i] = dp[i >> 1] + (i & 1)`. Если задача решается за один проход с накоплением — это, скорее всего, тоже ДП, просто со свёрнутым состоянием.

#### Рюкзак 0-1

Дано $n$ предметов с весами и стоимостями, вместимость $W$. Каждый предмет можно взять **один раз или не брать**. Максимизировать стоимость.

**Состояние:** `dp[i][w]` — максимальная стоимость из первых `i` предметов при вместимости `w`. **Переход:** предмет либо не берём, либо берём (если влезает).

```python
def рюкзак(веса, стоимости, W):
    n = len(веса)
    dp = [[0] * (W + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for w in range(W + 1):
            dp[i][w] = dp[i - 1][w]                          # 1. не берём предмет
            if веса[i - 1] <= w:                             # 2. берём, если влезает
                dp[i][w] = max(dp[i][w],
                               dp[i - 1][w - веса[i - 1]] + стоимости[i - 1])
    return dp[n][W]

рюкзак([1, 3, 4], [15, 20, 30], 4)      # → 35   веса 1+3, стоимости 15+20
```

Та же задача на одной строке вместо таблицы — и здесь **направление внутреннего цикла решает всё**:

```python
def рюкзак_1d(веса, стоимости, W):
    dp = [0] * (W + 1)
    for вес, цена in zip(веса, стоимости):
        for w in range(W, вес - 1, -1):       # ← НАЗАД: предмет берётся один раз
            dp[w] = max(dp[w], dp[w - вес] + цена)
    return dp[W]
```

> 🔴 **Разница между 0-1 и неограниченным рюкзаком — это одна стрелка цикла.** Идём по `w` **назад** — `dp[w - вес]` ещё не тронут на этой итерации, значит предмет учтён один раз (0-1). Идём **вперёд** — `dp[w - вес]` уже мог включить этот же предмет, и он берётся сколько угодно раз (неограниченный рюкзак = размен монет выше). Это самый частый вопрос по рюкзаку на секции.

#### Расстояние редактирования (Левенштейна)

Минимальное число операций **вставить / удалить / заменить**, чтобы превратить одну строку в другую. Используется в поиске опечаток, `diff`, автодополнении.

**Состояние:** `dp[i][j]` — расстояние между префиксами `a[:i]` и `b[:j]`. **Три перехода** — по одному на каждую операцию:

```python
def расстояние_редактирования(a, b):
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n + 1):
        dp[i][0] = i                              # база: удалить весь префикс a
    for j in range(m + 1):
        dp[0][j] = j                              # база: вставить весь префикс b

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]       # символы совпали — бесплатно
            else:
                dp[i][j] = 1 + min(
                    dp[i - 1][j],                 # удалить a[i-1]
                    dp[i][j - 1],                 # вставить b[j-1]
                    dp[i - 1][j - 1],             # заменить a[i-1] на b[j-1]
                )
    return dp[n][m]

расстояние_редактирования("котёнок", "коток")     # → 2   удалить «ё» и «н»
```

**Как читать три перехода.** Шаг «вверх» по таблице — удаление из первой строки, «влево» — вставка, «по диагонали» — замена. Совпали символы — идём по диагонали бесплатно, и в этом весь алгоритм.

#### Наибольшая общая подпоследовательность (LCS)

Самая длинная последовательность символов, идущих в обеих строках **в одном порядке**, но не обязательно подряд. Отличие от подстроки принципиально: подстрока — непрерывна, подпоследовательность — нет.

```python
def lcs(a, b):
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1               # символ идёт в ответ
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])    # выкидываем один символ
    return dp[n][m]

lcs("ABCBDAB", "BDCABA")        # → 4   подпоследовательность BCBA
```

**LCS для трёх последовательностей** — то же самое, но состояние трёхмерное: `dp[i][j][k]`, символ идёт в ответ только если совпал во всех трёх (`dp[i-1][j-1][k-1] + 1`), иначе берётся максимум из трёх вариантов «выкинуть символ». Цена — $O(nmk)$ по времени и памяти; на этом обычно и ломается наивное обобщение на много строк.

Сложность у первых трёх — $O(nm)$ по времени и памяти: число состояний $n \times m$, переход константный. Память сводится к $O(\min(n, m))$ приёмом из раздела ниже.

#### Разбиение на равные части (subset sum)

Прямой родственник рюкзака: можно ли разложить числа на несколько частей с равными суммами. Ключевой ход — **сначала проверить делимость общей суммы**, и только потом считать ДП.

```python
def на_две_равные(числа):
    всего = sum(числа)
    if всего % 2:                              # нечётная сумма — сразу нет
        return False

    цель = всего // 2
    достижимо = {0}                            # какие суммы можно набрать
    for x in числа:
        достижимо |= {s + x for s in достижимо if s + x <= цель}
    return цель in достижимо

на_две_равные([1, 5, 11, 5])                   # → True    11 = 1+5+5
на_две_равные([1, 2, 3, 5])                    # → False
```

Это рюкзак, где «стоимость» равна весу, а вопрос не «максимум», а «достижимо ли ровно `цель`». На три равные части состояние становится двумерным — `dp[s1][s2]`, третья сумма получается автоматически, — и цена растёт до $O(n \cdot V^2)$, где $V$ — треть суммы.

#### Интервальное ДП (ДП на отрезках)

Отдельный класс: состояние — **отрезок** `dp[l][r]`, а переход перебирает **точку деления** внутри него. Так решают «расставить скобки», перемножение цепочки матриц, разрезание палки, разбиение строки на палиндромы.

```python
# максимальное значение выражения при любой расстановке скобок
def расставить_скобки(числа, знаки):
    n = len(числа)
    мин = [[0] * n for _ in range(n)]
    макс = [[0] * n for _ in range(n)]
    for i in range(n):
        мин[i][i] = макс[i][i] = числа[i]      # 1. база: отрезок из одного числа

    for длина in range(1, n):                  # 2. от коротких отрезков к длинным
        for l in range(n - длина):
            r = l + длина
            мин[l][r], макс[l][r] = float("inf"), float("-inf")
            for m in range(l, r):              # 3. перебор ПОСЛЕДНЕЙ операции
                for a in (мин[l][m], макс[l][m]):
                    for b in (мин[m + 1][r], макс[m + 1][r]):
                        v = применить(знаки[m], a, b)
                        мин[l][r] = min(мин[l][r], v)
                        макс[l][r] = max(макс[l][r], v)

    return макс[0][n - 1]
```

**Два нетривиальных места.** Первое: **порядок обхода идёт по длине отрезка**, а не по `l` и `r` — иначе на момент подсчёта `dp[l][r]` его половинки ещё не готовы. Второе: **хранить приходится и минимум, и максимум**. Причина — вычитание и умножение: максимум большого выражения может получиться из двух минимумов (`минус на минус`), поэтому одной таблицы не хватает.

Сложность — $O(n^3)$: $O(n^2)$ отрезков × $O(n)$ точек деления. Память $O(n^2)$.

> **Признак интервального ДП в условии:** «расставить скобки», «склеить/разрезать в каком-то порядке», «оптимально объединить соседние элементы» — то есть ответ зависит от **порядка объединения**, а не от выбора «брать или не брать».

### Восстановление ответа и экономия памяти

Два шага, которые в задачах требуют отдельно от самого ДП.

**Восстановить сам ответ** — пройти по таблице назад из финального состояния, повторяя те решения, которые дали значение:

```python
# продолжение lcs(): собрать саму подпоследовательность
i, j, ответ = n, m, []
while i > 0 and j > 0:
    if a[i - 1] == b[j - 1]:
        ответ.append(a[i - 1])                     # символ был взят
        i, j = i - 1, j - 1
    elif dp[i - 1][j] >= dp[i][j - 1]:
        i -= 1                                     # шли сверху
    else:
        j -= 1                                     # шли слева
"".join(reversed(ответ))                           # → 'BCBA'
```

**Сэкономить память** — если переход смотрит только на предыдущую строку, всю таблицу хранить не нужно: $O(nm) \to O(m)$.

```python
пред = list(range(m + 1))
for i in range(1, n + 1):
    тек = [i] + [0] * m
    for j in range(1, m + 1):
        тек[j] = пред[j - 1] if a[i - 1] == b[j - 1] else 1 + min(пред[j], тек[j - 1], пред[j - 1])
    пред = тек
пред[m]                                            # расстояние редактирования на двух строках
```

**Правило, по которому это делается механически:** посмотри, на сколько шагов назад смотрит переход — столько состояний и храни, остальное выбрасывай. Отсюда вся лестница экономии:

| Переход смотрит на | Хранить | Память |
|---|---|---|
| `dp[i-1]`, `dp[i-2]` | две переменные | $O(1)$ |
| всю предыдущую строку | одну-две строки | $O(m)$ |
| произвольные `dp[j]`, $j < i$ | всю таблицу | $O(n)$ или $O(nm)$ |

Последняя ступень для линейных ДП — свернуть массив до пары переменных. Табуляция Фибоначчи выше хранит `dp` целиком, хотя нужны только два последних значения:

```python
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b        # инвариант: a = F(i), b = F(i+1)
    return a
```

Так же сворачиваются лестница (#70), грабитель (#198) и [Кадане](../../Алгоритмы/Приёмы/Алгоритм%20Кадане.md) (#53): везде переход смотрит на один-два шага назад. Задача, решаемая за $O(2^n)$, доходит до $O(n)$ по времени и $O(1)$ по памяти — и это самый частый follow-up после «а можно ли лучше?».

> ⚠️ Тонкость свёртки: `a, b = b, a + b` работает потому, что **правая часть вычисляется целиком до присваивания**. Записав в две строки (`a = b`, следом `b = a + b`), во второй строке возьмёшь уже новое `a` и получишь неверный ответ — типичная ошибка при переписывании из псевдокода.

> ⚠️ **Экономия памяти и восстановление ответа несовместимы напрямую:** выбросив таблицу, ты теряешь и путь. Нужны оба — либо храни таблицу, либо применяй алгоритм Хиршберга (восстановление через «разделяй и властвуй» за $O(m)$ памяти). На контесте почти всегда проще оставить таблицу.

---

### Когда применять

- В задаче видны **выбор на каждом шаге** и **перекрывающиеся** подзадачи.
- Наивная рекурсия экспоненциальна из-за повторов (как `fib`).
- Оптимизация («максимум/минимум/сколько способов») с зависимостью от предыдущих решений.

- [Алгоритм Кадане](../../Алгоритмы/Приёмы/Алгоритм%20Кадане.md) — #53 и #121: ДП, свёрнутое до двух переменных, и история улучшений $O(n^3) \to O(n)$;
- [Битовые приёмы](../../Алгоритмы/Приёмы/Битовые%20приёмы.md) — #338: состояние индексируется числом, а переход берёт биты;
