# HyperLogLog

**HyperLogLog** (HLL) — вероятностный алгоритм для приближённого подсчёта количества **уникальных элементов** в потоке данных. Использует фиксированный объём памяти независимо от размера потока.

> **Аналогия:** оцениваешь сколько людей посетило концерт не пересчитывая всех, а глядя на толпу с балкона. Точность ±2%, но это занимает секунды, а не часы переклички.

Ответ всегда приближённый с погрешностью ~1–2%. Это компромисс: точный подсчёт требует $O(n)$ памяти, HLL — константную.

---

### Проблема которую решает HyperLogLog

```
задача: сколько уникальных пользователей посетило сайт за день?

наивно — хранить всех:
  set() → добавлять каждый user_id
  1 000 000 пользователей × 8 байт = 8 МБ   — ещё терпимо
  1 000 000 000 пользователей       = 8 ГБ   — уже проблема
  несколько серверов, несколько дней — не масштабируется

HyperLogLog:
  любое количество пользователей → ~1.5 КБ памяти
  погрешность ~1–2%
```

---

### Ключевая идея — вероятность ведущих нулей

Хешируем каждый элемент → получаем случайную битовую строку. Вероятность того что строка начинается с $k$ нулей = $\frac{1}{2^k}$.

Если в потоке видели строку с 10 нулями — значит, скорее всего, видели $\approx 2^{10} = 1024$ уникальных элементов.

```
видим максимальный префикс из нулей = 10
оцениваем количество уникальных ≈ 2^10 = 1024
```

Один регистр — очень грубая оценка. HLL использует $m$ регистров и усредняет — это резко снижает дисперсию.

---

### Как работает

1. Разделить $m = 2^b$ «вёдер» (регистров)
2. Для каждого элемента: хешировать → первые $b$ бит = номер ведра → остальные биты = считать ведущие нули + 1
3. Каждый регистр хранит **максимум** наблюдавшихся позиций первого единичного бита
4. Финальная оценка = гармоническое среднее по всем регистрам × корректирующая константа

```
b=4 → m=16 вёдер (регистров)

элемент "user_123":
  hash = 10110010...
  первые 4 бита = 1011 → ведро #11
  остальные биты = 0010... → ведущих нулей = 2, позиция первой 1 = 3
  регистр[11] = max(регистр[11], 3)

элемент "user_456":
  hash = 10110001...
  первые 4 бита = 1011 → ведро #11
  остальные биты = 0001... → позиция первой 1 = 4
  регистр[11] = max(4, 3) = 4

...обрабатываем все элементы...

оценка = α_m × m² × (Σ 2^(-регистр[i]))^(-1)
```

### Реализации

#### Базовая реализация

```python
import hashlib
import math

class HyperLogLog:
    def __init__(self, точность=0.01):
        """
        точность — относительная стандартная ошибка (0.01 = 1%)
        """
        # количество вёдер m = 2^b
        b = max(4, math.ceil(math.log2(1.04 / точность) ** 2))
        self.m = 2 ** b
        self.b = b
        self._регистры = [0] * self.m
        self._добавлено = 0

        # корректирующая константа α_m
        if self.m == 16:
            self._альфа = 0.673
        elif self.m == 32:
            self._альфа = 0.697
        elif self.m == 64:
            self._альфа = 0.709
        else:
            self._альфа = 0.7213 / (1 + 1.079 / self.m)

    def _хеш(self, элемент):
        данные = str(элемент).encode()
        return int(hashlib.sha256(данные).hexdigest(), 16)

    def _ведущие_нули(self, биты, макс_бит):
        """Позиция первого единичного бита (1-indexed)."""
        for i in range(макс_бит, 0, -1):
            if биты & (1 << (i - 1)):
                return макс_бит - i + 1
        return макс_бит

    def добавить(self, элемент):
        хеш = self._хеш(элемент)
        # первые b бит = номер ведра
        ведро = хеш >> (256 - self.b)
        # оставшиеся биты
        остаток = хеш & ((1 << (256 - self.b)) - 1)
        # позиция первого единичного бита
        позиция = self._ведущие_нули(остаток, 256 - self.b) + 1
        self._регистры[ведро] = max(self._регистры[ведро], позиция)
        self._добавлено += 1

    def подсчитать(self):
        """Оценка количества уникальных элементов."""
        # гармоническое среднее
        z = sum(2 ** (-r) for r in self._регистры)
        оценка = self._альфа * self.m ** 2 / z

        # коррекция для малых значений (LinearCounting)
        if оценка <= 2.5 * self.m:
            нулевых = self._регистры.count(0)
            if нулевых > 0:
                оценка = self.m * math.log(self.m / нулевых)

        # коррекция для больших значений
        elif оценка > (1/30) * 2**32:
            оценка = -2**32 * math.log(1 - оценка / 2**32)

        return int(оценка)

    def слить(self, другой):
        """Объединить два HLL — поэлементный максимум регистров."""
        if self.m != другой.m:
            raise ValueError("разный размер регистров")
        результат = HyperLogLog.__new__(HyperLogLog)
        результат.m = self.m
        результат.b = self.b
        результат._альфа = self._альфа
        результат._добавлено = self._добавлено + другой._добавлено
        результат._регистры = [
            max(a, b) for a, b in zip(self._регистры, другой._регистры)
        ]
        return результат

    def __repr__(self):
        return (f"HyperLogLog(m={self.m}, "
                f"оценка={self.подсчитать()}, "
                f"добавлено={self._добавлено})")


# пример:
hll = HyperLogLog(точность=0.02)   # 2% погрешность

# добавляем 10 000 уникальных пользователей + 5 000 повторных
for i in range(10_000):
    hll.добавить(f"user_{i}")
for i in range(5_000):
    hll.добавить(f"user_{i}")   # повторные — не считаются

print(f"реальное:      10000")
print(f"HLL оценка:    {hll.подсчитать()}")
print(f"погрешность:   {abs(hll.подсчитать() - 10000) / 10000:.1%}")
```

#### Слияние нескольких HLL — распределённый подсчёт

Ключевое преимущество HLL: можно посчитать уникальных на нескольких серверах, а потом слить за $O(m)$.

```python
# сервер 1: дневные пользователи
hll_день1 = HyperLogLog(точность=0.01)
for u in ["user_1", "user_2", "user_3", "user_4"]:
    hll_день1.добавить(u)

# сервер 2: ночные пользователи (с пересечением)
hll_день2 = HyperLogLog(точность=0.01)
for u in ["user_3", "user_4", "user_5", "user_6"]:
    hll_день2.добавить(u)

# слить — уникальных за весь день:
hll_итог = hll_день1.слить(hll_день2)
print(f"уникальных за день: {hll_итог.подсчитать()}")
# → ~6 (user_1 .. user_6)
```

#### Сравнение с точным подсчётом

```python
import random
import sys

def сравнить(n_уникальных, n_повторных):
    элементы = [f"user_{i}" for i in range(n_уникальных)]
    поток = элементы + random.choices(элементы, k=n_повторных)
    random.shuffle(поток)

    # точный подсчёт
    точный = set()
    for x in поток:
        точный.add(x)

    # HyperLogLog
    hll = HyperLogLog(точность=0.01)
    for x in поток:
        hll.добавить(x)

    память_set = sys.getsizeof(точный)
    память_hll = sys.getsizeof(hll._регистры)

    print(f"реальных уникальных: {len(точный)}")
    print(f"HLL оценка:          {hll.подсчитать()}")
    print(f"погрешность:         {abs(hll.подсчитать() - len(точный))/len(точный):.2%}")
    print(f"память set:          {память_set // 1024} КБ")
    print(f"память HLL:          {память_hll} байт")

сравнить(n_уникальных=100_000, n_повторных=500_000)
# реальных уникальных: 100000
# HLL оценка:          ~100800
# погрешность:         ~0.8%
# память set:          ~4096 КБ
# память HLL:          ~2048 байт  (в 2000 раз компактнее!)
```

### Big O

|Операция|Сложность|
|---|---|
|Добавление элемента|$O(1)$|
|Получение оценки|$O(m)$|
|Слияние двух HLL|$O(m)$|
|Память|$O(m)$ — фиксированная, не зависит от $n$|

$m$ — количество регистров (обычно 64–2048). Для точности 1%: $m \approx 1024$, память $\approx 1$ КБ.

---

### Плюсы и минусы

**Плюсы:**

- Фиксированная память независимо от $n$ — можно считать миллиарды элементов за ~1 КБ
- $O(1)$ на добавление
- Легко сливать — распределённый подсчёт без передачи всех данных
- Стандартная погрешность ~1–2% — достаточно для большинства задач

**Минусы:**

- Только приближённый результат
- Не хранит сами элементы — нельзя узнать что именно
- Нельзя удалять элементы
- При малом $n$ (< ~100) точность хуже

### Применение

- **Google Analytics / Яндекс.Метрика** — уникальные посетители за день/месяц
- **Redis** — встроенная команда `PFADD / PFCOUNT / PFMERGE`
- **Apache Spark / Flink** — approxCountDistinct
- **Базы данных** — PostgreSQL, Redshift, BigQuery имеют функции HLL
- **Сети** — подсчёт уникальных IP-адресов, уникальных запросов
