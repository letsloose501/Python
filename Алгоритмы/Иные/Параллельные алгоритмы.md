# Параллельные алгоритмы

**Параллельные алгоритмы** — алгоритмы, которые выполняют несколько вычислений **одновременно**, разбивая задачу на независимые части и распределяя их по нескольким ядрам или процессам.

> **Аналогия:** один повар чистит картошку час. Четыре повара чистят по 15 минут. Но четверо никогда не будут в четыре раза быстрее — мешают друг другу, делят одну разделочную доску.

Ускорение всегда **меньше** числа ядер — закон Амдала.

---

### Виды параллелизма в Python

|Вид|Инструмент|Когда|
|---|---|---|
|Многопоточность|`threading`|I/O-задачи (сеть, файлы)|
|Многопроцессорность|`multiprocessing`|CPU-задачи (вычисления)|
|Асинхронность|`asyncio`|Много I/O-задач одновременно|
|Пул потоков/процессов|`concurrent.futures`|Удобная абстракция над обоими|

**GIL (Global Interpreter Lock)** — в CPython только один поток выполняет Python-байткод в любой момент. Поэтому `threading` не ускоряет вычисления — только I/O. Для CPU → `multiprocessing`.

---

### Закон Амдала

Максимальное теоретическое ускорение при параллелизации:

$$S(n) = \frac{1}{(1 - p) + \frac{p}{n}}$$

- $p$ — доля кода которую можно распараллелить
- $n$ — число процессоров

```
p=0.9 (90% распараллеливается):
  2 ядра:    S = 1/(0.1 + 0.9/2)  = 1.82x
  4 ядра:    S = 1/(0.1 + 0.9/4)  = 3.08x
  8 ядер:    S = 1/(0.1 + 0.9/8)  = 4.71x
  ∞ ядер:    S = 1/0.1            = 10x  ← потолок!

10% последовательного кода → максимальное ускорение в 10 раз, сколько бы ядер ни добавить
```

### Реализации

#### Многопоточность — для I/O

```python
import threading
import time
import urllib.request

def скачать(url, результаты, индекс):
    try:
        with urllib.request.urlopen(url, timeout=5) as r:
            результаты[индекс] = len(r.read())
    except Exception as e:
        результаты[индекс] = 0

urls = [
    "https://example.com",
    "https://httpbin.org/get",
    "https://httpbin.org/delay/1",
]

# последовательно:
начало = time.time()
результаты_посл = []
for url in urls:
    try:
        with urllib.request.urlopen(url, timeout=5) as r:
            результаты_посл.append(len(r.read()))
    except:
        результаты_посл.append(0)
print(f"последовательно: {time.time() - начало:.2f}с")

# параллельно через потоки:
начало = time.time()
результаты = [0] * len(urls)
потоки = [threading.Thread(target=скачать, args=(url, результаты, i))
          for i, url in enumerate(urls)]
for п in потоки:
    п.start()
for п in потоки:
    п.join()   # ждём завершения всех
print(f"параллельно:     {time.time() - начало:.2f}с")
```

#### ThreadPoolExecutor — удобный пул потоков

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def обработать_запрос(id):
    time.sleep(0.1)   # имитация I/O
    return f"результат_{id}"

# пул из 4 потоков:
with ThreadPoolExecutor(max_workers=4) as executor:
    # submit — запустить задачу, получить Future
    futures = {executor.submit(обработать_запрос, i): i for i in range(10)}

    for future in as_completed(futures):
        id = futures[future]
        результат = future.result()
        print(f"задача {id}: {результат}")

# map — как обычный map, но параллельно:
with ThreadPoolExecutor(max_workers=4) as executor:
    результаты = list(executor.map(обработать_запрос, range(10)))
```

#### Multiprocessing — для CPU-задач

```python
import multiprocessing
import time

def вычислить(n):
    """CPU-интенсивная задача."""
    return sum(i * i for i in range(n))

числа = [10_000_000] * 8

# последовательно:
начало = time.time()
результаты_посл = [вычислить(n) for n in числа]
print(f"последовательно: {time.time() - начало:.2f}с")

# параллельно (по числу ядер):
начало = time.time()
with multiprocessing.Pool(processes=multiprocessing.cpu_count()) as pool:
    результаты_пар = pool.map(вычислить, числа)
print(f"параллельно:     {time.time() - начало:.2f}с")
```

#### ProcessPoolExecutor — удобная обёртка

```python
from concurrent.futures import ProcessPoolExecutor

def факториал(n):
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

числа = [50_000, 60_000, 70_000, 80_000]

with ProcessPoolExecutor() as executor:
    результаты = list(executor.map(факториал, числа))
    print([len(str(r)) for r in результаты])   # количество цифр
```

#### Параллельная сортировка слиянием

Классический пример: левую и правую половины сортируем в отдельных процессах.

```python
import multiprocessing

def параллельная_сортировка(arr, глубина=0, max_глубина=2):
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    левая = arr[:mid]
    правая = arr[mid:]

    if глубина < max_глубина:
        # параллельно:
        with multiprocessing.Pool(2) as pool:
            будущее_л = pool.apply_async(параллельная_сортировка,
                                          (левая, глубина + 1, max_глубина))
            будущее_п = pool.apply_async(параллельная_сортировка,
                                          (правая, глубина + 1, max_глубина))
            левая = будущее_л.get()
            правая = будущее_п.get()
    else:
        # последовательно:
        левая = sorted(левая)
        правая = sorted(правая)

    # слияние:
    результат = []
    i = j = 0
    while i < len(левая) and j < len(правая):
        if левая[i] <= правая[j]:
            результат.append(левая[i]); i += 1
        else:
            результат.append(правая[j]); j += 1
    результат.extend(левая[i:])
    результат.extend(правая[j:])
    return результат
```

#### asyncio — много I/O-задач одновременно

Один поток, но эффективно переключается между задачами пока ждут I/O.

```python
import asyncio
import aiohttp   # pip install aiohttp

async def скачать(session, url):
    async with session.get(url) as response:
        данные = await response.read()
        return url, len(данные)

async def скачать_все(urls):
    async with aiohttp.ClientSession() as session:
        задачи = [скачать(session, url) for url in urls]
        результаты = await asyncio.gather(*задачи)
    return результаты

urls = ["https://example.com"] * 10
# asyncio.run(скачать_все(urls))
```

#### Разделяемая память между процессами

```python
import multiprocessing

def прибавить(счётчик, lock, n):
    for _ in range(n):
        with lock:             # блокировка для атомарного доступа
            счётчик.value += 1

счётчик = multiprocessing.Value("i", 0)   # shared int
lock = multiprocessing.Lock()

процессы = [
    multiprocessing.Process(target=прибавить, args=(счётчик, lock, 1000))
    for _ in range(4)
]
for п in процессы:
    п.start()
for п in процессы:
    п.join()

print(счётчик.value)   # → 4000  (без lock было бы меньше из-за гонок)
```

### Big O с параллелизмом

Если задача делится на $n$ равных частей и выполняется на $n$ ядрах:

|Алгоритм|Последовательно|Параллельно|
|---|---|---|
|Сортировка слиянием|$O(n \log n)$|$O(n)$ при $\log n$ ядрах|
|Поиск в массиве|$O(n)$|$O(n/p)$ при $p$ ядрах|
|Перемножение матриц|$O(n^3)$|$O(n^3/p)$ при $p$ ядрах|
|PageRank итерация|$O(V + E)$|$O((V+E)/p)$ при $p$ ядрах|

На практике из-за накладных расходов (создание процессов, синхронизация, передача данных) реальное ускорение всегда меньше теоретического.

### Типичные проблемы

**Гонка данных** (race condition) — два процесса читают и пишут одну переменную без синхронизации → непредсказуемый результат.

```python
# ПЛОХО — гонка:
счётчик = 0
def увеличить():
    global счётчик
    for _ in range(100_000):
        счётчик += 1   # не атомарная операция!

# ХОРОШО — с блокировкой:
lock = threading.Lock()
def увеличить_безопасно():
    global счётчик
    for _ in range(100_000):
        with lock:
            счётчик += 1
```

**Дедлок** — два потока ждут друг друга.

```python
# ОПАСНО — дедлок если порядок захвата замков разный:
# поток 1: захватывает lock_a → ждёт lock_b
# поток 2: захватывает lock_b → ждёт lock_a → зависание
```

### Плюсы и минусы

**Плюсы:**

- Ускорение CPU-задач пропорционально числу ядер (с оговорками)
- I/O-задачи выполняются одновременно, не блокируя друг друга
- Масштабирование на несколько машин (MapReduce)

**Минусы:**

- GIL в Python ограничивает потоки для CPU
- Накладные расходы: создание процессов, сериализация данных
- Трудная отладка: гонки, дедлоки
- Закон Амдала — потолок ускорения определяется последовательной частью

---

### Применение

- **Веб-серверы** — каждый запрос в отдельном потоке/процессе (gunicorn, uvicorn)
- **Парсинг данных** — скачивать сотни страниц параллельно
- **Машинное обучение** — обучение на нескольких GPU (PyTorch DataParallel)
- **Обработка изображений** — каждое изображение независимо
- **Финансовые расчёты** — портфельный анализ по тысячам активов
- **MapReduce / Spark** — распределённая обработка терабайт данных

> Распределённые вычисления (MapReduce, CAP, консенсус) — Распределённые вычисления. Нотация — Вычислительная сложность.
