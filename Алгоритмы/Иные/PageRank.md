# PageRank

**PageRank** — алгоритм оценки **важности узлов в графе** по качеству и количеству входящих связей. Важность передаётся рекурсивно: ссылка с важной страницы весит больше.

> **Аналогия:** рекомендации учёных. Если известный профессор ссылается на твою работу — это весит больше, чем ссылка от студента. PageRank формализует эту интуицию: важность страницы = взвешенная сумма важностей тех, кто на неё ссылается.

Алгоритм итеративный — запускается много раз пока значения не сойдутся. Придуман Ларри Пейджем и Сергеем Брином для ранжирования результатов поиска Google.

---

### Веб как цепь Маркова

Под формулой лежит простая модель: **случайный блуждатель**. Представь пользователя, который открыл случайную страницу и дальше бесконечно кликает по случайным ссылкам. Со временем доля времени, которую он проводит на каждой странице, стабилизируется — и **эта доля и есть PageRank**.

Формально это цепь Маркова:

| Понятие цепи | Что это в вебе |
|---|---|
| Состояние | веб-страница |
| Переход | клик по ссылке |
| Вероятность перехода | $1/\text{число исходящих ссылок}$ |
| **Стационарное распределение** | **вектор рангов** |

Отсюда видно, зачем нужны итерации: считая $PR$ раз за разом, мы просто прогоняем цепь вперёд, пока распределение не перестанет меняться ($\pi P = \pi$).

> Тот же приём работает на **любом** графе, а не только на ссылках: цитирование статей, переводы между кошельками, подписки в соцсети. Достаточно, чтобы «важность» имело смысл передавать по рёбрам.

---

### Математическая основа

$$PR(v) = \frac{1 - d}{N} + d \sum_{u \in In(v)} \frac{PR(u)}{Out(u)}$$

- $PR(v)$ — ранг вершины $v$
- $d$ — коэффициент затухания (обычно 0.85)
- $N$ — общее число вершин
- $In(v)$ — вершины, ссылающиеся на $v$
- $Out(u)$ — количество исходящих ссылок у $u$

**$(1-d)/N$** — вероятность «телепортации»: случайный пользователь может перейти на любую страницу напрямую. Не позволяет рангу «затекать» в тупики.

**Коэффициент затухания $d = 0.85$** означает: пользователь с вероятностью 85% переходит по ссылке, и с вероятностью 15% открывает случайную страницу.

---

### Зачем нужна телепортация

Телепортация выглядит как костыль, но это **математическое условие корректности**. Без неё у цепи может не быть единственного ответа — ломается эргодичность:

- **Тупик (dangling node)** — страница без исходящих ссылок. Блуждатель в неё проваливается и не выходит; ранг всего графа постепенно «вытекает» в тупики.
- **Ловушка-цикл (spider trap)** — группа страниц, ссылающихся только друг на друга. Попав внутрь, блуждатель никогда не выберется, и вся важность накопится там.
- **Несвязный граф** — результат зависит от того, откуда начали. Единственного правильного ответа просто нет.

Добавив всюду вероятность 15% прыгнуть на случайную страницу, мы делаем **любую** пару страниц взаимно достижимой. Цепь становится эргодичной, а значит, у неё гарантированно есть **ровно одно** стационарное распределение, и итерации сойдутся к нему из любого старта.

> Число 0.85 — не физическая константа, а компромисс: чем ближе $d$ к 1, тем точнее модель отражает реальные ссылки, но тем медленнее сходимость. Скорость сходимости определяется как раз $d$: погрешность падает примерно как $d^k$ за $k$ итераций.

---

### Как работает итерация

```
граф (→ = ссылка):
A → B
A → C
B → C
C → A

начальный ранг: все = 1/N = 0.25

итерация 1:
  PR(A) = 0.15/4 + 0.85 * (PR(C)/1)        = 0.0375 + 0.85*0.25 = 0.25
  PR(B) = 0.15/4 + 0.85 * (PR(A)/2)        = 0.0375 + 0.85*0.125 = 0.144
  PR(C) = 0.15/4 + 0.85 * (PR(A)/2 + PR(B)/1) = 0.0375 + 0.85*0.375 = 0.356

итерация 2... итерация 3... → сходится

финальные ранги (после многих итераций):
  C: 0.387  ← самый важный (получает от A и B)
  A: 0.345  ← получает от C
  B: 0.268  ← получает только от A
```

### Реализации

#### Базовая итеративная

```python
def pagerank(граф, d=0.85, эпох=100, tol=1e-6):
    """
    граф: {u: [v, ...]} — направленный граф (u → v)
    """
    вершины = list(граф.keys())
    N = len(вершины)
    ранг = {v: 1 / N for v in вершины}

    входящие = {v: [] for v in вершины}
    for u in граф:
        for v in граф[u]:
            if v in входящие:
                входящие[v].append(u)

    for _ in range(эпох):
        новый_ранг = {}
        for v in вершины:
            сумма = sum(
                ранг[u] / len(граф[u])
                for u in входящие[v]
                if граф[u]
            )
            новый_ранг[v] = (1 - d) / N + d * сумма

        если_сошлись = max(abs(новый_ранг[v] - ранг[v]) for v in вершины) < tol
        ранг = новый_ранг
        if если_сошлись:
            break

    total = sum(ранг.values())
    return {v: round(r / total, 4) for v, r in ранг.items()}


граф = {
    "A": ["B", "C"],
    "B": ["C"],
    "C": ["A"],
    "D": ["C"],
}
ранги = pagerank(граф)
# сортируем по убыванию:
for страница, ранг in sorted(ранги.items(), key=lambda x: -x[1]):
    print(f"{страница}: {ранг:.4f}")
# → C: 0.387  A: 0.345  B: 0.213  D: 0.054
```

#### Обработка «тупиковых» вершин (dangling nodes)

Вершина без исходящих ссылок «поглощает» ранг. Стандартное решение — считать что она ссылается на все вершины.

```python
def pagerank_полный(граф, d=0.85, эпох=100, tol=1e-6):
    вершины = list(граф.keys())
    N = len(вершины)
    ранг = {v: 1.0 / N for v in вершины}

    входящие = {v: [] for v in вершины}
    for u in вершины:
        for v in граф[u]:
            if v in входящие:
                входящие[v].append(u)

    тупики = [v for v in вершины if not граф[v]]

    for _ in range(эпох):
        новый_ранг = {}
        # ранг от тупиков распределяется равномерно
        утечка = sum(ранг[v] for v in тупики) / N

        for v in вершины:
            вклад = утечка
            for u in входящие[v]:
                if граф[u]:
                    вклад += ранг[u] / len(граф[u])
            новый_ранг[v] = (1 - d) / N + d * вклад

        дельта = max(abs(новый_ранг[v] - ранг[v]) for v in вершины)
        ранг = новый_ранг
        if дельта < tol:
            break

    return ранг


# граф с тупиком (E не ссылается никуда):
граф = {
    "A": ["B", "C"],
    "B": ["C"],
    "C": ["A"],
    "D": ["C"],
    "E": [],      # тупик
}
ранги = pagerank_полный(граф)
```

#### Персонализированный PageRank

Вместо равномерной «телепортации» — пользователь всегда возвращается к набору интересующих вершин. Используется для рекомендаций.

```python
def персонализированный_pagerank(граф, источники, d=0.85, эпох=100, tol=1e-6):
    """
    источники: {вершина: вероятность_телепортации}
    сумма вероятностей должна = 1
    """
    вершины = list(граф.keys())
    N = len(вершины)
    ранг = {v: 1.0 / N for v in вершины}

    входящие = {v: [] for v in вершины}
    for u in вершины:
        for v in граф[u]:
            if v in входящие:
                входящие[v].append(u)

    for _ in range(эпох):
        новый_ранг = {}
        for v in вершины:
            телепорт = (1 - d) * источники.get(v, 0)
            вклад = sum(ранг[u] / len(граф[u])
                        for u in входящие[v] if граф[u])
            новый_ранг[v] = телепорт + d * вклад

        дельта = max(abs(новый_ранг[v] - ранг[v]) for v in вершины)
        ранг = новый_ранг
        if дельта < tol:
            break

    return ранг


# рекомендации: пользователь интересуется вершиной A
граф = {"A": ["B", "C"], "B": ["C", "D"], "C": ["A"], "D": []}
источники = {"A": 1.0}   # всегда возвращается к A
ранги = персонализированный_pagerank(граф, источники)
# A и его соседи получат высокий ранг
```

### Почему накрутка ссылками не работает

Самая частая мысль при знакомстве с алгоритмом: создам 100 страниц со ссылками на себя — получу 100 голосов и первое место. Не выйдет, и причина ровно в том, что ранг считается **итеративно**.

```
итерация 1:  100 пустышек отдают свой начальный ранг (1/N каждая) → цель заметно растёт
итерация 2:  а кто отдал ранг самим пустышкам? никто — на них не ссылаются
итерация 3:  их собственный ранг просел почти до (1-d)/N …
     …       вклад пустышек стремится к минимуму, цель откатывается назад
```

Ранг **не создаётся из ничего** — он перетекает по графу. Ферма ссылок может лишь перераспределить тот мизер, который сама получает от телепортации. Ранние итерации дают всплеск, но с каждой следующей вклад страниц, на которые никто не ссылается, тает.

> Это и было отличие от поиска середины 90-х. Yahoo и конкуренты ранжировали по **частоте ключевого слова на странице** — сигналу, который автор страницы контролирует полностью (достаточно было напечатать слово 500 раз белым по белому). PageRank взял сигнал, который контролируют **другие**: чтобы его подделать, нужно убедить чужие авторитетные сайты поставить ссылку. Подделать чужое поведение всегда дороже, чем своё.

### История: от BackRub к Google

Идея пришла из библиотечной аналогии: чем больше штампов на формуляре книги, тем, вероятно, она полезнее. Брин и Пейдж перенесли это на веб, добавив ключевое уточнение — **чем больше ссылок исходит со страницы, тем меньше весит каждая**.

- **1996** — Пейдж и Брин начинают работу в Стэнфорде. Поисковик называется **BackRub**: он анализирует обратные ссылки (backlinks).
- **15 сентября 1997** — регистрируется домен `google.com`. Название хотели дать от **гугола** ($10^{100}$), но при проверке домена его написали с опечаткой — `google` вместо `googol`. Опечатка и осталась.
- **1998** — запуск. Инвесторы сомневались: хороший поиск отдаёт ответ с первой попытки, а значит, пользователь быстрее уходит и видит меньше рекламы.
- **~2002** — Google обгоняет Yahoo и становится самой популярной поисковой системой.

> **Оговорка про современность.** PageRank давно не «алгоритм Google», а один сигнал из сотен. Публичный показатель Toolbar PageRank Google отключил в 2016 году, объяснив, что «изолированная метрика» вводит людей в заблуждение. При этом компания подтвердила, что **внутри** ранжирования PageRank по-прежнему используется — просто во внутренней, куда более сложной форме, а не как число от 0 до 10. Так что верно: «PageRank — один из сигналов Google»; неверно: «Google работает на PageRank».

### Big O

|Операция|Сложность|
|---|---|
|Одна итерация|$O(V + E)$|
|Полное выполнение|$O(k \cdot (V + E))$|
|Память|$O(V + E)$|

$k$ — количество итераций до сходимости (обычно 20–100). Для веба с миллиардами страниц — задача распределённых вычислений (MapReduce).

### Плюсы и минусы

**Плюсы:**
- Учитывает качество связей, а не только количество
- Устойчив к накрутке — трудно поднять ранг без качественных ссылок
- Работает на любом графе, не только веб-страницах
- Персонализируется под конкретного пользователя

**Минусы:**
- Медленная сходимость на больших графах
- Тупиковые вершины требуют специальной обработки
- Статический — не учитывает актуальность страницы
- Сам по себе не решает задачу поиска — нужны дополнительные сигналы

### Применение

- **Поисковые системы** — Google изначально строился на PageRank
- **Социальные сети** — TwitterRank, влиятельность пользователей
- **Научные статьи** — важность по числу цитирований (аналог PageRank)
- **Рекомендательные системы** — персонализированный PageRank по графу предпочтений
- **Биоинформатика** — важность генов в сетях взаимодействий
- **Анализ ссылок** — SEO, определение авторитетности ресурсов
