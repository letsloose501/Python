# Контрольная цифра и алгоритм Луна

**Контрольная цифра** — лишний разряд в номере, вычисленный из остальных по фиксированному правилу. Он не несёт информации, его задача одна: **поймать опечатку до того, как номер уйдёт дальше**.

> **Аналогия:** как заранее посчитанная сумма в конце счёта. Пересчитал — сходится, значит цифры переписали верно.

Так устроены номера банковских карт, IMEI телефонов, ISBN книг, штрихкоды EAN, ИНН. **Алгоритм Луна** (Luhn, 1954) — самая распространённая схема, ей проверяются карты.

---

## Зачем это нужно, если есть хеши

Вопрос, который стоит задать сразу — и он же ответ на секции:

| | Контрольная цифра | [Криптографический хеш](../../Библиотеки/Модули/Безопасность%20и%20интернет/hashlib.md) | Цифровая подпись |
|---|---|---|---|
| **От чего защищает** | от **опечатки** человека | от **случайного повреждения** данных | от **подделки** |
| **Против злоумышленника** | нет — цифру легко подогнать | нет — хеш пересчитывается | да |
| **Размер** | 1 разряд | 32–64 байта | сотни байт |
| **Где** | номера карт, ИНН, ISBN | контроль целостности файлов | [JWT](../../JWT%20—%20подпись%20и%20проверка%20токенов.md), TLS |

**Луна ловит не мошенника, а человека.** Он гарантированно обнаруживает **любую одиночную ошибку в цифре** и **почти все перестановки соседних цифр** (`34` вместо `43`) — а это две самые частые опечатки при вводе номера руками. Смысл в том, чтобы отсеять кривой номер **на клиенте**, не тратя запрос в платёжную систему.

## Как работает

Идём по цифрам **справа налево**, начиная с той, что перед контрольной. Каждую вторую удваиваем; если удвоение дало больше 9 — вычитаем 9 (это то же, что сложить цифры результата: $16 \to 1+6=7$ и $16-9=7$). Суммируем всё. Номер верен, если сумма делится на 10.

```
номер:        1   2   3   4   5   6   7   4      ← последняя (4) контрольная
позиция:      6   5   4   3   2   1   0
справа:       ↑       ↑       ↑       ↑          ← каждая вторая от контрольной
удвоить:     1×2     3×2     5×2     7×2
результат:    2       6      10      14
−9 если >9:   2       6       1       5
не тронуты:       2       4       6       4

сумма = (2 + 6 + 1 + 5) + (2 + 4 + 6 + 4) = 14 + 16 = 30
30 % 10 == 0  →  номер верен
```

Испортим одну цифру: `12345675` даёт сумму 31 — не делится на 10, ошибка поймана. То же с перестановкой двух последних: `12345647` даёт 36.

## Реализация

```python
def луна_верна(номер: str) -> bool:
    """Проверить номер (последняя цифра — контрольная)."""
    цифры = [int(c) for c in номер if c.isdigit()]
    сумма = 0
    for i, d in enumerate(reversed(цифры)):     # идём справа налево
        if i % 2 == 1:                          # каждая вторая от конца
            d *= 2
            if d > 9:
                d -= 9
        сумма += d
    return сумма % 10 == 0

луна_верна("4539148803436467")     # → True
луна_верна("4539148803436468")     # → False   одна цифра испорчена
```

**Посчитать контрольную цифру** для номера без неё — обратная задача: дописываем `0`, считаем сумму и берём столько, сколько не хватает до круглого десятка.

```python
def контрольная_цифра(основа: str) -> int:
    """Какую цифру дописать в конец, чтобы номер прошёл проверку."""
    сумма = 0
    for i, c in enumerate(reversed(основа)):
        d = int(c)
        if i % 2 == 0:                          # ← сдвиг на 1: контрольной ещё нет
            d *= 2
            if d > 9:
                d -= 9
        сумма += d
    return (10 - сумма % 10) % 10

основа = "453914880343646"
цифра = контрольная_цифра(основа)               # → 7
луна_верна(основа + str(цифра))                 # → True
```

> ⚠️ **Единственная тонкость — с какой позиции удваивать.** В проверке контрольная цифра уже на месте и стоит нулевой справа, поэтому удваиваются позиции `i % 2 == 1`. При **генерации** её ещё нет, всё сдвигается на один разряд — и удваивать надо `i % 2 == 0`. Перепутать эти два случая — ровно тот баг, который даёт «мой генератор выдаёт номера, не проходящие мою же проверку».

## Чего Луна не умеет

- **Не проверяет существование** карты, счёта или банка — только арифметическую согласованность цифр. Номер может пройти Луна и не существовать.
- **Не ловит перестановку `09` ↔ `90`** — единственное исключение среди соседних пар (обе дают одинаковый вклад в сумму).
- **Не защищает от подбора:** валидный номер генерируется тривиально, что видно из кода выше. Поэтому Луна — это проверка формы ввода, а не защита; настоящая проверка идёт на стороне платёжной системы.

## Связи

- [hashlib](../../Библиотеки/Модули/Безопасность%20и%20интернет/hashlib.md) — когда нужна целостность, а не защита от опечатки; чем хеш отличается от контрольной цифры;
