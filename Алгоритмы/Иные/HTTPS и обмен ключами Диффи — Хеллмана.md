# HTTPS и обмен ключами Диффи — Хеллмана

**Протокол Диффи — Хеллмана** (DH) — алгоритм, позволяющий двум сторонам выработать **общий секретный ключ** через открытый канал, не передавая сам ключ. Основа безопасного обмена ключами в TLS/HTTPS.

> **Аналогия:** смешивание красок. Алиса и Боб договариваются об общей «публичной» краске (жёлтой). Каждый добавляет свою секретную краску. Обмениваются результатами (смесями). Каждый добавляет свою секретную краску в смесь другого — получают одинаковый цвет. Перехватчик видит только жёлтую краску и смеси, не может восстановить секретные компоненты.

---

### Зачем это нужно

**Проблема:** Алиса хочет зашифровать сообщение для Боба. Для симметричного шифрования им нужен **общий ключ**. Но как передать ключ если канал открытый и всё слушает Ева?

**Решение Диффи-Хеллмана:** выработать общий ключ математически, не передавая его.

```
Ева перехватывает: g, p, A=g^a mod p, B=g^b mod p
Ева НЕ может вычислить: a, b, или g^(ab) mod p   ← задача дискретного логарифма
```

---

### Математическая основа

Работает на основе **однонаправленной функции**: легко вычислить $g^a \bmod p$, но по результату найти $a$ — вычислительно невозможно (задача дискретного логарифма).

**Параметры (публичные):**

- $p$ — большое простое число
- $g$ — примитивный корень по модулю $p$ (генератор)

**Протокол:**

1. Алиса выбирает секрет $a$, вычисляет $A = g^a \bmod p$, отправляет $A$
2. Боб выбирает секрет $b$, вычисляет $B = g^b \bmod p$, отправляет $B$
3. Алиса вычисляет $s = B^a \bmod p = (g^b)^a \bmod p = g^{ab} \bmod p$
4. Боб вычисляет $s = A^b \bmod p = (g^a)^b \bmod p = g^{ab} \bmod p$
5. $s$ — общий секрет, никогда не передавался по каналу

### Реализации

#### Простая демонстрация протокола

```python
import random

def диффи_хеллман_демо():
    # публичные параметры (в реальности p — 2048+ бит)
    p = 23   # простое число
    g = 5    # генератор

    print(f"Публичные параметры: p={p}, g={g}")

    # Алиса
    a = random.randint(2, p - 2)   # секрет Алисы
    A = pow(g, a, p)               # A = g^a mod p
    print(f"\nАлиса: секрет a={a}, отправляет A={A}")

    # Боб
    b = random.randint(2, p - 2)   # секрет Боба
    B = pow(g, b, p)               # B = g^b mod p
    print(f"Боб:   секрет b={b}, отправляет B={B}")

    # Алиса и Боб независимо вычисляют общий ключ:
    ключ_алисы = pow(B, a, p)   # B^a mod p = g^(ba) mod p
    ключ_боба  = pow(A, b, p)   # A^b mod p = g^(ab) mod p

    print(f"\nКлюч Алисы: {ключ_алисы}")
    print(f"Ключ Боба:  {ключ_боба}")
    print(f"Совпадают: {ключ_алисы == ключ_боба}")

    # Ева видела: p, g, A, B
    # Пытается найти общий ключ перебором (работает только при малом p):
    print(f"\nЕва перехватила: p={p}, g={g}, A={A}, B={B}")
    for возможный_a in range(1, p):
        if pow(g, возможный_a, p) == A:
            ключ_евы = pow(B, возможный_a, p)
            print(f"Ева нашла a={возможный_a}, ключ={ключ_евы}  (при p=23 — тривиально!)")
            break
    print("При p в 2048 бит перебор займёт дольше возраста вселенной")

    return ключ_алисы


диффи_хеллман_демо()
```

#### Реалистичная реализация с большими числами

```python
import random
import hashlib

# Стандартная группа DH из RFC 3526 (2048 бит)
# В реальных системах используются такие числа
P_2048 = int(
    "FFFFFFFF FFFFFFFF C90FDAA2 2168C234 C4C6628B 80DC1CD1"
    "29024E08 8A67CC74 020BBEA6 3B139B22 514A0879 8E3404DD"
    "EF9519B3 CD3A431B 302B0A6D F25F1437 4FE1356D 6D51C245"
    "E485B576 625E7EC6 F44C42E9 A637ED6B 0BFF5CB6 F406B7ED"
    "EE386BFB 5A899FA5 AE9F2411 7C4B1FE6 49286651 ECE45B3D"
    "C2007CB8 A163BF05 98DA4836 1C55D39A 69163FA8 FD24CF5F"
    "83655D23 DCA3AD96 1C62F356 208552BB 9ED52907 7096966D"
    "670C354E 4ABC9804 F1746C08 CA18217C 32905E46 2E36CE3B"
    "E39E772C 180E8603 9B2783A2 EC07A28F B5C55DF0 6F4C52C9"
    "DE2BCBF6 95581718 3995497C EA956AE5 15D22618 98FA0510"
    "15728E5A 8AACAA68 FFFFFFFF FFFFFFFF".replace(" ", ""), 16
)
G = 2

class СторонаDH:
    def __init__(self, имя, p=P_2048, g=G):
        self.имя = имя
        self.p = p
        self.g = g
        self._секрет = random.randint(2, p - 2)
        self.публичный_ключ = pow(g, self._секрет, p)
        self._общий_секрет = None

    def получить_публичный(self):
        return self.публичный_ключ

    def вычислить_общий_ключ(self, публичный_другого):
        # g^(ab) mod p
        сырой = pow(публичный_другого, self._секрет, self.p)
        # хешируем чтобы получить ключ фиксированной длины
        self._общий_секрет = hashlib.sha256(str(сырой).encode()).digest()
        return self._общий_секрет

    def шифровать(self, текст):
        """XOR-шифрование для демонстрации (не для продакшена!)"""
        if not self._общий_секрет:
            raise RuntimeError("общий ключ не установлен")
        байты = текст.encode("utf-8")
        ключ_байты = (self._общий_секрет * (len(байты) // 32 + 1))[:len(байты)]
        return bytes(a ^ b for a, b in zip(байты, ключ_байты))

    def расшифровать(self, зашифровано):
        return self.шифровать(зашифровано.decode("latin-1")).decode("utf-8")


# симуляция обмена:
алиса = СторонаDH("Алиса")
боб   = СторонаDH("Боб")

# обмен публичными ключами через открытый канал:
ключ_алисы = алиса.вычислить_общий_ключ(боб.получить_публичный())
ключ_боба  = боб.вычислить_общий_ключ(алиса.получить_публичный())

print(f"Ключи совпадают: {ключ_алисы == ключ_боба}")
print(f"Ключ (hex): {ключ_алисы.hex()[:32]}...")

# теперь можно шифровать:
сообщение = "Привет, Боб! Это секретное сообщение."
зашифровано = алиса.шифровать(сообщение)
расшифровано = боб.расшифровать(зашифровано)
print(f"Расшифровано: {расшифровано}")
```

#### ECDH — эллиптические кривые (современный стандарт)

ECDH (Elliptic Curve DH) — то же что DH, но на группе точек эллиптической кривой. При той же безопасности нужны **намного меньшие ключи**: 256-битный ECDH ≈ 3072-битному DH.

```python
# Через cryptography (pip install cryptography):
from cryptography.hazmat.primitives.asymmetric.x25519 import X25519PrivateKey
from cryptography.hazmat.primitives.kdf.hkdf import HKDF
from cryptography.hazmat.primitives import hashes

def обмен_ecdh():
    # Алиса генерирует пару ключей
    приватный_алисы = X25519PrivateKey.generate()
    публичный_алисы = приватный_алисы.public_key()

    # Боб генерирует пару ключей
    приватный_боба = X25519PrivateKey.generate()
    публичный_боба = приватный_боба.public_key()

    # Вычисляют общий ключ:
    общий_алисы = приватный_алисы.exchange(публичный_боба)
    общий_боба  = приватный_боба.exchange(публичный_алисы)

    # Оба получают одинаковый ключ:
    print(f"Совпадают: {общий_алисы == общий_боба}")

    # Производим ключ шифрования через HKDF:
    ключ = HKDF(
        algorithm=hashes.SHA256(),
        length=32,
        salt=None,
        info=b"handshake data",
    ).derive(общий_алисы)

    print(f"Ключ AES-256: {ключ.hex()}")
    return ключ
```

### Как HTTPS использует Диффи — Хеллмана

TLS Handshake (упрощённо):

```
Клиент                          Сервер
  |                               |
  |──── ClientHello ─────────────→|  версия TLS, cipher suites
  |                               |
  |←─── ServerHello ─────────────|  выбранный cipher, сертификат
  |                               |
  |←─── ServerKeyExchange ───────|  g, p, B=g^b mod p (публичный DH)
  |                               |
  |──── ClientKeyExchange ───────→|  A=g^a mod p (публичный DH)
  |                               |
  | оба вычисляют g^(ab) mod p   |  ← общий PreMasterSecret
  |                               |
  | производят сессионные ключи  |  из PreMasterSecret + случайных nonce
  |                               |
  |──── Finished (зашифровано) ──→|
  |←─── Finished (зашифровано) ──|
  |                               |
  |======= зашифрованный канал ===|  AES-256-GCM или ChaCha20
```

Каждая сессия — новая пара DH-ключей. Даже если приватный ключ сервера утечёт — прошлые сессии не расшифровать. Это называется **Perfect Forward Secrecy (PFS)**.

---

### Почему безопасно — дискретный логарифм

```
известно: g=5, p=23, A=8
найти: a такое что 5^a ≡ 8 (mod 23)

при p=23 — перебор из 22 вариантов, тривиально
при p=2048 бит — 2^2048 вариантов, больше атомов в наблюдаемой вселенной
```

Задача дискретного логарифма для больших $p$ — вычислительно неразрешима на классических компьютерах. Квантовый компьютер с алгоритмом Шора теоретически мог бы решить её — поэтому разрабатываются постквантовые алгоритмы.

---

### Уязвимости и атаки

**Атака «человек посередине» (MITM):**

```
Алиса ↔ Ева (притворяется Бобом) ↔ Боб
```

Ева устанавливает отдельные DH-сессии с обоими. Решение — **сертификаты**: подпись публичного ключа доверенным центром сертификации (CA). Браузер проверяет подпись.

**Слабые параметры (Logjam):** если использовать стандартные малые $p$ — атакующий может предвычислить таблицу. Решение — использовать 2048+ бит или ECDH.

**Ephemeral DH (DHE/ECDHE):** «E» = Ephemeral (эфемерный) — новые ключи для каждой сессии, обеспечивают PFS.

---

### Big O

|Операция|DH (2048 бит)|ECDH (256 бит)|
|---|---|---|
|Генерация ключей|$O(k^2)$ — $k$ бит|$O(k^2)$|
|Вычисление публичного ключа|$O(k^3)$|$O(k^3)$|
|Вычисление общего ключа|$O(k^3)$|$O(k^3)$|

ECDH с $k=256$ бит примерно эквивалентен DH с $k=3072$ бит по безопасности, но значительно быстрее на практике.

---

### Плюсы и минусы

**Плюсы:**

- Решает проблему распределения ключей — общий ключ без передачи
- Perfect Forward Secrecy в режиме DHE/ECDHE — прошлые сессии защищены
- Доказуемая безопасность при правильных параметрах
- ECDH — компактные ключи, быстрые вычисления

**Минусы:**

- Не защищён от MITM без аутентификации (нужны сертификаты)
- Уязвим к квантовым компьютерам (алгоритм Шора)
- Требует хороших генераторов случайных чисел — слабый RNG = слабая безопасность
- Вычислительно дороже симметричного шифрования

---

### Применение

- **TLS/HTTPS** — каждое HTTPS-соединение использует DHE или ECDHE
- **SSH** — установка защищённого канала
- **Signal, WhatsApp** — расширенный протокол на основе DH (Double Ratchet)
- **VPN** — IPSec, WireGuard используют ECDH
- **PGP/GPG** — шифрование электронной почты

```python
# Проверить какой cipher использует соединение:
import ssl, socket

контекст = ssl.create_default_context()
with socket.create_connection(("example.com", 443)) as сокет:
    with контекст.wrap_socket(сокет, server_hostname="example.com") as tls:
        print(tls.cipher())
# → ('TLS_AES_256_GCM_SHA384', 'TLSv1.3', 256)
# → или ('ECDHE-RSA-AES256-GCM-SHA384', 'TLSv1.2', 256)
#          ↑ ECDHE = Elliptic Curve Diffie-Hellman Ephemeral
```
