# Инвертированный индекс

**Инвертированный индекс** (Inverted Index) — структура данных: **слово → список мест где оно встречается**. Позволяет мгновенно найти все документы по ключевому слову без перебора каждого документа.

> **Аналогия:** предметный указатель в конце учебника. Вместо того чтобы листать все страницы в поисках слова «рекурсия» — открываешь указатель и сразу видишь: «рекурсия — с. 42, 87, 134».

Реализуется через [хеш-таблицу](../../Данные/Структуры%20данных/Хеш-таблица.md). Поиск по слову — $O(1)$. Это основа всех поисковых систем.

---

### Как работает

```
документы:
  doc1: "кот сидит на коврике"
  doc2: "кот и пёс"
  doc3: "пёс бежит быстро"

инвертированный индекс:
  "кот"     → [doc1, doc2]
  "сидит"   → [doc1]
  "на"      → [doc1]
  "коврике" → [doc1]
  "и"       → [doc2]
  "пёс"     → [doc2, doc3]
  "бежит"   → [doc3]
  "быстро"  → [doc3]

запрос "кот":
  индекс["кот"] → [doc1, doc2]   мгновенно, без перебора документов
```

Без индекса поиск по $n$ документам с суммарным объёмом $w$ слов — $O(n \cdot w)$. С индексом — $O(1)$ на слово.

---

### Реализации

#### Базовый — слово → список документов

```python
from collections import defaultdict

class ИнвертированныйИндекс:
    def __init__(self):
        self._индекс = defaultdict(set)   # слово → {doc_id, ...}
        self._документы = {}               # doc_id → текст

    def добавить(self, doc_id, текст):
        self._документы[doc_id] = текст
        for слово in текст.lower().split():
            слово = слово.strip(".,!?;:\"'()-")   # убрать пунктуацию
            if слово:
                self._индекс[слово].add(doc_id)

    def найти(self, запрос):
        слово = запрос.lower().strip()
        return self._индекс.get(слово, set())


индекс = ИнвертированныйИндекс()
индекс.добавить("doc1", "кот сидит на коврике")
индекс.добавить("doc2", "кот и пёс")
индекс.добавить("doc3", "пёс бежит быстро")

индекс.найти("кот")   # → {"doc1", "doc2"}
индекс.найти("пёс")   # → {"doc2", "doc3"}
индекс.найти("нет")   # → set()
```

#### С позициями слов — для фразового поиска

Хранит не только в каком документе, но и на какой позиции. Позволяет искать точные фразы.

```python
from collections import defaultdict

class ПозиционныйИндекс:
    def __init__(self):
        # слово → {doc_id: [позиция, ...]}
        self._индекс = defaultdict(lambda: defaultdict(list))
        self._документы = {}

    def добавить(self, doc_id, текст):
        self._документы[doc_id] = текст
        слова = текст.lower().split()
        for позиция, слово in enumerate(слова):
            слово = слово.strip(".,!?;:")
            if слово:
                self._индекс[слово][doc_id].append(позиция)

    def найти_слово(self, слово):
        return dict(self._индекс.get(слово.lower(), {}))

    def найти_фразу(self, фраза):
        """Найти документы где слова фразы идут подряд."""
        слова = фраза.lower().split()
        if not слова:
            return set()

        # начинаем с документов содержащих первое слово
        кандидаты = set(self._индекс[слова[0]].keys())

        for сдвиг, слово in enumerate(слова[1:], 1):
            новые_кандидаты = set()
            для_слова = self._индекс.get(слово, {})
            for doc_id in кандидаты & set(для_слова.keys()):
                позиции_первого = self._индекс[слова[0]][doc_id]
                позиции_текущего = для_слова[doc_id]
                # ищем позицию текущего слова = позиция первого + сдвиг
                нужные = {p + сдвиг for p in позиции_первого}
                if нужные & set(позиции_текущего):
                    новые_кандидаты.add(doc_id)
            кандидаты = новые_кандидаты

        return кандидаты


индекс = ПозиционныйИндекс()
индекс.добавить("doc1", "быстрая коричневая лиса прыгает")
индекс.добавить("doc2", "коричневая лиса живёт в лесу")
индекс.добавить("doc3", "лиса и заяц")

индекс.найти_фразу("коричневая лиса")
# → {"doc1", "doc2"}  — есть в обоих подряд

индекс.найти_слово("лиса")
# → {"doc1": [2], "doc2": [1], "doc3": [0]}
```

#### С tf-idf весами — ранжирование результатов

**TF** (Term Frequency) — как часто слово встречается в документе. **IDF** (Inverse Document Frequency) — насколько редкое слово во всей коллекции. Редкие слова важнее.

```python
import math
from collections import defaultdict, Counter

class TFIDFИндекс:
    def __init__(self):
        self._документы = {}        # doc_id → список слов
        self._индекс = defaultdict(dict)   # слово → {doc_id: tf_idf}
        self._df = defaultdict(int)  # сколько документов содержат слово

    def _токенизировать(self, текст):
        слова = текст.lower().split()
        return [с.strip(".,!?;:\"'()") for с in слова if с.strip(".,!?;:\"'()")]

    def добавить(self, doc_id, текст):
        слова = self._токенизировать(текст)
        self._документы[doc_id] = слова
        for слово in set(слова):
            self._df[слово] += 1

    def построить(self):
        n = len(self._документы)
        for doc_id, слова in self._документы.items():
            частоты = Counter(слова)
            всего = len(слова)
            for слово, count in частоты.items():
                tf = count / всего
                idf = math.log(n / self._df[слово])
                self._индекс[слово][doc_id] = tf * idf

    def найти(self, запрос, top_k=5):
        слова_запроса = self._токенизировать(запрос)
        счёт = defaultdict(float)
        for слово in слова_запроса:
            for doc_id, вес in self._индекс.get(слово, {}).items():
                счёт[doc_id] += вес
        return sorted(счёт.items(), key=lambda x: -x[1])[:top_k]


индекс = TFIDFИндекс()
индекс.добавить("wiki_python",  "Python язык программирования общего назначения")
индекс.добавить("wiki_java",    "Java объектно-ориентированный язык программирования")
индекс.добавить("wiki_кот",     "Кот домашнее животное")
индекс.построить()

результаты = индекс.найти("язык программирования")
# → [("wiki_python", 0.xxx), ("wiki_java", 0.xxx)]  — без wiki_кот
```

#### AND / OR / NOT запросы

```python
class БулевыйИндекс:
    def __init__(self):
        self._индекс = defaultdict(set)

    def добавить(self, doc_id, текст):
        for слово in текст.lower().split():
            self._индекс[слово.strip(".,!?")].add(doc_id)

    def _найти(self, слово):
        return self._индекс.get(слово.lower(), set())

    def AND(self, *слова):
        """Документы содержащие ВСЕ слова."""
        результат = self._найти(слова[0])
        for слово in слова[1:]:
            результат = результат & self._найти(слово)
        return результат

    def OR(self, *слова):
        """Документы содержащие ХОТЯ БЫ ОДНО слово."""
        результат = set()
        for слово in слова:
            результат = результат | self._найти(слово)
        return результат

    def NOT(self, слово, все_документы):
        """Документы НЕ содержащие слово."""
        return все_документы - self._найти(слово)


индекс = БулевыйИндекс()
индекс.добавить("d1", "Python и машинное обучение")
индекс.добавить("d2", "Python веб-разработка")
индекс.добавить("d3", "Java и машинное обучение")

все = {"d1", "d2", "d3"}
индекс.AND("python", "машинное")   # → {"d1"}
индекс.OR("python", "java")        # → {"d1", "d2", "d3"}
индекс.NOT("python", все)          # → {"d3"}
```

---

### Big O

|Операция|Сложность|
|---|---|
|Построение индекса|$O(n \cdot w)$ — $n$ документов, $w$ слов каждый|
|Поиск по одному слову|$O(1)$ — хеш-таблица|
|AND-запрос (пересечение)|$O(\min(r_1, r_2))$ — размер меньшего результата|
|OR-запрос (объединение)|$O(r_1 + r_2)$|
|Память|$O(n \cdot w)$ — все слова всех документов|

---

### Плюсы и минусы

**Плюсы:**

- Поиск по слову за $O(1)$ — независимо от числа документов
- Масштабируется на миллиарды документов (Google, Elasticsearch)
- AND/OR/NOT запросы через операции над множествами
- Легко добавлять новые документы

**Минусы:**

- Много памяти — хранит каждое слово из каждого документа
- Нет поиска по подстроке — «прогр» не найдёт «программирование»
- Нет семантического поиска — синонимы нужно добавлять явно
- Построение индекса при обновлении требует пересчёта

---

### Применение

- **Поисковые системы** — Google, Яндекс хранят инвертированный индекс на миллиардах страниц
- **Полнотекстовый поиск** — Elasticsearch, Solr, PostgreSQL (GIN индексы)
- **IDE** — поиск по проекту, «найти все использования»
- **Почтовые клиенты** — поиск по письмам
- **Базы данных** — полнотекстовые индексы в MySQL, PostgreSQL

> Используемая структура — [Хеш-таблица](../../Данные/Структуры%20данных/Хеш-таблица.md). Нотация — Вычислительная сложность. Место среди индексов БД — Виды индексов. Когда слов уже не хватает и нужен поиск по смыслу — Векторный поиск.

> **Две половины поиска.** Инвертированный индекс и tf-idf отвечают на вопрос «**про то ли** этот документ» — это релевантность. Они ничего не говорят о том, **хорош** ли документ, и потому легко накручиваются: достаточно натыкать ключевое слово сотню раз. Второй сигнал — качество — приходит извне текста, из ссылок: [PageRank](../../Алгоритмы/Иные/PageRank.md). Поисковики 90-х умели только первое и проигрывали именно на этом.
