# Битовые приёмы

**Битовый приём** — решение задачи через двоичное представление числа вместо арифметики: вместо того чтобы считать, складывать и хранить, мы пользуемся тем, что число — это набор битов, а операции над ними обратимы и стоят один такт процессора.

> **Аналогия:** выключатели в щитке. Число `12` — это не «двенадцать», а «включены третий и четвёртый выключатели» (`1100`). Операции `&`, `|`, `^` щёлкают всеми выключателями сразу, за один приём.

Сами операторы (`&`, `|`, `^`, `~`, `<<`, `>>`) описаны в [Операторы Python](../../Ядро%20языка/Операторы%20Python.md#побитовые-операторы), запись чисел по основаниям — в Системы счисления. Здесь — **что этими операторами решают** на собеседованиях: два-три трюка, из которых состоит почти весь класс задач.

---

### Три свойства XOR, из которых всё следует

**XOR** (`^`, исключающее ИЛИ) даёт 1, когда биты **различаются**. Отсюда:

| Свойство | Запись | Смысл |
|---|---|---|
| Самоуничтожение | `x ^ x == 0` | одинаковые пары исчезают |
| Нейтральный элемент | `x ^ 0 == x` | ноль ничего не меняет |
| Порядок не важен | `a ^ b ^ c == c ^ a ^ b` | коммутативность и ассоциативность |

Вместе они дают главный вывод: **если сложить XOR-ом весь массив, всё, что встречается парами, взаимно уничтожится, а останется то, что было в единственном экземпляре.** Порядок при этом не имеет значения — сортировать ничего не нужно.

```
2 ^ 3 ^ 2 = (2 ^ 2) ^ 3 = 0 ^ 3 = 3
```

**#136 Single Number** — найти единственное непарное число:

```python
def single_number(nums):
    mask = 0
    for x in nums:
        mask ^= x
    return mask

single_number([4, 1, 2, 1, 2])    # → 4
single_number([-5, -5, -7])       # → -7   (знак не мешает)
```

Время $O(n)$, память $O(1)$ — против решения через [множество](../../Данные/Структуры%20данных/Хеш-таблица.md), где память $O(n)$. Готовая свёртка: `functools.reduce(operator.xor, nums)`.

### Один приём — две задачи: пропавшее число

Приём с самоуничтожением решает и **#268 Missing Number** (числа `0..n`, одно пропало). Идея: сложить XOR-ом *и* индексы, *и* значения — всё, что есть в обоих наборах, погасится, останется недостающее.

```python
def missing_number(nums):
    acc = len(nums)                  # n — единственное, чего нет среди индексов
    for i, x in enumerate(nums):
        acc ^= i ^ x
    return acc
```

Ту же задачу обычно решают формулой суммы арифметической прогрессии: «идеальная» сумма минус фактическая.

```python
def missing_number_sum(nums):
    n = len(nums)
    return n * (n + 1) // 2 - sum(nums)
```

Оба решения верны — проверено на 20 000 случайных тестах, расхождений нет. Но у них разная устойчивость:

> **XOR не может переполниться, а сумма может.** При ограничении LeetCode `n ≤ 10⁵` идеальная сумма равна 5 000 050 000 — это **больше 2³¹**, то есть в C++ или Java на `int` решение через сумму молча ломается и требует 64-битного типа. В Python проблемы нет: целые неограниченной длины. То есть совет «решай формулой Гаусса» безопасен **благодаря языку**, а не сам по себе; XOR-версия работает везде одинаково.

Третье решение той же задачи — [циклическая сортировка](../../Алгоритмы/Приёмы/Циклическая%20сортировка.md). Полезно держать в голове все три: на собеседовании после первого решения почти всегда просят альтернативу.

### Работа с младшим битом

Два трюка, которые заменяют арифметику и лежат в основе задач на подсчёт битов.

```python
n & 1         # чётность: 1 — нечётное, 0 — чётное  (то же, что n % 2)
n >> 1        # деление на 2 с округлением вниз      (то же, что n // 2)
n << 1        # умножение на 2
```

Последний бит хранит чётность, потому что все остальные разряды — степени двойки, а значит чётны. Сдвиг вправо выбрасывает младший бит — это буквально «отрезать последнюю двоичную цифру».

> В Python это **не оптимизация**: замер даёт `& 1` быстрее `% 2` лишь в ~1,4 раза (0,031 с против 0,043 с на 2 млн операций) — на фоне общей стоимости интерпретатора разница незаметна. Пишут так не ради скорости, а потому что в задачах на биты это выражает намерение: «меня интересует младший бит», а не «остаток от деления».

### `n & (n - 1)` — сброс младшей единицы

Вычитание единицы превращает младшую единицу в ноль, а все нули справа от неё — в единицы. Побитовое И оставляет только то, что выше:

```
n     = 1100          n     = 1000
n - 1 = 1011          n - 1 = 0111
n & (n-1) = 1000      n & (n-1) = 0000
```

Отсюда два следствия.

**Подсчёт единиц (алгоритм Кернигана)** — цикл крутится столько раз, сколько единиц, а не сколько битов:

```python
def popcount(n):
    count = 0
    while n:
        n &= n - 1          # гасим младшую единицу
        count += 1
    return count
```

**Проверка степени двойки** — у степени двойки ровно одна единица, значит после сброса остаётся ноль:

```python
def is_power_of_two(n):
    return n > 0 and n & (n - 1) == 0
```

> Условие `n > 0` обязательно: `0 & -1 == 0`, поэтому без него ноль пройдёт проверку как «степень двойки». Проверено запуском — типичная ошибка на один символ.

Родственный трюк — `n & -n` **выделяет** младшую единицу вместо того, чтобы гасить её: `12 & -12 == 4`. На нём держится дерево Фенвика.

### #338 Counting Bits — ДП по битам

Посчитать число единиц для всех чисел от `0` до `n`. Наивно — `popcount` для каждого, то есть $O(n \log n)$. Но ответ для нового числа уже посчитан для меньшего: **сдвиг вправо отрезает младший бит, а он и есть единственная разница**.

```python
def count_bits(n):
    memo = [0] * (n + 1)
    for i in range(1, n + 1):
        memo[i] = memo[i >> 1] + (i & 1)     # ответ для i//2 плюс младший бит
    return memo

count_bits(5)      # → [0, 1, 1, 2, 1, 2]
```

Это [динамическое программирование](../../Алгоритмы/Стратегии/Динамическое%20программирование.md) в чистом виде: переход `dp[i] = dp[i >> 1] + (i & 1)` за $O(1)$, общее время $O(n)$.

Второй переход даёт тот же ответ через сброс младшей единицы:

```python
memo[i] = memo[i & (i - 1)] + 1              # на одну единицу больше, чем у i без неё
```

Оба варианта проверены на всех числах до 100 000 — совпадают с `bin(i).count("1")`. Первый нагляднее (видно «отрезали цифру»), второй короче.

---

### Что даёт Python из коробки

```python
(5).bit_count()      # → 2    число единиц, Python 3.10+
(12).bit_length()    # → 4    сколько битов занимает число
bin(12).count("1")   # → 2    работает везде, но медленнее
```

`bit_count()` считает единицы **в модуле** числа, поэтому `(-5).bit_count() == 2`. На собеседовании такую встроенную функцию обычно просят не использовать — весь смысл задачи в том, чтобы показать трюк.

### Ловушки Python

**1. Отрицательные числа ведут себя как бесконечная лента единиц.** Python не хранит числа в фиксированных 32 или 64 битах, а работает так, будто слева у отрицательного числа бесконечно много единиц:

```python
-1 >> 10      # → -1    сколько ни сдвигай, единицы не кончатся
-5 >> 1       # → -3    сдвиг вправо округляет ВНИЗ, а не к нулю
~5            # → -6    ~n всегда равно -(n + 1)
```

**2. `bin()` для отрицательных не даёт дополнительный код.** `bin(-5)` возвращает `'-0b101'` — знак и модуль. Чтобы увидеть привычное машинное представление, нужно наложить маску: `-5 & 0xFF` → `251` (то есть `11111011`).

**3. XOR-обмен без временной переменной ломается сам на себе.** Классический трюк `a ^= b; b ^= a; a ^= b` меняет значения местами — но только если это **разные ячейки**:

```python
arr = [5, 7]
i = j = 0                                        # оба индекса указывают в одну ячейку
arr[i] ^= arr[j]; arr[j] ^= arr[i]; arr[i] ^= arr[j]
arr                                              # → [0, 7]  элемент обнулился
```

Значение уничтожает само себя по правилу `x ^ x == 0`. В Python этот трюк не нужен вовсе: `a, b = b, a` короче, быстрее и безопаснее.

### Когда применять

- В условии есть **пары** и просят найти непарное или недостающее → XOR.
- Требуют $O(1)$ **памяти** там, где просится множество или счётчик → XOR.
- Задача про **двоичное представление**: число единиц, степень двойки, отрезать/выделить бит.
- Нужен компактный набор флагов: множество из ≤ 64 элементов — это одно число (битовая маска подмножества в переборе).

Не применять, когда элементы встречаются не парами, а произвольное число раз, — тогда XOR ничего не гасит и нужен обычный подсчёт частот.
