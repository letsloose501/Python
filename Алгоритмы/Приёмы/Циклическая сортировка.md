# Циклическая сортировка

**Циклическая сортировка** (cyclic sort) — приём для массивов, где числа берутся из известного узкого диапазона `1..n` или `0..n`: каждое число само подсказывает, на каком индексе оно должно лежать, поэтому расставить всё по местам можно **за один проход и без дополнительной памяти**.

> **Аналогия:** гардероб с номерками. Не нужно ни сортировать пальто, ни заводить журнал — на каждом висит номер, и место у номера ровно одно. Взял пальто с номером 7 — отнёс в ячейку 7, а то, что там лежало, понёс дальше.

Ценность приёма в том, что он ломает привычный размен «время против памяти». Обычный ответ на «найди пропавшее число» — завести [множество](../../Данные/Структуры%20данных/Хеш-таблица.md) и потратить $O(n)$ памяти. Циклическая сортировка решает тот же класс задач за $O(n)$ времени и $O(1)$ памяти — и на собеседовании это ровно тот follow-up, который просят после первого решения.

---

### Ключевое условие: числа образуют перестановку

Приём работает не для любого массива, а только когда **значения и индексы — это одно и то же множество**. Массив из `n` чисел, где каждое лежит в `1..n`, — это перестановка (возможно, испорченная дубликатами и пропусками). Отсюда правило соответствия:

```
значение:  1  2  3  4  5        nums[i] должно лежать
индекс:    0  1  2  3  4        на индексе nums[i] - 1
```

Диапазон бывает двух видов, и разметка у них разная — это первое, что нужно уточнить в условии:

| Диапазон | Длина массива | Куда должно лечь значение `v` | Задачи |
|---|---|---|---|
| `1..n` | `n` | индекс `v - 1` | #448, #442, #41, #287, #645 |
| `0..n` | `n` (одно число пропущено) | индекс `v` | #268 |

Во втором случае чисел на одно больше, чем мест, поэтому значение `n` пристроить некуда — его пропускают проверкой `nums[i] < n`.

---

### Базовый шаблон

```python
def cyclic_sort(nums):
    i = 0
    while i < len(nums):
        j = nums[i] - 1                          # законное место для nums[i]
        if nums[i] != nums[j]:                   # там лежит не то же самое значение
            nums[i], nums[j] = nums[j], nums[i]  # меняем местами и НЕ двигаем i
        else:
            i += 1                               # на месте или дубликат — идём дальше
    return nums

cyclic_sort([3, 1, 5, 4, 2])      # → [1, 2, 3, 4, 5]
cyclic_sort([4, 3, 2, 7, 8, 2, 3, 1])   # → [1, 2, 3, 4, 3, 2, 7, 8]
```

**Как это читать.** Указатель `i` стоит на месте, пока текущее число не окажется «своим». Каждый обмен отправляет одно число домой и приносит на его место новое, которое тут же проверяется. Второй пример показывает главное: с дубликатами массив полностью не сортируется — и это не баг. Позиции, где после прохода лежит «не то» число (`nums[i] != i + 1`), и есть ответ задачи.

---

### Почему это $O(n)$, а не $O(n^2)$

Вложенность `while` внутри прохода обманчива: кажется, что это квадрат. Аргумент — амортизационный: **каждый обмен ставит хотя бы одно число на его законное место, и оттуда оно уже никогда не сдвинется**. Мест всего `n`, значит обменов не может быть больше `n - 1`. Плюс не больше `n` шагов, когда `i` продвигается вперёд. Итого не более `2n` операций.

Замер на случайных перестановках (200 прогонов на каждый размер) подтверждает потолок:

| `n` | Максимум обменов за 200 прогонов | Теоретический потолок `n − 1` |
|---|---|---|
| 10 | 9 | 9 |
| 100 | 99 | 99 |
| 1 000 | 998 | 999 |
| 10 000 | 9 997 | 9 999 |

> Это стандартный приём рассуждения на собеседовании: если внутренний цикл ограничен не длиной массива, а **числом необратимых событий**, оценка складывается, а не перемножается. Тот же аргумент работает в [монотонном стеке](../../Алгоритмы/Приёмы/Монотонный%20стек.md) — каждый элемент кладётся и снимается один раз.

### Ловушка: сравнивать значения, а не позицию

Самая частая ошибка — написать условие обмена через индекс: «пока число не на своём месте — меняй».

```python
# НЕПРАВИЛЬНО — вечный цикл на дубликатах
while i < len(nums):
    j = nums[i] - 1
    if nums[i] != i + 1:        # сравниваем с позицией
        nums[i], nums[j] = nums[j], nums[i]
    else:
        i += 1

# ПРАВИЛЬНО
    if nums[i] != nums[j]:      # сравниваем с тем, что лежит в месте назначения
```

Причина: если два одинаковых числа, одно уже стоит правильно, а второе хочет туда же — обмен ничего не меняет, условие остаётся истинным, и цикл крутится вечно. Проверено запуском на `[4, 3, 2, 7, 8, 2, 3, 1]` (пример из #448): версия «по значению» завершается за 14 шагов, версия «по индексу» уходит в бесконечный цикл — счётчик оборвал её на 100 000 итераций.

> Правильная формулировка звучит иначе, чем интуитивная: не «пока число не на месте», а **«пока в месте назначения лежит другое значение»**. На дубликате обмен бессмыслен, поэтому его надо не совершать, а пропускать.

### Класс задач

Все они — один и тот же проход, отличается только вопрос в конце.

**#448 Find All Numbers Disappeared in an Array** — какие числа из `1..n` пропали.

```python
def find_disappeared(nums):
    i = 0
    while i < len(nums):
        j = nums[i] - 1
        if nums[i] != nums[j]:
            nums[i], nums[j] = nums[j], nums[i]
        else:
            i += 1
    return [i + 1 for i, x in enumerate(nums) if x != i + 1]

find_disappeared([4, 3, 2, 7, 8, 2, 3, 1])   # → [5, 6]
```

**#442 Find All Duplicates** — тот же проход, но собираем сами значения, а не индексы: `[x for i, x in enumerate(nums) if x != i + 1]`.

**#268 Missing Number** — диапазон `0..n`, поэтому место для `v` это индекс `v`, а значение `n` пропускаем:

```python
def missing_number(nums):
    n, i = len(nums), 0
    while i < n:
        j = nums[i]
        if nums[i] < n and nums[i] != nums[j]:
            nums[i], nums[j] = nums[j], nums[i]
        else:
            i += 1
    for i, x in enumerate(nums):
        if x != i:
            return i
    return n            # пропало последнее число диапазона
```

**#41 First Missing Positive** — самая ценная в классе (Hard, но по механике та же). Диапазон не гарантирован: в массиве могут быть нули, отрицательные и числа больше `n`. Все они бесполезны — ответ всё равно лежит в `1..n+1`, поэтому «мусор» просто пропускают охраной `0 < nums[i] <= n`.

**#287 Find the Duplicate Number** — если менять массив запрещено, циклическая сортировка не подходит; каноническое решение — [быстрый и медленный указатель](../../Алгоритмы/Приёмы/Два%20указателя.md) по «ссылкам» `i → nums[i]`.

### Родственный приём: пометка знаком

Когда обмены нежелательны (например, порядок элементов важен), тот же трюк «индекс как ключ» делается **без перестановок** — через знак числа как флаг «этот индекс встречался»:

```python
def find_disappeared_marking(nums):
    for x in nums:
        j = abs(x) - 1
        nums[j] = -abs(nums[j])          # видели значение j+1 — гасим индекс j
    return [i + 1 for i, x in enumerate(nums) if x > 0]
```

Память по-прежнему $O(1)$, но массив портится знаками, а работает приём только с положительными числами. Циклическая сортировка универсальнее — она даёт готовую перестановку, из которой видно и пропуски, и дубликаты сразу.

---

### Циклическая сортировка ≠ сортировка циклами

Два разных предмета под похожими именами, и их регулярно путают:

| | **Cyclic sort** (приём) | **Cycle sort** (алгоритм сортировки) |
|---|---|---|
| Что это | приём для перестановок `1..n` | полноценный алгоритм сортировки любых сравнимых данных |
| Время | $O(n)$ | $\Theta(n^2)$ |
| Чем ценен | память $O(1)$ вместо множества | **минимально возможное число записей** в массив |
| Откуда | учебные подборки задач на собеседования | статья B. K. Haddon, *The Computer Journal*, 1990 |

Общая у них только идея: перестановку можно разложить на **циклы** (`1 → 4 → 3 → 1`), и достаточно прокрутить каждый цикл один раз. Настоящая сортировка циклами придумана ради железа, где запись дороже чтения (флеш-память с ограниченным ресурсом перезаписи): каждый элемент записывается либо ноль раз, если уже стоит верно, либо ровно один раз.

---

### Когда применять и когда нет

**Применять:** в условии явно сказано, что числа из диапазона `1..n` или `0..n`, длина массива связана с этим диапазоном, а от решения хотят $O(1)$ памяти.

**Не применять:**
- значения произвольные — соответствия «значение → индекс» нет, нужна [хеш-таблица](../../Данные/Структуры%20данных/Хеш-таблица.md);
- массив менять нельзя (сказано «read-only» или он чужой) — приём разрушающий;
- нужен ответ, а порядок исходных элементов важен — бери пометку знаком или доп. память.

> Опознавательный знак в условии: **числа из диапазона, а длина массива равна размеру этого диапазона**. Влад Тен в разборе называет это «много подсказок в условии» — и это правда главный сигнал: такое ограничение пишут в задаче не просто так, а чтобы им воспользовались.
