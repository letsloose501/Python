# Интервалы

**Интервал** — пара «начало и конец»: бронь номера, встреча в переговорке, окно доступности, отрезок на прямой. Задачи на интервалы — отдельный класс на собеседованиях, и почти все они решаются одним движением: **отсортировать и пройти один раз**.

> **Аналогия:** расписание на стене. Пока брони разбросаны по листкам, ничего не понятно; разложи их слева направо по времени начала — и пересечения видно глазами.

Ценность класса в том, что он практический: «сколько нужно переговорок», «сколько операционных при таком потоке», «сколько взлётных полос», «влезет ли ещё одна бронь» — это одна и та же задача.

---

### Пересечение: где ошибаются в первой строке

Два интервала пересекаются, если **каждый начинается раньше, чем заканчивается другой**:

```python
def пересекаются(a, b):
    return a[0] < b[1] and b[0] < a[1]
```

```
[1───5)   [3───8)     пересекаются:  1 < 8 и 3 < 5
[1───5)      [5───8)  НЕ пересекаются: 5 < 5 ложно
```

> **Договорись о границах до того, как писать код.** Считается ли, что `[1, 5)` и `[5, 8)` конфликтуют? В задачах про брони и переговорки — **нет**: комнату освободили ровно тогда, когда её заняли снова. Это полуинтервал `[начало, конец)`, и сравнения идут строгие (`<`, `>=`). Если же речь про отрезки на прямой и касание считается пересечением — знаки становятся нестрогими. Половина неверных решений в этом классе — именно перепутанные `<` и `<=`.

---

### Мастер-ключ: сортировка

Почти всё сводится к одному: **отсортировать интервалы и пройти линейно**. Вопрос только в том, **по какому концу** сортировать — и это не деталь, а выбор алгоритма:

| Сортируем по | Зачем | Задачи |
|---|---|---|
| **началу** | идти по времени вперёд, накапливая состояние | слияние, подсчёт комнат, вставка |
| **концу** | жадно хватать то, что раньше освобождает место | максимум непересекающихся встреч |

Сортировка сразу задаёт нижнюю границу сложности — $O(n \log n)$. Дальнейшие ухищрения её не улучшат, поэтому линейный проход после сортировки можно писать спокойно.

---

### Слияние интервалов

[#56 Merge Intervals](https://leetcode.com/problems/merge-intervals/). Схлопнуть пересекающиеся в один.

```python
def merge(intervals):
    intervals.sort(key=lambda x: x[0])          # по началу
    result = [intervals[0]]
    for начало, конец in intervals[1:]:
        if начало <= result[-1][1]:             # налезает на последний
            result[-1][1] = max(result[-1][1], конец)
        else:
            result.append([начало, конец])
    return result

merge([[1, 3], [2, 5], [4, 15]])    # → [[1, 15]]
merge([[1, 3], [6, 9]])             # → [[1, 3], [6, 9]]
```

**Как это читать.** После сортировки достаточно смотреть только на **последний** добавленный интервал: если новый начинается до его конца — растягиваем конец, иначе начинаем новый. `max` обязателен: интервал `[1, 20]` может целиком поглотить `[3, 5]`, и без `max` конец схлопнется до 5.

### Минимум переговорок

Главная задача класса ([#253 Meeting Rooms II](https://leetcode.com/problems/meeting-rooms-ii/)): дано расписание встреч, сколько нужно комнат, чтобы все провести. Это же — сколько номеров в отеле при данных бронях и сколько операционных при данном потоке.

Ответ — **максимальное число одновременно идущих встреч**.

#### Через кучу

Держим [min-кучу](../../Алгоритмы/Иные/Двоичная%20куча%20и%20очередь%20с%20приоритетом.md) концов занятых комнат. В корне всегда та комната, которая освободится раньше всех, — единственная, которую имеет смысл проверять.

```python
import heapq

def min_rooms(intervals):
    if not intervals:
        return 0
    intervals.sort(key=lambda x: x[0])          # обязательно по НАЧАЛУ
    занятые = [intervals[0][1]]                 # куча концов

    for начало, конец in intervals[1:]:
        if начало >= занятые[0]:                # самая ранняя уже освободилась
            heapq.heappop(занятые)              # переиспользуем комнату
        heapq.heappush(занятые, конец)

    return len(занятые)

min_rooms([[1, 30], [5, 10], [15, 20]])   # → 2
min_rooms([[7, 10], [2, 4]])              # → 1
```

**Как это читать.** Куча — это множество занятых комнат, а её размер и есть ответ. На каждой встрече спрашиваем только одно: освободилась ли самая ранняя? Если да — занимаем её повторно (`pop` + `push`), если нет — комнат не хватает, и `push` без `pop` заводит новую.

> **Почему сортировка по началу обязательна.** Без неё алгоритм тихо завышает ответ. Возьмём те же данные в порядке `[1,30], [15,20], [5,10]`: сначала в куче `30`; встреча `[15,20]` — 15 < 30, заводим вторую комнату; встреча `[5,10]` — 5 < 20, заводим **третью**. Ответ 3 вместо 2. Причина: алгоритм считает, что время идёт вперёд, а мы подсунули ему прошлое.

#### Через разметку событий (без кучи)

Ту же задачу решает **сканирующая прямая** (sweep line): забыть про то, что интервалы парные, и смотреть только на события «кто-то пришёл» и «кто-то ушёл».

```python
def min_rooms_sweep(intervals):
    события = []
    for начало, конец in intervals:
        события.append((начало, +1))            # пришёл — комната занята
        события.append((конец, -1))             # ушёл — освободил
    события.sort()                              # -1 раньше +1 при равном времени

    текущие = ответ = 0
    for _, дельта in события:
        текущие += дельта
        ответ = max(ответ, текущие)
    return ответ
```

Асимптотика та же $O(n \log n)$ — упирается в сортировку, — но кода меньше и куча не нужна.

> Тонкость, ради которой это работает: при одинаковом времени `-1` должно обрабатываться раньше `+1`. Кортеж `(время, дельта)` сортируется как раз так, потому что `-1 < +1` — уход в момент `t` освобождает комнату для прихода в момент `t`. Поменяй знаки местами — и касающиеся встречи начнут требовать лишнюю комнату.

Приём шире одной задачи: так же считают пиковую нагрузку на сервер по логам сессий и максимальное число пассажиров в машине.

### Максимум непересекающихся: сортировка по концу

Задача-контрапункт ([#435 Non-overlapping Intervals](https://leetcode.com/problems/non-overlapping-intervals/)): провести **как можно больше** встреч в **одной** комнате. Здесь сортировка по началу даёт неверный ответ, и нужна сортировка по концу.

```python
def max_встреч(intervals):
    intervals.sort(key=lambda x: x[1])          # по КОНЦУ
    последний_конец = float("-inf")
    сколько = 0
    for начало, конец in intervals:
        if начало >= последний_конец:           # влезает
            сколько += 1
            последний_конец = конец
    return сколько

max_встреч([[1, 30], [5, 10], [15, 20]])   # → 2  (взяли [5,10] и [15,20])
```

Логика [жадности](../../Алгоритмы/Стратегии/Жадные%20алгоритмы.md): чтобы уместить максимум встреч, каждый раз бери ту, которая **раньше всех освобождает** комнату — она оставляет больше всего места остальным. Сортировка по началу тут проваливается: длинная встреча `[1, 30]` начинается первой, займёт комнату целиком и вытеснит две коротких.

> Это и есть главный водораздел класса: **считаем ресурсы — сортируем по началу; выбираем максимум непересекающихся — по концу.** Перепутать эти два случая — самая содержательная ошибка в интервальных задачах, в отличие от механической путаницы со знаками.

---

### Сложность

| Задача | Время | Память |
|---|---|---|
| Слияние | $O(n \log n)$ | $O(n)$ на ответ |
| Минимум комнат (куча) | $O(n \log n)$ | $O(n)$ на кучу |
| Минимум комнат (события) | $O(n \log n)$ | $O(n)$ на события |
| Максимум непересекающихся | $O(n \log n)$ | $O(1)$ |

Везде доминирует сортировка. Если интервалы **уже отсортированы** (частый случай в проде — данные пришли из индекса по времени), проход становится $O(n)$.

---

### Ловушки

- **Забыли отсортировать.** Алгоритм не падает, а молча даёт завышенный или заниженный ответ — на маленьком тесте можно не заметить.
- **Сортировка не по тому концу.** По началу вместо конца в задаче на максимум встреч — неверный ответ на любых данных с одной длинной встречей.
- **Перепутали строгость сравнения.** `[1,5)` и `[5,8)` в бронях не конфликтуют; `<=` вместо `<` заводит лишнюю комнату.
- **`max` при слиянии.** `result[-1][1] = конец` вместо `max(...)` ломается на вложенных интервалах.
- **Пустой вход.** `intervals[0]` на пустом списке — падение; проверять до обращения.
