# Префиксные суммы

**Префиксные суммы** (prefix sums, cumulative sums) — вспомогательный массив, где `pref[i]` хранит сумму всех элементов исходного массива до позиции `i`. Позволяет узнать сумму **любого отрезка за $O(1)$** после предподсчёта за $O(n)$.

> **Аналогия:** отметки километража на трассе. Чтобы узнать расстояние между двумя городами, не меряешь дорогу заново — берёшь разность отметок: `км(Б) − км(А)`.

Базовый приём для всего, где часто спрашивают «сумму на отрезке» или ищут подмассив с заданной суммой. Тесно связан с [Два указателя](../../Алгоритмы/Приёмы/Два%20указателя.md) и [Скользящее окно](../../Алгоритмы/Приёмы/Скользящее%20окно.md) — но, в отличие от них, работает и с **отрицательными** числами.

---

### Как работает

Договорённость: `pref` длиннее массива на 1, `pref[0] = 0` (пустой префикс), `pref[i] = pref[i-1] + a[i-1]`.

```
a    =    [2, 4, 1, 3]
pref = [0, 2, 6, 7, 10]
        ↑           ↑
     pref[0]=0   pref[4]=сумма всего
```

Тогда сумма отрезка `a[l..r]` (включительно) — это разность двух префиксов:

$$\text{sum}(l..r) = pref[r+1] - pref[l]$$

Сдвиг на 1 в `pref` избавляет от отдельной обработки случая `l == 0`.

### Реализации

#### Построение и сумма отрезка

```python
def build_prefix(a):
    pref = [0] * (len(a) + 1)
    for i, x in enumerate(a):
        pref[i + 1] = pref[i] + x
    return pref

def range_sum(pref, l, r):        # сумма a[l..r] включительно
    return pref[r + 1] - pref[l]

pref = build_prefix([2, 4, 1, 3])   # → [0, 2, 6, 7, 10]
range_sum(pref, 1, 2)               # → 5   (a[1] + a[2] = 4 + 1)
range_sum(pref, 0, 3)               # → 10  (вся сумма)
```

Готовый инструмент из stdlib — `itertools.accumulate`:

```python
from itertools import accumulate
list(accumulate([2, 4, 1, 3]))              # → [2, 6, 7, 10]
list(accumulate([2, 4, 1, 3], initial=0))   # → [0, 2, 6, 7, 10]  (как pref выше)
```

#### Предподсчёт в конструкторе класса (#303)

Задача [#303 Range Sum Query — Immutable](https://leetcode.com/problems/range-sum-query-immutable/) сформулирована как класс: массив приходит один раз в `__init__`, запросов суммы потом много. Это и есть канон приёма — предподсчёт живёт в конструкторе.

```python
class NumArray:
    def __init__(self, nums):
        self.pref = [0] * (len(nums) + 1)
        for i, x in enumerate(nums):
            self.pref[i + 1] = self.pref[i] + x

    def sumRange(self, left, right):
        return self.pref[right + 1] - self.pref[left]
```

> **Зачем нужен сдвиг на единицу, видно именно здесь.** Если хранить суммы «включительно» (`pref[i]` = сумма по `i`-й элемент), то `sumRange` требует ветки: при `left == 0` вернуть `pref[right]`, иначе `pref[right] - pref[left - 1]`. Ветка не ошибка, но она есть в каждом запросе и на ней легко промахнуться индексом. Соглашение `pref[0] = 0` убирает `if` совсем — одна формула на все случаи.

#### Число подмассивов с суммой = k (префикс + хеш)

Главный трюк: подмассив `a[l..r]` имеет сумму `k` ⟺ `pref[r+1] − pref[l] == k` ⟺ `pref[l] == pref[r+1] − k`. Значит, идя слева направо, храним, сколько раз каждый префикс уже встречался.

```python
from collections import defaultdict

def subarray_sum(nums, k):
    count = prefix = 0
    seen = defaultdict(int)
    seen[0] = 1                     # пустой префикс встречался 1 раз
    for x in nums:
        prefix += x
        count += seen[prefix - k]   # сколько прошлых префиксов дают нужную разницу
        seen[prefix] += 1
    return count

subarray_sum([1, 1, 1], 2)      # → 2
subarray_sum([1, -1, 0], 0)     # → 3   (работает и с отрицательными/нулём)
```

Это `O(n)` вместо `O(n²)` перебором пар — и, в отличие от [скользящего окна](../../Алгоритмы/Приёмы/Скользящее%20окно.md), работает при отрицательных элементах.

#### Разностный массив (обратный приём)

Если наоборот — много запросов «прибавить `v` на отрезке `[l, r]`», а результат нужен один раз в конце: копим приращения в `diff`, потом берём его префиксную сумму.

```python
def apply_ranges(n, updates):        # updates: список (l, r, v)
    diff = [0] * (n + 1)
    for l, r, v in updates:
        diff[l] += v
        diff[r + 1] -= v             # «выключаем» приращение за концом отрезка
    res, running = [], 0
    for i in range(n):
        running += diff[i]
        res.append(running)
    return res

apply_ranges(5, [(0, 2, 3), (1, 3, 2)])   # → [3, 5, 5, 2, 0]
```

#### 2D — префиксные суммы по матрице

Сумма любого прямоугольника за $O(1)$ по формуле включения-исключения:

```python
def build_prefix_2d(matrix):
    rows = len(matrix)
    cols = len(matrix[0])

    prefix = [[0] * (cols + 1) for _ in range(rows + 1)]

    for row in range(rows):
        for col in range(cols):
            prefix[row + 1][col + 1] = (
                matrix[row][col]
                + prefix[row][col + 1]
                + prefix[row + 1][col]
                - prefix[row][col]
            )

    return prefix


def rectangle_sum(prefix, top_row, left_col, bottom_row, right_col):
    """
    Сумма прямоугольника:
    от (top_row, left_col) до (bottom_row, right_col).
    """
    return (
        prefix[bottom_row + 1][right_col + 1]
        - prefix[top_row][right_col + 1]
        - prefix[bottom_row + 1][left_col]
        + prefix[top_row][left_col]
    )
```
---

### Big O 

| | Предподсчёт | Один запрос суммы |
|---|---|---|
| 1D | $O(n)$ | $O(1)$ |
| 2D | $O(R \cdot C)$ | $O(1)$ |
| Память | $O(n)$ / $O(R \cdot C)$ | — |

Выгодно, когда запросов много: `q` запросов наивно — $O(q \cdot n)$, с префиксами — $O(n + q)$.

---

### Когда применять

- Много запросов **суммы на отрезке** к неизменяемому массиву.
- Подмассив с **заданной суммой** / **нулевой суммой** / кратной `k` (префикс по модулю + хеш).
- Баланс/разность (например, «сколько единиц минус нулей» на отрезке).
- Много **обновлений на отрезке** с одним финальным чтением → разностный массив.
- Задачи на сетке — суммы подпрямоугольников (2D).

> Если массив меняется между запросами, префиксные суммы не спасут — нужно [дерево отрезков](../../Данные/Структуры%20данных/Дерево.md) или Fenwick-дерево.

---

### Плюсы и минусы

**Плюсы:**
- Запрос суммы за $O(1)$, простая идея.
- Работает с отрицательными числами (в отличие от скользящего окна).
- Хорошо комбинируется с хеш-таблицей (подмассивы с условием на сумму).

**Минусы:**
- Массив должен быть неизменяемым (иначе пересчёт $O(n)$).
- Лишняя память $O(n)$.
- Легко ошибиться на ±1 в индексах — помогает соглашение `pref[0] = 0`.
