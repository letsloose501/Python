# Фиктивный узел

**Фиктивный узел** (dummy node, sentinel, «заглушка», «страж») — пустой узел, который ставят перед началом или после конца [связного списка](../../Данные/Структуры%20данных/Связный%20и%20двусвязный%20список.md). Данных он не хранит и в ответе не участвует; его единственная работа — **гарантировать, что у каждого настоящего узла есть сосед**.

> **Аналогия:** ограничители на книжной полке. Книг между ними может быть сколько угодно, хоть ноль, но крайняя книга никогда не падает — слева и справа всегда что-то есть. Убери ограничители — и придётся каждый раз проверять, не крайняя ли книга в руках.

Приём ничего не ускоряет. Он убирает **ветвления на крайние случаи** — те самые `if node.prev is None`, на которых код в списках чаще всего и ломается.

---

### Какую боль лечит

В связном списке любая операция раздваивается: обычный случай и «а если это голова». Классическое удаление узла без заглушки:

```python
# БЕЗ ЗАГЛУШКИ — три ветки вместо одной
def remove(self, node):
    if node.prev:                    # не первый?
        node.prev.next = node.next
    else:                            # первый — двигаем head
        self.head = node.next
    if node.next:                    # не последний?
        node.next.prev = node.prev
    else:                            # последний — двигаем tail
        self.tail = node.prev
```

Четыре ветки, две переменные состояния (`head`, `tail`), и каждая — шанс забыть случай «в списке остался один узел». С двумя заглушками то же самое сжимается до двух строк:

```python
# С ЗАГЛУШКАМИ — веток нет вообще
def remove(self, node):
    node.prev.next = node.next       # сосед слева есть всегда
    node.next.prev = node.prev       # сосед справа есть всегда
```

Разница не в скорости — обе версии $O(1)$. Разница в том, что вторую **невозможно написать неправильно**: не осталось случая, который можно не обработать.

### Как устроено

#### Одна заглушка — односвязный список

Ставится перед головой. Нужна, когда список может **лишиться первого элемента** или начаться с пустого.

```
dummy → [A] → [B] → [C] → None
  ↑
результат всегда возвращаем как dummy.next
```

```python
def remove_all(head, target):
    """Удалить из списка все узлы со значением target (LeetCode #203)."""
    dummy = Node(None)
    dummy.next = head
    prev = dummy
    while prev.next:
        if prev.next.data == target:
            prev.next = prev.next.next     # выкинули, head в том числе
        else:
            prev = prev.next
    return dummy.next                      # ← новая голова, какой бы она ни стала
```

Без заглушки пришлось бы отдельно крутить цикл «пока голова равна target — сдвинуть голову», и только потом идти по остатку. Заглушка делает голову обычным узлом.

> Главное правило: **возвращать `dummy.next`, а не `head`.** Переменная `head` могла устареть — если первый узел удалили, она указывает на выброшенный элемент. Это самая частая ошибка при использовании приёма.

#### Две заглушки — двусвязный список

Голова и хвост, замкнутые друг на друга. Настоящие узлы живут строго между ними.

```
пустой список:   [head] ←→ [tail]
две записи:      [head] ←→ [A] ←→ [B] ←→ [tail]

вставка в голову = вставка после head
вытеснение с конца = удаление tail.prev
```

```python
class DLL:
    def __init__(self):
        self.head = Node()               # заглушки, в данных не участвуют
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    def add_to_head(self, node):
        node.next = self.head.next       # порядок важен: сначала новый смотрит наружу
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def is_empty(self):
        return self.head.next is self.tail    # проверка пустоты без счётчика
```

Пустой список перестаёт быть особым состоянием: `head.next is tail` — обычная проверка, а не «а вдруг `None`». Именно эта схема стоит внутри [LRU-кэша](../../Алгоритмы/Задачки/LRU-кэш.md) и внутри [`functools.lru_cache`](../../Библиотеки/Модули/Функциональные%20инструменты/functools.md) в стандартной библиотеке — там роль обеих заглушек играет один узел `root`, замкнутый сам на себя в кольцо.

#### Кольцевой вариант — одна заглушка вместо двух

Если список замкнуть в кольцо, хватит одного стража: он же и голова, и хвост.

```
        ┌──────────────────────┐
        ↓                      │
     [root] ←→ [A] ←→ [B] ←→ ──┘

root.next  — самый свежий
root.prev  — самый старый (кандидат на вылет)
пустой список: root.next is root
```

Экономит один узел и убирает разделение «начало/конец» — так сделано в CPython.

#### Страж в массиве

Тот же приём вне списков: добавить в конец данных элемент, который гарантированно завершит обработку, — чтобы не писать отдельный цикл «доработать остаток» после основного.

```python
for i, h in enumerate(heights + [0]):     # +страж: 0 ниже любого столбца
    while stack and heights[stack[-1]] > h:
        ...                               # он вытолкнет из стека всё, что осталось
```

Без нуля в конце после цикла понадобился бы второй, дублирующий тело первого. Разобрано в [наибольшем прямоугольнике](../../Алгоритмы/Приёмы/Монотонный%20стек.md#наибольший-прямоугольник-в-гистограмме-классика-посложнее).

### Цена

| | Без заглушек | С заглушками |
|---|---|---|
| Ветвления на краях | 2–4 на операцию | нет |
| Память | — | +1–2 узла на список |
| Скорость | та же | та же |
| Где ошибаются | забытый крайний случай | забыли вернуть `dummy.next` |

Один-два лишних узла на всю структуру — константа, которая не зависит от размера. Плата символическая, поэтому в продакшн-реализациях связных списков заглушки — норма, а не оптимизация.

---

### Когда применять

- Операция может **удалить или заменить первый узел** — тогда `head` перестаёт быть надёжной.
- Список может стать **пустым** в середине работы.
- Нужны **вставка и удаление с обоих концов** — двусвязный список с двумя заглушками.
- В коде появились парные `if node.prev is None` / `if node.next is None` — верный признак, что стража не хватает.

**Сигнал:** пишешь операцию над связным списком и ловишь себя на «а если это первый элемент» — ставь заглушку, не разбирай случай.

---

### Ловушки

- **Вернули `head` вместо `dummy.next`.** Если первый узел удалён, `head` указывает на мусор. Возвращать всегда `dummy.next`.
- **Удалили голову, не подвинув `head`.** Отказ от заглушки в структуре с полем `self.head` даёт худший вид ошибки: код не падает, а **молча не работает** — узлы перецеплены, но объект списка по-прежнему ссылается на удалённый. С заглушкой поля `head` нет вовсе, настоящая голова — это `dummy.next`, и рассинхронизироваться нечему.
- **Заглушка попала в данные.** Её нельзя класть в словарь ключей, считать в длине или отдавать наружу при обходе. В [LRU-кэше](../../Алгоритмы/Задачки/LRU-кэш.md) заглушки принципиально не хранятся в хеш-таблице — иначе они окажутся кандидатами на вытеснение.
- **Забыли связать заглушки при создании.** `head.next = tail` и `tail.prev = head` — без этой пары в конструкторе первая же операция упрётся в `None`, и весь смысл приёма пропадёт.
- **Один `dummy` на два списка.** При слиянии двух списков каждому нужен свой страж; общий свяжет их между собой.
