# Алгоритм Дейкстры

**Алгоритм Дейкстры** — нахождение кратчайшего пути от одной вершины до всех остальных во взвешенном графе с **неотрицательными** весами рёбер.

> **Аналогия:** ищешь самый дешёвый маршрут между городами. На каждом шаге выбираешь ближайший ещё не посещённый город, обновляешь стоимость проезда через него к его соседям. Когда достиг нужного города — нашёл оптимальный маршрут.

[BFS](../../Алгоритмы/Поиск/BFS.md) находит путь с **наименьшим числом рёбер**. Дейкстра — путь с **наименьшей суммой весов**. Если нужно учитывать стоимость, время или расстояние — нужен Дейкстра.

---

### Как работает

```
граф (взвешенный):
    A —(4)— B
    |       |
   (2)     (1)
    |       |
    C —(5)— D

старт: A

инициализация:
  расстояния = {A: 0, B: ∞, C: ∞, D: ∞}
  не обработаны: {A, B, C, D}

шаг 1: берём A (расстояние 0)
  через A до B: 0+4=4 < ∞ → обновить B=4
  через A до C: 0+2=2 < ∞ → обновить C=2
  расстояния = {A:0, B:4, C:2, D:∞}

шаг 2: берём C (расстояние 2, наименьшее из необработанных)
  через C до D: 2+5=7 < ∞ → обновить D=7
  расстояния = {A:0, B:4, C:2, D:7}

шаг 3: берём B (расстояние 4)
  через B до D: 4+1=5 < 7 → обновить D=5
  расстояния = {A:0, B:4, C:2, D:5}

шаг 4: берём D (расстояние 5) — все обработаны

итог: A→C→B→D = 0+2+4+1 = 7? нет:
  A→C = 2, C не ведёт в B
  A→B = 4, B→D = 1 → A→B→D = 5 ✓
```

Ключевая идея: когда вершина выбирается как «с наименьшим расстоянием» — более дешёвого пути к ней уже не существует. Поэтому обработанные вершины не пересматриваются.

---

### Реализации

#### С очередью с приоритетом — $O((V + E) \log V)$

Стандартная эффективная реализация через `heapq`.

```python
import heapq

def дейкстра(граф, старт):
    """
    граф: {вершина: [(сосед, вес), ...]}
    возвращает: (расстояния, предшественники)
    """
    расстояния = {v: float("inf") for v in граф}
    расстояния[старт] = 0
    предшественник = {старт: None}

    # (расстояние, вершина)
    очередь = [(0, старт)]

    while очередь:
        текущее, вершина = heapq.heappop(очередь)

        # устаревшая запись — пропустить
        if текущее > расстояния[вершина]:
            continue

        for сосед, вес in граф[вершина]:
            новое = расстояния[вершина] + вес
            if новое < расстояния[сосед]:
                расстояния[сосед] = новое
                предшественник[сосед] = вершина
                heapq.heappush(очередь, (новое, сосед))

    return расстояния, предшественник


def восстановить_путь(предшественник, цель):
    путь = []
    текущая = цель
    while текущая is not None:
        путь.append(текущая)
        текущая = предшественник.get(текущая)
    return путь[::-1]


граф = {
    "A": [("B", 4), ("C", 2)],
    "B": [("D", 1)],
    "C": [("B", 1), ("D", 5)],
    "D": [],
}
расст, пред = дейкстра(граф, "A")
print(расст)                           # → {"A":0, "B":3, "C":2, "D":4}
print(восстановить_путь(пред, "D"))    # → ["A", "C", "B", "D"]
```

#### Наивная реализация — $O(V^2)$

Без очереди с приоритетом. Проще, но медленнее на больших графах.

```python
def дейкстра_наивный(граф, старт):
    расстояния = {v: float("inf") for v in граф}
    расстояния[старт] = 0
    предшественник = {старт: None}
    обработаны = set()

    while len(обработаны) < len(граф):
        # найти необработанную вершину с минимальным расстоянием
        вершина = min(
            (v for v in граф if v not in обработаны),
            key=lambda v: расстояния[v]
        )
        if расстояния[вершина] == float("inf"):
            break   # остальные вершины недостижимы

        обработаны.add(вершина)

        for сосед, вес in граф[вершина]:
            новое = расстояния[вершина] + вес
            if новое < расстояния[сосед]:
                расстояния[сосед] = новое
                предшественник[сосед] = вершина

    return расстояния, предшественник
```

#### Дейкстра на матрице (сетка с весами)

```python
import heapq

def дейкстра_матрица(сетка, старт, цель):
    """
    сетка — двумерный список весов (стоимость прохода через клетку)
    """
    строк, столбцов = len(сетка), len(сетка[0])
    расст = [[float("inf")] * столбцов for _ in range(строк)]
    sr, sc = старт
    расст[sr][sc] = 0
    очередь = [(0, старт)]
    предшественник = {старт: None}

    направления = [(0,1),(0,-1),(1,0),(-1,0)]

    while очередь:
        стоимость, (r, c) = heapq.heappop(очередь)
        if стоимость > расст[r][c]:
            continue
        if (r, c) == цель:
            break
        for dr, dc in направления:
            nr, nc = r + dr, c + dc
            if 0 <= nr < строк and 0 <= nc < столбцов:
                новая = расст[r][c] + сетка[nr][nc]
                if новая < расст[nr][nc]:
                    расст[nr][nc] = новая
                    предшественник[(nr, nc)] = (r, c)
                    heapq.heappush(очередь, (новая, (nr, nc)))

    # восстановить путь
    путь = []
    текущая = цель
    while текущая is not None:
        путь.append(текущая)
        текущая = предшественник.get(текущая)
    return расст[цель[0]][цель[1]], путь[::-1]


сетка = [
    [1, 3, 1],
    [1, 5, 1],
    [4, 2, 1],
]
стоимость, путь = дейкстра_матрица(сетка, (0,0), (2,2))
print(стоимость)   # → 7
print(путь)        # → [(0,0),(0,1),(0,2),(1,2),(2,2)] или другой
```

#### Двунаправленный Дейкстра — быстрее на больших графах

Запускаем поиск одновременно от старта и от цели. Встречаемся посередине — примерно в два раза быстрее.

```python
import heapq

def двунаправленный_дейкстра(граф, обратный_граф, старт, цель):
    """обратный_граф — те же рёбра, но в другую сторону"""
    dist_f = {v: float("inf") for v in граф}
    dist_b = {v: float("inf") for v in граф}
    dist_f[старт] = 0
    dist_b[цель] = 0

    heap_f = [(0, старт)]
    heap_b = [(0, цель)]
    посещ_f = set()
    посещ_b = set()

    лучший = float("inf")

    while heap_f or heap_b:
        # шаг вперёд
        if heap_f:
            d, v = heapq.heappop(heap_f)
            if v not in посещ_f:
                посещ_f.add(v)
                for сосед, вес in граф[v]:
                    if dist_f[v] + вес < dist_f[сосед]:
                        dist_f[сосед] = dist_f[v] + вес
                        heapq.heappush(heap_f, (dist_f[сосед], сосед))
                if v in посещ_b:
                    лучший = min(лучший, dist_f[v] + dist_b[v])

        # шаг назад
        if heap_b:
            d, v = heapq.heappop(heap_b)
            if v not in посещ_b:
                посещ_b.add(v)
                for сосед, вес in обратный_граф[v]:
                    if dist_b[v] + вес < dist_b[сосед]:
                        dist_b[сосед] = dist_b[v] + вес
                        heapq.heappush(heap_b, (dist_b[сосед], сосед))
                if v in посещ_f:
                    лучший = min(лучший, dist_f[v] + dist_b[v])

        if посещ_f & посещ_b:
            break

    return лучший
```

---

### Big O

|Реализация|Время|Память|
|---|---|---|
|Наивная (линейный поиск минимума)|$O(V^2)$|$O(V)$|
|С бинарной кучей (`heapq`)|$O((V + E) \log V)$|$O(V + E)$|
|С фибоначчиевой кучей|$O(V \log V + E)$|$O(V)$|

На разреженных графах ($E \ll V^2$) — куча лучше. На плотных ($E \approx V^2$) — наивная может быть сравнима.

---

### Ограничения

**Отрицательные веса — не работает.** Когда вершина «закрывается», считается что дешевле не будет. Отрицательное ребро может опровергнуть это предположение.

```
A —(1)— B —(-3)— C
A —(3)— C

Дейкстра от A:
  закрывает C на расстоянии 3
  позже через B: 1 + (-3) = -2 — но C уже закрыта!
  → неверный ответ
```

Для графов с отрицательными весами — [Алгоритм Беллмана — Форда](../../Алгоритмы/Поиск/Алгоритм%20Беллмана%20—%20Форда.md).

---

### Дейкстра vs другие алгоритмы поиска пути

|Алгоритм|Веса|Отриц. веса|Сложность|Когда|
|---|---|---|---|---|
|[BFS](../../Алгоритмы/Поиск/BFS.md)|Нет|—|$O(V+E)$|Невзвешенный граф|
|Дейкстра|Да|✗|$O((V+E)\log V)$|Веса ≥ 0|
|[Беллман-Форд](../../Алгоритмы/Поиск/Алгоритм%20Беллмана%20—%20Форда.md)|Да|✓|$O(V \cdot E)$|Есть отрицательные веса|
|A*|Да|✗|$O(E \log V)$|Есть эвристика (координаты)|

---

### Плюсы и минусы

**Плюсы:**

- Гарантированно находит кратчайший путь при неотрицательных весах
- Эффективен с очередью с приоритетом
- Находит расстояния до **всех** вершин за один запуск
- Основа для A*, навигационных алгоритмов

**Минусы:**

- Не работает с отрицательными весами
- На очень плотных графах медленнее наивного $O(V^2)$
- Не подходит для динамически меняющихся графов

---

### Применение

- GPS-навигация — кратчайший маршрут между городами
- Маршрутизация в сетях — OSPF-протокол строит таблицы маршрутизации через Дейкстру
- Игры — поиск пути персонажа по карте с разной стоимостью клеток
- Авиабилеты — минимальная стоимость перелёта с пересадками
- Логистика — минимальное время или стоимость доставки

```python
# пример: граф городов
города = {
    "Москва":       [("Тверь", 167), ("Тула", 193)],
    "Тверь":        [("Москва", 167), ("Питер", 485)],
    "Тула":         [("Москва", 193), ("Воронеж", 390)],
    "Питер":        [("Тверь", 485)],
    "Воронеж":      [("Тула", 390)],
}
расст, пред = дейкстра(города, "Москва")
print(расст)
# → {"Москва":0, "Тверь":167, "Тула":193, "Питер":652, "Воронеж":583}
print(восстановить_путь(пред, "Питер"))
# → ["Москва", "Тверь", "Питер"]
```

> Отрицательные веса → [Алгоритм Беллмана — Форда](../../Алгоритмы/Поиск/Алгоритм%20Беллмана%20—%20Форда.md). Невзвешенный граф → [BFS — поиск в ширину](../../Алгоритмы/Поиск/BFS.md). Нотация — Вычислительная сложность.
