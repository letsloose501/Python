# Сортировка слиянием

**Сортировка слиянием** (Merge Sort) — разбить массив пополам, рекурсивно отсортировать каждую половину, затем слить две отсортированных части в одну. Стратегия «разделяй и властвуй».

> **Аналогия:** две колоды карт, каждая уже отсортирована. Чтобы слить их в одну: смотришь на верхние карты обеих колод, берёшь меньшую — и так пока колоды не кончатся.

Гарантирует $O(n \log n)$ в любом случае. Это делает её надёжнее быстрой сортировки — нет худшего случая.

---

### Как работает

```
[5, 3, 1, 4, 2]

разбить:
  [5, 3, 1]       [4, 2]
  [5, 3] [1]    [4] [2]
  [5][3]

сортировать и сливать снизу вверх:
  [3, 5]  [1]  →  [1, 3, 5]
  [2, 4]
  [1, 3, 5] + [2, 4] → [1, 2, 3, 4, 5]
```

Слияние двух отсортированных массивов: смотрим на начало каждого, берём меньший элемент, двигаемся дальше.

```
[1, 3, 5]  +  [2, 4]
 ↑                ↑
 1 < 2  → берём 1    → [1]
 3 > 2  → берём 2    → [1, 2]
 3 < 4  → берём 3    → [1, 2, 3]
 5 > 4  → берём 4    → [1, 2, 3, 4]
 остаток [5]         → [1, 2, 3, 4, 5]
```

### Реализации

#### Классическая рекурсивная

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr                         # базовый случай

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])           # рекурсивно левую половину
    right = merge_sort(arr[mid:])          # рекурсивно правую половину
    return merge(left, right)

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:            # <= для устойчивости
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])               # добавить остаток
    result.extend(right[j:])
    return result

merge_sort([5, 3, 1, 4, 2])   # → [1, 2, 3, 4, 5]
```

#### На месте (in-place) — без дополнительного массива

Экономит $O(n)$ памяти, но медленнее из-за сдвигов элементов.

```python
def merge_sort_inplace(arr, left=0, right=None):
    if right is None:
        right = len(arr) - 1
    if left >= right:
        return
    mid = (left + right) // 2
    merge_sort_inplace(arr, left, mid)
    merge_sort_inplace(arr, mid + 1, right)
    merge_inplace(arr, left, mid, right)

def merge_inplace(arr, left, mid, right):
    i, j = left, mid + 1
    while i <= mid and j <= right:
        if arr[i] <= arr[j]:
            i += 1
        else:
            val = arr[j]
            # сдвинуть [i..j-1] вправо на 1
            for k in range(j, i, -1):
                arr[k] = arr[k - 1]
            arr[i] = val
            i += 1
            mid += 1
            j += 1

arr = [5, 3, 1, 4, 2]
merge_sort_inplace(arr)
print(arr)   # → [1, 2, 3, 4, 5]
```

#### Итеративная (снизу вверх) — без рекурсии

Начинаем с подмассивов размером 1, сливаем в 2, потом в 4, 8 и т.д. Избегает накладных расходов рекурсии и переполнения стека.

```python
def merge_sort_iterative(arr):
    n = len(arr)
    размер = 1
    while размер < n:
        for left in range(0, n, размер * 2):
            mid = min(left + размер, n)
            right = min(left + размер * 2, n)
            if mid < right:
                merged = merge(arr[left:mid], arr[mid:right])
                arr[left:right] = merged
        размер *= 2
    return arr

merge_sort_iterative([5, 3, 1, 4, 2])   # → [1, 2, 3, 4, 5]
```

#### С ключом и направлением

```python
def merge_sort_key(arr, key=None, reverse=False):
    key = key or (lambda x: x)

    def _merge(left, right):
        result = []
        i = j = 0
        while i < len(left) and j < len(right):
            a, b = key(left[i]), key(right[j])
            if (a <= b) if not reverse else (a >= b):
                result.append(left[i]); i += 1
            else:
                result.append(right[j]); j += 1
        result.extend(left[i:])
        result.extend(right[j:])
        return result

    def _sort(arr):
        if len(arr) <= 1:
            return arr
        mid = len(arr) // 2
        return _merge(_sort(arr[:mid]), _sort(arr[mid:]))

    return _sort(list(arr))


# сортировка по длине строки:
merge_sort_key(["банан", "киви", "яблоко"], key=len)
# → ["киви", "банан", "яблоко"]

# сортировка по убыванию:
merge_sort_key([3, 1, 4, 1, 5], reverse=True)
# → [5, 4, 3, 1, 1]
```

#### Natural Merge Sort — использует уже отсортированные «пробеги»

Вместо принудительного деления пополам — находит уже отсортированные подпоследовательности (runs) и сливает их. Эффективен на почти отсортированных данных.

```python
def find_runs(arr):
    """Найти уже отсортированные подпоследовательности."""
    runs = []
    i = 0
    while i < len(arr):
        run_start = i
        i += 1
        while i < len(arr) and arr[i] >= arr[i - 1]:
            i += 1
        runs.append(arr[run_start:i])
    return runs

def natural_merge_sort(arr):
    runs = find_runs(arr)
    while len(runs) > 1:
        merged = []
        for i in range(0, len(runs), 2):
            if i + 1 < len(runs):
                merged.append(merge(runs[i], runs[i + 1]))
            else:
                merged.append(runs[i])
        runs = merged
    return runs[0] if runs else []

natural_merge_sort([1, 3, 5, 2, 4, 6])
# runs: [[1,3,5], [2,4,6]] → [1,2,3,4,5,6]
```

### Big O

|Случай|Время|Память|
|---|---|---|
|Лучший|$O(n \log n)$|$O(n)$|
|Средний|$O(n \log n)$|$O(n)$|
|Худший|$O(n \log n)$|$O(n)$|

$\log n$ уровней рекурсии × $O(n)$ на слияние каждого уровня = $O(n \log n)$ всегда.

Память $O(n)$ — нужен вспомогательный массив для слияния. Это главный недостаток по сравнению с быстрой сортировкой ($O(\log n)$ памяти).

---

### Устойчивость

**Устойчивый** алгоритм — при `left[i] <= right[j]` (строгое ≤) элементы из левой половины предпочитаются при равенстве, исходный порядок сохраняется.

```python
данные = [("Аня", 2), ("Боря", 1), ("Вася", 2)]
merge_sort_key(данные, key=lambda x: x[1])
# → [("Боря", 1), ("Аня", 2), ("Вася", 2)]
# Аня стоит перед Васей — порядок сохранён ✓
```

Именно поэтому `sorted()` и `list.sort()` в Python используют **Timsort** — гибрид сортировки слиянием и сортировки вставками — который тоже устойчив.

---

### Плюсы и минусы

**Плюсы:**

- Гарантированный $O(n \log n)$ — нет плохих входных данных
- Устойчивый алгоритм
- Хорошо параллелится — левая и правая половины независимы
- Эффективен для связных списков — не нужен случайный доступ
- Основа Timsort (Python, Java, Android)

**Минусы:**

- $O(n)$ дополнительной памяти — нужен вспомогательный массив
- На практике медленнее быстрой сортировки из-за большей константы
- Рекурсивная версия использует $O(\log n)$ стека вызовов

---

### Применение

- Сортировка связных списков — слияние не требует случайного доступа, $O(1)$ памяти
- Внешняя сортировка — данные не помещаются в RAM: читаем блоками, сортируем, сливаем с диска
- Когда нужна устойчивость — сохранить относительный порядок равных элементов
- Параллельные системы — подмассивы сортируются независимо на разных ядрах
- Timsort — именно на этом основан `sorted()` в Python

```python
# Python уже использует Timsort (гибрид merge sort + insertion sort):
data = [("Аня", 2), ("Боря", 1), ("Вася", 2)]
sorted(data, key=lambda x: x[1])   # устойчиво, O(n log n)
```
