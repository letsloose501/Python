# Сортировка вставками

**Сортировка вставками** (Insertion Sort) — берём элементы по одному и **вставляем** каждый на своё место среди уже отсортированной левой части, сдвигая большие элементы вправо.

> **Аналогия:** раскладываешь игральные карты в руке. Берёшь новую карту и вдвигаешь её между уже упорядоченными, отодвигая соседей, пока не найдёшь место.

Простая квадратичная сортировка, но на практике — **быстрейшая из простых**: на маленьких и почти отсортированных массивах обгоняет пузырёк и выбор. Именно её используют внутри «взрослых» сортировок (Timsort) для коротких участков.

---

### Как работает

Левая часть всегда отсортирована; берём первый элемент справа и вставляем его на место.

```
[5 | 3, 4, 1, 2]        отсортировано: [5]
взять 3: 3 < 5 → сдвинуть 5 → [3, 5 | 4, 1, 2]
взять 4: 4 < 5 сдвиг, 4 > 3 стоп → [3, 4, 5 | 1, 2]
взять 1: меньше всех → [1, 3, 4, 5 | 2]
взять 2: → [1, 2, 3, 4, 5]
```

Ключ: во внутреннем цикле большие элементы **сдвигаются вправо**, освобождая место, и только потом вставляется взятый.

---

### Реализация

```python
def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]                     # элемент, который вставляем
        j = i - 1
        while j >= 0 and arr[j] > key:   # сдвигаем большие вправо
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key                 # вставляем на найденное место
    return arr

insertion_sort([5, 3, 4, 1, 2])   # → [1, 2, 3, 4, 5]
```

С ключом и порядком:

```python
def insertion_sort(arr, key=lambda x: x, reverse=False):
    arr = list(arr)
    for i in range(1, len(arr)):
        cur = arr[i]
        j = i - 1
        while j >= 0 and ((key(arr[j]) > key(cur)) != reverse):
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = cur
    return arr
```

### Big O

|Случай|Сложность|Когда|
|---|---|---|
|Лучший|$O(n)$|Массив уже отсортирован — внутренний `while` не срабатывает|
|Средний|$O(n^2)$|Произвольный порядок|
|Худший|$O(n^2)$|Обратный порядок — каждый элемент едет в начало|
|Память|$O(1)$|На месте, сдвигами|

**Адаптивна:** чем ближе массив к отсортированному, тем быстрее (мало сдвигов). На почти готовых данных — почти $O(n)$.

---

### Устойчивость

**Устойчива:** равные элементы не меняют порядок — сдвиг идёт при строгом `arr[j] > key`, равный элемент останавливает цикл, и взятый встаёт **после** него.

---

### Плюсы и минусы

**Плюсы:**
- Простая, компактная реализация.
- $O(1)$ памяти, сортирует на месте.
- Устойчивая и **адаптивная** — быстра на почти отсортированных данных.
- **Онлайн** — может сортировать поток: вставлять элементы по мере поступления.

**Минусы:**
- $O(n^2)$ — медленна на больших случайных данных.
- Много сдвигов при обратном порядке.

---

### Применение

- Маленькие массивы (десятки элементов) — быстрее «умных» сортировок из-за низкой константы.
- Почти отсортированные данные (адаптивность).
- **Внутри Timsort** (стандартный `sorted()`/`list.sort()` в Python) и introsort — короткие участки досортировываются именно вставками.
- Онлайн-сортировка потока данных.
