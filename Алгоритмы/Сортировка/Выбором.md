# Сортировка выбором

**Сортировка выбором** (Selection Sort) — на каждом шаге находить минимальный (или максимальный) элемент в оставшейся части массива и ставить его на нужную позицию. Повторять до конца.

> **Аналогия:** раскладываешь карты в руке. Смотришь на все, вытаскиваешь наименьшую, кладёшь первой. Потом снова смотришь на оставшиеся, вытаскиваешь наименьшую из них — и так далее.

Прямолинейный алгоритм с минимальным числом обменов. $O(n^2)$ всегда, без исключений.

---

### Как работает

```
[5, 3, 1, 4, 2]

шаг 1: минимум в [5,3,1,4,2] = 1 (индекс 2) → меняем с позицией 0
       [1, 3, 5, 4, 2]

шаг 2: минимум в [3,5,4,2] = 2 (индекс 4) → меняем с позицией 1
       [1, 2, 5, 4, 3]

шаг 3: минимум в [5,4,3] = 3 (индекс 4) → меняем с позицией 2
       [1, 2, 3, 4, 5]

шаг 4: минимум в [4,5] = 4 (уже на месте)
       [1, 2, 3, 4, 5]

шаг 5: один элемент — готово
```

За $n$ шагов выполняется ровно $n-1$ обменов — это главное отличие от пузырьковой, где обменов в разы больше.

---

### Реализации

#### Базовая (поиск минимума)

```python
def selection_sort(arr):
    n = len(arr)
    for i in range(n):
        min_idx = i
        for j in range(i + 1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]   # не более n-1 обменов
    return arr

selection_sort([5, 3, 1, 4, 2])   # → [1, 2, 3, 4, 5]
```

#### По убыванию (поиск максимума)

```python
def selection_sort_desc(arr):
    n = len(arr)
    for i in range(n):
        max_idx = i
        for j in range(i + 1, n):
            if arr[j] > arr[max_idx]:
                max_idx = j
        arr[i], arr[max_idx] = arr[max_idx], arr[i]
    return arr

selection_sort_desc([3, 1, 4, 1, 5])   # → [5, 4, 3, 1, 1]
```

#### С ключом сортировки

```python
def selection_sort_key(arr, key=None, reverse=False):
    arr = list(arr)
    n = len(arr)
    key = key or (lambda x: x)
    for i in range(n):
        best_idx = i
        for j in range(i + 1, n):
            a, b = key(arr[j]), key(arr[best_idx])
            если_лучше = a < b if not reverse else a > b
            if если_лучше:
                best_idx = j
        arr[i], arr[best_idx] = arr[best_idx], arr[i]
    return arr

# сортировка строк по длине:
selection_sort_key(["банан", "яблоко", "киви"], key=len)
# → ["киви", "банан", "яблоко"]

# сортировка словарей по полю:
users = [{"имя": "Боря", "возраст": 30}, {"имя": "Аня", "возраст": 25}]
selection_sort_key(users, key=lambda u: u["возраст"])
# → [{"имя": "Аня", ...}, {"имя": "Боря", ...}]
```

#### Двойной выбор — минимум и максимум за один проход

За каждую итерацию внешнего цикла ищем сразу оба — минимум и максимум — и ставим на свои места. Количество проходов уменьшается вдвое, но сложность остаётся $O(n^2)$.

```python
def double_selection_sort(arr):
    arr = list(arr)
    left, right = 0, len(arr) - 1
    while left < right:
        min_idx, max_idx = left, left
        for i in range(left, right + 1):
            if arr[i] < arr[min_idx]:
                min_idx = i
            if arr[i] > arr[max_idx]:
                max_idx = i
        arr[left], arr[min_idx] = arr[min_idx], arr[left]
        # max_idx мог сдвинуться если он был на left:
        if max_idx == left:
            max_idx = min_idx
        arr[right], arr[max_idx] = arr[max_idx], arr[right]
        left += 1
        right -= 1
    return arr

double_selection_sort([3, 1, 5, 2, 4])   # → [1, 2, 3, 4, 5]
```

#### Через класс

```python
class SelectionSort:
    def __init__(self, key=None, reverse=False):
        self.key = key or (lambda x: x)
        self.reverse = reverse

    def sort(self, arr):
        arr = list(arr)
        n = len(arr)
        for i in range(n):
            best = i
            for j in range(i + 1, n):
                a, b = self.key(arr[j]), self.key(arr[best])
                if (a < b) if not self.reverse else (a > b):
                    best = j
            arr[i], arr[best] = arr[best], arr[i]
        return arr


sorter = SelectionSort(key=lambda x: -x)   # по убыванию через ключ
sorter.sort([3, 1, 4, 1, 5, 9])            # → [9, 5, 4, 3, 1, 1]
```

### Big O

|Случай|Сложность|Причина|
|---|---|---|
|Лучший|$O(n^2)$|Всегда делает полный поиск минимума|
|Средний|$O(n^2)$|—|
|Худший|$O(n^2)$|—|
|Память|$O(1)$|Сортировка на месте|
|Обменов|$O(n)$|Ровно $n-1$ обмен максимум|

Сравнений всегда $\frac{n(n-1)}{2}$ — независимо от исходного порядка. Это отличает её от пузырьковой, у которой в лучшем случае $O(n)$ сравнений.

---

### Устойчивость

**Неустойчивый** алгоритм — равные элементы могут менять взаимный порядок.

```python
данные = [("Боря", 2), ("Аня", 2), ("Вася", 1)]
# после сортировки по второму полю:
# → [("Вася", 1), ("Аня", 2), ("Боря", 2)]  — порядок Боря/Аня нарушен
```

Обмен с далёким элементом может «перепрыгнуть» через равные. Для стабильной сортировки нужно использовать [Сортировка слиянием](../../Алгоритмы/Сортировка/Слиянием.md) или [Сортировка пузырьком](../../Алгоритмы/Сортировка/Пузырьком.md).

---

### Плюсы и минусы

**Плюсы:**

- Минимальное число обменов — ровно $n-1$. Важно когда запись в память дороже чтения (например, флеш-память)
- $O(1)$ памяти — сортирует на месте
- Простая реализация
- Предсказуемое поведение — сложность не зависит от входных данных

**Минусы:**

- $O(n^2)$ сравнений всегда — нельзя сократить даже на отсортированном массиве
- Медленнее пузырьковой на почти отсортированных данных
- Неустойчивый — нарушает порядок равных элементов

---

### Применение

- Запись дорогостоящая, чтение дешёвое — EEPROM, флеш-память, SSD: минимизировать количество записей выгодно
- Маленькие массивы (до ~10 элементов) — накладные расходы других алгоритмов не оправданы
- Учебные задачи — простейшая иллюстрация инварианта «отсортированный префикс»
- Сортировка когда количество данных фиксировано и мало — железо с ограниченными ресурсами
