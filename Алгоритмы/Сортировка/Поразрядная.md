# Поразрядная сортировка

**Поразрядная сортировка** (Radix Sort) — сортировка **без сравнений** для чисел (или строк фиксированной длины): упорядочивает данные по **разрядам**, обрабатывая по одному разряду за раз устойчивой [сортировкой подсчётом](../../Алгоритмы/Сортировка/Подсчётом.md). Вариант **LSD** идёт от младшего разряда к старшему.

> **Идея:** сначала разложить числа по последней цифре, потом по предпоследней, и так до самой старшей. После прохода по всем разрядам массив отсортирован. Магия — в **устойчивости** подсортировки: она не ломает порядок, уже наведённый по младшим разрядам.

---

### Как работает (LSD)

Массив `[170, 45, 75, 90, 2, 802, 66]`:

```
по единицам:  170, 90, 2, 802, 45, 75, 66
по десяткам:  2, 802, 45, 66, 170, 75, 90
по сотням:    2, 45, 66, 75, 90, 170, 802   ← отсортировано
```

На каждом шаге числа лишь перераспределяются по одной цифре — но устойчиво, поэтому равенство по текущему разряду сохраняет порядок, наведённый ранее.

---

### Реализация

```python
def radix_sort(arr):
    if not arr:
        return arr
    max_val = max(arr)
    exp = 1                               # разряд: 1 (единицы), 10, 100, ...
    while max_val // exp > 0:
        arr = _counting_by_digit(arr, exp)   # устойчиво по текущему разряду
        exp *= 10
    return arr

def _counting_by_digit(arr, exp):
    count = [0] * 10                      # 10 цифр: 0..9
    for x in arr:
        count[(x // exp) % 10] += 1       # цифра текущего разряда
    for i in range(1, 10):
        count[i] += count[i - 1]          # префиксные суммы → позиции
    result = [0] * len(arr)
    for x in reversed(arr):               # с конца — устойчивость ОБЯЗАТЕЛЬНА
        d = (x // exp) % 10
        count[d] -= 1
        result[count[d]] = x
    return result

radix_sort([170, 45, 75, 90, 2, 802, 66])   # → [2, 45, 66, 75, 90, 170, 802]
```

> Подсортировка по разряду **должна быть устойчивой** — иначе порядок по уже обработанным (младшим) разрядам разрушится, и алгоритм даст неверный результат.

---

### Big O

|Показатель|Значение|
|---|---|
|Время|$O(d \cdot (n + k))$: $d$ — число разрядов, $k$ — основание (10)|
|Память|$O(n + k)$|
|Устойчивость|да (и требует устойчивой подсортировки)|
|На месте|нет|

Для чисел **фиксированной ширины** $d$ — константа, поэтому фактически $O(n)$. Но при больших числах (много разрядов) и малом $n$ константа $d$ может сделать её медленнее $O(n\log n)$-сортировок.

---

### Когда применять

- Много **целых чисел фиксированной ширины**: id, телефоны, почтовые индексы.
- Строки одинаковой длины (сортировка по символам-разрядам).
- Когда важна устойчивость и линейное по $n$ время, а диапазон значений слишком велик для чистой [подсчётом](../../Алгоритмы/Сортировка/Подсчётом.md).

**Не применять:** разнотипные/дробные ключи, произвольные объекты со сравнением — берут [быструю](../../Алгоритмы/Сортировка/Быстрая.md) или [слияние](../../Алгоритмы/Сортировка/Слиянием.md).
