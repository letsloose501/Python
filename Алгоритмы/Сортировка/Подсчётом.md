# Сортировка подсчётом

**Сортировка подсчётом** (Counting Sort) — сортировка **без сравнений**: считаем, сколько раз встречается каждое значение, и восстанавливаем массив прямо по счётчикам. Работает для **целых ключей из ограниченного диапазона**.

> **Идея:** не «какой элемент больше», а «сколько каких». Если известно, что троек — две, а единица — одна, можно выложить `1, 3, 3` без единого сравнения.

Именно отказ от сравнений позволяет обойти теоретическую границу $O(n \log n)$: она доказана **только для сортировок сравнением** (Вычислительная сложность), а подсчёт сравнений не делает — отсюда линейное время.

---

### Как работает

Массив `[1, 4, 1, 2, 4, 1]`, значения из диапазона `0..4`:

```
считаем вхождения:
  0→0   1→3   2→1   3→0   4→2
восстанавливаем по счётчикам:
  1, 1, 1,  2,  4, 4
```

---

### Реализация

Простая версия — для чистых чисел:

```python
def counting_sort(arr, k):            # k — максимальное значение
    count = [0] * (k + 1)
    for x in arr:
        count[x] += 1                 # посчитать вхождения
    result = []
    for value, cnt in enumerate(count):
        result.extend([value] * cnt)  # выложить каждое значение cnt раз
    return result

counting_sort([1, 4, 1, 2, 4, 1], 4)   # → [1, 1, 1, 2, 4, 4]
```

Устойчивая версия (через **префиксные суммы**) — нужна, когда сортируем **объекты** по числовому ключу и когда подсчёт вызывается из [поразрядной](../../Алгоритмы/Сортировка/Поразрядная.md):

```python
def counting_sort_stable(arr, key, k):
    count = [0] * (k + 1)
    for x in arr:
        count[key(x)] += 1
    for i in range(1, k + 1):
        count[i] += count[i - 1]        # префиксные суммы → границы позиций
    result = [None] * len(arr)
    for x in reversed(arr):             # идём с конца — сохраняет устойчивость
        count[key(x)] -= 1
        result[count[key(x)]] = x
    return result
```

---

### Big O

|Показатель|Значение|
|---|---|
|Время|$O(n + k)$, где $k$ — размер диапазона значений|
|Память|$O(n + k)$|
|Устойчивость|да (в версии с префиксными суммами)|
|На месте|нет — нужен доп. массив|

Линейно, **только если** $k$ сравним с $n$. Если диапазон огромен ($k \gg n$), память и время $O(k)$ убивают выгоду.

---

### Когда применять

- Значения — **целые в небольшом диапазоне**: оценки 0–100, возраст, байты 0–255, буквы алфавита.
- Нужна устойчивость и линейное время.
- Как **подпрограмма** поразрядной сортировки (по одному разряду).

**Не применять:** большой или неизвестный диапазон (значения до $10^9$), дробные/произвольные ключи — тут сравнительные сортировки ([Быстрая сортировка](../../Алгоритмы/Сортировка/Быстрая.md), [Сортировка слиянием](../../Алгоритмы/Сортировка/Слиянием.md)).
