# Инкапсуляция Python

> Инкапсуляция — две вещи сразу: **связывание** данных и методов в единый объект, и **контроль доступа** к внутреннему состоянию. Внешний код работает через публичный интерфейс — не лезет во внутренности.
> 
> В отличие от Java и C++, Python не запрещает доступ к приватным атрибутам на уровне компилятора. Вместо этого — соглашения и культура: «мы все взрослые люди здесь».

### Зачем нужна инкапсуляция

Без инкапсуляции любой код может изменить внутреннее состояние объекта напрямую, обойти валидацию, сломать инварианты:

```python
# Без инкапсуляции — катастрофа
class Счёт:
    def __init__(self):
        self.баланс = 0

счёт = Счёт()
счёт.баланс = -999999   # никто не проверил — данные сломаны
```

С инкапсуляцией — изменение только через методы, которые обеспечивают валидацию:

```python
class Счёт:
    def __init__(self):
        self._баланс = 0

    def пополнить(self, сумма):
        if сумма <= 0:
            raise ValueError("сумма должна быть положительной")
        self._баланс += сумма

    def снять(self, сумма):
        if сумма > self._баланс:
            raise ValueError("недостаточно средств")
        self._баланс -= сумма

    @property
    def баланс(self):
        return self._баланс
```

### Уровни доступа в Python — соглашения об именовании

Python не имеет ключевых слов `private` / `protected`. Вместо этого — соглашения по именованию.

#### `имя` — публичный атрибут

Доступен всем. Часть публичного API класса.

```python
class Точка:
    def __init__(self, x, y):
        self.x = x   # публичный — можно читать и писать снаружи
        self.y = y
```

#### `_имя` — защищённый (protected)

**Соглашение**: «не трогай снаружи, если не знаешь что делаешь». Технически доступен — Python не запрещает. Сигнал другим разработчикам: это детали реализации.

```python
class Парсер:
    def __init__(self):
        self._буфер = []      # внутренний — не трогай
        self._позиция = 0     # внутренний — не трогай

    def _читать_токен(self):  # внутренний метод
        pass

    def парсить(self, текст): # публичный API
        self._буфер = list(текст)
        return self._читать_токен()

парсер = Парсер()
парсер._буфер  # технически можно, но не стоит
```

#### `__имя` — приватный (name mangling)

Python **переименовывает** атрибут при компиляции байткода: `__атрибут` в классе `Foo` становится `_Foo__атрибут`. Доступ по оригинальному имени снаружи — `AttributeError`.

```python
class Пользователь:
    def __init__(self, логин, пароль):
        self.логин = логин
        self.__пароль = пароль   # станет _Пользователь__пароль

    def проверить_пароль(self, введённый):
        return self.__пароль == введённый

user = Пользователь("иван", "secret123")
user.__пароль           # AttributeError: 'Пользователь' object has no attribute '__пароль'
user._Пользователь__пароль   # → "secret123"  ← не рекомендуется
```

#### Как работает name mangling под капотом

```python
class Пример:
    def __init__(self):
        self.__x = 42

print(Пример().__dict__)
# → {'_Пример__x': 42}
# Переменной __x не существует — она была переименована при компиляции
```

**Зачем это нужно** — защита от случайного переопределения в подклассах:

```python
class База:
    def __init__(self):
        self.__важное = "данные базы"   # → _База__важное

    def получить(self):
        return self.__важное            # ищет _База__важное

class Наследник(База):
    def __init__(self):
        super().__init__()
        self.__важное = "данные наследника"  # → _Наследник__важное — другой атрибут!

obj = Наследник()
obj.получить()   # → "данные базы" — не сломалось!
```

> **Итог**: `__` — не «сделать секрет», а защита от коллизий при наследовании. Для обычного «не трогай» достаточно `_`.

### @property — питонический способ геттеров и сеттеров

В Java/C++ геттеры и сеттеры — явные методы: `get_age()`, `set_age()`. В Python — `@property`: снаружи выглядит как атрибут, внутри — метод с валидацией.

```python
class Температура:
    def __init__(self, celsius=0):
        self._celsius = celsius

    @property
    def celsius(self):              # геттер — вызывается при t.celsius
        return self._celsius

    @celsius.setter
    def celsius(self, значение):    # сеттер — вызывается при t.celsius = x
        if значение < -273.15:
            raise ValueError("ниже абсолютного нуля")
        self._celsius = значение

    @celsius.deleter
    def celsius(self):              # делитер — вызывается при del t.celsius
        self._celsius = 0

    @property
    def fahrenheit(self):           # вычисляемое свойство — нет сеттера
        return self._celsius * 9/5 + 32

t = Температура(100)
print(t.celsius)      # → 100    (вызвал геттер)
t.celsius = 200       # вызвал сеттер
t.celsius = -500      # ValueError
print(t.fahrenheit)   # → 392.0  (вычисляемое, только чтение)
```

#### Readonly свойство — только геттер

```python
class Окружность:
    def __init__(self, радиус):
        self._радиус = радиус

    @property
    def радиус(self):
        return self._радиус

    @property
    def площадь(self):         # вычисляемое — readonly
        import math
        return math.pi * self._радиус ** 2

c = Окружность(5)
c.радиус         # → 5
c.площадь        # → 78.53...
c.площадь = 10   # AttributeError: can't set attribute
```

#### Как @property работает под капотом

`@property` — это встроенный дескриптор. Когда ты пишешь `@property`, создаётся объект `property` с методами `__get__`, `__set__`, `__delete__`. Python вызывает их автоматически при обращении к атрибуту.

```python
# @property эквивалентно:
class Класс:
    def _get_x(self):
        return self._x

    def _set_x(self, значение):
        self._x = значение

    x = property(_get_x, _set_x)   # создать дескриптор вручную
```

### `__slots__` — жёсткое ограничение атрибутов

Обычный объект хранит атрибуты в словаре `__dict__` — поэтому ему можно на ходу приписать что угодно. Гибко, но за это платят памятью: словарь есть **у каждого экземпляра**.

`__slots__` — объявление «у этого класса ровно эти атрибуты и никаких других». Python тогда не создаёт `__dict__`, а раскладывает атрибуты по фиксированным ячейкам, как поля структуры в C.

```python
class Точка:
    __slots__ = ('x', 'y')   # разрешены только x и y

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Точка(1, 2)
p.x = 10       # OK
p.z = 5        # AttributeError: 'Точка' object has no attribute 'z'
p.__dict__     # AttributeError: 'Точка' object has no '__dict__'
```

Отсюда два эффекта: **память** (нет словаря на объект) и **опечатки ловятся сразу** — `p.кординаты = 5` падает, а не создаёт молча новый атрибут.

**Сколько экономит** _(замер на CPython 3.13, `sys.getsizeof`)_:

| Класс с двумя атрибутами | Память на экземпляр |
|---|---|
| обычный | 344 байта _(объект 48 + `__dict__` 296)_ |
| с `__slots__` | **48 байт** |

> Разница в разы, но она имеет смысл только на **большом количестве** мелких объектов (миллионы точек, узлов, записей). Ради трёх экземпляров `__slots__` — преждевременная оптимизация: платишь гибкостью, не выигрывая ничего.

#### Три ловушки `__slots__`

**1. Подкласс без `__slots__` возвращает `__dict__` — и экономия исчезает.** Самая частая ошибка: класс объявили со слотами, наследника — нет, и вся оптимизация тихо отменилась.

```python
class A:
    __slots__ = ('x',)

# НЕПРАВИЛЬНО: наследник не объявил __slots__
class B(A):
    pass
b = B()
b.произвольный = 1      # прошло! у B снова есть __dict__

# ПРАВИЛЬНО: пустой кортеж — «своих атрибутов не добавляю»
class C(A):
    __slots__ = ()
C().произвольный = 1    # AttributeError — защита сохранена
```

**2. Слот и атрибут класса с одним именем несовместимы** — слот занимает имя, присвоить его же в теле класса нельзя:

```python
class D:
    __slots__ = ('x',)
    x = 5     # ValueError: 'x' in __slots__ conflicts with class variable
```

То же и с [`@property`](../../ООП/Принципы/Инкапсуляция%20Python.md#property--питонический-способ-геттеров-и-сеттеров): одноимённое свойство перекроет слот. Обычный приём — слот `_x`, а `@property x` поверх него.

**3. Два слотовых родителя не совмещаются** — у каждого своя раскладка памяти, объединить их нельзя:

```python
class E: __slots__ = ('a',)
class F: __slots__ = ('b',)
class G(E, F): __slots__ = ()
# TypeError: multiple bases have instance lay-out conflict
```

> Практический вывод для секции: `__slots__` — не «сделать класс строгим», а **оптимизация памяти для массовых объектов**, у которой есть цена — ломается множественное наследование, `__dict__` и динамическое добавление атрибутов. Для «строгости» есть [`@dataclass(frozen=True)`](../../Библиотеки/Модули/Типы%20и%20объекты/dataclass.md) и [`@property`](../../ООП/Принципы/Инкапсуляция%20Python.md#property--питонический-способ-геттеров-и-сеттеров). Как `__slots__` соотносится с устройством памяти Python — [Управление памятью в Python](../../Ядро%20языка/Управление%20памятью%20в%20Python.md).

### dataclass — автоматизация служебных методов

`@dataclass` снимает рутину с класса-хранилища: по объявленным полям Python сам генерирует `__init__`, `__repr__` и `__eq__`. Меньше ручного кода — меньше мест для ошибки.

```python
from dataclasses import dataclass

@dataclass
class Точка:
    x: int
    y: int
# __init__, __repr__, __eq__ сгенерированы автоматически
Точка(3, 4) == Точка(3, 4)   # → True
```

Для инкапсуляции особенно ценен `frozen=True` — он делает объект **неизменяемым**: запись в поле после создания даёт `FrozenInstanceError`. Это питонический readonly-объект; заодно он становится хешируемым (можно класть в `set`, использовать ключом `dict`).

```python
@dataclass(frozen=True)
class Точка:
    x: int
    y: int

p = Точка(3, 4)
p.x = 10        # FrozenInstanceError — поле только для чтения
{p}             # OK — frozen-объект хешируем
```

Подробнее о модуле, `field(default_factory=...)` и `__post_init__` — [dataclass](../../Библиотеки/Модули/Типы%20и%20объекты/dataclass.md).

> **Контракт `__eq__` / `__hash__`:** если определяешь `__eq__` вручную (как `Вектор` в [перегрузке операторов](../../ООП/Принципы/Полиморфизм%20Python.md#перегрузка-операторов--полиморфизм-через-магические-методы)), Python сбрасывает `__hash__` в `None` — объект становится нехешируемым. Нужен хешируемый неизменяемый объект — задай оба метода согласованно либо возьми `@dataclass(frozen=True)`, который делает это правильно.

### Дескрипторы — продвинутый контроль доступа

Дескриптор — объект, реализующий `__get__`, `__set__`, `__delete__`. Позволяет вынести логику геттера/сеттера в отдельный класс для переиспользования.

```python
class ТолькоПоложительное:
    """Дескриптор: атрибут обязан быть > 0"""
    def __set_name__(self, owner, name):
        self._name = f"_{name}"   # _радиус, _цена и т.д.

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self._name)

    def __set__(self, obj, значение):
        if значение <= 0:
            raise ValueError(f"{self._name}: ожидается > 0, получено {значение}")
        setattr(obj, self._name, значение)

class Товар:
    цена = ТолькоПоложительное()    # дескриптор применяется к атрибуту
    количество = ТолькоПоложительное()

    def __init__(self, цена, количество):
        self.цена = цена
        self.количество = количество

t = Товар(100, 5)
t.цена = -1    # ValueError
```

### Паттерны инкапсуляции

#### Публичный API через методы, данные скрыты

```python
class Стек:
    def __init__(self):
        self._данные = []   # скрыт

    def push(self, элемент):
        self._данные.append(элемент)

    def pop(self):
        if not self._данные:
            raise IndexError("стек пуст")
        return self._данные.pop()

    def peek(self):
        if not self._данные:
            raise IndexError("стек пуст")
        return self._данные[-1]

    def __len__(self):
        return len(self._данные)

    def __bool__(self):
        return bool(self._данные)
```

#### Кэшированное свойство

```python
class Отчёт:
    def __init__(self, данные):
        self._данные = данные
        self._кэш = {}

    @property
    def статистика(self):
        if "статистика" not in self._кэш:
            # тяжёлое вычисление — только один раз
            self._кэш["статистика"] = self._вычислить()
        return self._кэш["статистика"]

    def _вычислить(self):
        return sum(self._данные) / len(self._данные)

# Или через functools.cached_property (Python 3.8+):
from functools import cached_property

class Документ:
    def __init__(self, текст):
        self._текст = текст

    @cached_property
    def слова(self):
        return self._текст.split()  # вычислится один раз, потом кэшируется
```

### Сквозной пример — банковский счёт

Все механизмы вместе: приватные поля (`__`) прячут состояние, `@property` даёт контролируемый доступ к названию банка, методы `add`/`pay` — единственный способ менять баланс с валидацией.

```python
class Account:
    def __init__(self, bank, owner, balance=0):
        self.__bank = bank          # приватные (name mangling) —
        self.__owner = owner        # состояние скрыто от внешнего кода:
        self.__balance = balance    # → _Account__bank, _Account__owner, _Account__balance

    @property                       # геттер: acc.bank_name
    def bank_name(self):
        return self.__bank

    @bank_name.setter               # сеттер: acc.bank_name = "..."
    def bank_name(self, new_bank):
        self.__bank = new_bank

    def add(self, amount):          # пополнить — единственный путь увеличить баланс
        self.__balance += amount
        return True

    def pay(self, amount):          # списать — с проверкой достаточности средств
        if amount > self.__balance:
            print('Недостаточно средств')
            return False
        self.__balance -= amount
        return True

    def show(self):
        print(f'На счету {self.__owner} есть {self.__balance} рублей.')

acc = Account('Beta-Bank', "Timur", 100_000)
acc.bank_name              # → 'Beta-Bank'   (геттер)
acc.bank_name = "Alpha"    # (сеттер)
acc.pay(30_000)            # → True  — баланс 70000
acc.pay(1_000_000)         # → 'Недостаточно средств', False
acc.__dict__               # → {'_Account__bank': ..., '_Account__owner': ..., '_Account__balance': 70000}
```

Снаружи `__balance` не изменить напрямую (`acc.__balance` → `AttributeError`) — только через `add`/`pay`. Это и есть контроль доступа: инвариант «баланс не уходит в минус» держится в одном месте.

### Сводка уровней доступа

|Имя|Уровень|Доступ снаружи|Когда использовать|
|---|---|---|---|
|`имя`|Публичный|Всегда|Часть API, можно читать и писать|
|`_имя`|Защищённый|Да, но не стоит|Внутренние детали, могут измениться|
|`__имя`|Приватный|Через `_Класс__имя`|Защита от коллизий при наследовании|
|`@property`|Контролируемый|Через метод|Валидация, вычисляемые атрибуты|
|`__slots__`|Жёсткий|Только заявленные|Производительность, строгие объекты|
|`@dataclass(frozen=True)`|Неизменяемый|Только чтение после создания|Immutable value-объекты, хешируемые|
