# Полиморфизм Python

> Полиморфизм — «много форм». Один и тот же вызов работает с объектами разных типов, и каждый отвечает по-своему. `фигура.площадь()` работает и для круга, и для квадрата — но считается по разным формулам.
> 
> В Python полиморфизм глубоко встроен в язык: `len()`, `+`, `for`, `print()` — всё это полиморфные операции.

Связанные файлы: [Наследование Python](../../ООП/Принципы/Наследование%20Python.md) · [Абстракция Python](../../ООП/Принципы/Абстракция%20Python.md) · [Магические методы Python](../../Ядро%20языка/Магические%20методы%20Python.md) · [SOLID Python](../../ООП/Принципы/SOLID%20Python.md)

### Виды полиморфизма в Python

**Утиная типизация** — полиморфизм без иерархии наследования. Главное — наличие нужных методов, а не тип.

**Полиморфизм через наследование** — подклассы переопределяют методы родителя.

**Перегрузка операторов** — операторы `+`, ` == `, `<` работают по-разному для разных типов через магические методы.

**Полиморфизм встроенных функций** — `len()`, `str()`, `iter()` и другие работают с любым объектом, реализующим нужный метод.

### Утиная типизация (Duck Typing)

> «Если нечто ходит как утка и крякает как утка — это утка.»

Python не проверяет тип объекта — он проверяет наличие нужного метода. Если метод есть — объект подходит, неважно, от какого класса наследует.

```python
class Утка:
    def звук(self):
        return "Кря!"

    def плыть(self):
        return "Утка плывёт"

class Человек:
    def звук(self):
        return "Привет!"

    def плыть(self):
        return "Человек плывёт"

class Робот:
    def звук(self):
        return "Бип-буп"

    def плыть(self):
        return "Робот плывёт"

# Функция не знает о типах — ей нужен только метод звук()
def издать_звук(существо):
    print(существо.звук())

для_пруда = [Утка(), Человек(), Робот()]
for существо in для_пруда:
    издать_звук(существо)   # работает с любым — у всех есть звук()
# → Кря!
# → Привет!
# → Бип-буп
```

Утиная типизация — **не** отсутствие типов. Это отсутствие **проверки** типов: полагаемся на протокол (набор методов), а не на иерархию классов.

### Полиморфизм через наследование

Подклассы переопределяют методы родителя. Код работает с родительским типом, но вызывает реализацию подкласса — это и есть полиморфизм через наследование.

```python
class Фигура:
    def площадь(self) -> float:
        raise NotImplementedError

    def описание(self):          # использует полиморфный площадь()
        return f"{type(self).__name__}: площадь = {self.площадь():.2f}"

class Круг(Фигура):
    def __init__(self, r):
        self.r = r

    def площадь(self):
        import math
        return math.pi * self.r ** 2

class Прямоугольник(Фигура):
    def __init__(self, ш, в):
        self.ш, self.в = ш, в

    def площадь(self):
        return self.ш * self.в

class Треугольник(Фигура):
    def __init__(self, о, в):
        self.о, self.в = о, в

    def площадь(self):
        return 0.5 * self.о * self.в

фигуры: list[Фигура] = [Круг(5), Прямоугольник(4, 6), Треугольник(3, 8)]

for ф in фигуры:
    print(ф.описание())   # описание() вызывает площадь() — но какую?
                           # Зависит от реального типа объекта!
# → Круг: площадь = 78.54
# → Прямоугольник: площадь = 24.00
# → Треугольник: площадь = 12.00

# Суммирование через единый интерфейс:
суммарная = sum(ф.площадь() for ф in фигуры)
```

### Зачем базовый класс, если работает утиная типизация

В Java и C# полиморфизм иначе как через общего предка не объяснить: чтобы сложить разные зелья в один массив `Potion[]`, у них **обязан** быть общий базовый тип — иначе компилятор не примет коллекцию. Оттуда же растёт приём «объявить в базовом классе пустой метод, чтобы его можно было вызвать в цикле».

В Python этого ограничения нет:

```python
class Health:
    def drink(self): return "+10 hp"

class Mana:
    def drink(self): return "+10 mana"

for potion in (Health(), Mana()):        # общего предка нет — и не требуется
    print(potion.drink())                # → +10 hp / +10 mana
```

Список принимает что угодно, метод ищется в рантайме по фактическому типу. То есть **базовый класс в Python не нужен для того, чтобы полиморфизм заработал** — он нужен ради других вещей:

| | С базовым классом / `Protocol` | Только duck typing |
|---|---|---|
| Пропущенный метод | `TypeError` при создании объекта (`ABC`) | `AttributeError` при вызове, в проде |
| Проверка mypy | ловит несоответствие до запуска | нечего проверять |
| Общий код и поля | в одном месте | дублируются по классам |
| Что обязан уметь новый класс | видно в объявлении | выясняется чтением чужого кода |

> Что выбрать: **`Protocol`** — когда классы уже существуют и править их нельзя (сторонние библиотеки, разные иерархии); **`ABC`** — когда семейство пишешь ты сам и хочешь, чтобы забытая реализация падала сразу. Пустой метод-заглушка в базовом классе — вариант из статически типизированных языков, в Python он лишь маскирует ошибку: [сравнение трёх заглушек](../../ООП/Принципы/Абстракция%20Python.md#три-вида-заглушки-в-базовом-классе--и-цена-выбора).

### Полиморфизм через ABC — явный контракт

`ABC` + `@abstractmethod` гарантирует, что каждый подкласс реализует метод. Ошибка обнаруживается при создании объекта, а не при первом вызове.

```python
from abc import ABC, abstractmethod

class Уведомление(ABC):
    @abstractmethod
    def отправить(self, кому: str, текст: str) -> bool: ...

    @abstractmethod
    def название(self) -> str: ...

class Email(Уведомление):
    def отправить(self, кому, текст):
        print(f"Email → {кому}: {текст}")
        return True

    def название(self): return "Email"

class SMS(Уведомление):
    def отправить(self, кому, текст):
        print(f"SMS → {кому}: {текст[:160]}")
        return True

    def название(self): return "SMS"

class PushNotification(Уведомление):
    def отправить(self, кому, текст):
        print(f"Push → {кому}: {текст}")
        return True

    def название(self): return "Push"

def разослать(каналы: list[Уведомление], кому, текст):
    for канал in каналы:
        успех = канал.отправить(кому, текст)
        if not успех:
            print(f"[{канал.название()}] не удалось отправить")

разослать([Email(), SMS(), PushNotification()], "user@example.com", "Привет!")
```

### Перегрузка операторов — полиморфизм через магические методы

Python реализует операторы через магические методы. Один оператор — разное поведение для разных типов:

```python
# + для разных типов:
1 + 2           # → 3    (int.__add__)
"ab" + "cd"     # → "abcd"  (str.__add__)
[1] + [2]       # → [1, 2]  (list.__add__)
```

```python
class Вектор:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):
        return Вектор(self.x + other.x, self.y + other.y)

    def __mul__(self, скаляр):            # v * 3
        return Вектор(self.x * скаляр, self.y * скаляр)

    def __rmul__(self, скаляр):           # 3 * v
        return self.__mul__(скаляр)

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __abs__(self):                    # len(v) через abs()
        return (self.x**2 + self.y**2) ** 0.5

    def __repr__(self):
        return f"Вектор({self.x}, {self.y})"

v1 = Вектор(1, 2)
v2 = Вектор(3, 4)
v1 + v2    # → Вектор(4, 6)
v1 * 3     # → Вектор(3, 6)
3 * v1     # → Вектор(3, 6)
abs(v1)    # → 2.236...
```

### Полиморфизм встроенных функций

Встроенные функции Python — полиморфны. Они работают с любым объектом, реализующим нужный магический метод:

```python
# len() вызывает __len__
len("строка")     # → 6
len([1, 2, 3])    # → 3
len({"a": 1})     # → 1

class МояКоллекция:
    def __init__(self, данные):
        self._данные = данные
    def __len__(self):
        return len(self._данные)

len(МояКоллекция([1, 2, 3]))  # → 3  ← len() работает с нашим классом

# str() / print() вызывает __str__
# iter() / for вызывает __iter__
# bool() вызывает __bool__
# abs() вызывает __abs__
# hash() вызывает __hash__
```

### Протоколы — неявные интерфейсы

Python работает через **протоколы**: если объект реализует нужные методы, он соответствует протоколу. Объявлять принадлежность не нужно.

| Протокол             | Методы                                   | Что даёт                             |
| -------------------- | ---------------------------------------- | ------------------------------------ |
| Итерируемый          | `__iter__`                               | `for`, `list()`, `sum()`, распаковка |
| Итератор             | `__iter__`, `__next__`                   | `next()`, `for`                      |
| Последовательность   | `__len__`, `__getitem__`                 | `[]`, `len()`, `for`                 |
| Отображение          | `__len__`, `__getitem__`, `__contains__` | как `dict`                           |
| Контекстный менеджер | `__enter__`, `__exit__`                  | `with`                               |
| Сравнимый            | `__eq__`, `__lt__`                       | `==`, `<`, сортировка                |
| Хэшируемый           | `__hash__`                               | использование в `set`, ключом `dict` |

```python
class Счётчик:
    """Реализует протокол итератора"""
    def __init__(self, максимум):
        self.максимум = максимум
        self._текущий = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self._текущий >= self.максимум:
            raise StopIteration
        self._текущий += 1
        return self._текущий

for n in Счётчик(5):
    print(n)   # → 1 2 3 4 5

list(Счётчик(3))   # → [1, 2, 3]
sum(Счётчик(10))   # → 55
```

### typing.Protocol — явные протоколы (Python 3.8+)

`Protocol` позволяет объявить протокол явно и использовать его для аннотаций типов. Класс не обязан наследовать `Protocol` — достаточно реализовать методы (structural subtyping).

```python
from typing import Protocol

class Drawable(Protocol):
    def draw(self) -> None: ...
    def get_bounds(self) -> tuple[int, int, int, int]: ...

class Кнопка:
    def draw(self) -> None:
        print("рисую кнопку")

    def get_bounds(self):
        return (0, 0, 100, 50)

class Текст:
    def draw(self) -> None:
        print("рисую текст")

    def get_bounds(self):
        return (0, 0, 200, 20)

def отрисовать(элемент: Drawable) -> None:
    элемент.draw()

# Кнопка и Текст не наследуют Drawable — но соответствуют протоколу
отрисовать(Кнопка())   # OK — mypy проверит
отрисовать(Текст())    # OK
```

### Протокол для вызываемого объекта

Зависимостью не обязан быть объект — часто это просто функция (отправить сообщение, посчитать скидку, выбрать реализацию). Первый порыв — типизировать её через `Callable`, но у этой записи есть **неочевидное ограничение: имена параметров теряются, и вызвать функцию с именованными аргументами уже нельзя**.

```python
Send = Callable[[int, str], None]

def notify(send: Send) -> None:
    send(chat_id=1, message="привет")
    # mypy: Unexpected keyword argument "chat_id"  [call-arg]
    # mypy: Unexpected keyword argument "message"  [call-arg]
```

Формально `Callable[[int, str], None]` описывает функцию с **позиционными** параметрами без имён. Понять из аннотации, что первое число — это `chat_id`, а не `user_id`, невозможно.

Решение — протокол с `__call__`: имена сохраняются, опечатка в ключевом слове ловится.

```python
class Send(Protocol):
    def __call__(self, chat_id: int, message: str) -> None: ...

def send_telegram(chat_id: int, message: str) -> None:
    ...

def notify(send: Send) -> None:
    send(chat_id=1, message="привет")   # OK
    send(chat=1, message="привет")      # mypy: Unexpected keyword argument "chat"

notify(send_telegram)   # обычная функция соответствует протоколу — наследовать нечего
```

> Правило выбора: `Callable` — когда функция передаётся насквозь и её параметры не важны (колбэк, ключ сортировки). `Protocol.__call__` — когда функция это **зависимость с осмысленным контрактом**. Практическое применение — [инъекция функций вместо классов](../../ООП/Принципы/SOLID%20на%20практике%20—%20рефакторинг%20сервиса.md#шаг-1-d--принять-зависимости-снаружи).

### Python не поддерживает перегрузку методов

В отличие от Java/C++, нельзя определить два метода с одним именем и разными сигнатурами. Последнее определение перезапишет предыдущее:

```python
class Пример:
    def метод(self, x):
        return x

    def метод(self, x, y):  # ← перезапишет предыдущий!
        return x + y

# Решение через аргументы по умолчанию:
class Решение:
    def метод(self, x, y=None):
        if y is None:
            return x
        return x + y

# Или через singledispatch:
from functools import singledispatch

@singledispatch
def обработать(значение):
    raise TypeError(f"неизвестный тип: {type(значение)}")

@обработать.register(int)
def _(значение):
    return f"int: {значение * 2}"

@обработать.register(str)
def _(значение):
    return f"str: {значение.upper()}"

обработать(42)     # → "int: 84"
обработать("hi")   # → "str: HI"
```

### До каких операций сводится полиморфизм

Python реализует полиморфизм через **динамическое связывание**: при вызове метода Python смотрит в тип объекта в рантайме, а не на тип переменной.

```python
# Каждый вызов метода:
obj.метод()

# Разворачивается примерно в:
type(obj).__dict__["метод"](obj)
# или через MRO:
type(obj).метод(obj)
```

```python
фигура = Круг(5)
фигура.площадь()
# 1. Python смотрит: type(фигура) → Круг
# 2. Ищет площадь в Круг.__dict__ → нашёл
# 3. Вызывает Круг.площадь(фигура)
```

Если тип меняется в рантайме — поведение меняется вместе с ним. Именно это делает полиморфизм динамическим.
