# Абстракция Python

> Абстракция — скрыть детали реализации, показать только нужное снаружи. Пользователь вызывает `файл.сохранить()` и не знает, как данные кодируются, куда пишутся, какой буфер используется. Видит только интерфейс — не механизм.
> 
> Абстракция **определяет, что делает объект**. Инкапсуляция — **как** он это прячет. Полиморфизм — **как** разные объекты делают одно и то же по-разному.

Связанные файлы: [Инкапсуляция Python](../../ООП/Принципы/Инкапсуляция%20Python.md) · [Полиморфизм Python](../../ООП/Принципы/Полиморфизм%20Python.md) · [Наследование Python](../../ООП/Принципы/Наследование%20Python.md) · [SOLID Python](../../ООП/Принципы/SOLID%20Python.md) · [Моделирование — что попадает в класс](../../ООП/Принципы/Моделирование%20—%20что%20попадает%20в%20класс.md)

### Что такое абстракция

В ООП абстракция — это выделение существенных характеристик объекта и игнорирование несущественных. Ты проектируешь **интерфейс**, а не реализацию.

> **Одним словом называют две разные вещи.** Эта заметка — про абстракцию как **артефакт кода**: `ABC`, `@abstractmethod`, интерфейс. Но «абстракцией» называют и **процесс проектирования** — решение, что вообще войдёт в модель, из-за которого одна и та же машина в гоночной игре и в навигаторе становится двумя разными классами. Про него — [Моделирование — что попадает в класс](../../ООП/Принципы/Моделирование%20—%20что%20попадает%20в%20класс.md).

Два уровня:

**Абстракция данных** — показываешь только нужные атрибуты, скрываешь остальные.

**Абстракция поведения** — определяешь, _что_ умеет делать объект, без указания _как именно_.

```python
# Абстракция: пользователю нужен метод площадь()
# Не нужно знать, что внутри — формула, кэш, что угодно
фигура.площадь()
файл.прочитать()
соединение.отправить(данные)
```

### Абстракция через обычные классы

Простейший уровень — просто не выставляй детали наружу. Метод `завести()` скрывает всё нутро:

```python
class Машина:
    def __init__(self, модель):
        self.модель = модель
        self._топливо = 100      # скрыто
        self._обороты = 0        # скрыто

    def завести(self):           # публичный интерфейс
        self._запустить_стартер()
        self._прогреть_двигатель()
        self._обороты = 800

    def _запустить_стартер(self):   # детали реализации — скрыты
        pass

    def _прогреть_двигатель(self):
        pass

bmw = Машина("BMW")
bmw.завести()   # пользователь не знает, что происходит внутри
```

### Абстрактные классы — ABC

**Абстрактный класс** — класс, который нельзя инстанциировать. Он только определяет интерфейс: какие методы должны быть в каждом подклассе. Реализацию требует от наследников.

Python реализует это через модуль `abc` (Abstract Base Classes).

```python
from abc import ABC, abstractmethod

class Фигура(ABC):
    @abstractmethod
    def площадь(self) -> float:
        """Каждая фигура обязана это реализовать"""
        pass

    @abstractmethod
    def периметр(self) -> float:
        pass

    def описание(self):           # обычный метод — не абстрактный
        return f"площадь={self.площадь():.2f}"

# Фигура()  ← TypeError: нельзя создать экземпляр абстрактного класса
```

```python
class Круг(Фигура):
    def __init__(self, радиус):
        self.радиус = радиус

    def площадь(self):
        import math
        return math.pi * self.радиус ** 2

    def периметр(self):
        import math
        return 2 * math.pi * self.радиус

class Квадрат(Фигура):
    def __init__(self, сторона):
        self.сторона = сторона

    def площадь(self):
        return self.сторона ** 2

    def периметр(self):
        return 4 * self.сторона

# Если не реализовать все abstractmethod — TypeError при создании объекта
class Треугольник(Фигура):
    pass

# Треугольник()  ← TypeError: Can't instantiate abstract class
```

```python
фигуры = [Круг(5), Квадрат(4), Круг(3)]
for ф in фигуры:
    print(ф.описание())
# → площадь=78.54
# → площадь=16.00
# → площадь=28.27
```

### @abstractmethod — детали

```python
from abc import ABC, abstractmethod

class База(ABC):
    # Абстрактный обычный метод
    @abstractmethod
    def метод(self):
        pass

    # Абстрактный classmethod
    @classmethod
    @abstractmethod
    def создать(cls):
        pass

    # Абстрактный staticmethod
    @staticmethod
    @abstractmethod
    def валидировать(x):
        pass

    # Абстрактное свойство
    @property
    @abstractmethod
    def имя(self):
        pass
```

### Интерфейс через ABC — только абстрактные методы

Если ABC содержит **только** `@abstractmethod` без реализаций — это чистый интерфейс (как `interface` в Java). Контракт: реализуй всё это.

```python
from abc import ABC, abstractmethod

class Drawable(ABC):
    """Интерфейс: всё что умеет рисоваться"""
    @abstractmethod
    def draw(self, canvas): pass

    @abstractmethod
    def get_bounds(self): pass

class Serializable(ABC):
    """Интерфейс: всё что умеет сериализоваться"""
    @abstractmethod
    def to_dict(self): pass

    @classmethod
    @abstractmethod
    def from_dict(cls, d): pass

# Класс реализует сразу несколько "интерфейсов"
class Иконка(Drawable, Serializable):
    def __init__(self, x, y, изображение):
        self.x, self.y = x, y
        self.изображение = изображение

    def draw(self, canvas):
        canvas.render(self.изображение, self.x, self.y)

    def get_bounds(self):
        return (self.x, self.y, 32, 32)

    def to_dict(self):
        return {"x": self.x, "y": self.y, "img": self.изображение}

    @classmethod
    def from_dict(cls, d):
        return cls(d["x"], d["y"], d["img"])
```

### register() — виртуальные подклассы

`register()` позволяет объявить класс подтипом ABC **без наследования**. Полезно для сторонних классов, которые нельзя изменить.

```python
from abc import ABC

class МойСписок(ABC):
    pass

# list не наследует МойСписок, но мы объявляем его подтипом
МойСписок.register(list)

print(isinstance([], МойСписок))   # → True
print(issubclass(list, МойСписок)) # → True
```

### До каких базовых операций сводится

```python
# ABC использует метакласс ABCMeta
from abc import ABC, abstractmethod

# ABC = class ABC(metaclass=ABCMeta): pass
# Когда создаётся класс — ABCMeta проверяет все @abstractmethod
# Когда создаётся объект — __new__ смотрит в __abstractmethods__
# Если __abstractmethods__ не пустой — TypeError

class Пример(ABC):
    @abstractmethod
    def метод(self): pass

print(Пример.__abstractmethods__)  # → frozenset({'метод'})

class Реализация(Пример):
    def метод(self): return 42

print(Реализация.__abstractmethods__)  # → frozenset()  ← пустой, можно создавать
```

### Абстракция без ABC — соглашение через NotImplementedError

До появления `abc` (и до сих пор, как упрощённый вариант) — ручной способ:

```python
class Фигура:
    def площадь(self):
        raise NotImplementedError(f"{type(self).__name__} должен реализовать площадь()")

    def периметр(self):
        raise NotImplementedError

# Можно создать объект, но падёт при вызове метода
# Менее строго: ABC запрещает создание сразу
```

### Три вида заглушки в базовом классе — и цена выбора

Когда базовый класс объявляет метод, который обязаны реализовать потомки, тело метода можно оставить тремя способами. Разница не косметическая: она решает, **когда обнаружится незаполненная реализация**.

Вводные курсы по ООП обычно показывают самый плохой вариант — пустое тело:

```python
class Potion:
    def drink(self, hero): pass          # «наследник перепишет»

class SpeedPotion(Potion):
    def dinrk(self, hero):               # ← опечатка в имени
        hero["speed"] += 10

SpeedPotion().drink(hero)                # ошибки нет, эффекта нет — молча ничего
```

Метод нашёлся (родительский), отработал, вернул `None`. Программа продолжает работать с неверным состоянием, и искать причину придётся по последствиям.

С `@abstractmethod` тот же код падает **в момент создания объекта**, до всякой логики:

```python
from abc import ABC, abstractmethod

class Potion(ABC):
    @abstractmethod
    def drink(self, hero): ...

class SpeedPotion(Potion):
    def dinrk(self, hero): hero["speed"] += 10

SpeedPotion()
# TypeError: Can't instantiate abstract class SpeedPotion
#            without an implementation for abstract method 'drink'
```

| Заглушка | Когда обнаружится пропуск | Объект без реализации | Когда брать |
|---|---|---|---|
| `pass` / пустое тело | **никогда** — тихо возвращает `None` | создаётся | только осознанный hook _(см. ниже)_ |
| `raise NotImplementedError` | при первом вызове метода | создаётся | базовый класс без `ABCMeta`, миксины |
| `@abstractmethod` | **при создании объекта** | `TypeError` | по умолчанию для контракта |

> Правило: чем раньше ошибка, тем дешевле. `@abstractmethod` двигает её на самый ранний момент, доступный без статического анализатора, — и потому это выбор по умолчанию.

**Когда пустое тело всё-таки правильно.** Если переопределение **не обязательно**, а метод — точка расширения (hook) в шаблонном методе, пустое тело и есть корректное поведение по умолчанию: «по умолчанию не делать ничего».

```python
class Task(ABC):                         # именно ABC — иначе @abstractmethod ничего не проверит
    def run(self):                       # шаблонный метод — общий каркас
        self.before()                    # hook: переопределять не обязано
        self._work()
        self.after()                     # hook

    def before(self): pass               # осознанно пусто — «ничего не делать»
    def after(self): pass

    @abstractmethod
    def _work(self): ...                 # а вот это обязано быть
```

Так устроен `setUp()` / `tearDown()` в [`unittest`](../../Библиотеки/Сторонние/Тесты/Юнит-тестирование%20Python.md). Разница с антипримером — в намерении: hook пуст потому, что «ничего» — валидный вариант, а не потому, что автор поленился объявить контракт.

### Практика — когда применять

**Применяй ABC когда:**

- есть группа классов с общим интерфейсом (базы данных, хранилища, форматы файлов)
- хочешь гарантировать, что подкласс реализовал все нужные методы
- пишешь каркас (framework), который будет расширяться другими разработчиками

```python
# Пример: система плагинов
from abc import ABC, abstractmethod

class Плагин(ABC):
    @abstractmethod
    def активировать(self): pass

    @abstractmethod
    def деактивировать(self): pass

    @property
    @abstractmethod
    def название(self) -> str: pass

    def статус(self):
        return f"Плагин '{self.название}' готов"

class ПлагинЛогирования(Плагин):
    @property
    def название(self): return "Логирование"
    def активировать(self): print("Логирование включено")
    def деактивировать(self): print("Логирование выключено")
```
