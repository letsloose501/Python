# Паттерны проектирования

> **Паттерн проектирования** — именованное, проверенное решение типичной задачи проектирования в конкретном контексте. Не изобретается заново — берётся готовая схема. Паттерны помогают говорить об архитектуре на высоком уровне: вместо описания деталей достаточно назвать имя.

### Из чего состоит паттерн

|Элемент|Что описывает|
|---|---|
|**Имя**|Короткое название — часть общего словаря проектировщика|
|**Задача**|Когда и в каком контексте применять|
|**Решение**|Абстрактная структура классов и объектов, их роли и взаимодействие|
|**Результаты**|Плюсы и минусы: гибкость, производительность, память|

Решение — это **шаблон**, не конкретный код. Две реализации одного паттерна могут отличаться, но оба следуют одной схеме.

### Каталог (23 паттерна)

#### Порождающие

|Паттерн|Суть|
|---|---|
|Абстрактная фабрика|Создаёт семейства связанных объектов без указания конкретных классов|
|Строитель|Отделяет конструирование сложного объекта от его представления|
|Фабричный метод|Подкласс решает, экземпляр какого класса создавать|
|Прототип|Создаёт объекты копированием прототипа|
|Одиночка|Гарантирует единственный экземпляр + глобальная точка доступа|

#### Структурные

|Паттерн|Суть|
|---|---|
|Адаптер|Преобразует интерфейс класса в ожидаемый клиентом|
|Мост|Отделяет абстракцию от реализации — меняются независимо|
|Компоновщик|Иерархия «часть — целое»; единичный и составной объект работают одинаково|
|Декоратор|Динамически добавляет объекту новые обязанности|
|Фасад|Упрощённый интерфейс к сложной подсистеме|
|Приспособленец|Разделяет состояние между множеством мелких объектов для экономии памяти|
|Заместитель|Суррогат объекта — контролирует доступ к нему|

#### Поведенческие

|Паттерн|Суть|
|---|---|
|Цепочка обязанностей|Запрос идёт по цепочке объектов, пока кто-то не обработает|
|Команда|Запрос инкапсулируется как объект — можно ставить в очередь, отменять|
|Интерпретатор|Определяет грамматику языка и интерпретирует его предложения|
|Итератор|Последовательный обход элементов без раскрытия внутреннего устройства|
|Посредник|Объект-посредник убирает прямые связи между объектами|
|Хранитель|Сохраняет и восстанавливает внутреннее состояние без нарушения инкапсуляции|
|Наблюдатель|Зависимость «один-ко-многим»: изменение одного уведомляет всех зависимых|
|Состояние|Поведение объекта меняется вместе с его состоянием|
|Стратегия|Семейство алгоритмов — взаимозаменяемы, выбираются в рантайме|
|Шаблонный метод|Скелет алгоритма в базовом классе, детали — в подклассах|
|Посетитель|Добавляет операции над объектами без изменения их классов|

### Два ключевых принципа

> **Программируй в соответствии с интерфейсом, а не с реализацией.** Не привязывайся к конкретным классам — работай через абстрактный тип. Клиент не зависит от деталей реализации.

```python
# Плохо — привязка к конкретному классу:
сортировщик = БыстраяСортировка()

# Хорошо — работа через интерфейс:
сортировщик: Сортировщик = фабрика.создать()
сортировщик.сортировать(данные)   # можно подменить любой реализацией
```

> **Предпочитай композицию наследованию.** Наследование статично и нарушает инкапсуляцию. Композиция динамична — объекты взаимодействуют только через интерфейсы.

```python
# Наследование: Window видит внутренности Rectangle
class Window(Rectangle): pass

# Композиция: Window знает только интерфейс Rectangle
class Window:
    def __init__(self):
        self._rect = Rectangle()     # можно подменить в рантайме

    def площадь(self):
        return self._rect.площадь()  # делегирование
```

### Когда паттерны спасают от перепроектирования

|Причина|Паттерны|
|---|---|
|Явное указание класса при создании|Абстрактная фабрика, Фабричный метод, Прототип|
|Зависимость от конкретных операций|Цепочка обязанностей, Команда|
|Зависимость от платформы|Абстрактная фабрика, Мост|
|Зависимость от алгоритма|Итератор, Стратегия, Шаблонный метод, Посетитель|
|Сильная связанность классов|Фасад, Посредник, Наблюдатель, Команда|
|Расширение через подклассы|Декоратор, Компоновщик, Стратегия|

### Паттерн vs каркас vs библиотека

| |Библиотека|Паттерн|Каркас|
|---|---|---|---|
|**Что это**|Готовый код|Схема решения|Готовая архитектура|
|**Кто кого вызывает**|Ты вызываешь её|—|Он вызывает твой код|
|**Уровень абстракции**|Низкий|Средний|Высокий|

### Когда НЕ применять паттерн

Каждый паттерн добавляет сложность: новые классы, косвенные вызовы, дополнительные объекты. Применяй только если гибкость действительно нужна сейчас или с высокой вероятностью понадобится.

Если класс создаваемого экземпляра никогда не изменится — не нужна Абстрактная фабрика. Если алгоритм фиксирован — не нужна Стратегия.

### Типичная эволюция проекта

Начинают с **Фабричного метода** (проще всего). При нехватке гибкости переходят к **Абстрактной фабрике**, **Строителю** или **Прототипу**.

### Паттерны на примере MVC

MVC (Model / View / Controller) — архитектурный паттерн из Smalltalk: **Модель** (данные), **Представление** (отображение), **Контроллер** (реакция на ввод). Хорошо показывает, как паттерны работают **вместе**:

- **Наблюдатель** — модель не знает о представлениях, лишь уведомляет подписчиков; к одной модели цепляют несколько представлений.
- **Компоновщик** — вложенные представления (панель с кнопками) как единый объект.
- **Стратегия** — контроллер инкапсулирует реакцию на ввод; сменил контроллер — сменил поведение в рантайме.

```python
модель.подписать(таблица); модель.подписать(диаграмма)
модель.изменить_данные(...)     # оба представления сами обновятся
```

### Наследование класса vs наследование интерфейса

Различие, на котором строятся многие паттерны:

| |Наследование класса|Наследование интерфейса|
|---|---|---|
|**Суть**|Повторное использование реализации|Определение подтипа|
|**Что передаётся**|Код и данные|Только контракт (интерфейс)|
|**Связанность**|Высокая|Низкая|
|**Пример**|`class Admin(User)`|`class Dog(Animal)`, где `Animal` абстрактный|

Паттерны Команда, Наблюдатель, Стратегия, Состояние задают **только интерфейс** (через абстрактные классы), а не реализацию.

### Делегирование

**Делегирование** — объект передаёт выполнение операции другому (делегату): замена наследования композицией.

```python
class Window:
    def __init__(self):
        self._фигура = Rectangle()
    def площадь(self):
        return self._фигура.площадь()   # делегируем фигуре

window._фигура = Circle()   # сменили поведение окна в рантайме
```

Используется в паттернах Состояние (делегирует объекту состояния), Стратегия (объекту-алгоритму), Посетитель.
