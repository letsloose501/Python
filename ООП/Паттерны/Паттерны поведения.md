# Паттерны поведения

> **Паттерны поведения** описывают алгоритмы и распределение обязанностей между объектами. Акцент — не на структуре, а на **связях и взаимодействии** во время выполнения. Паттерны класса используют наследование, паттерны объектов — композицию и делегирование.

Связанные файлы: [Паттерны проектирования](../../ООП/Паттерны/Паттерны%20проектирования.md) · [Структурные паттерны](../../ООП/Паттерны/Структурные%20паттерны.md) · [Порождающие паттерны](../../ООП/Паттерны/Порождающие%20паттерны.md)

### Цепочка обязанностей

**Задача:** избежать привязки отправителя запроса к получателю. Запрос передаётся по цепочке объектов, пока кто-то его не обработает.

> Обращение по инстанциям. Заявление идёт от сотрудника к менеджеру, от менеджера к директору. Каждый либо решает вопрос, либо передаёт выше.

```python
from abc import ABC, abstractmethod

class Handler(ABC):
    def __init__(self):
        self._next: Handler | None = None

    def set_next(self, handler: "Handler") -> "Handler":
        self._next = handler
        return handler   # для цепочки: a.set_next(b).set_next(c)

    @abstractmethod
    def handle(self, request: int) -> str | None: ...

class LowLevelSupport(Handler):
    def handle(self, request):
        if request <= 10:
            return f"LowLevel решил запрос {request}"
        return self._next.handle(request) if self._next else None

class MidLevelSupport(Handler):
    def handle(self, request):
        if request <= 100:
            return f"MidLevel решил запрос {request}"
        return self._next.handle(request) if self._next else None

class TopLevelSupport(Handler):
    def handle(self, request):
        return f"TopLevel решил запрос {request}"   # всегда обрабатывает

# Сборка цепочки через set_next:
low = LowLevelSupport()
mid = MidLevelSupport()
top = TopLevelSupport()
low.set_next(mid).set_next(top)

for req in [5, 50, 500]:
    print(low.handle(req))
# → LowLevel решил запрос 5
# → MidLevel решил запрос 50
# → TopLevel решил запрос 500
```

**Участники:** `Handler`, `ConcreteHandler`, `Client`.

**Плюсы:** ослабляет связанность — отправитель не знает, кто обработает; цепочку легко менять в рантайме.

**Минусы:** обработка не гарантирована — запрос может дойти до конца цепочки необработанным.

**Применять когда:** запрос может быть обработан одним из нескольких объектов, конкретный обработчик неизвестен заранее; хочется конфигурировать цепочку динамически.

### Команда

**Задача:** инкапсулировать запрос как объект. Позволяет параметризовать клиентов, ставить запросы в очередь, логировать и поддерживать отмену.

> Официант записывает заказ на бумажку и передаёт на кухню. Кухня не знает, кто заказал. Заказ можно отложить, отменить, повторить.

```python
from abc import ABC, abstractmethod

class Command(ABC):
    @abstractmethod
    def execute(self): ...
    @abstractmethod
    def undo(self): ...

# Receiver — объект, выполняющий реальную работу
class TextEditor:
    def __init__(self):
        self._text = ""

    def insert(self, text: str, pos: int):
        self._text = self._text[:pos] + text + self._text[pos:]

    def delete(self, pos: int, length: int):
        self._text = self._text[:pos] + self._text[pos + length:]

    @property
    def text(self): return self._text

# ConcreteCommand
class InsertCommand(Command):
    def __init__(self, editor: TextEditor, text: str, pos: int):
        self._editor = editor
        self._text = text
        self._pos = pos

    def execute(self):
        self._editor.insert(self._text, self._pos)

    def undo(self):
        self._editor.delete(self._pos, len(self._text))

class DeleteCommand(Command):
    def __init__(self, editor: TextEditor, pos: int, length: int):
        self._editor = editor
        self._pos = pos
        self._length = length
        self._deleted = ""

    def execute(self):
        self._deleted = self._editor.text[self._pos:self._pos + self._length]
        self._editor.delete(self._pos, self._length)

    def undo(self):
        self._editor.insert(self._deleted, self._pos)

# Invoker — управляет историей команд
class CommandHistory:
    def __init__(self):
        self._history: list[Command] = []
        self._undone: list[Command] = []

    def execute(self, cmd: Command):
        cmd.execute()
        self._history.append(cmd)
        self._undone.clear()

    def undo(self):
        if self._history:
            cmd = self._history.pop()
            cmd.undo()
            self._undone.append(cmd)

    def redo(self):
        if self._undone:
            cmd = self._undone.pop()
            cmd.execute()
            self._history.append(cmd)

editor = TextEditor()
history = CommandHistory()

history.execute(InsertCommand(editor, "Hello", 0))
history.execute(InsertCommand(editor, " World", 5))
print(editor.text)   # → "Hello World"

history.undo()
print(editor.text)   # → "Hello"

history.redo()
print(editor.text)   # → "Hello World"
```

**Участники:** `Command`, `ConcreteCommand`, `Invoker`, `Receiver`, `Client`.

**Применять когда:** нужно параметризовать объекты действиями; поддерживать отмену/повтор; ставить запросы в очередь или логировать их.

### Итератор

**Задача:** предоставить способ последовательного обращения к элементам составного объекта без раскрытия его внутреннего представления.

> Телевизионный пульт. Не важно, как сигнал хранится — аналог, кабель, стриминг. Кнопки «следующий» / «предыдущий» работают одинаково.

Python реализует итератор нативно через `__iter__` и `__next__`:

```python
class BinaryTreeNode:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right

class InOrderIterator:                 # обход дерева в порядке возрастания
    def __init__(self, root):
        self._stack = []
        self._push_left(root)

    def _push_left(self, node):
        while node:
            self._stack.append(node)
            node = node.left

    def __iter__(self): return self

    def __next__(self):
        if not self._stack:
            raise StopIteration
        node = self._stack.pop()
        self._push_left(node.right)
        return node.value

class BinaryTree:
    def __init__(self, root):
        self._root = root

    def __iter__(self):
        return InOrderIterator(self._root)

#      4
#     / \
#    2   6
#   / \ / \
#  1  3 5  7
tree = BinaryTree(
    BinaryTreeNode(4,
        BinaryTreeNode(2, BinaryTreeNode(1), BinaryTreeNode(3)),
        BinaryTreeNode(6, BinaryTreeNode(5), BinaryTreeNode(7))
    )
)

for value in tree:
    print(value, end=" ")   # → 1 2 3 4 5 6 7
# Клиент не знает про стек, структуру узлов — только интерфейс for
```

**Внешний итератор** — клиент вызывает `next()` явно, гибче. **Внутренний** — итератор сам обходит и вызывает операцию, проще.

**Участники:** `Iterator`, `ConcreteIterator`, `Aggregate`, `ConcreteAggregate`.

**Применять когда:** нужен доступ к элементам без раскрытия внутреннего устройства; нужно несколько одновременных обходов.

### Наблюдатель

**Задача:** определить зависимость «один ко многим»: при изменении одного объекта все зависящие от него уведомляются и обновляются автоматически.

> Подписка на новости. Редакция публикует статью — все подписчики получают уведомление. Редакция не знает, сколько подписчиков и кто именно.

```python
from abc import ABC, abstractmethod

class Observer(ABC):
    @abstractmethod
    def update(self, event: str, data): ...

class Subject:
    def __init__(self):
        self._observers: list[Observer] = []

    def subscribe(self, o: Observer):
        self._observers.append(o)

    def unsubscribe(self, o: Observer):
        self._observers.remove(o)

    def notify(self, event: str, data=None):
        for o in self._observers:
            o.update(event, data)

class EventStore(Subject):
    def __init__(self):
        super().__init__()
        self._events: list[dict] = []

    def add_event(self, event_type: str, payload):
        record = {"type": event_type, "data": payload}
        self._events.append(record)
        self.notify(event_type, payload)   # уведомляем подписчиков

class EmailNotifier(Observer):
    def update(self, event, data):
        if event == "order_placed":
            print(f"Email: новый заказ {data}")

class AnalyticsService(Observer):
    def update(self, event, data):
        print(f"Analytics: событие {event!r} → {data}")

class AuditLog(Observer):
    def update(self, event, data):
        print(f"Audit: {event} | {data}")

store = EventStore()
store.subscribe(EmailNotifier())
store.subscribe(AnalyticsService())
store.subscribe(AuditLog())

store.add_event("order_placed", {"id": 42, "total": 1500})
# → Email: новый заказ {'id': 42, 'total': 1500}
# → Analytics: событие 'order_placed' → {'id': 42, 'total': 1500}
# → Audit: order_placed | {'id': 42, 'total': 1500}

# Отписать логгер:
store.unsubscribe(store._observers[2])
```

**Модель вытягивания (pull):** наблюдатель сам запрашивает детали — субъект передаёт только сигнал. Слабее связывает. **Модель проталкивания (push):** субъект передаёт детали в `update()`. Быстрее, но предполагает знание о наблюдателях.

**Участники:** `Subject`, `Observer`, `ConcreteSubject`, `ConcreteObserver`.

**Применять когда:** изменение одного объекта требует обновления других, причём число зависящих неизвестно; нужна слабая связанность.

### Стратегия

**Задача:** определить семейство алгоритмов, инкапсулировать каждый и сделать их взаимозаменяемыми. Алгоритм изменяется независимо от клиента.

> Навигатор. Один и тот же маршрут — пешком, на машине или велосипеде. Алгоритм маршрута меняется, интерфейс — нет.

```python
from abc import ABC, abstractmethod
from typing import Callable

class SortStrategy(ABC):
    @abstractmethod
    def sort(self, data: list) -> list: ...

class BubbleSort(SortStrategy):
    def sort(self, data):
        data = data.copy()
        n = len(data)
        for i in range(n):
            for j in range(n - i - 1):
                if data[j] > data[j + 1]:
                    data[j], data[j + 1] = data[j + 1], data[j]
        return data

class QuickSort(SortStrategy):
    def sort(self, data):
        if len(data) <= 1: return data
        pivot = data[len(data) // 2]
        left = [x for x in data if x < pivot]
        mid = [x for x in data if x == pivot]
        right = [x for x in data if x > pivot]
        return self.sort(left) + mid + self.sort(right)

class MergeSort(SortStrategy):
    def sort(self, data):
        if len(data) <= 1: return data
        mid = len(data) // 2
        left = self.sort(data[:mid])
        right = self.sort(data[mid:])
        return self._merge(left, right)

    def _merge(self, left, right):
        result = []
        i = j = 0
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                result.append(left[i]); i += 1
            else:
                result.append(right[j]); j += 1
        return result + left[i:] + right[j:]

# Context — использует стратегию
class DataProcessor:
    def __init__(self, strategy: SortStrategy):
        self._strategy = strategy

    def set_strategy(self, strategy: SortStrategy):
        self._strategy = strategy   # можно менять в рантайме

    def process(self, data: list) -> list:
        return self._strategy.sort(data)

processor = DataProcessor(QuickSort())
print(processor.process([3, 1, 4, 1, 5, 9, 2, 6]))

processor.set_strategy(MergeSort())  # смена алгоритма — одна строка
print(processor.process([3, 1, 4, 1, 5, 9, 2, 6]))
```

**Стратегия как функция** (питонический вариант — без классов):

```python
from typing import Callable

def bubble_sort(data: list) -> list: ...
def quick_sort(data: list) -> list: ...

class DataProcessor:
    def __init__(self, sort_fn: Callable[[list], list]):
        self._sort = sort_fn

    def process(self, data):
        return self._sort(data)

DataProcessor(quick_sort).process([3, 1, 4])
DataProcessor(sorted).process([3, 1, 4])   # встроенная — тоже стратегия
```

**Стратегия таблицей** — когда стратегию выбирают не вручную, а по ключу (страна, формат файла, тип события). Вместо растущего `if/elif` — словарь «ключ → реализация» и запасной вариант:

```python
def composer_by_country(
    table: dict[str, MessageComposer],
    default: MessageComposer,
) -> Callable[[str], MessageComposer]:
    def select(country: str) -> MessageComposer:
        return table.get(country, default)
    return select

select = composer_by_country({"RU": Unisender()}, default=GreenSms())
select("RU")   # → Unisender
select("KZ")   # → GreenSms — запасной вариант, а не KeyError
```

Новая страна теперь — строка в словаре на уровне сборки приложения, а не ветка внутри сервиса. Это и есть «открыт для расширения, закрыт для изменения» ([OCP](../../ООП/Принципы/SOLID%20Python.md#o--openclosed-открытостьзакрытость)); разбор на живом сервисе — [SOLID на практике — рефакторинг сервиса](../../ООП/Принципы/SOLID%20на%20практике%20—%20рефакторинг%20сервиса.md).

**Отличие от Состояния:** Стратегия — взаимозаменяемые алгоритмы, задаётся снаружи клиентом. Состояние — поведение меняется само по внутренним условиям объекта.

**Участники:** `Strategy`, `ConcreteStrategy`, `Context`.

**Применять когда:** нужно несколько вариантов алгоритма; нужно изолировать алгоритм от сложных данных; условные операторы для выбора алгоритма разрастаются.

### Состояние

**Задача:** позволить объекту изменять поведение при изменении внутреннего состояния. Извне кажется, что изменился класс объекта.

> Торговый автомат. В разных состояниях (нет монеты / монета вставлена / выдаёт товар) на одно и то же нажатие — разная реакция.

```python
from abc import ABC, abstractmethod

class VendingState(ABC):
    @abstractmethod
    def insert_coin(self, machine): ...
    @abstractmethod
    def select_item(self, machine): ...
    @abstractmethod
    def dispense(self, machine): ...

class NoCoinState(VendingState):
    def insert_coin(self, machine):
        print("Монета принята")
        machine.set_state(machine.has_coin_state)

    def select_item(self, machine):
        print("Сначала вставьте монету")

    def dispense(self, machine):
        print("Сначала вставьте монету")

class HasCoinState(VendingState):
    def insert_coin(self, machine):
        print("Монета уже вставлена")

    def select_item(self, machine):
        print("Товар выбран")
        machine.set_state(machine.dispensing_state)

    def dispense(self, machine):
        print("Сначала выберите товар")

class DispensingState(VendingState):
    def insert_coin(self, machine):
        print("Подождите, выдача идёт")

    def select_item(self, machine):
        print("Подождите, выдача идёт")

    def dispense(self, machine):
        print("Товар выдан!")
        machine.set_state(machine.no_coin_state)

class VendingMachine:
    def __init__(self):
        self.no_coin_state = NoCoinState()
        self.has_coin_state = HasCoinState()
        self.dispensing_state = DispensingState()
        self._state: VendingState = self.no_coin_state

    def set_state(self, state: VendingState):
        self._state = state

    def insert_coin(self): self._state.insert_coin(self)
    def select_item(self): self._state.select_item(self)
    def dispense(self):    self._state.dispense(self)

machine = VendingMachine()
machine.select_item()    # → Сначала вставьте монету
machine.insert_coin()    # → Монета принята
machine.select_item()    # → Товар выбран
machine.dispense()       # → Товар выдан!
machine.dispense()       # → Сначала вставьте монету
```

**Участники:** `Context`, `State`, `ConcreteState`.

**Применять когда:** поведение объекта зависит от состояния и должно меняться в рантайме; много условных операторов, выбирающих ветку по состоянию.

### Шаблонный метод

**Задача:** определить скелет алгоритма, оставив реализацию некоторых шагов подклассам. Структура алгоритма не меняется.

> Рецепт с пропусками: «приготовить тесто → добавить начинку → выпекать». Тесто и начинка — ваши, порядок — фиксирован.

```python
from abc import ABC, abstractmethod

class DataMiner(ABC):
    # Шаблонный метод — фиксирует алгоритм, не переопределяется
    def mine(self, path: str):
        raw = self.extract(path)          # шаг 1 — переопределяется
        data = self.parse(raw)            # шаг 2 — переопределяется
        analysis = self.analyze(data)     # шаг 3 — переопределяется
        self.send_report(analysis)        # шаг 4 — общий (hook)

    @abstractmethod
    def extract(self, path: str) -> str: ...

    @abstractmethod
    def parse(self, raw: str) -> list: ...

    def analyze(self, data: list) -> dict:  # общая реализация по умолчанию
        return {"count": len(data), "sample": data[:3]}

    def send_report(self, analysis: dict):  # hook — можно переопределить
        print(f"Отчёт: {analysis}")

class CSVMiner(DataMiner):
    def extract(self, path):
        return open(path).read()

    def parse(self, raw):
        return [line.split(",") for line in raw.strip().split("\n")]

class PDFMiner(DataMiner):
    def extract(self, path):
        return f"PDF content from {path}"   # тут был бы pdfplumber

    def parse(self, raw):
        return raw.split("\n")

    def send_report(self, analysis):        # переопределяем hook
        print(f"PDF Отчёт → email: {analysis}")

CSVMiner().mine("data.csv")
PDFMiner().mine("report.pdf")
```

**Принцип Голливуда:** «не звоните нам — мы сами вам позвоним». Родитель вызывает подкласс, не наоборот.

**Отличие от Стратегии:** шаблонный метод изменяет часть алгоритма через **наследование**. Стратегия заменяет алгоритм целиком через **делегирование**.

**Участники:** `AbstractClass`, `ConcreteClass`.

**Применять когда:** нужно зафиксировать скелет алгоритма, позволив подклассам уточнить отдельные шаги; нужно вынести общий код из нескольких подклассов.

### Посредник

**Задача:** определить объект, инкапсулирующий взаимодействие множества объектов. Объекты знают только о посреднике.

> Авиадиспетчер. Самолёты не договариваются друг с другом напрямую — все команды через диспетчера.

```python
from abc import ABC, abstractmethod

class Mediator(ABC):
    @abstractmethod
    def notify(self, sender, event: str): ...

class Component:
    def __init__(self, mediator: Mediator):
        self._mediator = mediator

class Button(Component):
    def click(self):
        print("Button: клик")
        self._mediator.notify(self, "click")

class TextBox(Component):
    def __init__(self, mediator):
        super().__init__(mediator)
        self.text = ""

class CheckBox(Component):
    def __init__(self, mediator):
        super().__init__(mediator)
        self.checked = False

    def toggle(self):
        self.checked = not self.checked
        self._mediator.notify(self, "toggle")

class LoginDialog(Mediator):
    def __init__(self):
        self.username = TextBox(self)
        self.password = TextBox(self)
        self.remember_me = CheckBox(self)
        self.ok_button = Button(self)

    def notify(self, sender, event):
        if sender is self.remember_me and event == "toggle":
            if self.remember_me.checked:
                print("Показать поле 'Сохранить пароль'")
            else:
                print("Скрыть поле 'Сохранить пароль'")
        elif sender is self.ok_button and event == "click":
            print(f"Войти как {self.username.text}")

dialog = LoginDialog()
dialog.username.text = "ivan"
dialog.remember_me.toggle()   # Посредник решает, что обновить
dialog.ok_button.click()      # Посредник координирует действие
```

**Участники:** `Mediator`, `ConcreteMediator`, `Colleague`.

**Плюсы:** снижает число зависимостей; централизует логику взаимодействия.

**Минусы:** посредник может разрастись в сложный монолит.

**Применять когда:** объекты связаны сложными зависимостями; сложно переиспользовать объект из-за его связей с другими.

### Хранитель

**Задача:** без нарушения инкапсуляции зафиксировать внутреннее состояние объекта, чтобы позднее можно было его восстановить.

> Снимок (snapshot) в виртуальной машине. Откат к сохранённому состоянию без знания его внутреннего устройства.

```python
class Memento:
    def __init__(self, state: dict):
        self.__state = state.copy()   # приватно — только Originator видит

    def _restore(self) -> dict:
        return self.__state.copy()

class TextEditor:                     # Originator — хозяин состояния
    def __init__(self):
        self._content = ""
        self._cursor = 0

    def type(self, text: str):
        self._content += text
        self._cursor = len(self._content)

    def save(self) -> Memento:        # создать снимок
        return Memento({"content": self._content, "cursor": self._cursor})

    def restore(self, memento: Memento):  # восстановить из снимка
        state = memento._restore()
        self._content = state["content"]
        self._cursor = state["cursor"]

    @property
    def text(self): return self._content

class History:                        # Caretaker — хранит снимки, не знает содержимого
    def __init__(self, editor: TextEditor):
        self._editor = editor
        self._snapshots: list[Memento] = []

    def backup(self):
        self._snapshots.append(self._editor.save())

    def undo(self):
        if not self._snapshots:
            return
        self._editor.restore(self._snapshots.pop())

editor = TextEditor()
history = History(editor)

editor.type("Hello")
history.backup()

editor.type(" World")
history.backup()

editor.type(" broken!")
print(editor.text)   # → "Hello World broken!"

history.undo()
print(editor.text)   # → "Hello World"

history.undo()
print(editor.text)   # → "Hello"
```

**Участники:** `Memento`, `Originator` (хозяин), `Caretaker` (посыльный).

**Применять когда:** нужно сохранить снимок состояния для восстановления; прямое раскрытие состояния нарушало бы инкапсуляцию.

### Посетитель

**Задача:** описать операцию, выполняемую над каждым объектом структуры. Позволяет добавить новую операцию без изменения классов объектов.

> Налоговый инспектор проверяет разные типы имущества. Новый вид налога — новый инспектор, а не изменение классов «квартира», «машина», «бизнес».

```python
from abc import ABC, abstractmethod

class Visitor(ABC):
    @abstractmethod
    def visit_file(self, file): ...
    @abstractmethod
    def visit_folder(self, folder): ...

class FileSystemItem(ABC):
    @abstractmethod
    def accept(self, visitor: Visitor): ...

class File(FileSystemItem):
    def __init__(self, name: str, size: int):
        self.name = name
        self.size = size

    def accept(self, visitor):
        visitor.visit_file(self)    # двойная диспетчеризация

class Folder(FileSystemItem):
    def __init__(self, name: str):
        self.name = name
        self._children: list[FileSystemItem] = []

    def add(self, item): self._children.append(item)

    def accept(self, visitor):
        visitor.visit_folder(self)
        for child in self._children:
            child.accept(visitor)   # рекурсия — посетитель обходит всё дерево

# Добавляем новые операции без изменения File и Folder:
class SizeCalculator(Visitor):
    def __init__(self): self.total = 0
    def visit_file(self, file): self.total += file.size
    def visit_folder(self, folder): pass   # папки не имеют размера напрямую

class FileSearcher(Visitor):
    def __init__(self, extension: str):
        self.extension = extension
        self.found: list[File] = []

    def visit_file(self, file):
        if file.name.endswith(self.extension):
            self.found.append(file)

    def visit_folder(self, folder): pass

# Структура:
root = Folder("root")
src = Folder("src")
src.add(File("main.py", 2048))
src.add(File("utils.py", 1024))
root.add(src)
root.add(File("README.md", 512))
root.add(File("config.json", 256))

# Применяем посетителей:
size_calc = SizeCalculator()
root.accept(size_calc)
print(f"Итого: {size_calc.total} байт")   # → 3840

searcher = FileSearcher(".py")
root.accept(searcher)
print([f.name for f in searcher.found])   # → ['main.py', 'utils.py']
```

**Двойная диспетчеризация:** вызываемая операция зависит и от типа элемента (`File`), и от типа посетителя (`SizeCalculator`). Достигается через `accept()` + виртуальный `visit_*()`.

**Участники:** `Visitor`, `ConcreteVisitor`, `Element`, `ConcreteElement`, `ObjectStructure`.

**Плюсы:** легко добавлять операции без изменения элементов; родственные операции локализованы в одном классе.

**Минусы:** трудно добавлять новые классы элементов — нужно обновить все посетители; элементы должны открыть достаточно интерфейса.

**Применять когда:** структура объектов стабильна, но операции над ней часто меняются; нужны разнородные операции над объектами разных классов.

### Интерпретатор

**Задача:** для заданного языка определить представление его грамматики и интерпретатор предложений этого языка.

> SQL-запрос. `SELECT * FROM users WHERE age > 18` — предложение языка. Интерпретатор разбирает его и выполняет.

```python
from abc import ABC, abstractmethod

class Expression(ABC):
    @abstractmethod
    def interpret(self, context: dict) -> bool: ...

class Variable(Expression):
    def __init__(self, name): self._name = name
    def interpret(self, ctx): return ctx.get(self._name, False)

class Constant(Expression):
    def __init__(self, value): self._value = value
    def interpret(self, ctx): return self._value

class AndExpression(Expression):
    def __init__(self, left, right):
        self._left, self._right = left, right
    def interpret(self, ctx):
        return self._left.interpret(ctx) and self._right.interpret(ctx)

class OrExpression(Expression):
    def __init__(self, left, right):
        self._left, self._right = left, right
    def interpret(self, ctx):
        return self._left.interpret(ctx) or self._right.interpret(ctx)

class NotExpression(Expression):
    def __init__(self, expr): self._expr = expr
    def interpret(self, ctx): return not self._expr.interpret(ctx)

# Построение дерева: (admin OR editor) AND NOT banned
expr = AndExpression(
    OrExpression(Variable("admin"), Variable("editor")),
    NotExpression(Variable("banned"))
)

print(expr.interpret({"admin": True, "banned": False}))   # → True
print(expr.interpret({"editor": True, "banned": True}))   # → False
print(expr.interpret({"admin": False, "editor": False}))  # → False
```

**Участники:** `AbstractExpression`, `TerminalExpression`, `NonterminalExpression`, `Context`, `Client`.

**Применять когда:** грамматика проста; добавление операций над грамматикой важнее добавления правил.

### Сравнение паттернов поведения

|Паттерн|Что инкапсулирует|Ключевая идея|
|---|---|---|
|**Цепочка обязанностей**|Обработчики запроса|Запрос идёт по цепочке до обработчика|
|**Команда**|Запрос как объект|Отмена, очередь, логирование|
|**Интерпретатор**|Правило грамматики|Дерево классов = грамматика|
|**Итератор**|Механизм обхода|Обход без раскрытия структуры|
|**Посредник**|Протокол взаимодействия|Объекты знают только посредника|
|**Хранитель**|Снимок состояния|Сохранить и восстановить без раскрытия|
|**Наблюдатель**|Зависимость «один ко многим»|Автоматическое уведомление подписчиков|
|**Состояние**|Поведение по состоянию|Каждое состояние — отдельный класс|
|**Стратегия**|Алгоритм|Взаимозаменяемые алгоритмы|
|**Шаблонный метод**|Скелет алгоритма|Подклассы уточняют шаги|
|**Посетитель**|Операция над структурой|Новые операции без изменения классов|

**Паттерны, разделяющие отправителя и получателя:** Команда, Наблюдатель, Посредник, Цепочка обязанностей — разными способами.

**Классическое трио:** Компоновщик + Итератор + Посетитель — для обхода и обработки структур.
