# Порождающие паттерны

> **Порождающие паттерны** абстрагируют процесс создания объектов. Система перестаёт зависеть от того, как объекты создаются — она знает только их интерфейсы. Вместо жёстко прописанного `ConcreteClass()` — создание через абстракцию.

Связанные файлы: [Паттерны проектирования](../../ООП/Паттерны/Паттерны%20проектирования.md) · [Структурные паттерны](../../ООП/Паттерны/Структурные%20паттерны.md) · [Абстракция Python](../../ООП/Принципы/Абстракция%20Python.md)

### Абстрактная фабрика

**Задача:** создать семейство взаимосвязанных объектов без указания конкретных классов.

> Завод по производству мебели. Фабрика IKEA делает стул, стол, диван — всё в одном стиле. Меняешь фабрику — меняется всё семейство сразу.

```python
from abc import ABC, abstractmethod

# Абстрактная фабрика — определяет семейство продуктов
class UIFactory(ABC):
    @abstractmethod
    def create_button(self): ...
    @abstractmethod
    def create_checkbox(self): ...

# Конкретные фабрики — каждая производит своё семейство
class WindowsFactory(UIFactory):
    def create_button(self):
        return WindowsButton()
    def create_checkbox(self):
        return WindowsCheckbox()

class MacOSFactory(UIFactory):
    def create_button(self):
        return MacOSButton()
    def create_checkbox(self):
        return MacOSCheckbox()

# Клиент работает только через абстракцию
def build_ui(factory: UIFactory):
    btn = factory.create_button()     # не знает, какой именно Button
    chk = factory.create_checkbox()
    btn.render()
    chk.render()

# Смена темы оформления — одна строка:
build_ui(WindowsFactory())
build_ui(MacOSFactory())
```

**Участники:** `AbstractFactory`, `ConcreteFactory`, `AbstractProduct`, `ConcreteProduct`, `Client`.

**Плюсы:** изолирует конкретные классы от клиента; гарантирует совместимость продуктов одного семейства; замена семейства — одна строка.

**Минусы:** добавить новый вид продукта в семейство — надо менять интерфейс базовой фабрики и все подклассы.

**Применять когда:** система не должна зависеть от способа создания объектов; нужна гарантия, что объекты одного семейства используются вместе.

### Строитель

**Задача:** отделить конструирование сложного объекта от его представления. Один и тот же процесс конструирования — разные результаты.

> RTF-конвертер. Парсер RTF один и тот же, но в зависимости от переданного конвертора на выходе — ASCII, TeX или виджет.

```python
from abc import ABC, abstractmethod

class QueryBuilder(ABC):
    @abstractmethod
    def select(self, *fields): ...
    @abstractmethod
    def where(self, condition): ...
    @abstractmethod
    def limit(self, n): ...
    @abstractmethod
    def build(self): ...

class SQLBuilder(QueryBuilder):
    def __init__(self):
        self._parts = {"select": "*", "where": [], "limit": None}

    def select(self, *fields):
        self._parts["select"] = ", ".join(fields)
        return self   # для цепочки вызовов

    def where(self, condition):
        self._parts["where"].append(condition)
        return self

    def limit(self, n):
        self._parts["limit"] = n
        return self

    def build(self):
        q = f"SELECT {self._parts['select']} FROM table"
        if self._parts["where"]:
            q += " WHERE " + " AND ".join(self._parts["where"])
        if self._parts["limit"]:
            q += f" LIMIT {self._parts['limit']}"
        return q

class MongoBuilder(QueryBuilder):
    """Тот же интерфейс — другой результат (словарь для pymongo)"""
    def __init__(self):
        self._query = {}
        self._fields = None
        self._limit_val = None

    def select(self, *fields):
        self._fields = {f: 1 for f in fields}
        return self

    def where(self, condition):
        # упрощённо: condition = "age > 18"
        self._query.update({"$expr": condition})
        return self

    def limit(self, n):
        self._limit_val = n
        return self

    def build(self):
        return {"filter": self._query, "projection": self._fields, "limit": self._limit_val}

# Распорядитель — управляет процессом, не зависит от конкретного строителя
class Director:
    def build_user_query(self, builder: QueryBuilder):
        return (builder
                .select("id", "name", "email")
                .where("active = 1")
                .limit(100)
                .build())

director = Director()
sql = director.build_user_query(SQLBuilder())
# → "SELECT id, name, email FROM table WHERE active = 1 LIMIT 100"
mongo = director.build_user_query(MongoBuilder())
# → {"filter": ..., "projection": ..., "limit": 100}
```

**Участники:** `Builder`, `ConcreteBuilder`, `Director` (распорядитель), `Product`.

**Отличие от Абстрактной фабрики:** фабрика создаёт семейство объектов сразу. Строитель — шаг за шагом, продукт забирается в конце. Строитель лучше для сложных объектов, где важен порядок сборки.

**Применять когда:** алгоритм конструирования не должен зависеть от частей объекта; нужны разные представления одного и того же процесса конструирования.

### Фабричный метод

**Задача:** определить интерфейс для создания объекта, но дать подклассам решение — экземпляр какого класса создавать.

> Каркас приложения умеет открывать документы, но не знает их тип. `DrawingApp` создаёт `DrawDocument`. `TextApp` создаёт `TextDocument`. Каркас вызывает фабричный метод — подкласс решает.

```python
from abc import ABC, abstractmethod

class Notification(ABC):
    @abstractmethod
    def send(self, message: str): ...

class EmailNotification(Notification):
    def __init__(self, address): self.address = address
    def send(self, message):
        print(f"Email → {self.address}: {message}")

class SMSNotification(Notification):
    def __init__(self, phone): self.phone = phone
    def send(self, message):
        print(f"SMS → {self.phone}: {message}")

class SlackNotification(Notification):
    def __init__(self, channel): self.channel = channel
    def send(self, message):
        print(f"Slack #{self.channel}: {message}")

# Creator — содержит фабричный метод
class NotificationService(ABC):
    @abstractmethod
    def create_notification(self) -> Notification:
        """Фабричный метод — точка расширения"""
        ...

    def notify(self, message: str):     # использует фабричный метод
        n = self.create_notification()  # не знает, какой именно Notification
        n.send(message)

# ConcreteCreator — переопределяет фабричный метод
class EmailService(NotificationService):
    def __init__(self, address): self.address = address
    def create_notification(self):
        return EmailNotification(self.address)

class SMSService(NotificationService):
    def __init__(self, phone): self.phone = phone
    def create_notification(self):
        return SMSNotification(self.phone)

# Клиент работает через базовый тип
def alert_user(service: NotificationService):
    service.notify("Ваш заказ готов")

alert_user(EmailService("user@example.com"))
alert_user(SMSService("+7 999 123 45 67"))
```

**Участники:** `Product`, `ConcreteProduct`, `Creator`, `ConcreteCreator`.

**Отличие от Абстрактной фабрики:** фабричный метод — один метод в классе. Абстрактная фабрика — отдельный объект с несколькими методами. Абстрактная фабрика часто реализована через несколько фабричных методов.

**Применять когда:** класс заранее не знает, объекты каких классов создавать; хочется передать это решение подклассам.

### Прототип

**Задача:** задать виды создаваемых объектов через экземпляр-прототип. Новые объекты создаются копированием прототипа.

> Штамп на бумаге. Есть готовый оттиск — клонируй его сколько угодно раз, не зная деталей изготовления.

```python
import copy
from abc import ABC, abstractmethod

class Shape(ABC):
    def __init__(self):
        self.color = "white"
        self.x = self.y = 0

    @abstractmethod
    def clone(self): ...

    def __repr__(self):
        return f"{type(self).__name__}(color={self.color}, x={self.x}, y={self.y})"

class Circle(Shape):
    def __init__(self, radius=0):
        super().__init__()
        self.radius = radius

    def clone(self):
        return copy.copy(self)   # поверхностная копия достаточна

class Rectangle(Shape):
    def __init__(self, width=0, height=0):
        super().__init__()
        self.width = width
        self.height = height

    def clone(self):
        return copy.deepcopy(self)  # глубокая копия для вложенных объектов

# Реестр прототипов — хранит готовые экземпляры
class ShapeRegistry:
    def __init__(self):
        self._prototypes: dict[str, Shape] = {}

    def register(self, name: str, shape: Shape):
        self._prototypes[name] = shape

    def create(self, name: str) -> Shape:
        proto = self._prototypes.get(name)
        if not proto:
            raise KeyError(f"прототип {name!r} не зарегистрирован")
        return proto.clone()

# Регистрируем прототипы
registry = ShapeRegistry()
big_red = Circle(50)
big_red.color = "red"
registry.register("big_red_circle", big_red)

# Создание через клонирование — не нужно знать класс
c1 = registry.create("big_red_circle")
c2 = registry.create("big_red_circle")
c1.x = 10   # меняем только c1 — c2 не затронут
```

**Участники:** `Prototype`, `ConcretePrototype`, `Client`.

**Плюсы:** не нужно плодить подклассы фабрики; добавление и удаление продуктов в рантайме; клонирование сложных объектов без знания их классов.

**Минусы:** реализация `clone()` нетривиальна при циклических ссылках.

**Применять когда:** классы создаваемых экземпляров определяются в рантайме; нужно избежать параллельной иерархии фабрик.

### Одиночка

**Задача:** гарантировать, что у класса существует только один экземпляр, и предоставить к нему глобальную точку доступа.

> Президент страны. В один момент времени он только один — любой гражданин обращается к одному и тому же экземпляру.

```python
# Вариант 1 — через __new__:
class Config:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
            cls._instance._initialized = False
        return cls._instance

    def __init__(self):
        if self._initialized:
            return
        self.debug = False
        self.db_url = "sqlite:///app.db"
        self._initialized = True

a = Config()
b = Config()
assert a is b   # один и тот же объект

# Вариант 2 — через декоратор (более питонический):
def singleton(cls):
    instances = {}
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return get_instance

@singleton
class Logger:
    def __init__(self):
        self.log = []

    def write(self, message):
        self.log.append(message)

# Вариант 3 — через модуль (самый питонический):
# settings.py — модуль загружается один раз, сам по себе одиночка
# import settings → всегда один и тот же объект модуля
```

**Участники:** `Singleton`.

**Плюсы:** контролируемый доступ к единственному экземпляру; не засоряет пространство имён глобальными переменными.

**Минусы:** усложняет тестирование (глобальное состояние); в многопоточной среде требует синхронизации; нарушает принцип единственной ответственности.

> **Почему Singleton часто называют антипаттерном.** По сути это **глобальная переменная в маскировке**: класс тайно тянет общий объект (скрытая зависимость — не видно из сигнатуры), общее изменяемое состояние течёт между вызовами и тестами (тесты становятся хрупкими и зависят от порядка), в многопоточности нужна блокировка. Питоничная альтернатива — не прятать единственность в классе, а создать объект **один раз** и **передавать** его через [внедрение зависимостей (DI)](../../ООП/Принципы/Принципы%20разработки%20—%20DRY,%20KISS,%20DI.md#di-против-dip--техника-против-принципа); либо использовать модуль (вариант 3) — он и так загружается один раз.

**Применять когда:** нужен ровно один экземпляр класса, доступный из любой точки системы — конфиг, пул соединений, логгер.

### Сравнение порождающих паттернов

|Паттерн|Кто создаёт|Как параметризуется|Гибкость|
|---|---|---|---|
|**Фабричный метод**|Подкласс Creator|Переопределение метода|Просто, но порождает много подклассов|
|**Абстрактная фабрика**|Отдельный объект-фабрика|Подмена объекта фабрики|Семейства, но сложно добавить продукт|
|**Строитель**|Отдельный объект-строитель|Подмена строителя|Шаговая сборка, разные представления|
|**Прототип**|Сам объект через `clone()`|Подмена прототипа|Не нужны иерархии фабрик, но нужен `clone()`|
|**Одиночка**|Сам класс|—|Единственный экземпляр|
