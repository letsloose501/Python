# Структурные паттерны

> **Структурные паттерны** отвечают на вопрос: как из классов и объектов собираются более крупные структуры? Паттерны уровня класса используют наследование, уровня объектов — композицию в рантайме (это гибче).

Связанные файлы: [Паттерны проектирования](../../ООП/Паттерны/Паттерны%20проектирования.md) · [Порождающие паттерны](../../ООП/Паттерны/Порождающие%20паттерны.md) · [Паттерны поведения](../../ООП/Паттерны/Паттерны%20поведения.md)

### Адаптер

**Задача:** преобразовать интерфейс одного класса в другой, ожидаемый клиентом. Совместная работа несовместимых интерфейсов.

> Переходник для розетки. Прибор с евровилкой — существующий класс. Британская розетка — целевой интерфейс. Переходник — адаптер. Ни вилку, ни розетку переделывать не нужно.

```python
# Существующий класс с несовместимым интерфейсом (Adaptee):
class OldPaymentSystem:
    def make_payment(self, amount_cents: int, currency_code: str) -> dict:
        return {"status": "ok", "paid": amount_cents / 100}

# Целевой интерфейс, который ожидает клиент (Target):
class PaymentGateway:
    def pay(self, amount: float, currency: str) -> bool: ...

# Адаптер объекта — Target снаружи, Adaptee внутри (предпочтительный вариант):
class PaymentAdapter(PaymentGateway):
    def __init__(self, old_system: OldPaymentSystem):
        self._old = old_system

    def pay(self, amount: float, currency: str) -> bool:
        cents = int(amount * 100)           # преобразуем интерфейс
        result = self._old.make_payment(cents, currency.upper())
        return result["status"] == "ok"

# Клиент работает только с PaymentGateway:
def checkout(gateway: PaymentGateway, total: float):
    success = gateway.pay(total, "rub")
    print("Оплачено" if success else "Ошибка")

checkout(PaymentAdapter(OldPaymentSystem()), 299.99)
```

**Адаптер класса** — через множественное наследование. Адаптер объекта — через композицию. Адаптер объекта предпочтительнее: не привязан к конкретному классу, работает с подклассами.

**Участники:** `Target`, `Adaptee`, `Adapter`, `Client`.

**Применять когда:** нужно использовать существующий класс, но его интерфейс не подходит; нужна совместная работа заранее неизвестных классов.

### Мост

**Задача:** отделить абстракцию от реализации, чтобы обе могли изменяться независимо.

> Пульт управления (абстракция) и телевизор (реализация). Один пульт — разные модели телевизоров. Новый телевизор не требует нового пульта.

Без Моста: при добавлении нового вида (например, `IconWindow`) и новой платформы (Mac) — нужен `MacIconWindow`, `XIconWindow`, `PMIconWindow`. Классов `виды × платформы`.

С Мостом — две независимые иерархии, связанные ссылкой:

```python
from abc import ABC, abstractmethod

# Иерархия реализации (Implementor):
class Renderer(ABC):
    @abstractmethod
    def render_circle(self, x, y, radius): ...
    @abstractmethod
    def render_rect(self, x, y, w, h): ...

class VectorRenderer(Renderer):
    def render_circle(self, x, y, radius):
        print(f"SVG: <circle cx={x} cy={y} r={radius}/>")
    def render_rect(self, x, y, w, h):
        print(f"SVG: <rect x={x} y={y} width={w} height={h}/>")

class RasterRenderer(Renderer):
    def render_circle(self, x, y, radius):
        print(f"Pixels: drawing circle at ({x},{y}) r={radius}")
    def render_rect(self, x, y, w, h):
        print(f"Pixels: drawing rect ({x},{y}) {w}x{h}")

# Иерархия абстракции (Abstraction):
class Shape(ABC):
    def __init__(self, renderer: Renderer):
        self._renderer = renderer  # мост к реализации

    @abstractmethod
    def draw(self): ...

class Circle(Shape):
    def __init__(self, renderer, x, y, radius):
        super().__init__(renderer)
        self.x, self.y, self.radius = x, y, radius

    def draw(self):
        self._renderer.render_circle(self.x, self.y, self.radius)

class Rect(Shape):
    def __init__(self, renderer, x, y, w, h):
        super().__init__(renderer)
        self.x, self.y, self.w, self.h = x, y, w, h

    def draw(self):
        self._renderer.render_rect(self.x, self.y, self.w, self.h)

# Комбинируем независимо:
Circle(VectorRenderer(), 5, 5, 10).draw()   # SVG-круг
Circle(RasterRenderer(), 5, 5, 10).draw()   # пиксельный круг
Rect(VectorRenderer(), 0, 0, 20, 15).draw() # SVG-прямоугольник
# Добавляем новый вид — не трогаем Renderer:
# Добавляем новую платформу — не трогаем Shape:
```

**Участники:** `Abstraction`, `RefinedAbstraction`, `Implementor`, `ConcreteImplementor`.

**Отличие от Адаптера:** адаптер — для уже существующих несовместимых классов. Мост — проектируется с нуля, когда заранее известно, что оба измерения будут развиваться независимо.

**Применять когда:** нужно избежать взрыва подклассов от двух независимо меняющихся измерений; реализация должна выбираться в рантайме.

### Компоновщик

**Задача:** компоновать объекты в древовидные структуры «часть — целое». Клиент работает с единичным объектом и группой одинаково.

> Файловая система. Файл и папка — разные сущности, но к обоим можно применить `get_size()` и `delete()`. Папка рекурсивно делегирует содержимому.

```python
from abc import ABC, abstractmethod

class FileSystemItem(ABC):             # Component — общий интерфейс
    def __init__(self, name: str):
        self.name = name

    @abstractmethod
    def get_size(self) -> int: ...

    @abstractmethod
    def display(self, indent=0): ...

class File(FileSystemItem):            # Leaf — лист, без потомков
    def __init__(self, name, size):
        super().__init__(name)
        self._size = size

    def get_size(self): return self._size

    def display(self, indent=0):
        print(" " * indent + f"📄 {self.name} ({self._size} b)")

class Folder(FileSystemItem):          # Composite — составной объект
    def __init__(self, name):
        super().__init__(name)
        self._children: list[FileSystemItem] = []

    def add(self, item: FileSystemItem):
        self._children.append(item)

    def remove(self, item: FileSystemItem):
        self._children.remove(item)

    def get_size(self):
        return sum(c.get_size() for c in self._children)  # рекурсия

    def display(self, indent=0):
        print(" " * indent + f"📁 {self.name}/")
        for child in self._children:
            child.display(indent + 2)   # без isinstance — единый интерфейс

# Клиент не знает: работает с файлом или папкой
root = Folder("root")
src = Folder("src")
src.add(File("main.py", 1024))
src.add(File("utils.py", 512))
root.add(src)
root.add(File("README.md", 256))

root.display()
# → 📁 root/
# →   📁 src/
# →     📄 main.py (1024 b)
# →     📄 utils.py (512 b)
# →   📄 README.md (256 b)

print(root.get_size())   # → 1792 — рекурсивно посчитал всё дерево
```

**Участники:** `Component`, `Leaf`, `Composite`, `Client`.

**Плюсы:** клиент единообразен; легко добавлять новые виды компонентов.

**Минусы:** сложно ограничить, какие объекты могут быть потомками — только проверки в рантайме.

**Применять когда:** нужна иерархия «часть — целое»; клиент должен одинаково работать с одиночными и составными объектами.

### Декоратор

**Задача:** динамически добавить объекту новые обязанности. Гибкая альтернатива наследованию.

> Кофе с добавками. Базовый кофе — компонент. Молоко, сахар, карамель — декораторы. Любые комбинации без класса `КофеСМолокомСахаромКарамелью`.

```python
from abc import ABC, abstractmethod

class DataSource(ABC):
    @abstractmethod
    def write(self, data: str): ...
    @abstractmethod
    def read(self) -> str: ...

class FileDataSource(DataSource):       # ConcreteComponent
    def __init__(self, filename):
        self._filename = filename

    def write(self, data):
        with open(self._filename, "w") as f:
            f.write(data)

    def read(self):
        with open(self._filename) as f:
            return f.read()

class DataSourceDecorator(DataSource):  # базовый Decorator
    def __init__(self, wrappee: DataSource):
        self._wrappee = wrappee

    def write(self, data):
        self._wrappee.write(data)       # делегируем

    def read(self):
        return self._wrappee.read()

class EncryptionDecorator(DataSourceDecorator):
    def write(self, data):
        encrypted = data[::-1]          # упрощённо
        self._wrappee.write(encrypted)

    def read(self):
        return self._wrappee.read()[::-1]

class CompressionDecorator(DataSourceDecorator):
    def write(self, data):
        import zlib, base64
        compressed = base64.b64encode(zlib.compress(data.encode())).decode()
        self._wrappee.write(compressed)

    def read(self):
        import zlib, base64
        raw = self._wrappee.read()
        return zlib.decompress(base64.b64decode(raw)).decode()

# Обёртки вкладываются произвольно:
source = FileDataSource("data.txt")
encrypted = EncryptionDecorator(source)
compressed_encrypted = CompressionDecorator(encrypted)

compressed_encrypted.write("Secret data")
print(compressed_encrypted.read())   # → "Secret data"
# Снаружи — тот же интерфейс DataSource
```

**Python-экосистема:** декоратор — родной паттерн для Python. `@functools.wraps`, `@property`, `@staticmethod` — всё это декораторы функций, работающие по тому же принципу.

**Участники:** `Component`, `ConcreteComponent`, `Decorator`, `ConcreteDecorator`.

**Плюсы:** добавление обязанностей в рантайме; нет взрыва подклассов; можно добавить одно свойство дважды.

**Минусы:** много мелких похожих объектов; декорированный объект не идентичен исходному (`decorated is not source`).

**Применять когда:** нужно динамически добавлять или снимать обязанности объекта; расширение наследованием неудобно (много комбинаций).

### Фасад

**Задача:** предоставить единый упрощённый интерфейс к сложной подсистеме.

> Кнопка «Завариться» на кофемашине. Внутри — помол, нагрев воды, давление, дозирование. Пользователю видна одна кнопка.

```python
# Сложная подсистема (много классов):
class VideoConverter:
    def convert(self, filename, format): ...

class AudioMixer:
    def fix(self, audio): ...

class CodecFactory:
    def extract(self, filename): ...

class BitrateReader:
    def read(self, filename, codec): ...

class OggCompressionCodec:
    def compress(self, data): ...

class MPEG4CompressionCodec:
    def compress(self, data): ...

# Фасад — единая точка входа:
class VideoConversionFacade:
    def convert(self, filename: str, format: str) -> str:
        """Клиенту нужен только этот метод"""
        codec_factory = CodecFactory()
        source_codec = codec_factory.extract(filename)

        if format == "mp4":
            dest_codec = MPEG4CompressionCodec()
        else:
            dest_codec = OggCompressionCodec()

        buffer = BitrateReader().read(filename, source_codec)
        result = AudioMixer().fix(buffer)
        return VideoConverter().convert(result, dest_codec)

# Клиент не знает про CodecFactory, BitrateReader и т.д.:
facade = VideoConversionFacade()
output = facade.convert("movie.avi", "mp4")
# Но те, кому нужен низкий уровень, могут обратиться напрямую
```

**Участники:** `Facade`, классы подсистемы.

**Плюсы:** изолирует клиентов от деталей; уменьшает связанность; упрощает использование по умолчанию. Не запрещает прямой доступ к подсистеме — это особенность, а не минус.

**Применять когда:** нужен простой интерфейс к сложной подсистеме; много зависимостей между клиентами и подсистемой; хочется разложить систему на уровни.

### Приспособленец

**Задача:** применить совместное использование объектов для поддержки большого числа мелких объектов с минимальными затратами памяти.

> Буквы в книге. Буква 'A' встречается тысячи раз, но сам символ — один. Положение каждого конкретного 'A' на странице — внешнее состояние, передаётся при печати.

Ключевая идея — разделение состояния на **внутреннее** (хранится в объекте, не зависит от контекста, делится) и **внешнее** (зависит от контекста, передаётся при вызове):

```python
import sys

# Без Приспособленца: каждая частица — отдельный объект
class HeavyParticle:
    def __init__(self, x, y, velocity, color, sprite):
        self.x, self.y = x, y
        self.velocity = velocity
        self.color = color           # внутреннее — одинаково для многих
        self.sprite = sprite         # внутреннее — тяжёлый объект

# 1 000 000 частиц = 1 000 000 объектов со sprite

# С Приспособленцем:
class ParticleType:                  # Flyweight — внутреннее состояние
    def __init__(self, color, sprite):
        self.color = color           # общее для всех частиц типа
        self.sprite = sprite         # тяжёлый объект — хранится ОДИН раз

    def draw(self, x, y, velocity):  # внешнее состояние передаётся снаружи
        print(f"Draw {self.color} particle at ({x},{y}) v={velocity}")

class ParticleFactory:               # FlyweightFactory — пул типов
    _types: dict[str, ParticleType] = {}

    @classmethod
    def get_type(cls, color: str, sprite) -> ParticleType:
        key = f"{color}_{id(sprite)}"
        if key not in cls._types:
            cls._types[key] = ParticleType(color, sprite)
            print(f"Создан новый тип: {color}")
        return cls._types[key]

class Particle:                      # хранит только внешнее состояние
    def __init__(self, x, y, velocity, color, sprite):
        self.x, self.y = x, y
        self.velocity = velocity
        self.type = ParticleFactory.get_type(color, sprite)  # ссылка на общий

    def draw(self):
        self.type.draw(self.x, self.y, self.velocity)

# 1 000 000 частиц, но только несколько объектов-типов в памяти
```

**Участники:** `Flyweight`, `ConcreteFlyweight`, `FlyweightFactory`, `Client`.

**Плюсы:** резкое сокращение числа объектов и расхода памяти.

**Минусы:** усложняет код; внешнее состояние нужно вычислять или передавать — затраты CPU.

**Применять когда:** очень много объектов; затраты на хранение высоки; большую часть состояния можно вынести во внешнее.

### Заместитель

**Задача:** заменить объект суррогатом, который контролирует доступ к нему.

> Менеджер по работе с клиентами. Вы работаете с ним, не с директором напрямую. Он может сразу ответить на простые вопросы (кэш), записать вас (отложенная инициализация) или проверить ваши права.

Четыре вида заместителей:

|Вид|Что делает|
|---|---|
|**Виртуальный**|Создаёт тяжёлый объект только при первом обращении|
|**Удалённый**|Локальный представитель для объекта в другом адресном пространстве|
|**Защищающий**|Контролирует права доступа|
|**Умная ссылка**|Подсчёт ссылок, блокировки, логирование|

```python
from abc import ABC, abstractmethod

class Database(ABC):
    @abstractmethod
    def query(self, sql: str) -> list: ...

class RealDatabase(Database):
    def __init__(self, connection_string):
        print(f"Подключение к БД: {connection_string}")  # тяжёлая операция
        self._conn = connection_string

    def query(self, sql):
        print(f"Выполняю: {sql}")
        return [{"id": 1, "name": "test"}]

# Виртуальный заместитель — ленивая инициализация + кэш:
class CachedDatabaseProxy(Database):
    def __init__(self, connection_string):
        self._conn_str = connection_string
        self._db = None              # реальная БД ещё не создана
        self._cache: dict[str, list] = {}

    def _get_db(self) -> RealDatabase:
        if self._db is None:
            self._db = RealDatabase(self._conn_str)  # создаём при первом запросе
        return self._db

    def query(self, sql):
        if sql not in self._cache:
            self._cache[sql] = self._get_db().query(sql)
        else:
            print(f"Из кэша: {sql}")
        return self._cache[sql]

# Защищающий заместитель — контроль прав:
class AccessControlProxy(Database):
    def __init__(self, db: Database, role: str):
        self._db = db
        self._role = role

    def query(self, sql):
        if sql.strip().upper().startswith("DROP") and self._role != "admin":
            raise PermissionError("DROP разрешён только администраторам")
        return self._db.query(sql)

# Клиент работает через интерфейс Database — не знает, есть ли прокси:
def run_report(db: Database):
    return db.query("SELECT * FROM orders")

proxy = CachedDatabaseProxy("postgresql://localhost/mydb")
run_report(proxy)   # → подключится к БД, выполнит запрос
run_report(proxy)   # → из кэша
```

**Участники:** `Subject`, `RealSubject`, `Proxy`.

**Отличие от Декоратора:** декоратор добавляет обязанности; заместитель контролирует доступ. Интерфейс заместителя — точная копия интерфейса субъекта.

**Отличие от Адаптера:** адаптер меняет интерфейс; заместитель его повторяет.

**Применять когда:** прямой доступ к объекту неудобен или нежелателен — объект тяжёлый, удалённый, требует защиты.

### Сравнение структурных паттернов

|Паттерн|Что делает|Меняет интерфейс?|
|---|---|---|
|**Адаптер**|Совмещает несовместимые интерфейсы|Да|
|**Мост**|Разделяет абстракцию и реализацию|Нет|
|**Компоновщик**|Дерево «часть — целое»|Нет|
|**Декоратор**|Добавляет обязанности динамически|Нет|
|**Фасад**|Упрощённый интерфейс к подсистеме|Да (новый)|
|**Приспособленец**|Совместное использование мелких объектов|Нет|
|**Заместитель**|Контролирует доступ к объекту|Нет|

Адаптер, Декоратор и Заместитель внешне похожи — все хранят ссылку на другой объект. Но: Адаптер меняет интерфейс; Декоратор добавляет обязанности через тот же интерфейс; Заместитель контролирует доступ через тот же интерфейс.

> Как паттерны взаимодействуют с поведением объектов: [Паттерны поведения](../../ООП/Паттерны/Паттерны%20поведения.md). Как создаются объекты для структур: [Порождающие паттерны](../../ООП/Паттерны/Порождающие%20паттерны.md).
